01

시스템 확인

설치 스크립트는 운영체제와 프로세서, 그리고 Linux에서는 C 라이브러리(glibc 또는 musl)를 자동으로 감지하여 해당 조합에 맞게 공개된 서명된 빌드만 설치합니다.{{with .Latest}} 각 설치 명령어 아래 줄에는 릴리스 {{.Version}}에서 제공하는 대상 환경이 표시됩니다.{{end}}

Linux와 macOS에는 curl, tar, gzip, openssl이 필요하며(macOS에는 기본 포함), Windows에는 PowerShell만 있으면 됩니다. macOS 11 이상 및 Windows 10 버전 1809 이상은 베타로 지원됩니다. Linux와 macOS에서는 root가 아닌 일반 사용자로 설치 스크립트를 실행하세요. Windows에서도 관리자 권한이 필요하지 않습니다.

02

설치 전 검증

위의 설치 명령어는 프로그램을 교체하기 전에 서명과 아카이브 체크섬을 먼저 검증합니다.

실행하기 전에 설치 스크립트 원본인 install.sh 또는 install.ps1을 직접 확인해 보세요. 오프라인에서 검토하려면 스크립트를 저장해 내용을 살펴본 뒤 sh install.sh를 실행하거나 PowerShell에서 .\install.ps1을 실행하세요.

시스템에 변경되는 사항

단일 실행 파일
Rune은 ~/.local/bin/rune에, Windows에서는 사용자 프로필의 .local\bin\rune.exe에 설치됩니다. root나 관리자 권한이 필요하지 않습니다.
셸 설정 무변경
사용자의 셸 프로필이나 PATH를 임의로 수정하지 않습니다. 설치 폴더가 PATH에 없으면 설치 스크립트가 안내해 줍니다.
라이선스 고지
다른 사용자 데이터 옆인 ~/.local/share/runeagent(Windows는 %LOCALAPPDATA%\RuneAgent)에 저장됩니다.
Rune 데이터
설정, 세션, 암호화된 키는 Rune을 처음 실행할 때 생성되는 홈 디렉터리 내 단일 데이터 폴더에 보관됩니다.
내 모델 계정 사용
제공자 계정이나 지원하는 로컬 엔드포인트를 직접 연결해 사용합니다. Rune에는 기본 제공되는 API 크레딧이 없습니다.

설치 스크립트 옵션

환경 변수를 사용해 버전, 절대 설치 경로 또는 Linux의 C 라이브러리를 지정할 수 있습니다. 변수를 지정하지 않으면 공개된 최신 버전, 사용자 bin 폴더, 자동 감지 설정을 사용합니다. 검토 후 install.sh로 저장한 스크립트에서는 다음과 같이 실행합니다:

RUNE_VERSION=X.Y.Z sh install.sh
RUNE_INSTALL_DIR="$HOME/bin" sh install.sh
RUNE_LIBC=musl sh install.sh

PowerShell에서는 변수를 먼저 설정한 다음 설치 명령어를 실행합니다:

$env:RUNE_VERSION = "X.Y.Z"
irm {{.Origin}}{{url "install.ps1"}} | iex

X.Y.Z를 공개된 버전 번호로 바꾸세요. 위 예시들은 선택 가능한 개별 옵션이며 순서대로 모두 실행해야 하는 단계가 아닙니다. 존재하지 않는 운영체제, 프로세서 또는 라이브러리 아카이브 조합은 거부됩니다.

기존 설치 업데이트

원하는 릴리스에 대해 설치 스크립트를 다시 실행하세요. 별도의 RUNE_INSTALL_DIR을 사용했다면 동일한 경로를 지정하면 됩니다. 다운로드 파일을 검증한 뒤 한 단계로 프로그램을 교체합니다. 완료 후 rune -version으로 버전을 확인하세요.

Linux와 macOS에서는 열려 있는 호환 세션이 유휴 상태일 때 새로 설치된 빌드를 자동으로 채택하며, Windows에서는 다음에 여는 Rune부터 새 빌드가 적용됩니다. 진행 중인 작업을 강제로 종료하지 마세요. 중요한 프로젝트와 Rune 데이터는 별도로 백업해 두는 것이 좋습니다.

“rune: command not found”

설치 스크립트는 파일이 설치된 폴더 경로를 출력합니다. 전체 경로를 입력해 rune을 실행하거나, 해당 폴더를 직접 PATH에 추가하세요. 설치 스크립트는 사용자의 셸 프로필이나 PATH를 절대 수정하지 않습니다. 기본 폴더를 사용하는 경우 ~/.bashrc 또는 ~/.zshrc에 다음 줄을 추가하세요:

export PATH="$HOME/.local/bin:$PATH"

fish 셸에서는 fish_add_path ~/.local/bin을 한 번 실행하면 됩니다. Windows용 PowerShell 명령어는 설치 및 업데이트 문서에 안내되어 있습니다. 설정 후 새 터미널을 여세요.

Rune 제거

진행 중인 작업을 마치거나 중지하고 모든 Rune 창을 닫은 다음, 실행 파일과 라이선스 고지 파일을 삭제하세요. ~/.local/bin 대신 다른 폴더에 설치했다면 해당 경로를 지정하세요.

rm ~/.local/bin/rune
rm -r ~/.local/share/runeagent

Windows에서 Rune 명령어 샌드박스 권한 회수를 포함한 PowerShell 제거 절차는 설치 및 업데이트에서 확인할 수 있습니다. 설정, 세션, 암호화된 키, 복원 데이터는 사용자가 직접 삭제하기 전까지 Rune 데이터 폴더에 그대로 남습니다. 데이터 폴더 위치는 rune -config가 출력하는 첫 번째 줄에 나오므로 프로그램을 제거하기 전에 먼저 확인해 두세요. 해당 폴더를 삭제하면 대화 기록과 복원 지점이 모두 사라지며, 단순 프로그램 제거 시에는 굳이 삭제할 필요가 없습니다.
