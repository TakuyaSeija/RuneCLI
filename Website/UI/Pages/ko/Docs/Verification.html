검증이 확인해 주는 것

설치 스크립트는 먼저 체크섬 목록의 릴리스 서명을 검증한 뒤, 설치 전에 다운로드한 아카이브를 그 서명된 목록과 대조합니다. 이 두 단계는 역할이 다릅니다. 체크섬만으로는 배포 주체를 증명할 수 없고, 서명이 유효하다고 해서 릴리스에 버그나 위험한 동작이 전혀 없다고 증명할 수는 없습니다.

또한 설치 스크립트는 선택된 플랫폼, 예상 아카이브 파일 이름, 바이너리 정상 실행 여부를 확인한 뒤 불완전하게 복사된 실행 파일이 노출되지 않도록 원자적 이름 변경(atomic rename)으로 설치를 마무리합니다. 정확한 동작 방식을 직접 확인하고 싶다면 실행 전에 install.sh 또는 install.ps1 원본을 읽어 보세요.

다운로드한 파일 직접 검증하기

다운로드 목록에서 사용할 아카이브 파일, SHA256SUMS, SHA256SUMS.sig, 그리고 검증된 공개 키를 내려받으세요. 릴리스는 OpenSSL과 macOS 기본 내장 LibreSSL에서 모두 검증할 수 있는 SHA-256 기반 ECDSA P-256 키로 서명됩니다. 파일이 있는 디렉터리에서 먼저 서명을 검증한 다음 아카이브의 체크섬을 확인하세요. Linux:

openssl dgst -sha256 -verify signing-key.pem -signature SHA256SUMS.sig SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS

macOS에서도 서명 검증 명령어는 동일하며, 내려받은 아카이브 파일 이름으로 체크섬을 확인합니다:

openssl dgst -sha256 -verify signing-key.pem -signature SHA256SUMS.sig SHA256SUMS
grep ' rune-VERSION-macos-aarch64.tar.gz$' SHA256SUMS | shasum -a 256 --check

Windows에서는 설치 스크립트가 서명을 자동으로 검증합니다. 직접 내려받은 아카이브를 서명된 목록과 비교하려면 PowerShell에서 해시값을 출력한 뒤 SHA256SUMS의 해당 아카이브 줄에 적힌 값과 일치하는지 확인하세요:

(Get-FileHash .\rune-VERSION-windows-x86_64.zip -Algorithm SHA256).Hash.ToLower()

VERSION을 실제로 다운로드한 릴리스 버전으로 바꾸세요. 서명 검증은 반드시 Verified OK를 출력해야 하며, 체크섬 검사는 실제로 사용할 아카이브 파일 이름을 명시해 통과해야 합니다(목록의 다른 파일이 통과했다고 해서 누락된 대상 아카이브가 검증된 것은 아닙니다). 하나라도 일치하지 않으면 파일을 실행하지 말고 즉시 중단하세요.

한계 및 업데이트

서명은 파일의 바이트가 해당 릴리스 키로 서명되었음을 증명할 뿐, 소스 코드 감사, 재현 가능한 빌드(reproducible builds), 의존성 안전성 보장, 또는 유출된 서명 키의 무효화까지 보장하지는 않습니다. 검증 방법을 안내할 때도 이러한 신뢰의 범위를 명확히 구분해 주세요.

원하는 서명된 릴리스를 설치한 뒤 rune -version을 확인하세요. Linux와 macOS에서는 열려 있는 호환 세션이 유휴 상태일 때 새로 설치된 빌드로 자동 전환될 수 있으며, Windows에서는 새 Rune 창을 열 때까지 기존 빌드를 유지합니다. 단순히 버전 표시를 바꾸려고 진행 중인 작업을 강제 종료하지 마세요.
