메모리란 무엇인가

메모리(Memory)는 에이전트가 단일 프로젝트를 위해 유지하는 전용 폴더로, MEMORY.md라는 인덱스 파일 하나와 그 옆에 저장되는 개별 메모 파일들로 구성됩니다. 모델이 평소 사용하는 것과 동일한 파일 도구로 직접 일반 텍스트로 작성하며, 메모를 작성한 세션이 끝나도 그대로 유지됩니다. 별도로 배워야 할 메모리 전용 명령어나 특수 저장소 시스템은 없습니다.

서로 다른 두 프로젝트는 절대 메모를 공유하지 않습니다. 각 프로젝트의 메모리는 저장소(repository) 내부가 아니라, 선택된 Rune 홈 아래의 해당 프로젝트 전용 폴더 안에 보관됩니다.

모델에 전달되는 범위

세션이 열릴 때 모델에 참고 자료로 전달되는 것은 인덱스(MEMORY.md)뿐입니다. 개별 메모 본문은 모델이 해당 메모가 필요하다고 판단해 @memory/ 경로로 직접 열었을 때만 모델에 전달됩니다. 폴더의 나머지 메모들은 읽히지 않은 채로 남아 있으므로, 긴 메모 하나 때문에 프로젝트의 이후 모든 요청마다 매번 토큰 비용이 청구되는 일이 없습니다.

인덱스는 세션이 열릴 때와 대화 기록이 압축(compaction)될 때 다시 읽히며, 세션이 실행되는 내내 실시간으로 계속 읽히지는 않습니다. 따라서 그동안 다른 세션이 저장한 메모는 현재 세션을 다음에 다시 열 때 반영되며, 현재 세션이 직접 저장한 메모는 그것을 작성한 모델이 이미 알고 있습니다.

메모 읽기 및 쓰기

메모리 전용 도구는 따로 없습니다. 모델은 inspect_file로 메모를 읽고, find_files나 search_text로 메모를 찾으며, create_file과 patch_file로 메모를 추가하거나 수정합니다. @memory 별칭은 Rune이 변환해 처리하므로, 특정 기기에 종속된 절대 경로로 메모를 가리키거나 일반 프로젝트 파일을 메모로 착각하는 일이 없습니다.

Rune은 메모리 파일을 쓸 때 전체를 온전히 기록하거나 아예 기록하지 않으며(원자적 쓰기), 읽고 쓰는 동안 다른 세션과의 충돌을 막기 위해 잠금을 유지합니다. 따라서 다른 세션이 쓰는 도중에 열리는 세션은 이전 인덱스나 새 인덱스 중 온전한 쪽만 읽게 되며, 반쯤 쓰인 파일을 읽는 일은 없습니다.

인덱스 예산

인덱스 크기는 memory.recall_size(기본값 20 KiB)로 제한되며, 이 바이트 예산이 유일하게 적용되는 한도입니다. 인덱스가 이 크기를 넘어가면 가장 오래된 항목부터 제외되고 안내 문구가 표시되며, 모델은 인덱스를 계속 키우는 대신 내용을 압축해 정리하도록 안내받습니다. 예산을 늘리면 세션을 여는 매 요청마다 더 많은 컨텍스트를 소모할 뿐 메모 내용이 더 정확해지지는 않습니다.

메모리가 할 수 없는 일

Rune이 강제하는 어떠한 보안 규칙이나 설정도 메모리에서 읽어 오지 않습니다. 메모리는 에이전트가 작성한 텍스트이고 오해를 유도하는 지시문이 숨어들 수 있는 공간이므로, 권한, 경로, 한도, 구성 값은 절대 메모에서 가져오지 않습니다. 메모리는 오직 모델을 위한 참고 산문일 뿐이며 Rune 자체의 시스템 지침을 흉내 낼 수 없는 형태로 전달됩니다.

또한 메모리는 백업이나 명령어 실행 로그가 아닙니다. 다음 세션으로 이어갈 가치가 있는 결정 사항, 수정 사항, 미완성 작업 내용을 적어 두는 곳이며, 자격 증명이나 일시적인 명령어 출력은 여기에 속하지 않습니다.

저장 위치

메모리는 Rune 홈 아래의 프로젝트별 전용 폴더에 자리하며, 명령어 샌드박스는 이곳에 대한 접근 권한을 부여하지 않습니다. 즉, AI가 실행하는 셸 명령어는 메모리를 볼 수 없으며 오직 Rune 자체의 파일 도구를 통해서만 접근할 수 있습니다. 저장소 밖에 메모리를 두는 것은 의도적인 설계로, 에이전트만을 위한 메모가 Git 커밋에 섞여 들어가는 일을 방지합니다.
