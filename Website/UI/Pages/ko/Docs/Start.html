Rune이 하는 일

Rune은 터미널에서 실행되는 코딩 에이전트입니다. 원하는 결과를 설명하면 모델이 수행할 작업을 제안하고, Rune이 파일을 읽고 도구를 실행한 뒤 같은 대화창에서 결과를 보여 줍니다. Atoryn이 제공하는 별도의 구독이나 내장 모델이 아니라, 사용자가 직접 연결한 모델 계정으로 작동합니다.

프로그램과 세션 데이터는 내 컴퓨터에 저장됩니다. 단, 모든 작업이 오프라인으로만 이루어진다는 뜻은 아닙니다. 선택한 제공자에는 요청 처리에 필요한 프롬프트, 컨텍스트, 지원되는 첨부 파일이 전송되며, 실행되는 명령어나 연결된 서비스도 네트워크를 사용할 수 있습니다. 민감한 자료를 다루기 전에 먼저 프라이버시 및 데이터를 읽어 보세요.

프로젝트에서 시작하기

홈페이지의 명령어로 Rune을 설치하세요. 각 단계에 대한 자세한 설명은 설치 및 업데이트에 나와 있습니다. 설치 후 Rune으로 작업할 폴더를 여세요. 처음에는 버전 관리가 되고 있는 작은 프로젝트에서 시작하고, 기존의 변경 사항을 먼저 확인하는 것이 좋습니다.

cd path/to/your-workspace
rune

rune path/to/your-workspace처럼 폴더 경로를 직접 전달할 수도 있습니다. 실행한 작업 폴더가 파일 접근, 세션 선택, 프로젝트 지침의 기준 작업 공간이 됩니다. 홈 폴더 전체에서 시작하면 단일 저장소에서 시작할 때보다 훨씬 넓은 범위가 작업 공간으로 허용됩니다.

모델 연결 및 선택

  1. Ctrl+G를 누르고 Connections → Add connection을 엽니다.
  2. 사용할 모델 제공자를 선택합니다. 연결 대상 주소를 확인하고 필요한 주소를 입력한 뒤, 마스킹 처리된 API 키 입력란에 키를 입력합니다. 연결 과정에서는 실제 요청이 전송되며 요금이 부과될 수 있습니다.
  3. Models를 열고 연결된 제공자를 고른 뒤 Enter를 눌러 모델을 선택합니다. 목록을 둘러보거나 검색하는 것만으로는 현재 세션의 모델이 바뀌지 않습니다.
  4. 작업을 보내기 전에 입력창 옆에 표시된 모델 이름과 권한 모드를 확인하세요.

제공자 프리셋은 설정 편의를 위한 구성 정보일 뿐 계정 이용 권한 자체가 아닙니다. 사용할 수 있는 모델은 계정, 엔드포인트, 카탈로그에 따라 달라집니다. 자세한 내용은 모델 제공자, 연결, 모델 및 기능을 참고하세요.

명확한 범위의 작업 맡기기

기본 모드인 Ask에서 시작하세요. 작업 공간 안의 파일 읽기는 바로 진행되지만, 파일 편집과 명령어 실행은 매번 승인을 요청합니다. 목표 결과, 제약 조건, 확인 방법을 구체적으로 적으면 좋습니다:

임포터가 빈 날짜를 허용하는 원인을 찾아 주세요. 원인을 설명하고 회귀 테스트를 추가한 뒤, 명령어를 실행하기 전에 제안하는 수정안을 먼저 보여 주세요.

각 승인 카드에 표시된 실제 명령어, 파일 경로, 변경 내역(diff)을 꼼꼼히 확인하세요. 승인은 카드에 명시된 범위만 허용할 뿐 작업 전체의 안전을 보장하지는 않습니다. 진행 중인 AI 작업을 중지하려면 Esc를 두 번 누르세요. 에이전트가 작업하는 도중에도 추가 설명을 보낼 수 있으며, 이미 전송된 요청을 도중에 고치는 대신 다음 단계에서 순서대로 반영됩니다.

결과 검토하기

최종 보고서와 도구 실행 결과를 읽고, 변경된 파일을 살펴본 뒤 결과를 직접 검증하세요. 모델이 작업을 잘못 이해하거나 테스트가 입증한 것 이상으로 결과를 장담할 수 있습니다. 사이드 패널에서는 실제로 추적된 파일 변경 내역을 볼 수 있으며, /logs와 /context를 통해 실패 원인과 전달된 컨텍스트를 파악할 수 있습니다.

/undo는 복원 가능한 파일을 세션 시작 전 상태로 되돌립니다. 하지만 원격 배포, 외부 서비스로 보낸 메시지, 그 밖의 외부 부수 효과까지 되돌릴 수는 없습니다. Git이나 백업을 대체하는 수단이 아니라 파일 복원 도구로 활용하세요.
