지원 현황 한눈에 보기

Rune은 모든 운영체제에서 동일한 모드, 도구, 설정, 데이터 구조를 가진 단일 프로그램으로 작동합니다. 달라지는 부분은 실행 중인 프로그램 교체 방식, 명령어 격리 방식, 입력 대기 중인 명령어 감지 여부처럼 각 운영체제가 프로그램에 허용하는 시스템 기능입니다. Linux가 주력 플랫폼이며, macOS와 Windows는 실제 기기에서 빌드 및 테스트를 거친 베타 지원 단계입니다.

현재 릴리스에서 서명된 빌드가 제공되는 시스템은 홈페이지의 각 설치 명령어 아래에 표시됩니다.

Linux

대부분의 최신 배포판 커널처럼 커널이 자체 샌드박스를 제공하는 환경에서는 커널 샌드박스로 명령어를 격리합니다. 구형 커널 등에서 샌드박스를 지원하지 않으면 Rune이 이를 알리며, 이 경우 Auto 모드에서도 모든 명령어가 실행 전에 승인을 요청하고 Full 모드에서는 묻지 않고 실행합니다. /help의 This machine 항목에서 샌드박스 활성화 여부와 예외 사항을 확인할 수 있습니다.

텍스트 복사는 터미널을 거치므로 터미널에서 프로그램의 클립보드 설정(OSC 52 등)을 허용해야 합니다. SSH 접속 중이거나 tmux, screen 내부에서는 이 권한이 꺼져 있을 수 있으니 터미널이나 멀티플렉서에서 기능을 켜거나, Shift를 누른 채 드래그하여 터미널 자체 선택 기능을 사용하세요. 링크를 열려면 데스크톱 환경에서 제공하는 xdg-open이 필요합니다.

NixOS나 Guix처럼 프로그램을 읽기 전용 패키지 스토어에 보관하는 시스템에서는 명령어가 해당 스토어의 내용을 읽고 실행할 수 있습니다.

macOS

명령어는 macOS 자체 샌드박스 안에서 실행되며 Linux와 동일한 경계로 제한됩니다. 텍스트 복사 시에는 시스템 클립보드에 직접 복사하므로, 터미널 경유 클립보드 요청을 무시하는 기본 Terminal 앱에서도 정상 작동합니다.

macOS는 비밀번호 입력창처럼 화면에 입력 글자가 표시되지 않는(echo off) 대기 상태만 Rune에 알려 줍니다. 그 외 일반 입력을 조용히 기다리는 백그라운드 명령어는 계속 작업 중인 명령어처럼 보이므로, 판단하기 전에 먼저 로그를 확인하고 조용하다는 이유만으로 비밀번호를 추측해 보내거나 프롬프트를 임의로 승인하지 마세요.

명령어는 터미널의 기본 로그인 셸(macOS 기본값은 zsh)과 관계없이 macOS에 기본 포함된 bash에서 실행됩니다. 설치된 다른 셸을 쓰려면 terminal.shell에 절대 경로를 지정하세요.

설치는 홈페이지의 명령어를 사용하세요. 브라우저에서 직접 내려받은 파일에는 인터넷 다운로드 표시가 붙어 이를 제거하기 전까지 Gatekeeper가 실행을 차단합니다. 해제 방법은 설치 및 업데이트를 참고하세요.

Windows

Rune은 별도의 전용 로컬 계정을 사용해 명령어를 격리합니다. Rune을 처음 열 때 해당 계정을 설정하기 위해 관리자 권한 확인을 한 번 요청합니다. 거절하더라도 시작할 때마다 다시 묻지 않으며, 원할 때 rune -sandbox setup으로 설정하거나 rune -sandbox reset으로 전용 계정과 폴더 접근 권한을 모두 제거할 수 있습니다. rune -sandbox를 실행하면 부여된 접근 권한 목록과 현재 사용 중인 격리 방식이 표시됩니다.

전용 계정을 설정하지 않은 경우, Rune은 현재 사용자 계정의 제한된 토큰(restricted token)으로 명령어를 격리하며 다음과 같은 한계가 있습니다:

  • 드라이브 루트 폴더, 다른 드라이브, ProgramData 등 Windows가 모든 사용자에게 읽기를 허용하는 영역은 명령어가 여전히 읽을 수 있으며, ProgramData 안에 파일을 생성할 수 있습니다. 단, 사용자의 프로필 폴더에는 접근할 수 없습니다.
  • 다른 프로그램이 Windows 기본 보안 설정으로 만든 명명된 파이프(named pipe)를 읽기 전용으로 열 수 있습니다. 이러한 파이프에 쓰는 작업은 거부됩니다.
  • Git Bash 및 기타 MSYS2·Cygwin 프로그램은 매 명령어마다 승인을 요청한 뒤 전체 권한으로 실행됩니다. curl.exe와 Invoke-WebRequest가 사용하는 Windows 자체 HTTPS는 실패하지만, Git의 HTTPS는 정상 작동합니다.

전용 계정을 설정하면 격리된 명령어 안에서도 Git Bash와 Windows 자체 HTTPS가 정상 작동합니다. Rune은 Windows 시스템 폴더, 드라이브 루트, 전체 사용자 프로필 상위 폴더에는 접근 권한을 추가하지 않으므로, 이러한 위치에서 프로젝트를 열면 Ask와 Auto 모드에서 매 명령어마다 승인을 요청합니다.

Windows는 명령어가 키보드 입력을 기다리고 있는지 Rune에 알려 주지 않습니다. 조용히 실행 중인 백그라운드 명령어는 응답을 기다리는 중이거나 아직 작업 중일 수 있으므로, 입력을 보내기 전에 먼저 로그를 확인하세요. 또한 Windows에서는 실행 중인 프로그램 파일을 교체할 수 없으므로 업데이트는 이미 열린 창이 아니라 다음에 새로 여는 Rune부터 적용됩니다.

터미널 환경

키 입력과 마우스 제스처는 터미널이 Rune에 전달해 줄 때만 작동합니다. 예를 들어 Konsole은 프로필 설정을 바꾸지 않으면 Ctrl+휠을 화면 확대/축소로 처리하며, 일부 터미널은 Alt+휠을 가로 스크롤로 전환합니다. 일반 마우스 휠과 키보드 조작은 언제나 작동합니다. 마우스 휠의 부드러운 스크롤은 전체 프레임을 한 번에 빠르게 렌더링하는 터미널에서만 작동하며, 그 외 터미널에서는 한 칸씩 즉시 이동합니다. 색상, 투명도, 글꼴은 터미널 자체 설정을 따릅니다. 현재 빌드가 지원하는 단축키와 기능은 /help에서 확인하세요.
