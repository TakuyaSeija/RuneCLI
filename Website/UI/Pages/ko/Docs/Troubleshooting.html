가장 작고 유용한 단서부터 모으기

rune -version 출력, 정확한 오류 메시지, 화면 하단 상태 표시줄 문구, 문제가 발생한 명령어나 설정, 그리고 특정 세션만의 문제인지 전체 세션의 문제인지를 먼저 기록하세요. 관련된 /logs 항목을 읽고 explain으로 설정을 하나씩 확인하세요. 외부에 공유하기 전에는 비공개 작업 내용을 가리세요.

rune -version
rune -config check
rune -config explain network.stream_idle_timeout

위 명령어들은 버전과 설정을 점검합니다. 설정 파일 문법이 유효하다고 해서 제공자 연결까지 정상 작동한다는 뜻은 아닙니다. -doctor, 제공자 테스트, 모델 테스트는 실제 네트워크 요청을 보낼 수 있습니다.

설치 문제

rune: command not found
설치 스크립트가 출력한 설치 폴더 경로를 확인하세요. 전체 경로로 rune을 실행하거나 설치 및 업데이트의 안내에 따라 해당 폴더를 PATH에 추가한 뒤 새 터미널을 여세요.
No build for your system
현재 릴리스에 해당 운영체제, 프로세서 또는 C 라이브러리용으로 서명된 빌드가 없습니다. 홈페이지의 설치 명령어 아래 줄에 제공되는 빌드 목록이 표시되며, 시스템에는 아무것도 설치되지 않았습니다.
SIGNATURE CHECK FAILED 또는 CHECKSUM MISMATCH
다운로드한 파일이 공식 배포된 릴리스와 일치하지 않습니다. 아무것도 설치되지 않았으며 해당 파일들을 절대 사용하지 마세요. 신뢰할 수 있는 네트워크에서 나중에 다시 시도하고, 문제가 계속되면 제보해 주세요.
Run as your normal user
프로그램이 사용자의 홈 폴더에 설치되므로 Linux와 macOS 설치 스크립트는 root 실행을 거부합니다. 일반 사용자 터미널을 열어 다시 실행하세요. Windows에서도 관리자 권한 PowerShell은 필요하지 않으며 현재 창을 실행한 계정의 프로필에 설치됩니다.
프로그램이 이 시스템에서 실행되지 않음
운영체제 버전이 Rune이 지원하는 최소 버전보다 오래되었거나 프로세서 아키텍처가 맞지 않는 경우입니다. 플랫폼 지원에서 지원 버전을 확인하세요.

키보드, 마우스, 색상 및 복사 문제

단축키를 눌러도 아무 반응이 없다면 대개 터미널이 해당 키 입력을 가로챈 것입니다. 예를 들어 Konsole은 프로필 설정을 바꾸지 않으면 Ctrl+휠로 화면을 확대/축소하며, 일부 터미널은 Alt+휠을 가로 스크롤로 처리합니다. Rune이 응답하는 키 목록은 /help에서 확인하세요. 밝거나 어두운 배경에서 색상이 이상하게 보인다면 터미널이 배경색 정보를 전달하지 않은 경우이므로 RUNE_THEME 환경 변수를 dark, light 또는 16진수 색상으로 지정하세요.

Linux에서는 복사가 터미널을 거쳐 이루어지므로 터미널에서 프로그램의 클립보드 접근을 허용해야 합니다. SSH 접속 중이거나 tmux 안에서는 이 설정이 꺼져 있는 경우가 많으니 기능을 켜거나(tmux의 경우 set -g set-clipboard on), Shift를 누른 채 드래그하여 터미널 자체 선택 기능을 사용하세요.

Auto 모드인데도 명령어가 계속 승인을 요청함

Auto 모드는 명령어를 샌드박스로 격리할 수 있는 환경에서만 묻지 않고 실행합니다. 구형 Linux 커널처럼 시스템이 샌드박스를 지원하지 않으면 모든 명령어가 실행 전에 먼저 승인을 요청합니다(/help의 This machine 아래에서 샌드박스 활성화 여부를 확인할 수 있습니다). Windows에서 Rune 전용 샌드박스 계정을 설정하지 않은 경우 Git Bash 및 기타 MSYS2·Cygwin 프로그램이 매 명령어마다 승인을 요청합니다. rune -sandbox로 전용 계정이 사용되지 않는 이유를 확인하고 rune -sandbox setup으로 설정하세요. 또한 컨테이너 엔진이나 키 에이전트처럼 컴퓨터에서 이미 실행 중인 프로그램에 접근하는 명령어는 별도의 권한이 필요하므로 승인을 요청합니다.

백그라운드 명령어가 멈춘 것처럼 보임

명령어를 중지하거나 응답을 입력하기 전에 먼저 해당 명령어의 보고서와 로그를 읽으세요. Linux에서는 명령어가 키보드 입력을 기다릴 때 Rune이 이를 감지합니다. 반면 macOS는 비밀번호 프롬프트처럼 숨겨진 입력 대기만 감지하고 Windows는 입력 대기를 감지하지 않으므로, 조용히 실행 중인 명령어는 입력을 기다리는 중이거나 아직 작업 중일 수 있습니다. 단순히 명령어가 조용하다는 이유만으로 비밀번호를 추측해 입력하거나 프롬프트를 승인하지 마세요. 모든 Rune 창을 닫으면 분리된 세션 유지 시간(기본값 60초)이 지난 뒤 백그라운드 명령어도 종료됩니다.

모델이 컨텍스트가 너무 크다고 보고함

Rune은 제공자가 보고한 토큰 사용량을 기준으로, 또는 제공자가 컨텍스트 초과로 요청을 거부한 뒤 오래된 대화 기록을 압축합니다. 만약 안전하게 요약할 수 있는 이전 기록이 더 이상 없다면 제공자의 오류를 그대로 표시하고 동일한 요청을 재전송하지 않습니다. Models → Alt+C에서 모델의 컨텍스트 창 설정을 확인하고, 관련 없는 새 작업이라면 /new로 새 세션을 시작하거나 /compact를 실행하세요. 소형 요약 모델이 압축 묶음을 거부한다면 compact.max_batch_size 값을 낮추세요.

API 키를 사용할 수 없음(Unavailable)

Key missing은 데이터 폴더에 해당 계정의 키가 없다는 뜻이므로 Connections에서 키를 추가하면 됩니다. 반면 Unavailable은 암호화된 저장소가 존재하지만 키 파일이 없거나 다른 백업의 파일과 섞여 열 수 없다는 뜻입니다. 먼저 일치하는 백업 쌍을 복원하세요. 새 자격 증명 저장소 시작(new-store)은 기존 저장소를 따로 치워 두고 모든 키를 다시 등록해야 하므로 단순 테스트가 아닌 최후의 복구 단계로만 사용하세요. 각 상태에 대한 설명은 자격 증명에 나와 있습니다.

메시지가 계속 대기 중인 것처럼 보임

대기열에 들어간 입력, 아직 응답하지 않은 권한 카드나 질문 폼, 수신 데이터 없이 진행 중인 생성, 재시도 대기, 그리고 컨텍스트 압축(Compacting) 상태를 서로 구분하세요. 입력창이 비어 있다는 것만으로는 어떤 상태인지 알 수 없습니다. 상태를 확인하겠다며 Continue 같은 메시지를 반복해서 보내지 마세요(불필요한 추가 작업으로 쌓입니다).

데이터가 느리게라도 계속 들어오는 스트림과 완전히 멈춘 유휴 스트림은 다릅니다. 타임아웃 값을 바꾸기 전에 먼저 보고된 타임아웃 원인을 확인하세요. 또한 터미널 명령어가 백그라운드로 전환된 것은 실패나 강제 종료가 아니므로 작업 보고서를 확인하세요.

계정 또는 모델 요청이 실패함

선택한 제공자/모델과 대상 엔드포인트 주소가 맞는지 확인하세요. Key missing, Unavailable, Resting은 서로 다른 자격 증명 상태입니다. 카탈로그에 모델이 표시된다고 해서 계정 이용 권한이 보장되지는 않으며, 모델 ID에 특정 단어가 들어 있다고 해서 추론 모드를 지원한다는 증거가 되지도 않습니다.

잘못된 자격 증명이나 지원되지 않는 제어 옵션은 재시도해도 해결되지 않습니다. 먼저 정확한 실패 원인을 확인하고, 신중한 판단 없이 자격 증명 저장소를 초기화하거나 제공자를 바꾸거나 과금될 수 있는 테스트 요청을 반복해서 보내지 마세요.

출력이나 검색 결과가 불완전함

4줄 화면 접기(display fold), 반환 텍스트 상한(cap), 중단된 검색, 그리고 모델 컨텍스트 초과를 서로 구분하세요. 접힌 박스를 펼쳐 보고, 저장된 출력 안내나 이어보기 안내 문구를 확인한 뒤 파일 줄 범위나 검색 범위를 좁혀 보세요. 검색이 한도에 걸려 멈췄다고 해서 일치하는 다른 결과가 더 없다는 뜻은 아닙니다.

컨텍스트 크기는 최대 답변 길이가 아닙니다. 로컬에 표시되는 기능 한도 숫자를 키워도 제공자의 실제 한도는 늘어나지 않으며, 반대로 출력 한도를 너무 낮추면 추론 과정만 끝내고 정작 최종 답변을 작성할 여유가 남지 않을 수 있습니다.

정책 또는 웹 도구 상태가 이상함

분류기가 Enabled로 되어 있다고 해서 현재 활성(Active) 상태라는 뜻은 아닙니다. 권한 모드, 유효한 정책 파일 유무, 제외 도구 목록, 그리고 유휴 상태에서 다시 읽기(reload)가 필요한지 확인하세요. 검토 실패는 승인이 아닙니다. 또한 명시적으로 고정한 웹 제공자를 찾을 수 없을 때는 사용할 수 없는 상태(unavailable)가 되며 다른 제3자 서비스로 몰래 전환되지 않습니다.

검색(Search)과 가져오기(Fetch)는 제공자를 별도로 선택합니다. Connections에 웹 계정을 저장하는 것만으로는 도구 제공자가 선택되지 않으므로 Tools에서 직접 선택하세요.

업그레이드 이후 문제

Linux와 macOS 세션은 강제로 재시작하지 않아도 유휴 상태가 되면 새로 설치된 빌드를 채택합니다. Windows 창은 시작할 때의 빌드를 계속 유지하며 새로 여는 Rune부터 새 빌드가 적용됩니다. 특정 세션 재개가 실패했다고 해서 세션을 삭제해야 하는 것은 아닙니다.

데이터 폴더를 업데이트할 수 없다는 안내가 나오면 디스크 여유 공간이나 쓰기 권한 등 안내된 선행 조건을 해결한 뒤 다시 시도하세요. 특정 항목 하나가 변경되지 않았다고 보고되더라도 다른 모든 항목까지 실패했다고 단정하지 마세요. 원인을 확인하지 않은 채 실행 중인 런타임 파일을 지우거나, 정책 검토를 끄거나, Full 모드로 전환하거나, 스토리지를 통째로 삭제하는 식의 임시방편은 절대 사용하지 마세요.
