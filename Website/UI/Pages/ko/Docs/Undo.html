실제 변경 내역 확인하기

사이드 패널은 세션에서 추적하는 파일의 현재 차이점을 보여 줍니다. 추가 및 삭제 줄 수는 파일 내용 자체를 비교한 수치이며, 각 편집 제목들의 단순 합계가 아닙니다. 반복된 편집으로 변경 사항이 상쇄될 수 있으므로 도구의 줄 수 표시만으로 완전한 검토를 대신할 수 없습니다. 한 번 수정한 파일은 어떤 권한 모드에서도 목록에 그대로 유지됩니다. 작업 공간 외부의 접근 불가능한 경로는 기록된 집계 수치로 보고되며, 다시 접근할 수 있게 될 때까지 차이점 보기에 접근 제한 사유가 명시됩니다.

결과를 유지하기 전에 diff를 직접 읽고 관련 테스트나 검사를 다시 실행해 보세요. 명령어가 통과했다는 것은 오직 그 명령어가 검사한 항목만 통과했다는 뜻입니다. Rune은 작업 내용을 자동으로 커밋하지 않으며, 파일 복원 기능은 버전 관리 시스템(Git)이나 백업을 대체하지 않습니다.

파일 복원하기

  1. 해당 파일에 영향을 주는 작업이 모두 끝날 때까지 기다립니다.
  2. /undo를 열고 복원할 파일을 선택합니다. 목록에서 Alt+S 등 제공되는 diff 보기 동작을 사용해 어떤 내용이 바뀔지 확인합니다.
  3. 현재 파일 내용을 확인한 뒤 Enter를 눌러 복원 확인을 시작하고, 표시된 제한 시간 안에 한 번 더 확정합니다.
  4. 복원된 파일과 그에 의존하는 작업들을 다시 확인합니다.

Undo는 파일을 단순히 직전 패치 이전이 아니라 이번 세션에서 처음 변경하기 전 상태로 되돌립니다. 따라서 스냅샷 이후에 Rune 외부에서 수정한 내용까지 덮어써질 수 있습니다. 파일 복원 역시 실제 파일을 변경하는 작업이므로 변경 기록에 남습니다.

제한적인 다시 실행(Redo)

/redo는 가장 최근의 undo가 되돌린 내용을 다시 적용할 수 있습니다. undo와 동일한 방식으로 내용을 검토한 뒤 실행하세요. 임의의 모든 버전을 무제한으로 오갈 수 있는 타임라인이 아니므로 유일한 복구 수단으로 의존해서는 안 됩니다.

복원 기능이 보장하지 않는 것

파일 스냅샷은 원격 배포, 외부 서비스의 데이터베이스 트랜잭션, 전송된 이메일, 패키지 설치, 또는 임의의 셸 명령어가 일으킨 모든 부수 효과를 되돌리지 못합니다. 보호 및 추적 범위 밖의 파일이나 다른 프로그램이 만든 변경 사항은 별도의 복구 수단을 준비해야 합니다. 컴퓨터 전체가 보호된다고 가정하지 말고 실제 추적 파일 목록을 확인하세요.

보호 대상 파일의 기본 최대 크기는 64 MiB입니다. 이 크기를 넘는 파일 쓰기는 보호 없이 그대로 진행되는 대신 파일 변경 전에 실패할 수 있습니다. 한도를 늘리면 디스크 공간을 더 많이 사용하고, 낮추면 큰 파일 쓰기가 중단될 수 있습니다. 보호되지 않는 외부 부수 효과를 되돌릴 수 있다고 간주하지 마세요.

고급 옵션

checkpoint.max_file_size
파일 스냅샷을 생성할 수 있는 최대 파일 크기입니다(기본값 64 MiB).
checkpoint.diff.context
변경 내역 주변에 함께 보여 줄 문맥 줄 수입니다(기본값 3줄, 0~100 범위에서 설정 가능).

이 항목들은 Settings 화면의 일반 메뉴가 아니라 고급 구성 키입니다. 개별 옵션 설명은 rune -config explain <key>로 확인하고, 기본값 복원은 rune -config reset <key>를 사용하세요.
