신뢰 경계

모델은 작업을 제안할 뿐 스스로 권한을 승인하지 않습니다. 저장소 내 텍스트, 웹페이지, 첨부 파일, 외부 도구 응답에는 오해를 유도하는 지시문이 포함될 수 있습니다. 따라서 Rune의 실행 및 접근 검사는 모델의 선의에 기대지 않고 프로그램 자체가 직접 강제합니다.

어떠한 도구나 권한 모드도 임의의 코드를 무조건 안전하게 만들어 주지는 않습니다. 실행할 명령어, 대상 주소, 파일 경로, 예상되는 부수 효과를 직접 검토하세요. 컨테이너 엔진이나 키 에이전트 같은 로컬 서비스는 격리된 일반 명령어보다 훨씬 넓은 권한으로 작동할 수 있으며, 승인된 외부 도구에도 고유한 위험이 따를 수 있습니다.

권한 모드

Ask · 기본값
작업 공간 내부의 파일 읽기는 바로 진행됩니다. 모든 파일 편집과 모든 명령어 실행은 매번 승인을 요청하며, 작업 공간 외부 접근도 승인을 요청합니다. 명시된 범위에 한해 승인 기억(always allow) 옵션이 제공될 수 있습니다.
Auto
작업 공간 내부의 읽기와 쓰기는 질문 없이 진행됩니다. 작업 공간 외부 접근과 위험한 명령어는 여전히 승인을 요청합니다. 이러한 자율 실행이 실제로 필요할 때만 사용하세요.
Full
승인 질문이나 일반 명령어 격리 경계 없이 현재 OS 사용자 계정 권한으로 작업 공간 안팎에서 작업을 실행합니다. 기본 검증과 적용 가능한 정책 검토는 유지되지만, 그렇다고 해서 Full 모드가 무해해지는 것은 아닙니다.

폼이나 팔레트 밖에서 Tab을 누르면 모드가 순환되며, /mode ask, /mode auto, /mode full로 명시적으로 선택할 수 있습니다. 이는 세션별 선택 사항이며 전역 permissions.mode 설정 키는 존재하지 않습니다. 문제를 해결하려는 임시방편으로 Full 모드로 전환하지 마세요.

설계상 이러한 검사를 건너뛰는 유일한 예외는 사용자가 맨 앞에 !를 붙여 직접 입력한 수동 명령어입니다. Enter를 누르면 권한 질문이나 정책 검토 없이 현재 계정의 전체 권한으로 해당 스크립트를 한 번 실행합니다. 이 명령은 절대 AI가 생성할 수 없으며 세션 모드를 바꾸지도 않습니다(수동 명령어 참고).

승인의 적용 범위

한 번 허용(Allow once) 결정은 권한 모드를 바꾸지 않습니다. 항상 허용(Always) 옵션이 제공되더라도 해당 컨트롤에 명시된 범위 안에서만 유효합니다. 거부, 취소, 타임아웃은 실행이 아닙니다. 질문 폼 응답, Settings 확인, 또는 문서 안에 적힌 “이미 승인됨”이라는 문구는 실제 실행 승인을 대신할 수 없습니다.

명령어는 자신이 직접 시작한 서비스를 사용할 수 있습니다. 반면 컨테이너 엔진이나 키 에이전트처럼 컴퓨터에서 이미 실행 중인 로컬 서비스에 접근하려 할 때는 별도의 승인 요청이 발생할 수 있습니다. 실제 서비스 이름과 범위를 확인하세요. 이를 허용하면 단순 파일 접근을 넘어선 권한이 노출될 수 있습니다.

명령어 격리 및 플랫폼별 한계

Rune은 엔진 자체의 접근 검사와 운영체제가 제공하는 명령어 격리 기능을 결합해 사용합니다. 배포판 이름이나 머신 구조를 임의로 가정하지 않고 런타임에 실제 지원 기능을 감지합니다. 만약 명령어를 의도한 모드 경계 안에 가둘 수 없는 환경이라면, 격리된 척 조용히 넘어가지 않고 명시적인 승인을 요구합니다.

모드의 기본 원칙은 Linux, macOS, Windows에서 동일하지만 기반 운영체제가 보장하는 수준에는 차이가 있습니다. Windows에서는 전용 샌드박스 계정이 더 강력한 격리를 제공하며, 전용 계정을 쓰지 못할 때 적용되는 제한된 토큰(restricted-token) 대체 방식에는 모든 사용자에게 읽기가 허용된 일부 위치 및 특정 읽기 전용 명명된 파이프 접근 등 문서화된 한계가 있습니다. 실제 격리 상태는 rune -sandbox로 확인할 수 있으며, 전용 계정 설정 시 관리자 확인을 요청할 수 있습니다.

각 운영체제가 무엇을 격리하고 무엇을 감지하지 못하는지는 플랫폼 지원에 정리되어 있습니다. 이 설명은 애플리케이션 설계를 다루며 모든 플랫폼용 서명된 빌드가 항상 존재한다고 보장하지는 않습니다(현재 공개된 빌드는 홈페이지의 각 설치 명령어 아래에 표시됩니다).

정책 검토 및 복구

선택 사항인 AI 분류기는 Auto 및 Full 모드에서 적용 대상 작업을 CLASSIFIER.md 정책에 비추어 검토할 수 있습니다. 이는 실수할 가능성이 있는 추가 안전장치일 뿐 명령어 격리, 사용자의 직접 검토, 백업을 대체하지 않습니다. 사용자에게 직접 승인을 묻는 호출은 사용자의 명시적 결정을 따릅니다. 표시된 분류기 상태를 확인하고 분류기 정책 가이드를 읽어 보세요.

복원 대상 파일 변경 사항은 세션 스냅샷을 통해 되돌릴 수 있지만 외부 부수 효과는 모두 되돌릴 수 있는 것이 아닙니다. 각 영역의 구체적인 한계는 검토, 실행 취소 및 다시 실행, 자격 증명, 프라이버시 및 데이터를 참고하세요.

보안 문제 보고하기

공개 진단 자료에 실제 API 키, 비공개 파일, 또는 무기화된 익스플로잇 코드를 게시하지 마세요. 영향을 받는 Rune 버전, 예상했던 보안 경계, 최소한의 재현 예제, 실제 결과를 기록하고 확인된 비공개 메인테이너 연락처가 있을 때 그 경로를 통해 제보해 주세요(이 페이지는 검증되지 않은 보안 연락처나 응답 기한을 임의로 약속하지 않습니다).
