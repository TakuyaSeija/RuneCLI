권한 부여가 아닌 정책 검토

분류기(Classifier)는 제안된 작업들을 사용자가 작성한 CLASSIFIER.md 정책에 비추어 검토합니다. 작동하려면 유효한 정책 파일과 적용 가능한 모드가 필요합니다. Ask 모드에서는 비활성 상태이며, Auto 및 Full 모드에서는 제외 도구 설정과 사용자의 명시적 승인 여부에 따라 개별 호출의 검토 여부가 달라집니다. 단순히 Enabled(활성화됨) 스위치만 보지 말고 실제 Classifier 상태를 확인하세요.

검토 모델도 틀릴 수 있습니다. 분류기 검토는 접근 검사, 안전한 작업 경계, 사용자의 판단을 대체하지 않으며 Full 모드를 저위험 모드로 만들어 주지도 않습니다.

정책 우선순위

정책 파일은 선택된 Rune 홈에 전역으로 두거나 작업 공간 루트에 프로젝트별로 둘 수 있습니다. 전역 규칙이 프로젝트 규칙보다 우선하며, 프로젝트 규칙은 작업 중 출처가 확인된 사용자의 명시적 제약 지시보다 우선합니다. 모델이 명시되지 않은 승인을 알아서 추론할 것이라 기대하지 말고 요구 사항, 금지 사항, 예외를 명확하게 작성하세요.

CLASSIFIER.md는 프로젝트 지침인 AGENTS.md와는 별개입니다. 정책 파일의 소유권은 사용자에게 있으며 이 파일을 수정하는 것은 실제 프로젝트 및 전역 정책을 바꾸는 결정입니다. 어시스턴트가 작성한 설명이나 도구 응답이 사용자의 승인을 만들어 낼 수는 없습니다.

스냅샷 고정 및 다시 읽기(Reload)

세션은 첫 작업을 수락할 때 당시의 정책 상태(정책 파일 없음 또는 유효하지 않음 상태 포함)를 스냅샷으로 고정합니다. 따라서 도중에 파일을 편집하더라도 실행 중인 세션의 정책이 몰래 바뀌지 않습니다. 유휴 상태일 때 Generation 화면의 Reload classifier policy를 선택하거나 /classifier reload를 실행하세요. 다시 읽기에 실패하면 이전 정책이 그대로 유지되며, 새로 여는 호스트나 세션은 현재 유효한 정책을 읽습니다.

다시 읽기 후에는 상태 표시를 확인하세요. 사용할 수 있는 정책이 없다면 분류기 검토가 작동하고 있지 않은 것입니다. 평가가 실패했다는 이유만으로 분류기를 끄거나 권한 모드를 바꾸지 마세요.

검토 증거 및 한도

분류기 검토는 제안된 정확한 인수, 관련된 사용자의 원래 지침 및 추가 설명, 명시적인 텍스트·이미지 첨부 파일, 그리고 선택된 최근 도구 입력들을 증거로 사용합니다. 명령어에 특정 파일 이름이 언급되었다는 이유만으로 임의의 스크립트나 저장소 내용을 자동으로 수집해 읽지는 않습니다.

서식 적용 후 텍스트 증거의 초기 기본 허용량은 256 KiB이며 제안된 인수는 온전히 유지됩니다. 정책 파일에는 파일당 64 KiB의 별도 초기 기본 한도가 적용됩니다. 이미지 및 제공자 전체 요청 크기 한도는 별도로 유지되며, 기본 검토 기한은 120초, 요청 출력은 모델 한도 내에서 1,024토큰입니다.

제외 도구(excluded_tools)는 대상 호출 중 분류기 검토만 건너뛸 도구를 제어할 뿐 다른 권한 확인까지 우회하지는 않습니다. 컨텍스트 도구(context_tools)는 제외 도구 설정과 무관하게 어떤 최근 도구 입력을 참고 맥락으로 제공할지 제어합니다. 명시적인 빈 배열([])은 초기화(reset)가 아닙니다.

정제기(Sanitizer) 및 실패 처리

기본으로 켜져 있는 정제기는 검토를 위해 사용자의 원래 입력 출처에서 지침을 추출할 수 있습니다. 사용자의 메시지를 고쳐 쓰거나 소스 파일을 청소하지 않으며, 추출을 사용할 수 없을 때는 원래 제약 사항을 그대로 사용할 수 있습니다. 추가 모델 작업이 수반되므로 지연 시간과 비용이 발생할 수 있고 다른 제공자로 데이터가 전송될 수 있습니다.

검토 거부, 서비스 사용 불가, 유효하지 않은 평가 결과는 서로 다른 결과이며 어느 것도 자동 승인으로 처리되지 않습니다. 보고된 결과를 직접 확인하세요. 검토 모델, 증거 크기, 제외 도구를 변경하면 검토 범위가 달라질 수 있으므로 전역 설정을 적용하기 전에 그에 따른 위험을 먼저 파악하세요.
