실행 및 확인

아래 명령어들은 운영체제 셸에서 실행합니다. 설치된 빌드의 전체 도움말은 rune -help로 확인하세요. 제공자에 연결하거나, 계정을 변경하거나, 데이터를 삭제하거나, 서버를 시작하는 명령어는 단순 진단 플래그가 아니라 실제 작업을 수행하는 명령입니다.

rune [dir]
현재 폴더 또는 지정한 작업 공간에서 대화형 에이전트를 엽니다.
rune -p "prompt"
전체 화면 인터페이스 없이 단일 프롬프트를 실행하고 응답과 도구 진행 상황을 출력합니다. 응답할 사용자가 없으므로 권한 승인 요청은 조용히 허용되지 않고 즉시 거부됩니다.
-project <dir>
다른 명령어를 실행할 대상 작업 공간을 지정합니다.
-version · -help
애플리케이션 버전 또는 명령어 레퍼런스를 출력합니다.
-settings · -tools
유효 모델 제어 설정이나 에이전트에 제공되는 도구 목록을 확인합니다.
-read-only
파일이나 상태를 변경하는 도구들을 제한합니다. 단, 파일을 전혀 읽지 않거나 데이터를 외부로 전송하지 않는다는 보장은 아닙니다.
--no-color
색상 출력을 비활성화합니다. NO_COLOR 환경 변수도 지원합니다.

구성 관리

-config
현재 선택된 설정 파일 위치를 표시합니다.
-config show|defaults|check
현재 유효 설정값 표시, 초기 기본값 표시, 또는 설정 파일 유효성 검사를 수행합니다. show에는 비공개 계정 메타데이터가 포함될 수 있으며, check는 네트워크 연결 성공 여부를 검사하지 않습니다.
-config explain <key>
특정 설정 키의 현재 유효 값과 변경 사항이 적용되는 시점을 설명합니다.
-config set <key> <value>
전역 설정값을 저장합니다. 예: rune -config set terminal.command_timeout 2m.
-config reset <key>
전역 재정의(override) 값을 제거하여 기본값이나 상위 상속값이 적용되도록 합니다.
-config format
의미를 바꾸지 않고 설정 파일의 그룹과 서식을 깔끔하게 정리합니다.
-set key=value
임의의 전역 설정 키가 아니라 지원되는 작업 공간/모델 환경설정을 변경합니다.

계정 및 모델

자격 증명을 다룰 때는 가급적 Connections의 마스킹된 편집기를 사용하세요. 명령줄 인수에 실제 API 키를 직접 입력하면 셸 히스토리나 프로세스 목록에 노출될 수 있습니다. 아래 구문 예시는 의도적으로 플레이스홀더를 사용합니다.

rune -provider add <name> -key <key> [-preset <p>] [-base <url>] [-model <id>]
-provider list
등록된 계정, 프리셋, 웹 서비스 사용 가능 여부를 나열합니다.
-provider key <name> <key>
계정의 키 링에 키를 추가합니다. 자격 증명이 변경됩니다.
-provider keys <name>
마스킹된 키 메타데이터를 확인합니다.
-provider dropkey <name> <n>
번호로 지정된 자격 증명을 확인한 뒤 제거합니다.
-provider default <name>
새 세션에서 사용할 기본 제공자를 지정합니다. 기존 대화 전체의 제공자를 일괄 변경하지는 않습니다.
-provider remove <name>
제공자 구성을 제거합니다. 보관된 모든 자격 증명이 디스크에서 완전 소거된다고 가정하지는 마세요.
-provider test <name>
계정을 테스트하기 위해 실제로 과금될 수 있는 요청을 전송합니다.
-provider models <name>
계정의 모델 카탈로그를 조회합니다. 네트워크 요청이 발생합니다.
-provider dryrun <name> [model]
요청을 실제로 보내지 않고 미리 봅니다. 미리보기에는 비공개 컨텍스트가 포함될 수 있으므로 그대로 외부에 공유하지 마세요.
-provider timeout <name> <seconds>
계정별 요청 타임아웃을 5~3600초 사이로 설정하며, default를 지정하면 재정의를 해제합니다.
-provider new-store --yes
읽을 수 없게 된 자격 증명 저장소 쌍을 따로 치워 두고 빈 저장소로 새로 시작합니다. 신중히 복구를 결정한 경우에만 사용하세요. 모든 키를 다시 등록해야 합니다.
-model list · -model set <id>
선택한 작업 공간의 모델을 나열하거나 지정합니다.

세션 및 스토리지

-session · -resume <id>
세션 선택기를 열거나(파이프 연결 시 목록 출력) 지정한 세션을 이어서 진행합니다.
-session rename <id> <title>
특정 세션의 제목을 바꿉니다.
-session delete <id>
특정 세션을 영구적으로 삭제합니다. 삭제 전에 대상을 먼저 확인하세요.
-storage [list|prune]
프로젝트 스토리지를 확인하거나, 더 이상 존재하지 않는 프로젝트의 데이터를 정리합니다.
-sandbox [setup|reset]
Windows 명령어 격리 상태를 확인하고, 전용 계정을 설정하거나, Rune의 샌드박스 접근 권한 및 계정 설정을 제거합니다. 다른 플랫폼에서는 이 설정을 사용하지 않습니다.

확장 기능 및 진단

-skills [operation]
재사용 가능한 스킬 가이드를 나열, 조회, 활성화, 비활성화, 설치 또는 새로고침합니다. 설치 시에는 검토를 마친 폴더나 zip 파일을 받아 --scope user를 지정하지 않는 한 현재 프로젝트에 배치합니다.
-mcp [operation]
외부 도구 정의를 관리, 승인, 검증 및 테스트합니다. 연결 시 로컬 프로세스를 시작하거나 원격 서비스와 통신할 수 있으며, 형식 검증 통과가 곧 연결 성공을 뜻하지는 않습니다.
--scope user|project|private-project
확장 기능 변경 사항을 저장할 구성 범위를 선택합니다. 공유 프로젝트 범위로 저장한 변경 사항은 해당 프로젝트를 여는 다른 사용자에게도 영향을 줍니다.
-doctor
네트워크 연결 확인을 포함한 진단을 실행합니다. 네트워크 요청이 발생할 수 있으니 결과를 공유하기 전에 출력 내용을 먼저 검토하세요.
-db <path>
대체 엔진 데이터베이스 경로를 사용합니다. RUNE_HOME으로 설정 홈 전체를 바꾸는 것과는 별개입니다.
-host
대화형 UI 대신 프런트엔드 연동용 줄 단위 JSON(NDJSON) 모드로 실행합니다. 공개 네트워크 서버 용도가 아닙니다.
-script <file>
작성된 모델 스크립트를 재생합니다. 스크립트가 실제 도구 실행을 제안할 수 있으므로 검토하지 않은 스크립트를 실제 작업 공간에서 실행하지 마세요.

확장 기능 설정과 접근 권한에 대한 자세한 내용은 스킬 또는 MCP 연결에서 이어서 확인하세요. 단순 오류를 우회하려는 목적으로 Full 모드로 전환하거나 로컬 데이터를 삭제하지 마세요.
