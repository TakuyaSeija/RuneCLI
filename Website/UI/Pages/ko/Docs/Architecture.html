터미널 프런트엔드와 로컬 엔진의 분리

Rune은 인터페이스와 로컬 에이전트 엔진을 분리합니다. 터미널 프런트엔드는 사용자의 명령을 전달하고 이벤트를 화면에 렌더링하며, 로컬 엔진은 작업 실행, 제공자 요청, 권한 관리, 세션 상태, 파일 보호를 전담합니다. 덕분에 여러 창에서 동일한 세션을 동시에 지켜볼 때도 언제나 일관되고 권위 있는 결정이 유지됩니다.

모델 제공자는 추론 결과를 제공할 뿐 로컬 실행 권한의 주체가 되지 않습니다. 모델이 내놓는 출력은 하나의 제안일 뿐이며, 다른 모든 작업과 마찬가지로 동일한 도구 검증과 실행 제어 절차를 통과해야 합니다.

요청 처리 주기

  1. 사용자가 작업 지시와 명시적인 첨부 파일을 제출합니다.
  2. 엔진이 관련 컨텍스트를 준비해 선택한 모델 계정으로 요청을 보냅니다.
  3. 모델이 텍스트 응답이나 제안된 도구 호출들을 반환합니다.
  4. Rune이 각 호출의 유효성을 검사하고 현재 권한 모드, 접근 범위, 적용 가능한 정책 검토 결정을 적용합니다.
  5. 도구 실행 결과가 기록되고 다음 모델 단계의 컨텍스트로 전달됩니다.
  6. 프런트엔드가 진행 상황, 실패 내역, 최종 응답을 표시하면 사용자가 실제 결과를 검토합니다.

재시도, 출력 한도, 작업 취소는 런타임 엔진이 직접 통제합니다. 모델이 텍스트로 “권한 관문을 통과했다”고 적는다고 해서 스스로에게 접근 권한을 부여할 수는 없습니다. 또한 보조 모델 작업은 고유한 목적과 한도를 가진 별도의 제공자 요청으로 실행됩니다.

세션 및 순서 보장

하나의 세션은 단일한 공식 작업 스트림을 갖습니다. 추가로 연 창들은 각자 독립된 복사본을 따로 실행하는 대신 동일한 작업, 질문, 비용 집계, 파일 상태를 함께 관찰합니다. 새 메시지와 방향 수정 지시는 접수된 순서대로 처리되며, 이미 전송되어 실행 중인 제공자 요청은 전송 당시의 컨텍스트를 유지합니다.

대화 기록은 실제로 일어난 일에 대한 감사 기록으로 보존되며, 나중에 바뀐 설정이나 파일 버전이 처음부터 있었던 것처럼 과거 기록을 몰래 고쳐 쓰지 않습니다. 컨텍스트 압축(Compaction)은 모델에 전달할 요약본을 만들 뿐 저장된 원본 기록과는 별개로 관리됩니다.

도구 및 플랫폼 경계

내장 파일, 터미널, 웹 도구는 명시적인 입력과 제한된 출력 크기를 가지며 엔진 내부의 단일 실행 경로를 통과합니다. 파일 변경 도구는 내용을 교체하기 전에 복원 대상 원본을 먼저 보호합니다. 셸 명령어는 운영체제가 제공하는 격리 기능을 활용하며, 공통 권한 규칙과 플랫폼별 한계를 숨기지 않고 투명하게 보고합니다.

외부 MCP 도구는 선언된 인터페이스를 통해 탐색되고 호출됩니다. 스킬은 가이드로 읽힐 뿐이며, 가이드나 외부 도구 응답이 사용자의 승인을 대체할 수 없습니다. 네트워크 목적지 주소와 자격 증명은 모델이 다루는 텍스트와 철저히 분리되어 관리됩니다.

구성 및 업그레이드

전역 구성 파일은 사용자의 선택 사항만 기록하며 초기 기본값은 실행 중인 애플리케이션 버전에 속합니다. 실행 중인 프로세스는 각 설정의 적용 시점 규칙에 따라 변경 사항을 반영하며, 기존 세션의 선택 사항이나 진행 중인 요청이 새 기본값으로 무작정 덮어써지지 않습니다.

저장된 데이터 구조 변경은 정해진 순서에 따라 업그레이드됩니다. 선택적 도움말이나 열 수 없는 자격 증명 저장소가 정상 접근인 것처럼 위장하거나 관련 없는 데이터를 훼손해서는 안 됩니다. 새 릴리스 전환은 세션이 안전한 유휴 상태가 될 때까지 기다리므로, 설치를 이유로 진행 중인 작업을 강제 종료할 필요가 없습니다.

설계 경계는 결과의 무결성을 보장하지 않습니다

아키텍처는 실행 여부가 어디서 결정되고 결과가 어떻게 보고되는지를 강제할 수 있습니다. 하지만 모델이 세운 계획이 100% 옳다거나, 모든 외부 시스템을 원래대로 되돌릴 수 있다거나, 허용된 명령어가 언제나 무해하다고 증명할 수는 없습니다. 따라서 사용자의 직접 검토, 테스트, 최소 권한 작업 범위 유지, 그리고 별도의 독립적인 백업은 언제나 필수입니다.
