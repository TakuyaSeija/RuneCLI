자격 증명 입력란에 안전하게 입력하기

이름이 지정된 API 키를 추가하려면 Settings → Connections → 해당 계정을 여세요. Personal이나 Work 같은 이름을 붙이면 여러 키를 쉽게 구분할 수 있으며, 실제 키 값은 대화창이 아니라 반드시 마스킹된 자격 증명 입력란에 넣어야 합니다.

명령줄 인수로 전달한 키는 셸 히스토리나 프로세스 목록에 남을 수 있습니다. 예제 코드나 구성 출력 덤프 역시 실수로 공개하기 쉽습니다. 계정 구성에 기록된 자격 증명 참조 이름은 실제 키 값 자체가 아닙니다.

저장 및 전송 보안

Rune은 자격 증명 저장소를 암호화하여 디스크에 보관하며 로컬 키 자료에 대한 접근을 소유자 계정으로 제한합니다. 이는 평문 노출을 막아 주지만, 이미 탈취된 사용자 계정이나 동일 권한으로 제한 없이 실행되는 프로세스로부터는 보호하지 못합니다. 백업할 때는 암호화된 저장소와 그에 대응하는 키 자료를 안전한 곳에 함께 보관하세요.

등록된 자격 증명은 요청 및 로그 경계에서 마스킹 처리됩니다. 하지만 사용자가 대화창에 직접 붙여넣은 텍스트는 일반 대화 내용으로 취급되므로, 임의의 대화 기록이나 진단 덤프를 검토 없이 그대로 공유해서는 안 됩니다. 또한 Rune은 루프백(loopback) 로컬 서비스를 제외한 외부 머신으로 일반 HTTP(비암호화)를 통해 API 키를 전송하는 것을 거부합니다.

누락(Missing)과 사용 불가(Unavailable)의 차이

Key missing
선택된 데이터 홈에 해당 계정의 자격 증명이 없거나 자격 증명 저장소 자체가 없는 상태입니다. 지원되는 절차에 따라 사용할 키를 추가하세요.
Unavailable
저장소는 존재하지만 열 수 없는 상태입니다. 키 자료가 없거나 손상되었거나, 백업 쌍이 서로 맞지 않거나, 파일을 읽을 수 없거나 내용이 손상되었을 때 발생합니다.
키 링 순환
계정에 여러 키가 등록된 경우 각 키는 할당된 시도 횟수를 소진하면 즉시 링의 다음 키로 순서를 넘깁니다. Rename key를 사용하면 비밀 값을 다시 입력하지 않고도 키 이름을 바로 바꿀 수 있습니다.

자격 증명을 사용할 수 없는 상태여도 Rune 자체는 시작할 수 있으며, 해당 키가 필요한 작업을 실행할 때만 실패를 알립니다. 저장소가 비어 있는 척 꾸미거나 기존 저장소를 몰래 새 저장소로 덮어쓰지 않습니다.

신중한 복구 절차

먼저 의도한 Rune 홈 경로가 맞는지 확인하고, 일치하는 자격 증명 백업 쌍이 있다면 먼저 복원하세요. 진단 삼아 저장소를 섣불리 삭제하거나 관련 없는 대체 키 파일을 임의로 만들지 마세요.

복구가 불가능한 경우 Connections의 Start a new credential store를 선택하거나 rune -provider new-store --yes를 실행하면 기존 저장소 쌍을 따로 치워 두고 키가 없는 빈 저장소로 새로 시작합니다. 이 경우 모든 자격 증명을 처음부터 다시 등록해야 하므로, 일상적인 연결 테스트가 아니라 최후의 복구 수단으로만 신중하게 실행하세요.

키 교체 및 삭제

이름이 지정된 키를 추가하면 대체 키가 늘어납니다. 기존 키를 삭제하기 전에 키 이름과 마스킹된 미리보기를 먼저 확인하세요. 연결을 제거하더라도 암호화된 저장소에 키가 재사용 가능한 상태로 남아 있을 수 있습니다. 만약 자격 증명이 외부에 노출되었다면 로컬 참조만 지우지 말고 제공자 측에서도 해당 키를 즉시 폐기(revoke)하거나 재발급하세요.

Configured 표시나 등록된 키 개수는 유효한 인증이나 잔액을 보장하지 않습니다. 테스트는 실제로 과금될 수 있는 요청을 전송하므로 엔드포인트를 변경한 뒤에는 테스트 전에 대상 주소를 먼저 확인하세요.
