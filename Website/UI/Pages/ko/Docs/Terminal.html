포그라운드와 백그라운드 실행

에이전트는 작업 간 의존성에 따라 실행 의도(launch intent)를 선택합니다. 다음 단계를 진행하기 위해 명령어의 실행 결과가 반드시 필요하다면 일반 포그라운드 호출로 결과를 바로 돌려받습니다. 반면 독립적인 다른 작업을 먼저 진행할 수 있다면 명시적 백그라운드 실행으로 작업 ID를 즉시 돌려받습니다. 명령어 이름만으로는 어느 쪽이 맞는지 결정되지 않습니다.

포그라운드 명령어가 설정된 대기 시간(초기 기본값 120초)이 지나도 계속 실행 중이면 재시작되지 않고 동일한 프로세스 그대로 백그라운드로 전환됩니다. 시스템이 키보드 입력 대기 상태를 감지한 경우에는 대기 시간이 끝나기 전이라도 더 일찍 백그라운드로 전환될 수 있습니다. 단, 출력이 조용하다는 것만으로는 입력 프롬프트가 떴다고 단정할 수 없습니다.

셸 및 작업 디렉터리

매 호출은 새로운 셸을 시작하므로 이전 호출의 cd 상태가 다음 호출로 이어지지 않습니다. 명령어를 실행할 디렉터리는 해당 호출에 직접 지정해야 합니다. 자동(auto) 셸 설정은 운영체제에 맞는 지원 셸을 선택하며, 고급 구성에서 설치된 셸의 절대 경로를 직접 지정할 수도 있습니다.

명령어 박스는 실제로 실행된 셸을 표시합니다(bash와 zsh는 $, PowerShell은 PS>, 명령 프롬프트는 >). 셸을 바꾸면 명령어 문법도 달라집니다. 셸 명령어는 현재 권한 모드와 승인된 범위 안에서 실행되며, 터미널 설정 자체가 실행 권한이나 로컬 서비스 접근 권한을 부여하지는 않습니다.

실제 상태 보고 읽기

Running
프로세스가 아직 실행 중이며 성공적으로 완료된 상태가 아닙니다.
Waiting for input
시스템이 입력 대기 상태를 감지했습니다. 응답을 보내기 전에 프롬프트 내용을 먼저 읽으세요.
Completed / Failed
프로세스가 종료되었습니다. 종료 코드와 출력을 확인하세요. 종료 코드가 성공이더라도 그 명령어가 검사한 항목만 통과했음을 뜻합니다.
Killed
프로세스가 강제 중지되었습니다. 중간까지 진행된 작업이 자동으로 롤백되었다고 가정하지 마세요.
Lost
추적 중이던 런타임 연결이 끊기는 등의 이유로 정상적인 최종 결과를 확인할 수 없는 상태입니다. 성공이 아닙니다.

작업이 끝나거나 입력 대기가 감지되면 Rune은 어떤 작업인지, 어떻게 끝났는지, PID, 실행 시간, 로그 파일 경로, 그리고 에이전트에 아직 전달되지 않은 출력 내용을 담아 에이전트에 자동으로 알립니다. 별도로 결과를 조회할 필요가 없으므로 출력을 다시 보려고 같은 명령어를 중복 실행하지 않으며, 출력이 축약되었거나 불완전하게 캡처된 경우 해당 줄에 그 사실이 명시됩니다.

저장된 로그 파일

각 백그라운드 명령어는 컴퓨터에 로그 파일을 하나씩 기록합니다. 여기에는 완료된 출력과 함께 맨 끝에 현재 화면 상태가 담기므로, 아직 마지막 줄바꿈을 출력하지 않은 질문 프롬프트도 로그에서 바로 확인할 수 있습니다. 로그는 터미널 커서 이동이 반영된 일반 텍스트로 저장됩니다. 따라서 한 줄을 계속 다시 그리는 진행률 표시줄은 한 줄로 유지되고, 질문 줄에 입력한 답변은 줄을 중복해서 늘리는 대신 해당 줄에 반영됩니다.

에이전트가 백그라운드 명령어에서 읽는 첫 번째 보고서는 이전에 일부 출력이 표시되었더라도 로그의 맨 처음부터 시작하며, 이후 보고서는 새로 추가되거나 변경된 출력만 반환합니다. 프로세스와 로그 경로만 적힌 보고서는 새로 추가된 출력이 없었다는 뜻입니다. 또한 Rune은 명령어가 입력을 기다리고 있다고 알리기 전에 로그를 디스크에 먼저 기록하므로, Rune을 재시작하더라도 이전 대화 없이 로그를 읽을 수 있습니다(단, 디스크 오류나 쓰기 도중의 비정상 종료까지 막아 주는 보장은 아닙니다).

키보드 입력 전달

process_control은 실행 중인 백그라운드 작업에 텍스트를 타이핑해 넣거나, 해당 작업과 그 작업이 시작한 모든 하위 프로세스를 중지합니다. 작업 완료를 기다리거나 다음 출력을 바로 반환하지는 않습니다. 제출 옵션에 따라 끝에 Enter를 자동으로 붙이거나, 강제로 Enter를 보내거나, 텍스트만 입력할 수 있습니다(빈 텍스트에 Enter 옵션을 주면 Enter 키만 누릅니다).

입력 대기 감지 방식은 플랫폼마다 다릅니다. Linux는 키보드 입력 대기를 감지하고, macOS는 비밀번호 프롬프트처럼 입력 글자가 숨겨진 대기만 감지하며, Windows는 입력 대기를 감지하지 않습니다. 따라서 macOS나 Windows에서 조용히 실행 중인 작업은 실제로는 입력을 기다리고 있을 수 있습니다. 프로세스가 조용하다는 이유만으로 비밀번호를 추측해 입력하거나 파괴적인 확인 프롬프트를 승인하지 마세요.

출력 한도 및 작업 수명

초기 기본 반환 텍스트 상한은 30,000자입니다. 별도의 캡처 한도는 포그라운드 출력 8 MiB, 백그라운드 로그당 100 MiB이며, 캡처 또는 로그 한도를 초과하면 명령어가 중지될 수 있습니다. 대화 기록에 표시되는 4줄 미리보기는 단순한 화면 접기(display fold)일 뿐입니다.

마지막 Rune 창을 닫으면 진행 중인 AI 작업이 중지됩니다. 백그라운드 작업은 분리된 세션 유지 시간(기본값 60초) 동안 남아 있다가 종료됩니다. 오랫동안 독립적으로 계속 실행되어야 하는 서비스가 필요하다면 운영체제의 서비스 관리 기능을 직접 사용하세요. Rune의 백그라운드 작업이 영구히 유지된다고 가정해서는 안 됩니다.
