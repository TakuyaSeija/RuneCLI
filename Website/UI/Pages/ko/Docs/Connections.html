접근 정보 등록과 사용 선택은 별개입니다

Connections는 계정 주소와 API 키를 관리합니다. 현재 사용할 모델, 모델 요청 타임아웃, 웹 검색 경로, 웹페이지 리더 선택은 각각 Models, Runtime, Tools에서 담당합니다.

Configured
이 계정에 하나 이상의 API 키가 저장되어 있습니다. 요청 성공이나 잔액 보유를 증명하지는 않습니다.
Key missing
현재 데이터 홈에 이 계정의 키가 없습니다. Connections에서 키를 추가하세요.
Unavailable
암호화된 자격 증명 저장소가 디스크에 있으나 열 수 없습니다. 변경하기 전에 일치하는 백업 쌍을 복원하세요.

계정을 반복해서 다시 만드는 대신 /logs에서 실제 실패 원인을 먼저 확인하세요.

모델 계정 추가

각 제공자 프리셋과 필요한 키 형식 및 기본 주소는 모델 제공자 문서에 정리되어 있습니다.

  1. Settings → Connections → Add connection을 열고 원하는 모델 제공자를 선택합니다.
  2. 처음에는 Not connected yet으로 표시되는 입력 폼을 확인합니다. 고정 주소가 있는 프리셋은 키만 요청하며, 계정마다 주소가 다르거나 사용자 지정 엔드포인트인 경우에는 주소를 직접 입력해야 합니다.
  3. 연결 이름과 키 이름을 확인하고, 시크릿은 반드시 자격 증명 입력란에만 넣습니다.
  4. Connect를 선택합니다. Rune은 새 모델 계정을 저장하기 전에 실제 테스트 요청을 보내며, 이 요청에는 요금이 부과될 수 있습니다. Cancel을 누르면 저장하지 않고 취소합니다.
  5. 연결이 완료되면 Models에서 실제로 사용할 제공자/모델 쌍을 선택합니다.

프리셋은 호환되는 초기 설정값을 채워 줄 뿐 계정이나 API 이용 권한 자체를 제공하지 않으며, 해당 제공자의 모든 제품이 다 작동한다고 보장하지도 않습니다. 특정 요금제 전용 구독이나 지역별 주소는 일반 API 주소와 다를 수 있습니다.

웹 계정 추가

Search & Fetch 벤더를 선택하고 필요한 주소와 키를 입력해 계정을 저장하세요. 웹 계정 정보를 저장하는 것만으로는 검색이나 웹페이지 가져오기가 활성화되거나 작동이 검증되지 않습니다. 이어서 Tools → Web search 또는 Web fetch → Provider로 이동해 사용할 서비스를 추가하고 테스트한 뒤 선택하세요.

검색(Search)과 가져오기(Fetch)는 각각 독립적으로 제공자를 선택합니다. 로컬 모델 계정과 같은 벤더의 클라우드 웹 서비스는 서로 다른 주소나 키를 요구할 수 있습니다. 자세한 내용은 웹 검색 및 가져오기를 참고하세요.

편집 및 제거

기존 연결을 열면 Base URL을 변경하거나 이름이 지정된 키들을 관리할 수 있습니다. 모델 엔드포인트 주소를 변경하면 반영 전에 연결 테스트를 거칩니다. 주소 입력란의 Use default는 계정 이름에서 추측한 주소가 아니라 제공자 프리셋에 등록된 기본 주소를 복원합니다.

키를 추가하면 기존 키를 자동으로 모두 교체하는 대신 예비 키가 추가됩니다. 키를 삭제하기 전에 키 이름과 마스킹된 미리보기를 확인하세요. 연결을 제거하더라도 암호화된 저장소에 자격 증명이 재사용 가능한 상태로 남아 있을 수 있으므로, 계정 연결 제거가 곧 키 데이터의 완전 소거를 뜻하지는 않습니다.

전송 대상 및 테스트

엔드포인트를 변경하면 자격 증명과 프롬프트가 모두 다른 대상으로 전송될 수 있습니다. 연결하기 전에 대상 서버의 소유 주체와 의도한 리전이 맞는지 반드시 확인하세요. 키를 사용하는 원격 엔드포인트에는 암호화된 전송(HTTPS)이 필수이며, 내 컴퓨터 내부의 엔드포인트만 로컬 예외로 취급됩니다.

연결 테스트와 모델 테스트는 실제 요청을 보내므로 비용이 발생할 수 있습니다. 계정 테스트가 성공했다는 것은 해당 테스트 요청이 통과했음을 뜻할 뿐 모든 모델, 도구, 컨텍스트 길이, 권한이 다 허용된다는 보장은 아닙니다. 로그에서 정확한 오류를 먼저 확인한 뒤 필요한 테스트만 신중하게 실행하세요.
