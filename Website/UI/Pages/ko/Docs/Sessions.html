시작 및 이어하기

/new는 현재 작업 공간에서 새 세션을 시작합니다. /session은 세션 선택기를 열며, 검색어를 입력해 원하는 세션을 고른 뒤 Enter를 누르면 이어서 진행합니다. /resume <id>는 알고 있는 세션 ID를 바로 지정해 재개합니다. 셸에서 실행할 때는 rune -session 및 rune -resume <id>를 사용할 수 있습니다.

새 세션은 다른 세션의 입력창 기록을 가져오지 않습니다. 세션을 재개하면 저장된 대화와 설정 선택 사항이 복원되지만, 프로젝트의 모든 파일이 예전 상태와 그대로 일치한다는 보장은 없습니다. 외부에서 변경한 사항이 있다면 Rune에 알려 주고 다음 작업을 검토하세요.

방향 수정 및 중지

작업이 진행되는 도중에도 수정 지시를 보낼 수 있습니다. 보낸 메시지는 다음 단계에서 순서대로 반영되며, 이미 제공자로 전송된 요청을 취소하거나 이미 실행된 명령어를 되돌리지는 못합니다. 무엇을 어떻게 바꿀지, 그리고 이전 지시 중 어느 부분을 대체하는지 명확히 적어 주세요.

Esc를 두 번 누르면 Rune을 종료하지 않고 진행 중인 AI 작업만 중지합니다. Ctrl+C는 첫 입력 시 종료 대기를 알리고 한 번 더 누르면 Rune을 종료합니다. AI 작업을 중지했다고 해서 실행 중인 모든 백그라운드 명령어까지 종료된 것은 아니므로, 작업의 실제 상태는 별도로 확인하세요.

컨텍스트 및 압축(Compaction)

/context는 모델에 전달되는 컨텍스트 정보를 보여 줍니다. 컨텍스트 창 크기는 최대 답변 길이를 뜻하지 않으며, 미확인(unknown) 표시는 무제한을 의미하지 않습니다. /compact로 이전 대화 기록 요약을 요청할 수 있으며, Rune이 필요에 따라 자동으로 압축을 수행하기도 합니다.

Rune은 제공자가 보고한 입력 토큰 사용량을 기준으로, 또는 제공자가 모델 컨텍스트 한도 초과로 요청을 거부했을 때 자동으로 컨텍스트를 압축합니다. 텍스트나 사고 과정, 이미지, 파일 크기를 어림잡아 토큰 수를 추측하지 않으므로, 다음 요청의 정확한 크기는 제공자가 보고하기 전까지는 알 수 없습니다. 제공자가 요청을 거부했고 더 이상 안전하게 요약할 이전 기록이 없으면, Rune은 동일한 요청을 반복 전송하는 대신 실패를 보고합니다.

압축이 진행되는 동안(턴과 턴 사이 포함) 하단 상태 표시줄에는 Compacting이 표시되며, 새로 입력한 메시지는 순서대로 대기합니다. 필수 압축이 실패하면 재시도 여부를 묻는 질문이 표시될 수 있으며, 취소하면 해당 시도를 멈추고 실패한 요약은 완료된 것으로 처리되지 않습니다.

기본 설정은 컨텍스트가 허용하는 범위 내에서 최근 5개 턴을 원문 그대로 유지하고, 모델 한도 내에서 최대 32,768토큰의 요약 예산을 사용합니다. 긴 대화 기록은 한 번에 최대 128 KiB의 텍스트 묶음 단위로 요약됩니다(이는 분할 크기일 뿐 소형 모델이 무조건 수용한다는 보장은 아닙니다). 사용자의 원래 지침은 이전 어시스턴트 답변이나 도구 발췌본과 분리해 다루어지지만, 요약 과정에서 세부 내용이 일부 생략될 수 있습니다. 컨텍스트 압축은 모델 컨텍스트 여유 공간을 확보할 뿐 디스크 저장 공간을 비우지는 않습니다.

사용량 및 비용

지출 비용(Spend)은 가격 정보가 확인된 요청을 기준으로 계산됩니다. 미확인(Unknown)은 무료가 아니라 가격이 책정되지 않았음을 뜻합니다. 이전에 가격을 알 수 없었던 요청에 대해 나중에 모델 가격 정보가 확인되면 그때 비용이 반영되며, 이미 계산된 요청은 기록된 당시 비용을 유지합니다. 보조 모델 작업, 재시도, 연결 테스트에서도 비용이 발생할 수 있습니다.

로컬에서 집계한 금액은 제공자의 실제 청구서가 아닙니다. 또한 usage.warn_spend_usd는 경고 기준치일 뿐 강제 차단 한도가 아니므로, 엄격한 예산 제한이 필요하다면 제공자 측의 한도 설정을 함께 사용하세요.

종료 및 데이터 관리

마지막 창을 닫으면 진행 중인 AI 작업이 즉시 중지됩니다. 백그라운드 명령어는 분리된 세션 유지 시간(기본값 60초) 동안 남아 있을 수 있지만, Rune은 무기한 실행되는 서비스 관리자가 아닙니다.

rune -session rename <id> <title>은 세션 제목을 변경하고, rune -session delete <id>는 세션을 영구 삭제합니다. rune -storage list로 보관된 프로젝트 데이터를 확인하고, prune으로 더 이상 존재하지 않는 프로젝트의 데이터를 정리할 수 있습니다. 삭제하기 전에 대상을 먼저 확인하세요. 세션 목록 표시 개수 제한 설정은 오래된 세션을 삭제하지 않습니다.
