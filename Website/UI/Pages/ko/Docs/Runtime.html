알맞은 대기 시간 설정 고르기

Settings → Runtime은 모델 요청 타이밍, 공통 네트워크 대기 시간, 재시도 정책을 담당합니다. 반면 터미널 포그라운드 대기 시간, 웹 도구 기한, 권한 카드 만료 시간은 Tools 아래의 별도 설정입니다. 모든 타임아웃을 무조건 늘리면 근본 원인을 해결하지 못한 채 증상만 가릴 수 있습니다.

계정별 선택적 요청 타임아웃은 5초부터 3,600초까지의 정수를 받으며, 비워 두거나 default로 지정하면 재정의가 해제됩니다. 보조 모델 작업은 자체 작업 기한을 가질 수 있습니다. 데이터가 계속 오가는 활성 스트림과 아무 데이터도 오지 않는 멈춘 스트림은 서로 다른 상태로 구분됩니다.

선형적으로 증가하는 재시도 간격

설정 키초기 기본값설명
retry.max_attempts5첫 시도 이후의 재시도 횟수로, 총 최대 6회 시도합니다. 0으로 설정하면 재시도하지 않습니다.
retry.initial_delay3s기본 증가 폭으로, 대기 시간이 3초, 6초, 9초… 순으로 늘어납니다.
retry.max_delay1m다음 대기 시간이 이 값을 넘으면 다시 기본 단계(initial_delay)부터 순서를 시작합니다. 지수 백오프(exponential backoff)가 아닙니다.
retry.credit_cooldown15m잔액이 소진된 키를 다시 사용 가능 상태로 되돌리기 전까지 휴식시키는 시간입니다. 크레딧을 자동으로 충전해 주지는 않습니다.

모든 실패를 다 재시도하지는 않습니다. 잘못된 자격 증명, 지원되지 않는 제어 옵션, 잘못된 엔드포인트 주소는 재시도해도 해결되지 않습니다. 재시도 횟수를 너무 높게 잡으면 실패 확인만 늦어지고 불필요한 요금이 발생할 수 있으니 먼저 로그에서 분류된 오류 원인을 확인하세요.

네트워크 대기 시간

스트림 정체 한도(Stall limit)
network.stream_idle_timeout: 응답 데이터가 전혀 오지 않는 상태로 5분 대기합니다. 정상적으로 데이터가 흐르는 스트림의 전체 시간을 5분으로 제한하는 것이 아닙니다.
연결 타임아웃(Connect timeout)
network.connect_timeout: 연결을 수립하기까지 10초 동안 대기합니다.
프로브 타임아웃(Probe timeout)
network.probe_timeout: 명시적인 제공자 테스트 요청에 대해 45초 동안 대기합니다.
카탈로그(Catalog)
고급 설정값: 요청 타임아웃 10초, 최신 상태 유지 주기 1시간, 새로고침당 최대 100페이지. 카탈로그 유지 주기는 프롬프트 캐시 수명과는 다릅니다.

그 외 고급 한도 설정들은 스트리밍 및 비스트리밍 응답 크기를 제한하며 토큰이 아닌 바이트 단위로 측정합니다. 토큰 절약(token-saver) 호환성 옵션은 지원하는 라우터에 압축을 맡길 수 있지만, 이를 켠다고 항상 압축이 보장되지는 않으며 반환되는 세부 내용이 줄어들 수 있습니다.

분리된 세션 유지 시간

host.idle_lifetime은 고급 전역 설정으로 기본값은 60초입니다. 마지막 창이 닫히면 진행 중인 AI 작업은 멈추지만, 백그라운드 명령어는 이 유지 시간 동안 계속 실행될 수 있습니다. 제시간에 다시 창을 열면 실행 상태를 이어서 지켜볼 수 있습니다. 이는 계정 로그아웃 타이머가 아니며 무기한 실행되는 서버를 보장하지도 않습니다.

신중한 변경 및 초기화

관련 Runtime 행을 열고 값을 수정한 뒤 Apply를 누르세요. Use default는 재정의를 제거하며, rune -config explain <key>는 현재 유효 값과 적용 시점을 보여 줍니다. 스트림 유휴 타임아웃 변경은 이미 대기 중인 요청에도 영향을 줄 수 있는 반면, 다른 설정들은 주로 이후 작업부터 적용됩니다.

설정을 바꾸기 전에 먼저 원래 느리게 작업 중인 서비스인지, 응답 없이 멈춘 연결인지, 잔액이 바닥난 키인지, 아니면 지원되지 않는 요청인지를 구분하세요. 설정 저장이 성공했다고 해서 네트워크 연결 테스트까지 통과한 것은 아닙니다.
