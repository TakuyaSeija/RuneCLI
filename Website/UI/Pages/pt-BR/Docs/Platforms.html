Resumo do suporte

O Rune é um único programa com os mesmos modos, ferramentas, configurações e dados em todos os sistemas. O que muda é o que cada sistema operacional permite a um programa fazer: como um binário em execução é substituído, como os comandos são confinados e o que o sistema consegue informar sobre um comando que está aguardando entrada. O Linux é a plataforma principal. O macOS e o Windows estão em beta: compilados e testados em máquinas reais, mas com menos tempo de uso diário acumulado.

Os sistemas que possuem compilação assinada na versão atual estão informados abaixo de cada comando de instalação na página inicial.

Linux

Os comandos são confinados pela sandbox do próprio kernel onde o kernel oferece esse recurso, como ocorre na maioria das distribuições atuais. Onde não há suporte, como em um kernel antigo, o Rune avisa: no modo Auto, todo comando passa a pedir permissão antes de rodar; no modo Full, ele deixa de perguntar. O comando /help mostra em This machine se a sandbox está ativa e se há algo que possa escapar dela.

A cópia de texto passa pelo seu terminal, que precisa permitir que programas gravem na área de transferência. Via SSH, ou dentro do tmux ou screen, essa permissão pode estar desativada; ative-a no terminal ou no multiplexador, ou segure Shift ao arrastar para usar a seleção nativa do terminal. Abrir um link exige o xdg-open, já presente em ambientes de desktop.

Em sistemas que mantêm seus programas em um repositório de pacotes somente leitura, como NixOS ou Guix, os comandos podem ler e executar o que estiver nesse repositório.

macOS

Os comandos rodam na sandbox nativa do macOS, restritos aos mesmos locais do Linux. A cópia de texto grava diretamente na área de transferência do sistema, funcionando inclusive no aplicativo Terminal padrão, que ignora solicitações de programas para definir a área de transferência via sequência de terminal.

O macOS informa ao Rune apenas entradas ocultas, como solicitações de senha. Um comando em segundo plano que aguarde silenciosamente outro tipo de resposta parece um comando que ainda está trabalhando; leia o log antes de decidir o que fazer e nunca tente adivinhar uma senha nem confirme um prompt apenas porque o comando está em silêncio.

Os comandos rodam em bash (incluído no macOS), e não necessariamente no shell que o seu terminal abre por padrão (no macOS, o shell de login padrão é o zsh). Você pode escolher outro shell instalado informando o caminho absoluto em terminal.shell.

Instale usando o comando da página inicial. Uma cópia baixada pelo navegador recebe a marcação de arquivo vindo da internet, e o Gatekeeper se recusa a iniciá-la até que essa marcação seja removida; Instalação e atualização mostra como fazer isso.

Windows

O Rune confina comandos usando uma conta local separada própria. Na primeira vez que você abre o Rune, ele pede uma única vez confirmação de Administrador para criar e configurar essa conta. Se você recusar, ele não pergunta novamente a cada inicialização; execute rune -sandbox setup quando quiser configurá-la e rune -sandbox reset para removê-la junto com todas as permissões concedidas aos comandos do Rune nas suas pastas. O comando rune -sandbox lista esses acessos e informa qual método de confinamento está em uso.

Sem essa conta dedicada, o Rune confina os comandos usando uma forma restrita da sua própria conta, com estas limitações:

  • Um comando ainda pode ler o que o Windows permite a qualquer usuário ler, como pastas na raiz de uma unidade, outras unidades e a pasta ProgramData, além de poder criar arquivos em ProgramData. Sua pasta de perfil de usuário permanece fora de alcance.
  • Um comando pode abrir, somente para leitura, um named pipe criado por outro programa com a segurança padrão do Windows. A escrita nesse tipo de pipe é recusada.
  • O Git Bash e outros programas baseados em MSYS2 ou Cygwin pedem permissão antes de cada comando e executam aquela chamada com acesso total. O HTTPS nativo do Windows, usado por curl.exe e Invoke-WebRequest, falha nesse modo; o HTTPS do próprio Git continua funcionando.

Com a conta dedicada configurada, tanto o Git Bash quanto o HTTPS nativo do Windows funcionam normalmente dentro de um comando confinado. O Rune não concede acesso às pastas de sistema do Windows, à raiz de uma unidade nem à pasta que reúne os perfis de todos os usuários; por isso, um projeto aberto diretamente em um desses locais pede permissão antes de cada comando nos modos Ask e Auto.

O Windows não informa ao Rune quando um comando aguarda entrada digitada. Um comando silencioso em segundo plano pode estar esperando uma resposta ou ainda processando: leia o log antes de responder. Como um programa em execução não pode ser substituído no Windows, uma atualização passa a valer na próxima janela do Rune que você abrir, não nas janelas que já estavam abertas.

Terminais

Atalhos de teclado e gestos do mouse só chegam ao Rune quando o terminal os repassa. O Konsole aplica zoom com Ctrl+roda, a menos que seu perfil seja configurado de outra forma, e alguns terminais transformam Alt+roda em rolagem horizontal; a roda simples e as teclas funcionam sempre. A rolagem suave só desliza em terminais que desenham quadros inteiros de uma vez e acompanham a taxa de atualização; nos demais, cada passo da roda move as linhas de forma direta. Cores, transparência e fontes pertencem ao terminal. Execute /help para ver a quais atalhos sua compilação responde.
