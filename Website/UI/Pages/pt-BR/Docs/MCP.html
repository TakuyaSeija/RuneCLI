Capacidades externas

O protocolo MCP conecta servidores externos que oferecem ferramentas, recursos ou prompts. Use /mcp ou rune -mcp; não há uma aba separada para isso em Settings. Conectar um servidor é diferente de aprovar cada tarefa executada por meio de uma ferramenta.

Um servidor remoto recebe os dados que você envia a ele. Um servidor local inicia código neste computador. O texto retornado é tratado como dado de tarefa não confiável, mesmo quando afirma conter instruções oficiais.

Escopo e aprovação

User
Definições pessoais disponíveis nos projetos desejados.
Project
Definições compartilhadas na configuração MCP do projeto. Revise e aprove-as explicitamente; uma definição compartilhada que for alterada pode exigir uma nova aprovação.
Private project
Definições pessoais para um único projeto — o escopo padrão para alterações MCP. Elas podem substituir definições compartilhadas do projeto com o mesmo ID, que por sua vez têm precedência sobre definições pessoais do usuário.

Inspecione com list/status e valide as definições antes de conectar. A validação não é um teste de conectividade ao vivo. O comando add recebe um ID de servidor e uma URL remota desejada ou um executável local absoluto com argumentos. Consulte a ajuda do comando instalado para ver a sintaxe exata de cada operação.

Revise o acesso

Antes de adicionar ou ativar um servidor, inspecione seu executável/argumentos ou destino remoto, autenticação, variáveis de ambiente, permissão de escrita no projeto, pastas adicionais de leitura/escrita e acesso a serviços locais já em execução. Conceda apenas o que a tarefa realmente exigir.

Endpoints remotos exigem HTTPS; o uso de HTTP simples é restrito ao loopback. Não incorpore segredos em uma URL compartilhada nem em valores literais de variáveis de ambiente. Use o fluxo de credenciais suportado. Executáveis locais e pastas raiz extras são decisões reais de acesso, não meros rótulos descritivos.

Pastas externas adicionais podem exigir aprovação nos modos Ask/Auto antes que um servidor local seja iniciado. O acesso amplo a serviços locais pode alcançar programas que atuam com os direitos da sua conta. Não amplie essas opções apenas para silenciar uma falha de conexão.

Conectar, testar e remover

list · status
Inspeciona os servidores configurados e o estado atual da conexão.
validate
Verifica as definições sem afirmar que a conexão foi estabelecida com sucesso.
connect <id> · test <id>
Estabelece uma conexão real, podendo iniciar código local ou contatar um serviço remoto.
approve <id>
Aprova uma definição compartilhada revisada. Não aprove um arquivo que você não tenha inspecionado.
disconnect <id>
Encerra aquela conexão; isso não remove sua definição salva.
enable|disable|remove <id>
Altera a disponibilidade da definição desejada ou a remove, usando o escopo de configuração correto.
reload
Atualiza as conexões configuradas.
login <id> · login-status <id>
Inicia um fluxo de autenticação aplicável ou inspeciona seu estado.

Essas operações acompanham rune -mcp, por exemplo rune -mcp status. Revise o escopo e o ID selecionados em cada alteração. Comandos avançados de credenciais, como token/secret, aceitam valores sensíveis; prefira a interface de autenticação suportada em vez de deixar credenciais no histórico do shell.

A autenticação pode usar uma credencial bearer ou um fluxo OAuth. Não cole tokens na conversa. Um servidor conectado com sucesso não prova que todas as ferramentas sejam seguras, reversíveis ou compatíveis. O modelo descobre as entradas exatas das ferramentas e utiliza os controles normais de execução, sem inventar a API de outro servidor.
