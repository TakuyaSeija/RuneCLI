Reúna a menor evidência útil

Anote a saída de rune -version, o erro exato, o rodapé visível, o comando ou configuração afetada e se o problema ocorre em uma única sessão ou em todas. Leia a entrada correspondente em /logs e inspecione a configuração específica com explain. Remova informações privadas antes de compartilhar.

rune -version
rune -config check
rune -config explain network.stream_idle_timeout

Esses comandos inspecionam a versão e a configuração. Um arquivo de configuração válido não significa que a conexão com o provedor esteja funcionando. O comando -doctor, os testes de provedor e os testes de modelo podem realizar requisições reais de rede.

Instalação

rune: command not found
O instalador informa a pasta utilizada. Execute o rune a partir dela pelo caminho completo ou adicione essa pasta ao seu PATH conforme mostrado em Instalação e atualização e abra um novo terminal.
No build for your system
A versão não possui compilação assinada para esse sistema operacional, processador ou biblioteca C. A linha abaixo do comando de instalação na página inicial informa quais compilações existem. Nada foi instalado.
SIGNATURE CHECK FAILED ou CHECKSUM MISMATCH
O arquivo baixado não corresponde à versão oficial publicada. Nada foi instalado; não utilize esses arquivos. Tente novamente mais tarde, a partir de uma rede confiável, e relate o problema se persistir.
Run as your normal user
No Linux e no macOS, o instalador recusa execução como root, pois o programa é instalado na sua própria pasta pessoal. Abra um terminal comum e execute-o novamente. No Windows, não é necessário abrir o PowerShell como Administrador; o programa é instalado no perfil da conta em que a janela está rodando.
The program does not run on this system
O sistema é mais antigo do que o suportado pelo Rune ou o processador é incompatível. Suporte a plataformas lista as versões compatíveis.

Teclas, mouse, cores e cópia

Um atalho que não produz efeito geralmente foi interceptado pelo próprio terminal. O Konsole aplica zoom com Ctrl+roda, a menos que o perfil diga o contrário, e alguns terminais transformam Alt+roda em rolagem horizontal; /help lista os atalhos aos quais o Rune responde. Cores com contraste ruim em fundos claros ou escuros costumam indicar que o terminal não informou sua cor de fundo: defina RUNE_THEME como dark, light ou uma cor hexadecimal.

No Linux, a cópia de texto passa pelo terminal, que precisa permitir que programas definam a área de transferência; via SSH ou dentro do tmux isso costuma vir desativado. Ative a opção (no tmux, use set -g set-clipboard on) ou segure Shift ao arrastar para usar a seleção nativa do terminal.

Os comandos continuam pedindo permissão no modo Auto

O modo Auto só executa comandos sem perguntar quando eles podem ser confinados. Onde o sistema não oferece sandbox, como em um kernel Linux antigo, todo comando pede permissão primeiro; /help informa em This machine se a sandbox está ativa. No Windows sem a conta dedicada de sandbox do Rune, o Git Bash e outros programas MSYS2 ou Cygwin pedem permissão antes de cada comando; rune -sandbox explica por que a conta não está em uso e rune -sandbox setup a configura. Um comando que tenta acessar um programa já em execução no seu computador, como um motor de contêineres ou agente de chaves, também pede permissão; trata-se de uma autorização separada.

Um comando em segundo plano parece travado

Leia o relatório e o log do comando antes de interrompê-lo ou enviar uma resposta. No Linux, o Rune percebe quando um comando aguarda entrada digitada. Já o macOS informa ao Rune apenas entradas ocultas, como pedidos de senha, e o Windows não informa nenhuma espera; por isso, nesses sistemas um comando silencioso pode estar aguardando resposta ou ainda trabalhando. Nunca tente adivinhar uma senha nem confirme um prompt apenas porque o comando está em silêncio. Fechar todas as janelas do Rune encerra os comandos em segundo plano assim que termina o tempo de retenção da sessão desconectada (60 segundos por padrão).

O modelo informa que o contexto é grande demais

O Rune compacta o histórico mais antigo a partir do uso reportado pelo provedor ou após o provedor rejeitar uma requisição por exceder o limite de contexto. Se nenhuma parte antiga puder ser resumida com segurança, o erro do provedor é exibido e a mesma requisição não é reenviada. Confira a janela de contexto do modelo em Models → Alt+C, inicie uma nova sessão com /new para assuntos não relacionados ou execute /compact. Se um modelo de resumo pequeno rejeitar um lote, reduza o valor de compact.max_batch_size.

As chaves estão indisponíveis

O estado Key missing significa que a pasta de dados não possui chave salva para aquela conta; adicione-a em Connections. O estado Unavailable significa que o cofre criptografado existe, mas não pode ser aberto — por exemplo, porque o arquivo de chave está ausente ou pertence a outro backup. Restaure primeiro o par correspondente a partir de um backup. Iniciar um novo cofre de credenciais separa o antigo e exige que todas as chaves sejam cadastradas novamente; use isso como último recurso, não como teste. Credenciais explica cada estado.

Uma mensagem parece estar aguardando

Diferencie entre uma mensagem na fila, uma permissão ou pergunta sem resposta, uma geração ativa aguardando dados, uma espera entre tentativas e o estado Compacting. O campo de mensagem em branco, por si só, não identifica o estado. Evite enviar repetidas mensagens “Continue” como forma de diagnóstico; elas se tornam tarefas adicionais na fila.

Um stream lento mas contínuo é diferente de um stream inativo. Verifique o tempo limite reportado antes de alterá-lo. Um comando de terminal movido para segundo plano não significa automaticamente que falhou ou foi encerrado; leia o relatório da tarefa.

Uma conta ou modelo falha

Verifique o provedor/modelo selecionado e o endpoint pretendido. Os estados Key missing, Unavailable e Resting representam situações diferentes de credenciais. Um item listado no catálogo não comprova que sua conta tenha acesso a ele, e uma palavra no ID do modelo não prova que um modo de raciocínio esteja disponível.

Novas tentativas automáticas não corrigem credenciais inválidas nem controles incompatíveis. Verifique primeiro a falha exata; não substitua o cofre de credenciais, não troque de provedor nem envie repetidos testes tarifados sem uma decisão deliberada.

A saída ou a busca está incompleta

Diferencie entre um recolhimento visual de quatro linhas, um teto de texto retornado, uma busca interrompida e um estouro de contexto do modelo. Expanda o bloco recolhido, leia qualquer aviso de saída salva ou continuação e restrinja o intervalo de linhas ou o escopo da busca. Uma busca incompleta não prova que não existam outras ocorrências.

O tamanho do contexto não equivale ao tamanho máximo da resposta. Aumentar uma capacidade exibida localmente não amplia o limite real do provedor. Reduzir demais o limite de saída pode não deixar espaço para a resposta final após o raciocínio.

O status da política ou das ferramentas web parece incorreto

O classificador marcado como ativado (Enabled) não significa que esteja ativo (Active): verifique o modo da sessão, se há uma política válida, as exclusões e se é necessário recarregar a política com a sessão ociosa. Uma revisão que falhou nunca equivale a uma aprovação. Um provedor web explícito ausente torna a ferramenta indisponível, nunca autorizando a troca silenciosa por outro serviço de terceiros.

Busca e leitura de páginas têm seleções independentes. Salvar uma conta web em Connections não seleciona automaticamente o provedor da ferramenta; faça essa seleção em Tools.

Após uma atualização

Sessões abertas no Linux e no macOS adotam a nova compilação instalada assim que ficam ociosas, sem exigir reinicialização forçada. No Windows, as janelas abertas continuam na compilação em que iniciaram, e a próxima janela do Rune que você abrir usará a versão nova. Uma falha pontual ao retomar não significa que sua sessão deva ser excluída.

Se o Rune informar que seus dados não puderam ser atualizados, corrija o pré-requisito indicado — como espaço em disco ou permissão de escrita — e tente novamente. Se um item for reportado como mantido sem alteração, não presuma que todos os demais falharam. Nunca exclua arquivos de execução ativos, não desative a revisão, não mude para o modo Full nem apague o armazenamento como improviso sem entender a causa.
