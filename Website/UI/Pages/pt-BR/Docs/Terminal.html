Primeiro plano e segundo plano

O agente escolhe se executa um comando em primeiro ou segundo plano conforme as dependências da tarefa. Se a próxima etapa precisar do resultado imediato do comando, uma chamada normal em primeiro plano o retorna diretamente. Se um trabalho independente puder prosseguir, uma execução explícita em segundo plano retorna um ID de tarefa na hora. O nome do comando por si só não determina qual escolha é a correta.

Um comando em primeiro plano que continue rodando após o tempo de espera configurado passa para segundo plano como o mesmo processo; ele não é reiniciado. O tempo de espera de fábrica é de 120 segundos. Uma espera por entrada digitada detectada pelo sistema pode antecipar essa transferência. O silêncio na saída, por si só, não prova que o comando esteja pedindo entrada.

Shell e diretório

Cada chamada inicia um novo shell; o comando cd não persiste de uma chamada para outra. O diretório do comando precisa ser informado na própria chamada. O shell automático escolhe um shell compatível disponível para o sistema operacional; na configuração avançada, você pode definir o caminho absoluto de um shell instalado.

A caixa do comando mostra qual shell realmente rodou: $ para bash e zsh, PS> para PowerShell e > para Prompt de Comando. Trocar de shell altera a sintaxe dos comandos. Os comandos de shell rodam sob o modo de permissão atual e o escopo aprovado; as configurações de terminal não autorizam por conta própria a execução nem o acesso a serviços locais.

Leia o relatório real

Running
O processo continua ativo; não significa conclusão com sucesso.
Waiting for input
O sistema detectou que o processo aguarda entrada digitada. Leia o prompt antes de responder.
Completed / Failed
O processo terminou. Leia seu código de saída e o texto impresso; um código de saída zero comprova apenas o que o próprio comando verificou.
Killed
O processo foi interrompido. Não presuma que o trabalho parcialmente realizado tenha sido revertido.
Lost
O Rune não consegue confirmar o resultado final normal, por exemplo após perder a comunicação com o tempo de execução monitorado. Não equivale a sucesso.

Quando uma tarefa termina ou uma espera por entrada é detectada, o Rune notifica o agente com o próprio relatório: qual tarefa, como terminou, seu PID, por quanto tempo rodou, o caminho do arquivo de log e a saída que ainda não havia sido entregue ao agente. Nada precisa ser solicitado separadamente, de modo que o mesmo comando nunca é executado de novo apenas para recuperar sua saída; caso a captura tenha sido encurtada ou fique incompleta, essa linha informa isso claramente.

O log salvo

Cada comando em segundo plano grava um arquivo de log no seu computador. Ele guarda a saída já concluída e, no final, a tela atual do terminal, de forma que uma pergunta sem quebra de linha final já aparece ali. O log é salvo em texto puro após aplicar as movimentações de cursor do terminal: uma barra de progresso que redesenha a mesma linha permanece como uma única linha, e uma resposta digitada na linha de uma pergunta substitui essa linha em vez de duplicá-la.

O primeiro relatório que o agente lê de um comando em segundo plano começa no início do log, mesmo quando parte dele já foi exibida antes; relatórios seguintes trazem apenas a saída nova ou alterada. Um relatório que mencione apenas o processo e seu log indica que não houve saída nova. Antes de anunciar que um comando aguarda entrada digitada, o Rune grava o log em disco, permitindo que o Rune o leia mesmo após reiniciar, sem depender da conversa antiga. Isso não protege contra falhas físicas de disco ou travamentos no meio de uma escrita.

Entrada digitada

A ferramenta process_control envia texto digitado para uma tarefa conhecida em segundo plano ou a interrompe junto com todos os processos filhos que ela iniciou. Ela não aguarda a conclusão nem retorna a próxima saída. A opção de envio pode acrescentar Enter automaticamente, forçar Enter ou apenas digitar o texto. Enviar texto vazio com Enter apenas pressiona a tecla Enter.

A detecção de espera por entrada varia conforme a plataforma: o Linux detecta esperas por entrada digitada, o macOS detecta entradas ocultas (como pedidos de senha) e o Windows não detecta essas esperas. Uma tarefa silenciosa nesses dois últimos sistemas pode estar aguardando resposta. Nunca tente adivinhar uma senha nem confirme um prompt destrutivo apenas porque o processo está em silêncio.

Limites de saída e tempo de vida

O limite de fábrica para texto retornado ao modelo é de 30.000 caracteres. Os limites separados de captura são de 8 MiB para saída em primeiro plano e 100 MiB por log em segundo plano; ultrapassar um limite de captura ou log interrompe o comando. A prévia de quatro linhas na transcrição é apenas um recolhimento visual.

Fechar a última janela do Rune interrompe o trabalho ativo da IA. As tarefas em segundo plano permanecem durante o período de retenção da sessão desconectada (60 segundos por padrão) e depois são encerradas. Configure um serviço próprio do sistema operacional quando precisar de um processo rodando de forma permanente e independente; não presuma que uma tarefa em segundo plano do Rune continuará ativa para sempre.
