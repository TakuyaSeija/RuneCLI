Lancer et inspecter

Exécutez ces commandes dans le shell de votre système d’exploitation. Utilisez rune -help pour connaître les options de votre version installée. Les commandes qui contactent des fournisseurs, modifient des comptes, suppriment des données ou démarrent des serveurs sont de vraies opérations, et non de simples options de diagnostic sans effet.

rune [dir]
Ouvre l’agent interactif dans l’espace de travail courant ou dans le dossier indiqué.
rune -p "prompt"
Exécute une seule invite et affiche la réponse ainsi que la progression des outils sans l’interface plein écran. Les demandes d’autorisation sont refusées plutôt qu’approuvées en silence lorsqu’il n’y a personne pour répondre.
-project <dir>
Sélectionne l’espace de travail pour une autre commande.
-version · -help
Affiche la version de l’application ou l’aide des commandes.
-settings · -tools
Inspecte les réglages effectifs du modèle ou les outils mis à la disposition de l’agent.
-read-only
Restreint les outils de modification. Cela ne garantit pas qu’aucun fichier ne soit lu ni qu’aucune donnée ne soit envoyée.
--no-color
Désactive la couleur. La variable d’environnement NO_COLOR est également prise en charge.

Configuration

-config
Affiche l’emplacement des paramètres sélectionnés.
-config show|defaults|check
Affiche les valeurs effectives, affiche les valeurs par défaut ou valide le fichier. La commande show peut contenir des métadonnées de compte privées ; check ne prouve pas la connectivité réseau.
-config explain <key>
Explique la valeur effective d’une clé et le moment où elle s’applique.
-config set <key> <value>
Enregistre un choix global. Exemple : rune -config set terminal.command_timeout 2m.
-config reset <key>
Supprime un remplacement global afin que la valeur par défaut actuelle ou l’héritage s’applique.
-config format
Reformate les paramètres groupés sans modifier leur signification.
-set key=value
Modifie une préférence prise en charge pour l’espace de travail ou le modèle, et non une clé de configuration globale arbitraire.

Comptes et modèles

Préférez l’éditeur d’identifiants masqué sous Connections. Passer de vraies clés en argument sur la ligne de commande risque de les exposer dans l’historique du shell et la liste des processus. La syntaxe ci-dessous utilise volontairement des paramètres fictifs.

rune -provider add <name> -key <key> [-preset <p>] [-base <url>] [-model <id>]
-provider list
Liste les comptes, les préréglages et la disponibilité des services Web.
-provider key <name> <key>
Ajoute une clé au trousseau d’un compte. Cette opération modifie les identifiants.
-provider keys <name>
Inspecte les métadonnées masquées des clés.
-provider dropkey <name> <n>
Supprime l’identifiant portant ce numéro après vérification de son identité.
-provider default <name>
Choisit le fournisseur de repli pour les nouvelles sessions ; cela ne bascule pas toutes les conversations existantes.
-provider remove <name>
Supprime la configuration du fournisseur. Ne supposez pas que chaque identifiant conservé est effacé de manière irréversible.
-provider test <name>
Envoie une vraie requête, potentiellement facturée, pour tester le compte.
-provider models <name>
Interroge le catalogue de modèles du compte. Effectue une requête réseau.
-provider dryrun <name> [model]
Prévisualise une requête sans l’envoyer. L’aperçu peut contenir du contexte privé ; ne le partagez pas tel quel.
-provider timeout <name> <seconds>
Définit un délai d’expiration facultatif pour les requêtes du compte, de 5 à 3 600 secondes ; default supprime le remplacement.
-provider new-store --yes
Met de côté une paire d’identifiants illisible et repart d’un coffre vide. N’utilisez cette commande qu’après une décision délibérée de récupération ; chaque clé devra être ajoutée de nouveau.
-model list · -model set <id>
Liste ou sélectionne un modèle pour l’espace de travail choisi.

Sessions et stockage

-session · -resume <id>
Ouvre le sélecteur de session (ou affiche la liste dans un tube) ou reprend une session connue.
-session rename <id> <title>
Renomme une session.
-session delete <id>
Supprime définitivement une session. Vérifiez d’abord son identité.
-storage [list|prune]
Inspecte le stockage des projets ou supprime les données éligibles appartenant à des projets qui n’existent plus sur le disque.
-sandbox [setup|reset]
Inspecte l’état de l’isolation des commandes sous Windows, configure explicitement son compte dédié ou supprime les accès et le compte du bac à sable de Rune. Les autres plateformes n’utilisent pas ce mécanisme.

Extensions et diagnostics

-skills [operation]
Liste, affiche, active, désactive, installe ou recharge des guides réutilisables. L’installation prend un dossier ou une archive zip vérifiés et les place dans le projet courant, sauf si --scope user les rend personnels.
-mcp [operation]
Gère, approuve, valide et teste des définitions d’outils externes. Une connexion peut démarrer un processus ou contacter un service distant ; la validation seule ne vaut pas connexion réussie.
--scope user|project|private-project
Choisit la portée de configuration prise en charge pour une modification d’extension. Les modifications partagées au niveau du projet affectent les autres personnes travaillant sur ce projet.
-doctor
Exécute des diagnostics, y compris des tests de connectivité. Peut effectuer des requêtes réseau ; relisez la sortie avant de la partager.
-db <path>
Utilise une autre base de stockage du moteur. C’est distinct du choix d’un répertoire complet de paramètres via RUNE_HOME.
-host
Utilise du JSON délimité par des retours à la ligne pour l’intégration d’une interface, au lieu de l’interface interactive. Ce n’est pas un serveur réseau public.
-script <file>
Rejoue un script de modèle écrit. Un script pouvant proposer de vrais appels d’outils, n’exécutez jamais un script non vérifié sur un projet réel.

Pour configurer et gérer les accès aux extensions, poursuivez avec Compétences (Skills) ou Connexions MCP. Ne passez pas en mode Full et ne supprimez pas vos données locales simplement pour contourner une erreur.
