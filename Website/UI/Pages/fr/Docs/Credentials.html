Saisir les secrets dans le champ dédié

Utilisez Settings → Connections → compte pour ajouter une clé API nommée. Un nom tel que Personal ou Work aide à distinguer les clés ; la valeur secrète doit être saisie dans le champ d’identifiant masqué, et jamais dans la conversation.

Les clés passées en argument sur la ligne de commande peuvent apparaître dans l’historique du shell ou dans les informations des processus. Les exemples de code source et les exports de configuration sont également faciles à publier par inadvertance. Une référence à un identifiant dans la configuration d’un compte n’est pas la valeur de la clé elle-même.

Stockage et transport

Rune chiffre son coffre d’identifiants au repos et restreint le matériel cryptographique local au seul compte utilisateur propriétaire. Cela protège contre une exposition accidentelle en clair, mais pas contre un compte utilisateur compromis ni contre un processus non restreint s’exécutant avec vos droits. Conservez ensemble le coffre chiffré et son matériel de clé correspondant dans une sauvegarde sécurisée.

Les identifiants connus sont masqués aux frontières des requêtes et des journaux. Cela ne rend pas pour autant n’importe quelle conversation ou export de diagnostic sûr à partager : un texte que vous collez manuellement dans la discussion fait partie du contenu de la conversation. Rune refuse d’envoyer une clé API en HTTP non chiffré vers une autre machine ; les services en boucle locale (loopback) constituent un cas local distinct.

Absent et indisponible sont deux états différents

Key missing
Le répertoire de données sélectionné ne possède aucun identifiant pour ce compte, ou aucun coffre d’identifiants. Ajoutez la clé souhaitée via la procédure prévue.
Unavailable
Le coffre existe mais ne peut pas être ouvert. La cause peut être un matériel de clé manquant ou endommagé, une sauvegarde désappariée, des fichiers illisibles ou un contenu altéré.
Rotation de l’anneau de clés
Lorsqu’un compte possède plusieurs clés, chacune dispose de son propre quota de tentatives avant de passer immédiatement la main à la clé suivante. Les clés peuvent être renommées sur place via Rename key sans ressaisir leur secret.

Rune peut tout de même démarrer lorsque les identifiants sont indisponibles ; seules les tâches qui en ont besoin signalent l’échec. Il ne prétend pas que le coffre est vide et ne le remplace pas silencieusement par un nouveau.

Récupérer de manière délibérée

Vérifiez d’abord que vous utilisez le bon répertoire de données Rune et restaurez une sauvegarde cohérente du coffre et de sa clé si vous en disposez. Ne supprimez pas le coffre et ne créez pas de nouveau matériel de clé sans rapport comme raccourci de diagnostic.

Si la récupération est impossible, l’action Start a new credential store dans Connections, ou la commande rune -provider new-store --yes, met l’ancienne paire de côté et repart sans aucune clé. Chaque identifiant devra être ajouté de nouveau. Il s’agit d’une action de récupération délibérée, et non d’un simple test de connexion.

Rotation et suppression

Ajouter une clé nommée ajoute une alternative ; vérifiez le nom et l’aperçu masqué avant d’en supprimer une autre. La suppression d’une connexion peut laisser des clés disponibles pour une réutilisation. Si un identifiant a été exposé, révoquez-le ou remplacez-le également chez le fournisseur : supprimer une référence locale ne peut pas révoquer un jeton déjà copié ailleurs.

L’état Configured ou le nombre de clés ne prouve ni la validité de l’authentification ni la présence de crédit. Un test envoie une vraie requête, potentiellement facturée. Vérifiez toujours la destination avant de lancer un test après avoir modifié un point de terminaison.
