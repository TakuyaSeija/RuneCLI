Recueillir les éléments utiles les plus précis

Relevez le résultat de rune -version, le message d’erreur exact, le texte visible dans le pied de page, la commande ou le paramètre concerné, et vérifiez si le problème touche une seule session ou toutes les sessions. Consultez l’entrée correspondante dans /logs et inspectez le paramètre concerné avec explain. Masquez tout élément privé avant de partager ces informations.

rune -version
rune -config check
rune -config explain network.stream_idle_timeout

Ces commandes inspectent la version et la configuration. Un fichier de configuration valide ne prouve pas qu’une connexion à un fournisseur fonctionne. La commande -doctor ainsi que les tests de fournisseurs et de modèles peuvent effectuer de vraies requêtes réseau.

Installation

rune: command not found
L’installateur indique le dossier qu’il a utilisé. Exécutez rune depuis cet emplacement via son chemin complet, ou ajoutez ce dossier à votre PATH comme indiqué dans Installation et mise à jour, puis ouvrez un nouveau terminal.
No build for your system
La publication ne comporte aucune version signée pour ce système, ce processeur ou cette bibliothèque C. La ligne située sous la commande d’installation sur la page d’accueil indique quelles versions existent. Rien n’a été installé.
SIGNATURE CHECK FAILED ou CHECKSUM MISMATCH
Le fichier téléchargé ne correspond pas à la version officielle publiée. Rien n’a été installé ; n’utilisez pas ces fichiers. Réessayez plus tard depuis un réseau de confiance et signalez le problème s’il persiste.
Run as your normal user
Sous Linux et macOS, l’installateur refuse de s’exécuter en tant que root, car le programme s’installe dans votre répertoire personnel. Ouvrez un terminal ordinaire et relancez la commande. Sous Windows, une fenêtre PowerShell Administrateur n’est pas nécessaire ; le programme s’installe dans le profil du compte qui exécute la fenêtre.
Le programme ne se lance pas sur ce système
Le système est plus ancien que les versions prises en charge par Rune, ou l’architecture du processeur ne correspond pas. La page Plateformes prises en charge répertorie les versions compatibles.

Clavier, souris, couleurs et copie

Un raccourci qui ne produit aucun effet a généralement été intercepté par le terminal. Konsole zoome avec Ctrl+molette sauf réglage contraire de son profil, et certains terminaux transforment Alt+molette en défilement horizontal ; la commande /help répertorie les raccourcis reconnus par Rune. Des couleurs difficiles à lire sur un fond clair ou sombre indiquent généralement que le terminal n’a pas communiqué sa couleur de fond : définissez RUNE_THEME sur dark, light ou une couleur hexadécimale.

Sous Linux, la copie passe par le terminal, qui doit autoriser les programmes à écrire dans le presse-papiers ; via SSH ou dans tmux, cette option est souvent désactivée. Activez-la (dans tmux avec set -g set-clipboard on), ou maintenez Shift enfoncé tout en glissant la souris pour utiliser la sélection native du terminal.

Les commandes continuent de demander l’autorisation en mode Auto

Le mode Auto n’exécute les commandes sans poser de question que lorsqu’elles peuvent être confinées. Lorsque le système n’offre aucun bac à sable, par exemple sur un noyau Linux ancien, chaque commande demande votre accord au préalable ; /help indique sous This machine si le bac à sable est actif. Sous Windows, en l’absence du compte de bac à sable de Rune, Git Bash et les autres programmes MSYS2 ou Cygwin demandent confirmation avant chaque commande ; rune -sandbox explique pourquoi le compte n’est pas utilisé et rune -sandbox setup permet de le configurer. Une commande qui tente de joindre un programme déjà en cours d’exécution sur votre ordinateur, comme un moteur de conteneurs ou un agent de clés, demande également votre accord : il s’agit d’une autorisation distincte.

Une commande en arrière-plan semble bloquée

Lisez le rapport et le journal de la commande avant de l’arrêter ou de lui envoyer une saisie. Sous Linux, Rune détecte lorsqu’une commande attend une saisie clavier. macOS ne signale à Rune que les saisies masquées telles que les invites de mot de passe, et Windows ne signale rien : sur ces systèmes, une commande silencieuse peut donc attendre une réponse ou être encore en train de travailler. Ne devinez jamais un mot de passe et ne validez jamais une invite simplement parce qu’une commande est silencieuse. Fermer toutes les fenêtres Rune met fin aux commandes en arrière-plan une fois écoulée la durée de vie de session détachée (60 secondes par défaut).

Le modèle indique que le contexte est trop volumineux

Rune compacte l’historique ancien à partir de la consommation déclarée par votre fournisseur, ou après le rejet d’une requête jugée trop volumineuse par le fournisseur. Si aucune partie ancienne ne peut plus être résumée sans perte critique, l’erreur du fournisseur s’affiche et la même requête n’est pas renvoyée. Vérifiez la fenêtre de contexte du modèle dans Models → Alt+C, démarrez une nouvelle session avec /new pour une tâche indépendante ou lancez /compact. Si un petit modèle de résumé rejette un lot, réduisez compact.max_batch_size.

Les clés sont indisponibles

L’état Key missing signifie que le dossier de données ne contient aucune clé pour ce compte ; ajoutez-la dans Connections. L’état Unavailable signifie que le coffre chiffré existe mais ne peut pas être ouvert, par exemple parce que son fichier de clé est manquant ou provient d’une autre sauvegarde. Restaurez d’abord la paire correspondante à partir d’une sauvegarde. Créer un nouveau coffre d’identifiants met l’ancien de côté et oblige à ressaisir chaque clé : c’est une mesure de dernier recours, et non un test. La page Identifiants détaille chaque état.

Un message semble rester en attente

Distinguez un message mis en file d’attente, une question ou demande d’autorisation sans réponse, une génération active sans données reçues pour le moment, une attente entre deux tentatives et une opération de compaction (Compacting). Un compositeur vide ne suffit pas à identifier l’état. Évitez d’envoyer plusieurs messages « Continue » en guise de diagnostic : ils s’ajoutent comme autant de nouvelles tâches.

Un flux continu mais lent est différent d’un flux totalement figé. Vérifiez le délai d’expiration signalé avant de le modifier. Une commande de terminal qui passe en arrière-plan n’est pas une commande qui a échoué ou qui a été tuée ; lisez le rapport de la tâche.

Un compte ou un modèle échoue

Vérifiez le fournisseur et le modèle choisis, et le point d'accès voulu. Key missing et Unavailable sont deux états distincts ; une clé qui a échoué n'est pas marquée au repos, elle est réessayée dans l'ordre de l'anneau. Une entrée de catalogue ne prouve pas un droit, et un mot dans un ID de modèle ne prouve pas qu'un mode de raisonnement est disponible.

Les nouvelles tentatives ne réparent ni des identifiants invalides ni des réglages non pris en charge. Consultez d’abord l’erreur exacte ; ne remplacez pas votre coffre d’identifiants, ne changez pas de fournisseur et ne multipliez pas les tests facturables sans décision réfléchie.

Une sortie ou une recherche est incomplète

Distinguez un repli visuel de quatre lignes, un plafond de texte renvoyé, une recherche arrêtée et un dépassement de la fenêtre de contexte du modèle. Dépliez l’encadré, lisez toute mention de sortie enregistrée ou de suite disponible, et restreignez la plage de lignes ou le périmètre de recherche. Une recherche incomplète ne prouve pas qu’aucune autre correspondance n’existe.

La taille de la fenêtre de contexte n’est pas la longueur maximale d’une réponse. Augmenter une capacité affichée localement ne peut pas repousser la limite réelle du fournisseur. Réduire excessivement la limite de sortie peut ne laisser aucune place pour la réponse finale après la phase de raisonnement.

L’état de la politique ou des outils Web semble incorrect

Un classifieur marqué Enabled ne signifie pas qu’il est Active : vérifiez le mode de la session, la validité du fichier de politique, les outils exclus et la nécessité éventuelle d’un rechargement à l’état inactif. Un examen ayant échoué ne vaut jamais approbation. Si un fournisseur Web explicitement épinglé est absent, l’outil devient indisponible et ne choisit jamais un autre service tiers en silence.

La recherche et la récupération de pages possèdent des sélections distinctes. Enregistrer un compte Web dans Connections ne sélectionne pas le fournisseur utilisé par l’outil ; passez par Tools pour effectuer ce choix.

Le nouvel essai et ses deux quotas

Rune essaie une clé retry.attempts_per_key fois (dix par défaut) avant d'utiliser la suivante de son anneau, et l'appel entier s'arrête quand retry.max_attempts est épuisé. Une clé épuisée cède la main aussitôt ; la courbe (3, 6, 9... secondes) est l'attente entre deux essais avec la même clé. Le pied nomme la clé et les deux compteurs, et un changement de clé est aussi écrit dans le fil.

Un réglage que le moteur refuse

Un réglage est vérifié au chargement de rune.toml, pas à l'usage. Une clé inconnue, une valeur du mauvais type, un nombre ou une durée hors plage, ou un modèle ou une connexion qui n'existe pas arrêtent le moteur avec une phrase nommant la clé ; rien ne tourne sur une valeur devinée. Corrigez le fichier, ou retirez la clé avec rune -config reset, et vérifiez avec rune -config check. Toutes les clés, leurs défauts et les valeurs acceptées sont dans la Référence des réglages.

Après une mise à niveau

Sous Linux et macOS, les sessions ouvertes peuvent adopter la nouvelle version installée dès qu’elles sont inactives, sans redémarrage forcé. Sous Windows, les fenêtres ouvertes continuent de tourner sur leur version de départ ; toute nouvelle fenêtre Rune ouverte utilise la nouvelle version. Un échec ponctuel lors de la reprise d’une session ne signifie pas que vous devez supprimer cette session.

Si Rune indique que ses données n’ont pas pu être mises à jour, corrigez le prérequis mentionné (comme l’espace disque ou les droits d’écriture) et réessayez. Si un élément est signalé comme laissé intact, n’en déduisez pas que tous les autres éléments ont échoué. Ne supprimez jamais de fichiers d’exécution à chaud, ne désactivez pas l’examen par la politique, ne passez pas en mode Full et n’effacez pas le stockage comme solution de contournement à l’aveugle.
