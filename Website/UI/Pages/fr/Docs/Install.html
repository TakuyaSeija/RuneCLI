Ce dont vous avez besoin

Linux
x86_64 ou arm64, partout où une version signée pour ce processeur est publiée. Chaque version indique les architectures qu’elle propose. La version glibc fonctionne sur les distributions dotées de glibc 2.17 ou plus récent, et a été testée sur CentOS 7, Debian 11 et 12 et Ubuntu 24.04. La version statique musl ne nécessite aucune bibliothèque C du système et a été testée sur Alpine.
macOS
macOS 11 ou version ultérieure, sur Apple Silicon ou Intel. La prise en charge de macOS est en version bêta.
Windows
Windows 10 version 1809 ou ultérieure, ou Windows 11, sur x64 ou ARM64. La prise en charge de Windows est en version bêta.
L’installateur
Sous Linux et macOS : curl, tar, gzip et openssl (OpenSSL ou le LibreSSL inclus dans macOS) pour la vérification de signature. Sous Windows : PowerShell, inclus dans toutes les versions prises en charge de Windows. Sous Linux et macOS, exécutez-le avec votre compte utilisateur normal, sans root ; sous Windows, aucun droit d’administrateur n’est requis.
Un compte de modèle
Un compte auprès du fournisseur de votre choix, ou un service de modèle installé sur votre propre ordinateur. Voir Fournisseurs de modèles.

Les systèmes disposant d’une version signée dans la publication actuelle sont indiqués sous chaque commande d’installation sur la page d’accueil. Les différences entre systèmes sont détaillées dans Plateformes prises en charge.

Installateur

Les commandes d’installation se trouvent sur la page d’accueil : install.sh pour Linux et macOS, exécuté par sh, et install.ps1 pour Windows, exécuté dans PowerShell. Vous pouvez lire le script au préalable : tous deux sont servis en texte brut, install.sh et install.ps1, exactement tels que la commande les reçoit. Chacun exécute les étapes suivantes et s’arrête dès la première qui échoue, sans rien modifier :

  1. Vérifie le système et sa version, s’assure qu’il tourne sous un compte utilisateur normal et contrôle la présence des outils requis.
  2. Détecte le processeur et, sous Linux, la bibliothèque C (glibc ou musl).
  3. Télécharge la liste des sommes de contrôle de la version et vérifie sa signature à l’aide de la clé de publication intégrée au script.
  4. Télécharge l’archive correspondant à votre machine et la contrôle par rapport à cette liste signée.
  5. Vérifie que l’archive contient uniquement le programme et ses fichiers de licence, et que le programme démarre et renvoie la version attendue.
  6. Met le programme en place en un seul renommage, et place la licence ainsi que les avis relatifs aux composants tiers à côté de vos autres données utilisateur.
SystèmeProgrammeAvis de licence
Linux, macOS~/.local/bin/rune~/.local/share/runeagent (ou $XDG_DATA_HOME/runeagent)
Windows%USERPROFILE%\.local\bin\rune.exe%LOCALAPPDATA%\RuneAgent

Il ne modifie jamais votre profil shell ni votre variable PATH. Si le dossier ne figure pas dans votre PATH, il vous l’indique. La page Vérification des versions explique ce que la signature prouve ou non, et comment vérifier un téléchargement manuellement.

Les commandes d’installation téléchargent les fichiers avec curl et PowerShell, qui ne marquent pas le programme comme provenant d’Internet. En revanche, une archive téléchargée depuis un navigateur reçoit ce marquage. Sur macOS, Gatekeeper refuse alors de lancer cette copie de rune ; après avoir vérifié l’archive, retirez l’attribut de quarantaine avec xattr -d com.apple.quarantine rune. Sur Windows, SmartScreen peut afficher un avertissement lorsqu’un tel programme est ouvert depuis l’Explorateur de fichiers.

Options de l’installateur

Sans variable définie, l’installateur prend la dernière version publiée, votre dossier bin utilisateur et, sous Linux, la bibliothèque C détectée. Sous Linux et macOS, enregistrez le script sous le nom install.sh, lisez-le, puis exécutez-le avec l’une de ces variables. Sous Windows, définissez-les dans la même fenêtre PowerShell avant de lancer la commande.

RUNE_VERSION
Une version publiée telle que {{.DocVersion}}. Les versions antérieures s’installent par leur numéro.
RUNE_INSTALL_DIR
Un chemin absolu de dossier pour le programme à la place du dossier par défaut.
RUNE_LIBC
Linux uniquement : gnu ou musl, pour choisir la variante au lieu de la détecter. Toute combinaison sans archive publiée est refusée.
RUNE_VERSION={{.DocVersion}} sh install.sh
RUNE_INSTALL_DIR="$HOME/bin" sh install.sh
$env:RUNE_VERSION = "{{.DocVersion}}"
irm {{.Origin}}{{url "install.ps1"}} | iex

Ajouter rune à votre PATH

De nombreuses distributions Linux incluent déjà ~/.local/bin, mais uniquement si ce dossier existe au moment où vous ouvrez votre session ; macOS ne l’inclut pas par défaut. Si la commande rune est introuvable, ajoutez le dossier vous-même. Pour bash ou zsh (le shell par défaut sur macOS), ajoutez cette ligne à ~/.bashrc ou ~/.zshrc, puis ouvrez un nouveau terminal :

export PATH="$HOME/.local/bin:$PATH"

Sous fish, exécutez une seule fois fish_add_path ~/.local/bin. Sous Windows, cette commande PowerShell ajoute le dossier à votre PATH utilisateur ; ouvrez ensuite un nouveau terminal :

[Environment]::SetEnvironmentVariable("Path", [Environment]::GetEnvironmentVariable("Path", "User") + ";$HOME\.local\bin", "User")

Utilisez votre propre dossier si vous avez défini RUNE_INSTALL_DIR.

Le premier démarrage

Ouvrez un terminal dans votre projet et lancez rune. Lors de son premier démarrage, Rune crée son dossier de données, .rune dans votre répertoire personnel (%USERPROFILE%\.rune sous Windows), ou le dossier désigné par RUNE_HOME. Ce dossier contient :

  • rune.toml, vos paramètres. Il n’enregistre que les choix que vous avez modifiés ; toutes les autres valeurs proviennent de la version que vous exécutez.
  • Vos clés API, chiffrées.
  • Les sessions, la mémoire de projet et les instantanés utilisés par la fonction d’annulation, conservés par projet.

Sous Windows, le premier démarrage demande également une seule fois une confirmation Administrateur afin de configurer le compte séparé dans lequel Rune exécute les commandes. Si vous refusez, Rune ne vous le redemandera pas à chaque lancement ; exécutez rune -sandbox setup lorsque vous souhaiterez l’activer. La page Sécurité explique ce qui change sans ce compte.

La commande rune -config affiche le dossier utilisé sur sa première ligne. Rune y conserve ses propres données, et non dans vos projets : un projet n’est modifié que par les outils de l’IA selon le mode que vous choisissez, par vos propres commandes !, ou par une compétence ou une configuration MCP que vous enregistrez avec une portée projet. Poursuivez avec la section Connecter et sélectionner un modèle de l’Introduction.

Mise à jour

Relancez l’installateur pour la version souhaitée, avec le même RUNE_INSTALL_DIR si vous en aviez défini un. Il vérifie le téléchargement et remplace le programme en une seule étape ; contrôlez le résultat avec rune -version.

Les fenêtres Rune déjà ouvertes continuent de fonctionner. Sous Linux et macOS, elles passent d’elles-mêmes à la nouvelle version dès qu’elles sont inactives, et le premier lancement d’une nouvelle version met à jour votre dossier de données en conséquence. Sous Windows, un programme en cours d’exécution ne peut pas être remplacé à chaud : les fenêtres ouvertes conservent la version avec laquelle elles ont démarré, et la prochaine fenêtre Rune que vous ouvrirez utilisera la nouvelle. Ne fermez pas un travail en cours pour forcer ce passage.

Désinstallation

Terminez ou arrêtez votre travail et fermez toutes les fenêtres Rune. Supprimez ensuite le programme et ses avis de licence. Sous Linux et macOS :

rm ~/.local/bin/rune
rm -r ~/.local/share/runeagent

Sous Windows, dans PowerShell :

rune -sandbox reset
Remove-Item "$HOME\.local\bin\rune.exe"
Remove-Item -Recurse "$env:LOCALAPPDATA\RuneAgent"

Sous Windows, rune -sandbox reset retire d’abord les accès accordés au bac à sable de commandes de Rune sur vos dossiers et supprime son compte dédié ; une confirmation Administrateur peut être demandée. Votre dossier de données reste en place jusqu’à ce que vous le supprimiez vous-même. Il contient votre historique, vos paramètres, vos clés et vos points de restauration, et il n’est pas nécessaire de le supprimer pour désinstaller le programme. Si vous décidez de le supprimer, vérifiez d’abord son emplacement avec rune -config, et ne le supprimez jamais pendant que Rune est en cours d’exécution.

Variables d’environnement

RUNE_HOME
Utilise un autre dossier de données à la place de .rune dans votre répertoire personnel : avec ses propres paramètres, clés et sessions.
NO_COLOR
Affiche sans couleur, comme l’option --no-color.
RUNE_THEME
Indique à Rune la couleur de fond de votre terminal lorsque celui-ci ne la communique pas : dark, light ou une couleur hexadécimale. Ce n’est pas le choix du thème de couleurs, qui se règle dans Appearance.
RUNE_VERSION, RUNE_INSTALL_DIR, RUNE_LIBC
Lues uniquement par l’installateur ; voir Options de l’installateur.
