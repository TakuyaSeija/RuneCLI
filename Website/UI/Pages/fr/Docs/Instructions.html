Consignes de projet

Le fichier AGENTS.md à la racine de l’espace de travail fournit les consignes du projet : commandes de compilation, conventions et limites pertinentes pour le travail. Ce n’est ni un fichier de clés API, ni un octroi d’autorisation, ni la politique du classifieur. N’y mettez aucun identifiant secret et n’y incluez que du texte que vous acceptez d’envoyer comme contexte au modèle.

Le plafond par défaut des instructions chargées automatiquement est de 32 768 caractères, contrôlé par instructions.max_chars dans Settings → Tools → Project instructions. Lorsqu’un fichier dépasse ce plafond, Rune signale la partie omise et l’IA lit le reste avant de s’appuyer sur ces règles ; la suite du fichier ne cesse pas d’exister. Si les consignes changent au cours d’une session, Rune peut inviter le modèle à relire la source concernée.

Joindre le fichier voulu

/attach <path> ajoute un fichier au prochain message ; /detach <number|all> retire les pièces jointes en attente. Vérifiez la liste en attente avant d’envoyer votre message. Un modèle peut prendre en charge différemment le texte, les images ou d’autres médias ; la présence d’un fichier ne prouve pas que son contenu pourra être interprété.

Une pièce jointe envoyée identifie la version du fichier telle qu’elle a été envoyée. Modifier le fichier à cet emplacement par la suite ne doit pas transformer un ancien message en lui attribuant les nouveaux octets. Lorsque le contenu d’origine ne peut pas être récupéré, Rune signale que le fichier a changé ou disparu au lieu de présenter le nouveau contenu comme ancien. Joignez explicitement la nouvelle version lorsque la tâche l’exige.

Les limites par défaut comprennent 60 000 caractères de texte par fichier texte joint et jusqu’à dix pièces jointes historiques. Les limites de contexte et de taille de requête du fournisseur peuvent entraîner le retrait anticipé des médias plus anciens. Ces limites sont distinctes des pièces jointes du message en cours ainsi que du repli visuel dans la transcription.

Mémoire de projet

Rune prend en charge des notes de projet durables accompagnées d’un index MEMORY.md ; la page Mémoire explique où résident ces notes et ce qui est transmis au modèle. Le modèle reçoit l’index, mais pas chaque note automatiquement, et lit une note pertinente lorsque c’est nécessaire. Le budget de rappel de l’index est de 20 KiB par défaut ; l’augmenter consomme davantage de contexte de modèle sans améliorer l’exactitude des notes.

Utilisez la mémoire pour les décisions stables, les corrections et les travaux au long cours. N’y stockez ni identifiants secrets ni chaque résultat temporaire de commande. Les notes peuvent être incluses dans des requêtes ultérieures au modèle et ne constituent pas une source d’autorisation distincte. Le modèle accède à la mémoire de projet via les outils de fichiers en utilisant le préfixe @memory/, sans créer de dossier memory à l’intérieur de votre dépôt.

Garder les rôles bien séparés

AGENTS.md
Consignes de projet fournies comme contexte au modèle.
CLASSIFIER.md
Votre politique d’examen des actions applicables de l’IA. Elle possède un mécanisme de rechargement explicite et ne se confond pas avec les consignes de projet.
rune.toml
Paramètres situés dans le répertoire de données Rune sélectionné. Un fichier portant le même nom dans un projet n’est pas automatiquement le fichier de paramètres global.
Skill
Un guide réutilisable activé ou lu pour accomplir une tâche. Il ne peut pas accorder d’accès par lui-même.

Le texte d’un dépôt, une page Web ou la réponse d’un outil peuvent contenir des instructions trompeuses. Traitez leur contenu comme de simples données de travail et examinez les actions à la frontière d’autorisation plutôt que de croire un document affirmant qu’une approbation existe déjà.
