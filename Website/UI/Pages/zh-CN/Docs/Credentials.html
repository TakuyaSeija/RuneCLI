在专用凭据框中输入密钥

请通过 Settings → Connections → 具体账户 来添加命名的 API 密钥。使用 Personal 或 Work 等名称有助于区分不同密钥；真正的密钥值应填入带掩码的凭据字段中，切勿直接粘贴在对话窗口里。

通过命令行参数传入的密钥可能会留在 shell 历史记录或系统进程列表中。代码示例和配置导出内容也很容易在无意间公开泄露。账户配置中记录的凭据引用只是索引标识，并非密钥明文。

加密存储与传输安全

Rune 会对磁盘上的凭据存储进行静态加密，并将本地密钥材料的访问权限限制为当前系统账户。这能防止意外的明文泄露，但无法抵御系统账户本身失守或以你身份运行的非受限进程。备份时请将加密凭据库与对应的密钥材料一并妥善保存在安全位置。

已知的凭据会在请求和日志边界自动脱敏。但这并不意味着任意对话记录或诊断导出文件都可以随意公开：你手动粘贴进聊天框的文本属于对话内容。Rune 拒绝通过明文 HTTP 向其他机器发送 API 密钥；本机回环（loopback）服务则属于独立的本地场景。

区分“未配置”与“不可用”

Key missing（缺少密钥）
当前选定的数据主目录中没有该账户的凭据，或尚未创建凭据存储。请按正常流程添加所需密钥。
Unavailable（不可用）
凭据存储已存在但无法打开。原因可能是密钥材料丢失或损坏、备份配对不匹配、文件权限不可读或内容损坏。
密钥环轮换
当账户保存了多把密钥时，每把密钥拥有独立的尝试配额，耗尽后立即交棒给环中的下一把密钥。使用 Rename key 可直接修改密钥名称，无需重新输入密钥明文。

当凭据存储不可用时，Rune 依然可以正常启动，仅在执行需要凭据的任务时才会报告失败。系统不会假装凭据存储为空，也不会静默创建新存储来覆盖旧文件。

审慎恢复凭据存储

遇到凭据不可用时，请先核对当前使用的 Rune 主目录是否正确，若有配套的凭据备份请优先从备份恢复。切勿把删除凭据库或生成无关的替代密钥材料当成排查问题的捷径。

如果确实无法恢复，可在 Connections 页面选择 Start a new credential store，或运行 rune -provider new-store --yes，将无法读取的旧文件搁置保留，并从零开始建立空凭据库。此后所有凭据都需要重新添加。这是一项明确的灾难恢复操作，而非常规的连接测试手段。

密钥轮换与移除

添加命名密钥会增加一把备选密钥；移除其他密钥前请先核对名称和脱敏预览。移除连接后，相关密钥仍可能保留供后续复用。如果某把凭据已经泄露，请务必同时前往提供商后台吊销或轮换该密钥——仅删除本地引用无法使已被复制到别处的令牌失效。

显示已配置或显示密钥数量并不证明认证一定有效或账户内有余额。每次测试都会发起真实的、可能产生计费的请求。修改接口地址后，请先核实目标地址再执行测试。
