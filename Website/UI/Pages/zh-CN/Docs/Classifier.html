策略审查，而非授予权限

分类器会根据你编写的 CLASSIFIER.md 策略，对适用的拟议操作进行审查。它需要有效的策略文件以及符合条件的权限模式才会工作：在 Ask 模式下处于非活动状态；在 Auto 或 Full 模式下，工具排除列表与显式人工授权都会影响某次调用是否经过分类器审查。请以 Classifier status 显示的实际状态为准，不要将 Enabled（开关开启）直接等同于 Active（正在生效）。

审查模型也有可能判断失误。策略审查不能取代访问控制检查、合理的任务边界或你自己的判断，也不会让 Full 模式变成低风险模式。

策略优先级

策略文件既可以作为全局策略放在当前选定的 Rune 主目录中，也可以作为项目级策略放在工作区根目录下。全局规则优先于项目规则，而项目规则又优先于任务中附带的显式用户限制说明。请直接写出明确的要求、禁止项和例外情况，不要指望模型去揣测未写明的许可。

CLASSIFIER.md 与提供项目开发背景的 AGENTS.md 职责不同。策略文件完全由你掌控，修改它即代表做出真实的项目级或全局级策略决定。助手在回答中生成的解释或工具返回的结果，都无法凭空捏造你的批准。

策略快照与重新加载

会话会在接收第一项任务时锁定当时的策略状态（包括未找到策略文件或策略无效的状态）。直接编辑磁盘上的文件不会静默替换正在运行的会话策略。当会话处于空闲状态时，可在 Generation 页面选择 Reload classifier policy，或执行 /classifier reload。若重新加载失败，会话会保留原有策略；新建的会话或前端则会读取当前生效的最新策略。

重新加载后请检查状态提示。若没有可用的策略，系统绝不会声称审查处于活动状态。切勿仅仅因为某次评估未通过就禁用分类器或切换权限模式。

审查依据与配额限制

分类器审查依据包括：拟议调用的完整参数、相关的用户原始指令与补充说明、显式添加的文本/图片附件，以及选定的近期工具输入。它不会仅仅因为某条命令提及了某个文件名，就自动去读取任意脚本或仓库文件的内容。

格式化后的文本证据出厂配额上限为 256 KiB，其中拟议调用的参数会完整保留。策略文件本身另有独立的 64 KiB 出厂上限。图片大小限制与提供商的总请求大小限制各自独立。默认审查超时为 120 秒，请求输出上限为 1,024 token（受所选模型实际能力约束）。

Excluded tools（排除工具）仅控制哪些适用调用跳过分类器审查，不会绕过其他权限检查。Context tools（上下文工具）则独立控制将哪些近期工具输入纳入审查上下文。显式设置为空列表代表不选择任何项，不等同于重置。

清洗器与异常处理

默认启用的清洗器（Sanitizer）会从原始用户输入中提取指令供分类器审查。它不会改写用户的聊天消息，也不会清理源代码文件。若提取功能不可用，分类器仍可使用原始限制条件进行审查。额外的模型辅助任务可能会增加延迟、产生费用，并将相关数据发送给所配置的提供商。

审查被拒绝、服务不可用与评估结果无效属于三种不同的结果，绝不会自动转化为批准放行。请仔细阅读系统报告的具体结果。修改审查模型、证据上限或排除列表可能会改变安全覆盖范围；应用这些全局更改前请先评估相应风险。
