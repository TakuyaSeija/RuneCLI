区分三种不同层面的限制

视觉折叠（display fold）仅控制你在界面上初始看到的行数；返回输出上限（returned-output cap）控制单次调用最多向 AI 发送多少字符；而捕获/扫描工作量上限（capture/work limit）则会在超限时直接停止命令或结束搜索。调大其中一项不会连带调大另外两项，且任何配额设置都不会额外授予文件或网络访问权限。

打开 Settings → Tools，选择对应的工具分组，修改数值后选择 Apply 即可保存。选择 Use default 可移除全局覆盖值。下文列出的出厂默认值对应 Rune {{.DocVersion}}，不代表你已保存的自定义选项；可使用 rune -config explain <key> 查看具体配置键。

文件与搜索工具

inspect_file
读取单个文件（对文本文件支持指定包含首尾的行范围）。出厂默认最大文件体积为 16 MiB，返回文本上限为 30,000 个字符。受支持的非文本文件可作为附件发送给具备相应能力的模型。
find_files
按通配符（glob）搜索文件路径。模式支持 *、**、?、如 [a-z] 的字符类、| 备选项，以及如 *.{ts,tsx} 的花括号分组（包括嵌套分组）。出厂默认最多返回 200 条路径、总长不超过 20,000 个字符。单次调用传入的较小限制只能缩减而不能突破该上限。
search_text
搜索文件文本内容。其 include 过滤器接受相同的路径 glob 语法。出厂默认最多返回 100 条匹配行、单行最多 2,000 个字符、总计最多 30,000 个字符。单文件大小上限与 inspect_file 共用。
create_file
创建文件（若同名文件已存在则覆盖）。执行前仍需通过权限模式检查与文件快照保护。
patch_file
替换一处精确匹配的文本片段。旧文本在目标范围内必须且只能出现一次；若匹配到多处，系统会拒绝执行，而不会盲目替换所有出现位置。

路径搜索与文本搜索会包含隐藏文件和被忽略的文件名；只有当模式指明 .git 或 .rune 内的某个文件夹时，才会搜索这两个目录。两者共用的扫描限制为：最多 200,000 个条目、目录深度 32 层，以及每行 200,000 步正则匹配预算。因触及上限而停止的搜索会明确说明，并且可能还有更多结果。搜索从模式所指明的文件夹开始，因此在调高上限之前，请先在模式中指明文件夹。

终端与进程控制工具

terminal_use 在全新的 shell 进程中运行命令。出厂默认前台等待时长为 120 秒、返回文本上限为 30,000 个字符、单个后台日志上限为 100 MiB。前台等待超时通常会将命令平滑转入后台；而一旦超出输出或日志捕获体积上限，命令会被直接停止。process_control 用于向等待输入的后台任务发送文本，或连同整个进程树一并将其停止；它不负责读取输出，也不会阻塞等待。后台任务结束或等待输入时发出的通知会自带状态、PID、运行时长、日志路径以及尚未提供过的输出（默认最多 30,000 个字符，同时到达的多条通知共用这一上限）。

关于启动方式选择、各平台输入等待检测及任务生命周期，请参阅终端与后台任务。

网页与扩展工具

web_search
根据关键词搜索网页（可在单次调用中指定更少的结果数）。出厂默认最多返回 8 条结果、60 秒请求超时及 100,000 个输出字符。
web_fetch
读取单个公开网页的文本内容。出厂默认超时为 60 秒，返回字符上限为 100,000 个字符。该工具拥有独立的服务商选择设置。
discover_capabilities
查找未直接列在初始摘要中的技能、MCP 工具与资源。出厂默认返回文本上限为 30,000 个字符。
call_mcp_tool
按照已发现外部工具声明的准确输入格式发起调用；该外部服务器的具体行为与风险由其自身决定。
read_mcp_resource
读取已发现的 MCP 资源。出厂默认返回文本上限为 50,000 个字符。

任务规划、提问与编排

track_tasks 用于全量替换任务列表，默认支持最多 20 项任务，每项任务最多 120 字符。系统还具备提醒机制，以可配置的节奏将计划作为系统通知送回：默认每调用 8 次工具（plan.reminder_tools）或每隔 15 分钟（plan.reminder_seconds）提醒一次；设为 0 可关闭对应触发条件。ask_user_questions 采用显式表单请求用户决策。提问等待时间默认无期限，权限等待则在 10 分钟后超时。无期限仅代表不会超时，不等于自动同意操作。

tools.max_actions_per_response 默认允许单次模型响应包含最多 20 个拟议工具调用。它不是整个任务的总调用预算、不是并发工作线程数，也不代表这些调用会并行执行。每一次工具调用仍需逐个通过参数校验与权限控制。

合理调整限制参数

并非每个工具的所有内部参数都设有单独的界面输入框。调高限制可能会向模型暴露更多内容，并消耗更多时间、磁盘、内存或模型上下文；调低限制则可能遗漏关键证据或导致任务提前中止。请留意结果中的截断或未完成提示，切勿把被截断的输出当成完整结果。
