本地引擎与终端前端分离

Rune 将终端界面与本地智能体引擎分离。终端前端负责发送用户命令并渲染事件；本地引擎则掌管任务执行、提供商请求、权限控制、会话状态及文件保护。这样当多个窗口同时查看同一个会话时，所有核心决策依然由单一权威源统一管理。

模型提供商仅负责提供模型推理，不会成为本地执行的最高权限方。模型输出的内容只是行动提议，必须像其他待执行工作一样通过工具参数校验与执行权限控制。

请求生命周期

  1. 你提交任务说明及任何显式添加的附件。
  2. 引擎整理相关上下文，并向所选模型账户发送请求。
  3. 模型返回文本或拟议的工具调用。
  4. Rune 校验每一次调用，并应用当前的权限模式、访问控制及适用的策略审查决定。
  5. 工具执行结果会被记录下来，并作为下一步模型推理的上下文提供给模型。
  6. 前端界面实时展示执行进度、失败信息及最终回答；由你审阅实际结果。

超时重试、输出长度限制和取消操作均由运行时统一接管。模型无法通过在文本中声称“已通过审批”来为自己授予权限。各类辅助任务则是独立的提供商请求，拥有各自的用途和限制。

会话与执行顺序

每个会话只有一条权威工作流。额外打开的窗口观察的是同一个任务、同一组提问、同一份计费统计和文件状态，而不是各自运行独立副本。新消息和中途引导指令按先后顺序依次进入队列；已经发出的提供商请求则会保持发送时的上下文不变。

对话历史作为实际发生过程的审计记录保留下来，不会为了假装某项后续设置或后续文件版本从一开始就存在而暗中改写历史。上下文压缩会生成供模型读取的摘要，而已存储的原始历史记录则与之相互独立。

工具与平台边界

内置的文件、终端和网页工具具有明确的输入参数、受限的输出大小，并通过引擎走单一执行路径。文件修改操作会在替换内容前先保护符合条件的旧内容。命令执行在支持的系统上使用操作系统级隔离机制，并如实报告统一的权限语义与平台限制，绝不隐瞒。

外部 MCP 工具通过其声明的接口进行发现和调用。技能（Skill）仅作为文本指南读取；无论是技能指南还是外部工具返回的内容，都无法取代用户的授权。网络目标地址与凭据始终同模型的文本内容严格隔离。

配置与平滑升级

全局配置文件记录你的主动选择，而出厂默认值则随应用版本演进。正在运行的进程会根据各设置项的生效时机响应配置变更。已存在的会话选项和正在进行的请求不会被新的默认值盲目覆盖。

本地存储的数据结构变更按顺序执行升级迁移。可选辅助功能异常或凭据存储不可用时，绝不会伪装成访问成功，也不会破坏无关数据。版本更新交接会等待会话进入安全空闲状态；安装新版本绝不是强行终止活动任务的理由。

架构边界不等于结果担保

系统架构可以强制规范执行决策的位置与结果报告的方式，但无法证明模型的计划一定正确、无法保证每个外部系统都可逆，也无法保证一条获批执行的命令绝对无害。人工审阅、运行测试、最小权限任务范围以及独立备份依然必不可少。
