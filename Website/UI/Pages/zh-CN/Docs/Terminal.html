前台执行与后台启动

智能体会根据任务的先后依赖关系选择启动方式。如果下一步操作依赖于某条命令的输出结果，常规的前台调用会等待命令结束并直接返回结果；如果后续还有互不依赖的工作可以并行推进，显式的后台启动则会立即返回任务 ID。单凭命令名称本身并不能决定哪种启动方式正确。

当一条前台命令运行超过配置的等待时长仍未结束时，它会作为同一个进程平滑转入后台继续运行，而不会重启进程。出厂默认的前台等待时长为 120 秒。若操作系统检测到命令正在等待键盘输入，也会提前将其移交后台处理。注意：仅仅没有输出并不证明命令一定停在输入提示符处。

Shell 与工作目录

每次调用都会启动一个全新的 shell 进程；上一次调用中的 cd 不会延续到下一次调用，因此每次调用都必须显式传入目标工作目录。自动 shell（auto）会选用当前操作系统上可用且受支持的默认 shell；也可在高级配置中指定已安装 shell 的绝对路径。

命令框会标明实际运行该命令的 shell 提示符：bash 与 zsh 为 $，PowerShell 为 PS>，命令提示符（Command Prompt）为 >。切换不同 shell 会改变命令语法。所有 shell 命令均在当前权限模式与已批准的作用域下运行；调整终端设置本身不会自动授予执行权限或开放本机服务访问权限。

准确阅读任务报告

Running（运行中）
进程仍处于活动状态，尚不代表执行成功。
Waiting for input（等待输入）
系统检测到进程正在等待键盘输入。回复前请先阅读提示内容。
Completed / Failed（已完成 / 已失败）
进程已退出。请结合退出码与实际输出判断结果；退出码为 0 仅证明该命令自身的检查通过。
Killed（已终止）
进程已被停止。请勿假设执行了一半的操作已经自动回滚。
Lost（状态丢失）
Rune 无法确认该进程的最终正常退出状态（例如跟踪的运行时意外中断）。这绝不代表执行成功。

每当后台任务结束或检测到等待输入时，Rune 都会主动向智能体发送包含完整信息的通知报告：具体任务标识、结束原因、PID、运行时长、日志文件路径，以及尚未提供给智能体的新增输出。智能体无需额外发起查询，因此绝不会为了获取输出而把同一条命令重复运行第二遍；若输出被截断或未完整捕获，报告行中会明确注明。

持久化日志文件

每条后台命令都会在你的电脑上写入一个对应的日志文件。该文件保存着已完成的输出，并在末尾附上当前终端屏幕画面——因此哪怕某条提问提示符末尾没有打印换行符，也会完整包含在日志中。日志内容是应用了终端光标移动控制后的纯文本：原地刷新的单行进度条在日志中仍保持为一行，而在提问行上输入的回答则会替换该行，不会重复堆叠。

智能体首次读取某条后台命令的报告时，会从日志文件开头读起（即使其中一部分此前已在前台展示过）；后续报告则只返回新增或发生变化的部分。仅列出进程标识和日志路径的报告代表期间没有产生新输出。在 Rune 宣布某条命令正在等待输入前，会先将日志刷入磁盘，这样即使重启 Rune 也能在不依赖旧对话内存的情况下读取日志。但这一机制无法抵御磁盘硬件故障或写入中途发生的断电崩溃。

向后台任务发送输入

process_control 工具可向已知的后台任务发送键盘输入，或连同其启动的所有子进程一并将其停止。调用该工具不会阻塞等待进程结束，也不会同步返回下一段输出。提交选项支持自动追加回车（Enter）、强制发送回车或仅输入纯文本；在文本为空时选择发送回车即代表单独按下 Enter 键。

各平台对“等待输入”状态的检测能力存在差异：Linux 可检测常规键盘输入等待；macOS 仅检测不回显输入（如密码提示）；Windows 则不检测此类等待。在后两类系统上，安静运行的后台任务同样可能正在等待输入。切勿仅仅因为进程安静无输出就盲目猜测密码或确认破坏性提示。

输出配额与生命周期

返回给模型的文本出厂默认上限为 30,000 个字符。独立的输出捕获上限分别为：前台输出 8 MiB、单个后台日志 100 MiB；一旦超出捕获或日志体积上限，命令会被自动停止。对话流中默认显示的 4 行预览则纯粹是界面视觉折叠。

关闭最后一个 Rune 窗口会立即停止正在进行的 AI 推理任务。后台任务可在分离会话保留期内（默认 60 秒）继续运行，期满后即被终止。如果你需要独立长期运行的服务，请使用操作系统正规的服务管理机制，切勿假设 Rune 后台任务会永久存活。
