新建与恢复会话

/new 会在当前工作区开启一个全新会话。/session 会打开当前工作区的会话选择器：输入关键词即可搜索，选中目标结果后按 Enter 即可恢复会话。/resume <id> 可直接按已知 ID 恢复会话。对应的命令行标志为 rune -session 和 rune -resume <id>。

新建会话不会导入其他会话的输入框历史记录。恢复会话会还原已保存的对话记录与会话选项，但这并不意味着磁盘上的每个项目文件仍与当时的状态一致。若你在外部修改了文件，请告知 Rune 并仔细审阅它的下一步操作。

中途引导与停止

在任务运行期间，你可以随时发送补充说明或纠正指令。新消息会按顺序在后续步骤中处理；它无法撤回已经发往提供商的网络请求，也无法逆转已经执行完毕的命令。发送引导时，请明确说明需要更改什么以及它替代了此前的哪条指令。

连按两次 Esc 可在不退出 Rune 的情况下停止当前 AI 任务。按一次 Ctrl+C 进入待退出确认状态，再按一次即退出程序。注意：停止 AI 推理任务并不证明所有后台终端命令都已结束，请单独查看后台任务的实际报告状态。

上下文与自动压缩

/context 用于查看当前提供给模型的上下文详情。注意上下文窗口上限不等同于单次最大回复长度；显示未知（unknown）也不代表无限容量。输入 /compact 可手动请求总结较早的历史对话，Rune 也会在需要时自动执行压缩。

Rune 会根据提供商上报的输入 token 用量，或在提供商因请求超出模型上下文容量而实际拒绝请求后，自动触发上下文压缩。它绝不会根据文本字数、思考过程、图片或文件大小去凭空估算 token 数——因此在提供商返回实际用量前，下一次请求的准确 token 大小保持未知。如果提供商拒绝了过大请求，且已没有更早的历史片段可供安全压缩，Rune 会如实报告失败，而不会死循环重发同一请求。

在压缩任务运行期间（包括两轮对话间隙），底部状态栏会显示 Compacting，新发送的消息会按顺序排队等待。若关键步骤失败，系统会询问是否重试；选择取消会终止本次尝试，且失败的摘要绝不会被标记为已完成。

在上下文空间允许的前提下，出厂默认配置会完整保留最近 5 轮对话，并为历史摘要分配最高 32,768 token 的输出配额（受模型实际上限约束）。超长历史记录会按每批最多 128 KiB 文本分段总结；注意这是字节大小上限，并不保证小容量模型一定能接受该批次。用户的原始指令与历史助手回答/工具结果分开独立处理。压缩摘要仍可能丢失部分细节；上下文压缩释放的是模型上下文窗口，而非磁盘存储空间。

用量与花费统计

花费统计（Spend）仅汇总已知单价的请求。显示未知（unknown）明确代表尚未配置单价，而非免费。当此前未计价的请求在稍后获取到模型单价时，系统会为其补算费用；已计价的请求则保留当时记录的金额。辅助模型任务、自动重试和连接测试同样可能产生费用。

本地统计仅供参考，不等同于提供商出具的正式账单。usage.warn_spend_usd 只是提醒阈值，并非强制断网硬上限。若需严格控制预算，请使用提供商账户后台的限额功能。

关闭窗口与存储维护

当最后一个终端窗口关闭时，正在运行的 AI 任务会停止。已转入后台的命令可在分离会话保留期内（默认 60 秒）继续运行；Rune 并非无限期驻留的服务进程管理器。

运行 rune -session rename <id> <title> 可修改单个会话标题；rune -session delete <id> 会永久删除指定会话。rune -storage list 可查看各项目保留的数据占用；prune 子命令则会清理已不存在的旧项目所残留的符合条件的数据。执行删除前请先核对确认。修改会话列表显示条数上限不会删除较早的会话记录。
