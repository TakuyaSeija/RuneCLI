跨平台支持概览

Rune 在所有受支持系统上都是同一个程序，拥有完全一致的权限模式、工具集、设置体系和数据格式。不同之处仅在于各操作系统对程序的底层支持：如何替换正在运行的程序文件、如何隔离受限命令，以及系统能否感知后台命令正在等待键盘输入。Linux 是主力平台；macOS 与 Windows 目前处于公测阶段（beta）：均已在真实物理机上构建并通过测试，但日常高频使用积累相对较少。

当前版本为哪些系统提供了已签名构建包，均标明在首页各安装命令下方。

Linux

在内核提供沙盒支持的系统上（绝大多数现代主流发行版内核均具备），命令会运行在内核级沙盒的严格限制下。若运行在不支持沙盒的旧内核上，Rune 会明确提示：此时在 Auto 模式下每条命令执行前都会先询问你，而在 Full 模式下则不再询问。运行 /help 可在 This machine 小节下查看当前沙盒是否已启用，以及是否存在不受沙盒限制的例外路径。

复制文本通过终端模拟器完成，这需要终端允许程序写入剪贴板。在通过 SSH 远程连接，或运行在 tmux、screen 内部时，该权限可能处于关闭状态；你可以在终端或多路复用器中开启剪贴板透传，或者按住 Shift 键拖选以使用终端自带的选择复制功能。打开网页链接依赖桌面系统提供的 xdg-open。

在将软件包存放在只读存储池中的系统（如 NixOS 或 Guix）上，沙盒内的命令可以正常读取并运行该只读存储池中的程序。

macOS

命令运行在 macOS 自带的系统沙盒中，其读写边界规则与 Linux 保持一致。复制文本时会直接写入 macOS 系统剪贴板，因此即使在忽略终端剪贴板控制序列的 macOS 原生“终端”（Terminal.app）中也能正常复制。

macOS 仅在命令等待不回显输入（例如密码输入提示）时才会通知 Rune。如果某个后台命令静默等待其他类型的普通输入，在界面上看起来会像仍在运行中；做出处理前请先查看其输出日志，切勿仅仅因为命令没有动静就盲目猜测密码或发送确认字符。

命令默认在 macOS 自带的 bash 中执行，不一定与你打开终端时使用的交互式登录 shell（macOS 默认为 zsh）相同。如需改用已安装的其他 shell，可在 terminal.shell 中填入其绝对路径。

建议使用首页提供的命令安装。通过浏览器手动下载的程序包会被标记为来自互联网，在移除隔离标记前 Gatekeeper 会拒绝启动它；移除方法详见安装与更新。

Windows

Rune 使用专门创建的独立本地 Windows 账户来隔离命令。首次打开 Rune 时，系统会请求一次管理员权限确认以配置该专用账户。如果你拒绝，它不会在每次启动时反复提示；后续可随时运行 rune -sandbox setup 完成配置，或运行 rune -sandbox reset 移除该账户并收回此前授予 Rune 命令的所有文件夹访问权限。运行 rune -sandbox 可列出当前开放的访问权限及正在使用的隔离方式。

如果未配置专用沙盒账户，Rune 会退而使用当前用户账户的受限令牌（restricted token）来隔离命令，但存在以下局限：

  • 受限命令仍可读取 Windows 默认允许所有用户读取的位置（如磁盘根目录下的文件夹、其他盘符以及 ProgramData），并可在 ProgramData 中创建文件。你的个人用户配置目录（Profile）依然被严格排除在可访问范围之外。
  • 受限命令可以只读方式打开其他程序以 Windows 默认安全属性创建的命名管道（named pipe），但写入此类管道会被拒绝。
  • Git Bash 及其他基于 MSYS2 或 Cygwin 的程序在每次执行命令前都会先请求你确认，确认后该次调用将以完全访问权限运行。此外，curl.exe 和 Invoke-WebRequest 所依赖的 Windows 原生 HTTPS 栈在此受限模式下无法建立连接，但 Git 自带的 HTTPS 仍可正常工作。

一旦配置好专用沙盒账户，Git Bash 和 Windows 原生 HTTPS 都能在受限命令内部正常工作。Rune 绝不会向沙盒开放 Windows 系统目录、磁盘根目录或存放所有用户个人目录的父文件夹权限；因此如果直接在这类顶层目录中打开项目，在 Ask 和 Auto 模式下每次执行命令前都会先向你询问。

Windows 不会在命令等待键盘输入时通知 Rune。安静运行的后台命令可能是在等待输入，也可能仍在正常处理中：回复前请先查看其输出日志。此外，Windows 不允许直接替换正在运行的可执行文件，因此更新版本后，新打开的 Rune 窗口会使用新版本，而已打开的旧窗口则保持原版本不变。

终端兼容性细节

键盘快捷键和鼠标手势只有在终端模拟器将其透传给 Rune 时才能生效。例如 Konsole 默认将 Ctrl+滚轮用于画面缩放（除非在配置方案中修改），部分终端则会将 Alt+滚轮转为横向滚动；普通滚轮和键盘按键在所有终端上均可正常工作。只有在支持整帧同步刷新且渲染性能充裕的终端里，滚轮才会呈现平滑滚动效果；在其他终端里则按格跳动。配色、透明度与字体均由终端模拟器自身管理。可运行 /help 查看当前版本实际响应的快捷键列表。
