什么是项目记忆

项目记忆（Memory）是智能体为单个项目维护的专属笔记文件夹：包含一个名为 MEMORY.md 的索引文件，以及并排存放的多篇独立笔记文件。所有内容均由模型自身使用常规文件工具以纯文本格式写入，并在创建它的会话结束后持久保留。你无需学习任何额外的专用记忆命令或独立存储系统。

不同项目之间绝不共享笔记。每个项目的记忆都保存在当前 Rune 主目录下该项目自己的专属子文件夹中，而不会写进你的代码仓库里。

哪些内容会发送给模型

在会话开启时，只有 MEMORY.md 索引文件会作为参考资料提供给模型。单篇具体笔记只有在模型判断其与当前任务相关、并通过 @memory/ 路径主动打开时，才会进入模型上下文。文件夹中的其余笔记保持未读状态，因此哪怕某篇笔记写得很长，也绝不会在该项目今后的每一次请求中白白消耗上下文配额。

索引文件仅在会话刚打开时以及历史上下文执行压缩（compaction）时读取，不会在会话运行过程中持续轮询。如果另一个并行会话在此期间保存了新笔记，当前会话会在下次打开时读到它；而当前会话自己保存的笔记，写入它的模型自然已经知晓。

读写笔记的方式

Rune 没有专门为记忆另设一套工具。模型使用 inspect_file 读取笔记，使用 find_files 或 search_text 查找笔记，使用 create_file 和 patch_file 新增或修改笔记。虚拟路径别名 @memory 由 Rune 在底层自动解析转换，因此笔记绝不会暴露与具体机器绑定的绝对路径，项目里的普通文件也不会被误当成记忆笔记。

Rune 对记忆文件的写入采用原子操作（要么完整写入，要么完全不写），并在整个读写期间对其他会话加锁保持一致。因此，当一个会话在另一个会话写入期间打开时，它读到的要么是完整的旧索引，要么是完整的新索引，绝不会读到写了一半的残缺内容。

索引配额预算

索引文件的大小受 memory.recall_size 限制（出厂默认为 20 KiB），这是唯一应用的字节配额限制。当索引超出该配额时，最早的条目会被省略并附带明确提示；此时模型应当主动精简整合索引，而不是任由其无限膨胀。调高该配额会在每次打开会话的请求中占用更多上下文空间，且不会让笔记内容本身变得更准确。

项目记忆不能做什么

Rune 强制执行的任何安全与配置规则都绝不会从记忆笔记中读取。权限模式、路径边界、配额限制或配置项的值均不可能来自笔记——因为记忆是智能体自己写下的文本，外部误导性指令也有可能潜藏其中。它纯粹是供模型参考的普通文本，且在传递给模型时采用了无法冒充 Rune 系统级指令的封装形式。

此外，项目记忆既不是文件备份，也不是命令执行日志。它只用来记录值得带入下一次会话的架构决策、经验纠正和未尽事项；API 凭据和临时的命令输出都不应存放在这里。

存放位置与隔离

项目记忆存放在 Rune 主目录下对应项目的专属文件夹中，且命令沙盒不会向子进程开放该目录的访问权限：AI 在终端里运行的 shell 命令无法看到这些笔记，唯有通过 Rune 自身的文件工具才能访问。将它置于代码仓库之外是刻意为之的设计，确保你的 Git 提交永远不会夹带仅供智能体参考的内部笔记。
