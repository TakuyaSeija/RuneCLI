审阅真实的文件改动

侧边栏显示当前会话追踪文件的实时改动差异。新增与删除行数基于实际文本内容对比计算，并非每次编辑操作标题的简单累加。多次连续修改可能会互相抵消，仅凭单次工具的行数统计无法替代完整的代码审查。被改动过的文件在任何权限模式下都会保留在列表中：若路径位于工作区外部且不可访问，列表将显示已记录的统计数值，并在差异视图中说明访问受限情况，直至该文件重新可达。

在决定保留结果前，请先审阅代码差异（diff）并重新运行相关测试检查。一条测试命令通过仅证明该命令所覆盖的检查项通过。Rune 不会自动替你提交 Git 记录，文件快照还原也无法替代版本控制系统或常规的完整备份。

还原单个文件

  1. 等待涉及该文件的当前操作执行完毕。
  2. 输入 /undo 打开还原视图并选择目标文件。使用界面提供的差异查看操作（包括在列表中按 Alt+S）预览即将发生的变化。
  3. 先核对文件当前内容，再按 Enter 进入确认状态，并在倒计时有效期内再次确认。
  4. 还原完成后，验证文件内容及依赖该文件的相关工作。

撤销（Undo）会将文件恢复到本次会话首次修改它之前的初始状态，而不仅仅是退回上一次补丁之前。如果在快照创建后你在 Rune 外部用其他编辑器修改了该文件，还原操作可能会覆盖那些外部修改。文件还原属于一次真实的文件写入修改，并会如实记录在案。

重做（Redo）的范围限制

/redo 可以将最近一次撤销（undo）所替换掉的内容恢复回来。执行前请以同样的方式预览审阅差异。注意它并非保存任意历史版本的无限时间线，不应将其作为唯一的恢复手段。

快照还原无法撤回的事项

本地文件快照无法撤回远程部署、外部服务中的数据库事务、已发出的邮件、系统软件包安装，或任意终端命令产生的所有外部副作用。超出受保护/跟踪范围的文件以及由其他外部程序修改的文件，需要依赖各自的恢复策略。请以还原列表中实际显示的文件为准，切勿假设整台机器的所有改动都受快照保护。

受保护文件的出厂默认大小上限为 64 MiB。当符合条件的文件写入超出该体积上限时，操作会在实际修改文件前直接中止报错，而不会在失去快照保护的情况下强行写入。调高该上限会占用更多本地磁盘空间；调低则可能阻止大文件写入。切勿将不受快照保护的外部副作用当成可撤销操作。

高级快照配置项

checkpoint.max_file_size
单个符合条件的文件快照体积上限（出厂默认为 64 MiB）。
checkpoint.diff.context
差异视图中默认显示的上下相邻上下文行数（出厂默认为 3 行，可在 0 至 100 之间配置）。

以上均属高级配置键，不在当前交互式 Settings 界面中单独设行。可通过 rune -config explain <key> 查看详情，或通过 rune -config reset <key> 恢复默认值。
