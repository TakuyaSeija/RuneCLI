Yang Anda perlukan

Linux
x86_64 atau arm64, selama tersedia biner bertanda tangan yang diterbitkan untuk prosesor tersebut. Setiap rilis mencantumkan paket biner yang disediakannya. Biner glibc berjalan pada distribusi dengan glibc 2.17 atau lebih baru, dan telah diuji pada CentOS 7, Debian 11 dan 12, serta Ubuntu 24.04. Biner musl statis tidak bergantung pada pustaka C dari sistem, dan telah diuji pada Alpine.
macOS
macOS 11 atau lebih baru, pada Apple silicon atau Intel. Dukungan macOS berstatus beta.
Windows
Windows 10 versi 1809 atau lebih baru, atau Windows 11, pada x64 atau ARM64. Dukungan Windows berstatus beta.
Pemasang
Di Linux dan macOS: curl, tar, gzip, dan openssl (OpenSSL atau LibreSSL bawaan macOS) untuk memeriksa tanda tangan. Di Windows: PowerShell, yang sudah tersedia di setiap versi Windows yang didukung. Di Linux dan macOS, jalankan sebagai pengguna biasa, bukan root; di Windows tidak diperlukan hak Administrator.
Akun model
Akun pada penyedia pilihan Anda, atau layanan model di komputer Anda sendiri. Lihat Penyedia model.

Sistem mana saja yang memiliki biner bertanda tangan pada rilis saat ini tercantum di bawah setiap perintah pemasangan di halaman pemasangan. Perbedaan antarsistem dijelaskan di Dukungan platform.

Pasang

Perintah pemasangan tersedia di halaman pemasangan: install.sh untuk Linux dan macOS yang dijalankan dengan sh, serta install.ps1 untuk Windows yang dijalankan di PowerShell. Baca skripnya terlebih dahulu jika Anda mau: keduanya disajikan sebagai teks polos, install.sh dan install.ps1, persis seperti yang diterima oleh perintah pemasangan. Masing-masing menjalankan langkah berikut dan langsung berhenti pada langkah pertama yang gagal tanpa mengubah apa pun:

  1. Memeriksa sistem operasi beserta versinya, memastikan skrip berjalan sebagai pengguna biasa, dan memastikan perangkat pendukungnya tersedia.
  2. Mendeteksi prosesor, serta pustaka C di Linux (glibc atau musl).
  3. Mengunduh daftar checksum rilis dan memverifikasi tanda tangannya menggunakan kunci rilis yang tertulis di dalam skrip.
  4. Mengunduh arsip untuk mesin Anda dan mencocokkannya dengan daftar bertanda tangan tersebut.
  5. Memastikan arsip hanya berisi program dan berkas lisensinya, serta memastikan program dapat dijalankan dan melaporkan versi yang sesuai.
  6. Menempatkan program ke lokasi tujuan dalam satu langkah ganti nama (rename), serta menyimpan pemberitahuan lisensi dan pihak ketiga di samping data pengguna Anda yang lain.
SistemProgramPemberitahuan lisensi
Linux, macOS~/.local/bin/rune~/.local/share/runeagent (atau $XDG_DATA_HOME/runeagent)
Windows%USERPROFILE%\.local\bin\rune.exe%LOCALAPPDATA%\RuneAgent

Pemasang tidak pernah mengedit profil shell atau PATH Anda. Jika folder tujuan belum ada di PATH Anda, ia menautkan Rune ke folder yang sudah ada di PATH dan memberitahukannya; bila tidak bisa, ia mencetak satu baris yang membuat jendela yang sedang Anda pakai bisa menjalankannya. Halaman Verifikasi rilis menjelaskan apa yang dibuktikan dan tidak dibuktikan oleh tanda tangan kriptografis, serta cara memeriksa unduhan secara manual.

Perintah pemasangan mengunduh berkas menggunakan curl dan PowerShell, yang tidak menandai program sebagai unduhan internet. Sebaliknya, arsip yang Anda unduh lewat peramban web akan diberi tanda karantina. Di macOS, Gatekeeper akan menolak menjalankan salinan rune tersebut; setelah memverifikasi arsipnya, hapus tanda karantina dengan xattr -d com.apple.quarantine rune. Di Windows, SmartScreen dapat menampilkan peringatan saat program semacam itu dibuka dari File Explorer.

Opsi pemasang

Jika tidak diatur, pemasang akan mengambil versi terbaru yang diterbitkan, folder bin pengguna Anda, dan pustaka C yang terdeteksi secara otomatis di Linux. Di Linux dan macOS, simpan skrip sebagai install.sh, baca isinya, lalu jalankan dengan variabel lingkungan di bawah ini. Di Windows, atur variabel tersebut di jendela PowerShell yang sama sebelum menjalankan perintah pemasangan.

RUNE_VERSION
Versi yang telah diterbitkan seperti {{.DocVersion}}. Versi lama dapat dipasang dengan menyebutkan nomornya.
RUNE_INSTALL_DIR
Path folder absolut untuk menempatkan program sebagai ganti lokasi bawaan.
RUNE_LIBC
Khusus Linux: gnu atau musl, untuk memilih varian biner secara langsung tanpa deteksi otomatis. Kombinasi yang tidak memiliki arsip resmi akan ditolak.
RUNE_VERSION={{.DocVersion}} sh install.sh
RUNE_INSTALL_DIR="$HOME/bin" sh install.sh
$env:RUNE_VERSION = "{{.DocVersion}}"
irm {{.Origin}}{{url "install.ps1"}} | iex

Menambahkan rune ke PATH Anda

Banyak distribusi Linux sudah menyertakan ~/.local/bin di PATH, tetapi hanya jika folder tersebut sudah ada saat Anda masuk (login); macOS tidak menyertakannya secara bawaan. Jika perintah rune tidak ditemukan, tambahkan foldernya sendiri. Untuk bash atau zsh (shell bawaan di macOS), tambahkan baris ini ke ~/.bashrc atau ~/.zshrc, lalu buka terminal baru:

export PATH="$HOME/.local/bin:$PATH"

Di fish, jalankan fish_add_path ~/.local/bin satu kali. Di Windows, baris PowerShell berikut menambahkan folder tersebut ke PATH pengguna Anda; buka terminal baru setelahnya:

[Environment]::SetEnvironmentVariable("Path", [Environment]::GetEnvironmentVariable("Path", "User") + ";$HOME\.local\bin", "User")

Gunakan path folder pilihan Anda jika sebelumnya Anda mengatur RUNE_INSTALL_DIR.

Saat pertama kali dijalankan

Buka terminal di folder proyek Anda lalu jalankan rune. Saat pertama kali dijalankan, Rune membuat folder datanya, yaitu .rune di dalam folder home Anda (%USERPROFILE%\.rune di Windows), atau folder yang ditentukan oleh RUNE_HOME. Folder ini menyimpan:

  • rune.toml, berkas pengaturan Anda. Berkas ini hanya mencatat pilihan yang Anda ubah; nilai lainnya mengikuti bawaan versi yang Anda jalankan.
  • Kunci API Anda, dalam keadaan terenkripsi.
  • Sesi, memori proyek, dan potret berkas yang dipakai oleh fitur undo, disimpan terpisah untuk setiap proyek.

Di Windows, saat pertama kali dijalankan Rune juga meminta konfirmasi Administrator satu kali untuk menyiapkan akun lokal terpisah yang dipakai Rune saat menjalankan perintah. Jika Anda menolak, Rune tidak akan menanyakannya lagi setiap kali dibuka; jalankan rune -sandbox setup kapan saja Anda ingin mengaktifkannya. Halaman Keamanan menjelaskan perbedaan perlindungannya jika tanpa akun tersebut.

Perintah rune -config mencetak lokasi folder data yang sedang dipakai pada baris pertamanya. Rune menyimpan seluruh datanya di sana, bukan di dalam folder proyek Anda: folder proyek hanya berubah melalui perangkat AI sesuai mode izin yang Anda pilih, perintah ! yang Anda jalankan sendiri, atau perubahan skill maupun MCP yang Anda simpan dengan cakupan proyek. Lanjutkan dengan menyambungkan model di halaman Pengantar.

Memperbarui

Jalankan kembali pemasang untuk versi yang Anda inginkan, dengan RUNE_INSTALL_DIR yang sama jika Anda mengaturnya. Pemasang akan memverifikasi unduhan dan menggantikan program dalam satu langkah; periksa hasilnya dengan rune -version.

Jendela Rune yang sudah terbuka tetap dapat digunakan. Di Linux dan macOS, jendela tersebut akan beralih sendiri ke versi baru begitu sedang diam (idle), dan saat versi baru pertama kali berjalan ia akan memperbarui struktur folder data Anda bila diperlukan. Di Windows, program yang sedang berjalan tidak dapat digantikan di tengah jalan: jendela yang sudah terbuka tetap memakai versi awalnya, sedangkan jendela Rune berikutnya yang Anda buka akan memakai versi baru. Jangan menutup paksa pekerjaan yang sedang aktif hanya untuk mempercepat peralihan ini.

Mencopot pemasangan

Selesaikan atau hentikan pekerjaan Anda dan tutup semua jendela Rune. Setelah itu, hapus program beserta berkas pemberitahuan lisensinya. Di Linux dan macOS:

rm ~/.local/bin/rune
rm -r ~/.local/share/runeagent

Di Windows, melalui PowerShell:

rune -sandbox reset
Remove-Item "$HOME\.local\bin\rune.exe"
Remove-Item -Recurse "$env:LOCALAPPDATA\RuneAgent"

Di Windows, perintah rune -sandbox reset terlebih dahulu mencabut hak akses yang pernah diberikan kepada sandbox perintah Rune pada folder Anda lalu menghapus akun khususnya; langkah ini mungkin meminta konfirmasi Administrator. Folder data Anda tetap tersimpan sampai Anda menghapusnya sendiri. Folder tersebut memuat riwayat, pengaturan, kunci, dan titik pemulihan Anda, serta tidak perlu dihapus hanya untuk mencopot program. Jika Anda ingin menghapusnya juga, periksa lokasinya dengan rune -config terlebih dahulu, dan jangan pernah menghapusnya saat Rune masih berjalan.

Variabel lingkungan

RUNE_HOME
Menggunakan folder data lain sebagai ganti .rune di folder home Anda, lengkap dengan pengaturan, kunci, dan sesinya sendiri.
NO_COLOR
Mencetak keluaran tanpa warna, sama seperti flag --no-color.
RUNE_THEME
Memberi tahu Rune warna latar terminal Anda saat terminal tidak melaporkannya: dark, light, atau kode warna hex. Variabel ini bukan pemilih tema antarmuka yang ada di menu Appearance.
RUNE_VERSION, RUNE_INSTALL_DIR, RUNE_LIBC
Hanya dibaca oleh skrip pemasang; lihat Opsi pemasang.
