Ringkasan dukungan platform

Rune adalah satu program dengan mode, tool, pengaturan, dan struktur data yang sama di setiap sistem operasi. Perbedaannya terletak pada apa yang diizinkan oleh masing-masing sistem operasi terhadap sebuah program: bagaimana program yang sedang berjalan digantikan saat pembaruan, bagaimana perintah shell dibatasi di dalam sandbox, dan apa yang dapat dilaporkan sistem saat sebuah perintah menunggu masukan. Linux adalah platform utama. macOS dan Windows berstatus beta: dibangun dan diuji pada mesin nyata, namun dengan jam terbang penggunaan harian yang lebih sedikit.

Sistem mana saja yang memiliki biner bertanda tangan pada rilis saat ini tercantum di bawah setiap perintah pemasangan di halaman pemasangan.

Linux

Perintah shell dibatasi oleh sandbox milik kernel Linux selama kernel menyediakannya, sebagaimana pada sebagian besar distribusi Linux modern. Bila kernel tidak menyediakannya—misalnya pada kernel versi lama—Rune akan memberi tahu Anda: dalam mode Auto setiap perintah akan meminta izin terlebih dahulu, sedangkan mode Full berjalan tanpa bertanya. Perintah /help menampilkan di bawah bagian This machine apakah sandbox sedang aktif beserta hal-hal yang dapat melewatinya.

Penyalinan teks berjalan melalui terminal Anda, sehingga terminal harus mengizinkan program mengisi papan klip (clipboard). Saat terhubung lewat SSH, atau di dalam tmux maupun screen, izin tersebut mungkin mati secara bawaan; aktifkan di pengaturan terminal atau multiplexer Anda, atau tahan tombol Shift sambil menyeret mouse untuk menggunakan blok bawaan terminal. Membuka tautan web memerlukan xdg-open, yang umumnya sudah tersedia di lingkungan desktop Linux.

Pada sistem yang menyimpan programnya di dalam penyimpanan paket baca-saja (read-only), seperti NixOS atau Guix, perintah yang dijalankan dapat membaca dan mengeksekusi program yang ada di penyimpanan tersebut.

macOS

Perintah dijalankan di dalam sandbox bawaan macOS dengan batasan lokasi yang sama seperti di Linux. Menyalin teks langsung mengisi papan klip sistem macOS, sehingga tetap berfungsi di aplikasi Terminal bawaan macOS yang mengabaikan permintaan pengisian papan klip melalui urutan escape terminal.

macOS hanya memberi tahu Rune saat sebuah perintah menunggu masukan yang disembunyikan (echo off), seperti prompt kata sandi. Perintah latar belakang yang diam-diam menunggu jawaban biasa akan tampak seperti perintah yang masih bekerja; periksa log keluarannya sebelum mengambil keputusan, dan jangan pernah menebak kata sandi atau mengirim konfirmasi hanya karena sebuah perintah tampak diam.

Perintah dijalankan menggunakan bash (yang disertakan di macOS), belum tentu sama dengan shell interaktif yang dibuka oleh terminal Anda (shell login bawaan macOS adalah zsh). Anda dapat memilih shell lain yang terpasang dengan menuliskan path absolutnya di pengaturan terminal.shell.

Pasang Rune menggunakan perintah di halaman pemasangan. Salinan arsip yang diunduh melalui peramban web akan ditandai berasal dari internet sehingga Gatekeeper menolak menjalankannya sebelum tanda karantinanya dihapus; halaman Pasang & perbarui menjelaskan caranya.

Windows

Rune membatasi perintah menggunakan akun lokal terpisah yang dibuat khusus. Saat Anda pertama kali membuka Rune, aplikasi akan meminta konfirmasi Administrator satu kali untuk menyiapkan akun tersebut. Jika Anda menolak, Rune tidak akan menanyakannya setiap kali dibuka; jalankan rune -sandbox setup kapan saja Anda ingin mengaktifkannya, dan rune -sandbox reset untuk menghapus akun tersebut beserta seluruh hak akses yang pernah diberikan pada folder Anda. Perintah rune -sandbox mencantumkan daftar akses tersebut dan menampilkan metode pembatasan mana yang sedang aktif.

Tanpa akun terpisah tersebut, Rune membatasi perintah menggunakan token terbatas dari akun Anda sendiri, dengan keterbatasan berikut:

  • Perintah masih dapat membaca lokasi yang diizinkan Windows untuk dibaca oleh setiap pengguna, seperti folder di akar drive, drive lain, dan ProgramData, serta dapat membuat berkas di dalam ProgramData. Folder profil pengguna pribadi Anda tetap berada di luar jangkauannya.
  • Perintah dapat membuka (hanya untuk membaca) named pipe yang dibuat oleh program lain dengan keamanan bawaan Windows. Penulisan ke pipe semacam itu tetap ditolak.
  • Git Bash dan program berbasis MSYS2 atau Cygwin lainnya akan meminta izin sebelum setiap perintah dijalankan, lalu menjalankan pemanggilan tersebut dengan akses penuh. Koneksi HTTPS bawaan Windows yang dipakai oleh curl.exe dan Invoke-WebRequest tidak dapat berjalan di dalam token terbatas ini; namun HTTPS milik Git tetap berfungsi.

Dengan akun sandbox terpisah yang telah disiapkan, Git Bash maupun HTTPS bawaan Windows dapat berjalan normal di dalam perintah yang dibatasi. Rune tidak menambahkan hak akses ke folder sistem Windows, ke akar drive, atau ke folder induk yang menampung seluruh profil pengguna; karena itu, proyek yang dibuka langsung di lokasi-lokasi tersebut akan meminta izin sebelum menjalankan setiap perintah dalam mode Ask maupun Auto.

Windows tidak memberi tahu Rune saat sebuah perintah sedang menunggu ketikan masukan. Perintah latar belakang yang tampak diam bisa jadi sedang menunggu jawaban atau memang masih bekerja: baca log keluarannya sebelum mengirim masukan. Além itu, berkas program yang sedang berjalan di Windows tidak dapat ditimpa langsung, sehingga pembaruan versi baru akan berlaku pada jendela Rune berikutnya yang Anda buka, bukan pada jendela yang sudah telanjur terbuka.

Terminal

Pintasan papan ketik dan gestur mouse hanya sampai ke Rune apabila terminal meneruskannya. Konsole menggunakan Ctrl+wheel untuk memperbesar tampilan kecuali profilnya diubah, dan beberapa terminal mengubah Alt+wheel menjadi guliran mendatar; roda gulir biasa dan tombol panah selalu bekerja. Guliran layar tampak mulus di terminal yang mendukung sinkronisasi gambar satu frame penuh; di terminal lain, layar bergeser per takik. Warna dasar, transparansi, dan fon sepenuhnya diatur oleh terminal Anda. Jalankan /help untuk melihat pintasan yang dikenali oleh versi yang terpasang.
