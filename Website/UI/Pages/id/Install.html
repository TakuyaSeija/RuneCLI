Satu pemasangan. Ruang kerja Anda sendiri.

Periksa skrip pemasang, pastikan kesiapan sistem Anda, lalu sambungkan akun model yang ingin Anda gunakan.

01

Periksa sistem Anda

Pemasang mendeteksi sistem operasi dan prosesor Anda, serta pustaka C di Linux (glibc atau musl). Pemasang hanya memasang biner bertanda tangan yang diterbitkan untuk kombinasi tersebut.{{with .Latest}} Baris di bawah setiap perintah pemasangan menyebutkan paket yang tersedia pada rilis {{.Version}}.{{end}}

Linux dan macOS memerlukan curl, tar, gzip, dan openssl (sudah tersedia bawaan di macOS); Windows hanya memerlukan PowerShell. macOS 11 atau lebih baru dan Windows 10 versi 1809 atau lebih baru didukung, keduanya dalam status beta. Di Linux dan macOS, jalankan pemasang sebagai pengguna biasa, bukan root; di Windows tidak diperlukan hak Administrator.

02

Verifikasi sebelum memasang

Perintah pemasangan di atas memverifikasi tanda tangan dan checksum arsip sebelum menggantikan program.

Baca kode sumber pemasang, install.sh atau install.ps1, sebelum menjalankannya. Untuk memeriksa secara luring, simpan skripnya, periksa isinya, lalu jalankan sh install.sh, atau .\install.ps1 di PowerShell.

03

Buka proyek Anda

cd path/to/your-workspace
rune

Sambungkan akun model Anda di Settings → Connections, lalu pilih model di Models. Mulailah dalam mode Ask dan tinjau setiap perintah atau perubahan berkas.

Opsi pemasang

Variabel lingkungan menentukan versi, folder tujuan absolut, atau pustaka C di Linux. Jika dibiarkan kosong, pemasang akan memakai versi terbaru yang diterbitkan, folder bin pengguna Anda, dan deteksi otomatis. Untuk skrip yang telah diperiksa dan disimpan sebagai install.sh:

RUNE_VERSION=X.Y.Z sh install.sh
RUNE_INSTALL_DIR="$HOME/bin" sh install.sh
RUNE_LIBC=musl sh install.sh

Di PowerShell, atur variabelnya terlebih dahulu, lalu jalankan perintah pemasangan:

$env:RUNE_VERSION = "X.Y.Z"
irm {{.Origin}}{{url "install.ps1"}} | iex

Ganti X.Y.Z dengan versi yang telah diterbitkan. Contoh di atas adalah pilihan alternatif, bukan langkah berurutan yang wajib dijalankan semua. Arsip untuk sistem, prosesor, atau pustaka yang tidak tersedia akan ditolak.

Memperbarui pemasangan yang ada

Jalankan kembali pemasang untuk rilis yang diinginkan, dengan RUNE_INSTALL_DIR yang sama jika sebelumnya Anda memilih folder khusus. Pemasang akan memverifikasi unduhan dan menggantikan program dalam satu langkah. Periksa rune -version setelahnya.

Di Linux dan macOS, sesi terbuka yang kompatibel akan beralih ke versi baru saat sedang diam (idle); di Windows, sesi Rune berikutnya yang Anda buka akan memakainya. Jangan menghentikan paksa pekerjaan yang sedang berjalan hanya untuk memperbarui. Simpan cadangan terpisah untuk proyek penting dan data Rune Anda.

“rune: command not found”

Pemasang menyebutkan folder yang digunakannya. Jalankan rune dari sana menggunakan path lengkapnya, atau tambahkan folder tersebut ke PATH Anda sendiri; pemasang tidak pernah mengedit profil shell atau PATH Anda. Untuk folder bawaan, tambahkan baris ini ke ~/.bashrc atau ~/.zshrc:

export PATH="$HOME/.local/bin:$PATH"

Di fish, jalankan fish_add_path ~/.local/bin satu kali. Di Windows, halaman Pasang & perbarui memuat baris perintah PowerShell-nya. Setelah itu, buka terminal baru.

Menghapus Rune

Selesaikan atau hentikan pekerjaan Anda dan tutup semua jendela Rune, lalu hapus program beserta pemberitahuan lisensinya. Gunakan folder pilihan Anda sebagai ganti ~/.local/bin jika Anda memasangnya di lokasi lain.

rm ~/.local/bin/rune
rm -r ~/.local/share/runeagent

Di Windows, halaman Pasang & perbarui menjelaskan langkah-langkah PowerShell, termasuk mencabut akses sandbox perintah Rune. Pengaturan, sesi, kunci terenkripsi, dan data pemulihan tetap berada di folder data Rune sampai Anda menghapusnya sendiri. Lokasinya tercetak pada baris pertama keluaran rune -config; catat lokasinya sebelum menghapus program. Menghapus folder tersebut akan menghilangkan riwayat dan titik pemulihan Anda, serta tidak wajib dilakukan hanya untuk mencopot program.
