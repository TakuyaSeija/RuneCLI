実際の変更内容を確認する

サイドパネルには、セッションが追跡しているファイルの現在の差分が表示されます。追加行数と削除行数はファイルの実際の内容を比較したものであり、各編集ステップの見出しの単純合計ではありません。複数回の編集が互いに打ち消し合うこともあり、ツールの行数表示だけでは十分なコードレビューにはなりません。

変更を採用する前に、差分を確認し、関連するテストやチェックを再実行してください。コマンドが成功しても、それはそのコマンドがテストした範囲だけを証明するものです。Rune が自動的に Git コミットを行うことはなく、またファイルの復元機能はバージョン管理や定期的なバックアップの代わりにはなりません。

ファイルを復元する

  1. 対象ファイルに関わる作業が落ち着くのを待ちます。
  2. /undo を開き、目的のファイルを選択します。一覧で Alt+S などの差分表示アクションを使い、何が元に戻るかを確認します。
  3. 現在のファイル内容を確認したうえで、Enter で復元確認を開始し、表示された時間内にもう一度確定します。
  4. 復元されたファイルと、それに依存する処理を確認します。

Undo はファイルを「直前の 1 パッチ前」ではなく、このセッションが最初にそのファイルを変更する前の状態に復元します。そのため、スナップショット作成後に Rune の外部で加えた編集も上書きされる場合があります。復元操作自体も実際のファイル変更として記録されます。

やり直し（Redo）の範囲

/redo は、直前の Undo が置き換えた内容を元に戻します。Undo と同様に差分を確認して実行してください。任意の過去バージョンを無制限に行き来できるタイムラインではないため、これだけを唯一の復旧手段にしないでください。

復元機能では元に戻せないもの

ファイルのスナップショットは、リモートへのデプロイ、外部サービスのデータベース更新、送信済みメール、パッケージのインストール、あるいは任意のコマンドが引き起こしたあらゆる副作用を取り消すことはできません。保護・追跡対象外のファイルや他のプログラムが行った変更には、別途の復旧手段が必要です。マシン全体が保護されていると想定せず、実際の変更ファイル一覧を確認してください。

保護対象ファイルのサイズ上限は初期設定で 64 MiB です。これを超える対象ファイルへの書き込みは、保護なしで強行されるのではなく変更前にエラーで停止します。上限を引き上げるとストレージ消費が増え、引き下げると書き込みが止まる場合があります。保護対象外の外部副作用を「元に戻せる」とみなさないでください。

詳細設定オプション

checkpoint.max_file_size
対象ファイルのスナップショットの最大サイズ（初期値 64 MiB）。
checkpoint.refresh_interval
追跡中ファイルの差分再計算間隔（初期値 1 秒、100 ms〜1 分の範囲で設定可能）。
checkpoint.diff.context
差分表示に含める前後のコンテキスト行数（初期値 3 行、0〜100 の範囲で設定可能）。
checkpoint.diff.max_cells
差分比較アルゴリズムの計算量上限（初期値 1,000,000）。比較の手法にのみ影響し、ファイルアクセス権や許可される変更回数には影響しません。

これらは詳細設定キーであり、Settings 画面の通常の行には表示されません。確認には rune -config explain <key>、リセットには rune -config reset <key> を使用してください。
