プロバイダを追加する

プロバイダとは、Rune からのモデルリクエストに応答するアカウントのことです。Rune 自体にはアカウントも API クレジットも同梱されておらず、各リクエストはあなたが接続したプロバイダに送信され、そのプロバイダから課金されます。

  1. Ctrl+G を押し、Connections を開いて Add connection を選択します。
  2. MODEL PROVIDERS の中から使用するプロバイダのプリセットを選択します（一覧にない OpenAI 互換エンドポイントの場合は compatible を選びます）。
  3. プリセットに固定のアドレスがない場合は、まずアドレスを入力します。続いてマスクされた入力欄に API キーを貼り付け、Enter を押します。
  4. Rune は接続を保存する前に、アカウントを確認するためのテストリクエストを 1 回送信します。このリクエストはプロバイダへテスト用テキストを送信し、課金対象となる場合があります。
  5. Models を開き、接続したプロバイダを選んで Enter でモデルを選択します。

接続の保存は「そのアカウントが 1 回応答したこと」を確認するものであり、プロバイダの一覧にあるすべてのモデルが利用できることを保証するものではありません。キーはお使いの PC 上に暗号化して保存されます（詳しくは認証情報の保護をご覧ください）。

プロバイダ別の補足事項

推論（Reasoning）の制御方法はプロバイダやモデルによって異なります。以下は Rune が送信する内容をまとめたものですが、プロバイダ側でモデルの実際の挙動が変更されることもあります。各モデルの推論オプションは、Models 画面で Alt+C を押して設定します（詳しくは生成と推論をご覧ください）。

alibaba
お使いの Model Studio ワークスペースおよびリージョンの互換モードアドレスと、同じリージョンのキーを使用します。思考（Thinking）は段階なしのオン／オフ切り替えです。常時思考するモデルに対して Off を設定するとリクエストが拒否されるため、Off を選択肢に入れないでください。Model Studio 上の GLM モデルは Rune が送信しない独自オプションがないとツール呼び出しを返さないため、GLM モデルは Z.ai 経由で使用してください。
cerebras
推論レベルはモデルごとに異なり、サービス側の一覧からは返されません。gpt-oss-120b と qwen-3.8-27b は Low、Medium、High に対応しているため、Alt+C で追加してください。
cloudflare
Workers AI を使用します。アドレスにはアカウント ID を含め、キーには Tunnel トークンではなく Workers AI アクセス権を持つ API トークンを指定します。モデル一覧はお使いのアカウントのモデルリストから読み取られます。
compatible
任意の OpenAI 互換エンドポイントです。モデルの仕様は自動判別されないため、エンドポイントのドキュメントに従って Alt+C でコンテキスト長、最大出力、推論設定を入力してください。
deepinfra
モデルリストから単価と推論対応の有無が取得されます。推論レベルは Low、Medium、High で、レベルを指定しない場合はモデル側の既定値が適用されます。
fireworks
推論レベルは Low〜Max です。一部のレベルにのみ対応するモデルは Alt+C で調整してください。
huggingface
Inference Providers を呼び出す権限のあるトークンを使って Inference Providers ルーターに接続します。どのプロバイダがモデルを提供し、どの機能に対応するかはその組み合わせに依存します。
inclusionai
Ant Group の Ling API 経由で InclusionAI の Ling モデルを利用します。3.0 および 3.1 モデルは段階なしのオン／オフ切り替えに対応しています。自前でホストしている Ling サーバーは compatible で追加してください。
inference
モデルリストに各モデルの推論レベルが記載されており、Rune はその選択肢をそのまま提示します。
meta
Meta AI チャットボットのログインではなく、Meta Model API を使用します。推論レベルは Minimal〜Extra high です。Muse Spark は常時推論を行い、Off および停止文字列（Stop sequences）を拒否するため、Generation 設定の Stop は空欄にしてください。
mimo
従量課金キーと Token Plan キーでは接続先アドレスが異なりますが、入力されたキーから Rune が自動的にアドレスを選択します。
minimax
Rune は回答本文とは分離された形式で思考過程を要求します。推論レベル（Low〜Max）に対応しているのは MiniMax-M3.1-Flash のみのため、Alt+C で追加してください。MiniMax のモデルには Off を設定しないでください。
moonshot
Kimi です。kimi-k3 は Low、High、Max に対応しているため Alt+C で追加してください。kimi-k2 系モデルにはレベル指定はありません。Kimi のモデルには Off を設定しないでください。
novita
オン／オフ両方に対応するモデルでは、段階なしで思考のオン／オフを切り替えられます。単価はモデルリストから取得されます。
nvidia
ホスト版の NIM API です。思考制御はモデルごとに異なりサービス側の一覧からは返されないため、各モデルのカード情報を元にモデル単位で設定してください。セルフホスト版の NIM はその独自のアドレスを使用します。
openrouter
1 つのアカウントで単価や上限の異なる多数のモデルを利用できます。正確なモデルを選択し、現在の単価を確認してください。
siliconflow
グローバル版のアドレスを使用します（.cn アカウントは独自のアドレスとキーを使用します）。SiliconFlow が対応を明記しているモデルで思考のオン／オフが切り替えられます。deepseek-ai/DeepSeek-V3.1 は思考がオフのときのみツールを呼び出せます。
stepfun
推論レベルは Low、Medium、High です。step-3.5-flash-2603 は Low と High のみを受け付けるため、Alt+C で Medium を外してください。
tencent
Hunyuan は TokenHub へ移行中です。アドレス欄の横に案内されるお使いのリージョンの TokenHub アドレスと、同じリージョンのキーを入力してください。思考はオン／オフおよび Low、Medium、High のレベルに対応しています。TokenHub が提供する他社製モデルの中には Off を拒否するものがあります。
together
モデルリストには単価が含まれますが推論レベルは含まれないため、ドキュメントに記載されたレベルを Alt+C で追加してください。
tokenrouter
tokenrouter.com の TokenRouter です。別ドメインにある類似名称のサービスは別会社であり、接続先アドレスも異なります。
zai
Z.ai 標準 API です（Coding Plan はキー、アドレス、利用可能ツールが異なります）。推論レベルは Minimal〜Max で、未選択時はサービス側の既定値（Max）が適用されます。glm-5.3 は常時思考し、Low、High、Max のみを受け付けます。停止文字列（Stop）は 1 つだけ指定可能です。

この PC 上で動作するモデル

Ollama はこの PC のポート 11434 からキーなしでローカルモデルを提供します（Ollama のクラウド Web 検索サービスとは別物です）。ローカルモデルを使えばプロンプトはマシン外に出ませんが、Web ツール、補助ジョブ、またはシェルコマンドが外部サービスと通信する可能性はあります。

9router はお使いの PC 上（デフォルトはポート 20128）で動作するルーターアプリで、9router 側に登録した上流アカウントへリクエストを転送します。1 つの接続で 9router が提供するすべてのモデルを利用できます。Claude Code のモデル（cc/…）については、Rune が自動的に 9router の Anthropic 形式エンドポイントを使用するため、特別な設定なしでキャッシュ数や思考トークン数が取得できます。なお、Off はあくまで要求であり、思考を無効化できないとルートが報告した場合は代わりに Low を要求します。

プリセットのローカルアドレスは初期値であり、サービスがすでに PC 上で起動していることを意味しません。先にサービスを起動してから接続してください（応答があったかどうかは Rune のテストリクエストでわかります）。

キーとアカウントの管理

1 つの接続に複数のキーを登録できます。rune -provider keys <name> でマスクされた一覧を確認でき、Connections 画面でもキーの値を表示せずに管理できます。いずれかのキーが残高不足を報告するか割り当てを使い切った場合、Rune はリング内の次のキーへ即座に順番を譲ります（詳しくはランタイムと再試行をご覧ください）。

接続を削除すると設定は消えますが、暗号化ストア内のキーは再利用のために残る場合があります。キー自体を消したい場合は明示的にキーを削除してください。なお、キーが平文の HTTP で別のマシンへ送信されることは一切ありません。

モデルを選択する

Settings → Models には接続済みプロバイダが返すモデル一覧が表示され、カタログの更新も行えます。Enter で選択するか、会話欄で /model provider:id と入力してください。モデル上で Alt+C を押すと、コンテキストサイズ、最大出力、推論選択肢、単価など、Rune が保持するモデル情報を編集できます。入力した単価はサイドパネルの Spend 表示に使われます（プロバイダからの実際の請求額ではありません）。

Models → New-session fallback は、新しく開始するセッションの初期プロバイダを選択します。すでに開いている会話のプロバイダは切り替わらないため、開いている会話では /provider または /model を使用してください。
