接続情報の登録とモデルの選択は別

Connections はアカウントの接続先アドレスと API キーを管理します。現在使用するモデルの選択、モデルリクエストのタイムアウト、Web 検索の経路、またはページリーダーの選択はここではなく、それぞれ Models、Runtime、Tools で設定します。

キーの登録数や Configured（設定済み）という表示は、認証情報が保存されていることを意味するだけで、リクエストが成功することやクレジット残高があることを保証するものではありません。Resting（休止中）は認証情報が一時的に使用停止中であることを示す場合があります。アカウントを何度も作り直すのではなく、実際のエラー内容を確認してください。

モデルアカウントの追加

各プロバイダプリセットのキー形式と接続先アドレスの一覧は、モデルプロバイダに記載されています。

  1. Settings → Connections → Add connection を開き、目的のモデルプロバイダを選択します。
  2. 初期状態で Not connected yet と表示されているフォームを確認します。固定アドレスを持つプリセットではキーのみを入力し、アカウント固有またはカスタムのアドレスが必要な場合はアドレスも明示的に入力します。
  3. 接続名とキー名を確認します。シークレット値は必ずマスクされた認証情報フィールドにのみ入力してください。
  4. Connect を実行します。Rune は新しいモデルアカウントを保存する前にテストリクエストを送信します（課金対象となる場合があります）。キャンセルすると追加内容は保存されません。
  5. 接続後、Models 画面で実際に使用するプロバイダとモデルを選択します。

プリセットは互換性のある初期設定値を提供するものであり、アカウント自体や API の利用権、あるいはそのプロバイダの全製品の動作を保証するものではありません。プラン固有のサブスクリプションやリージョン別アドレスは、通常の API エンドポイントと異なる場合があります。

Web サービスアカウントの追加

Search & Fetch の提供元を選択し、必要なアドレスとキーを入力してアカウントを保存します。Web アカウントを保存しただけでは、検索やページ取得のプロバイダが有効化されたり動作が証明されたりするわけではありません。続いて Tools → Web search または Web fetch → Provider を開き、使用するサービスを追加・テスト・選択してください。

検索とページ取得はそれぞれ独立してプロバイダを選択します。ローカルモデルのアカウントと同じベンダーの Web サービスでは、異なるアドレスやキーが必要になる場合があります。詳しくは Web 検索とページ取得をご覧ください。

編集と削除

既存の接続を開くと、Base URL の変更や名前付きキーの管理が行えます。モデルのエンドポイントを変更した場合は、保存前にテストが実行されます。Use default を選ぶと、アカウント名からの推測ではなく、プリセット本来のアドレスに戻ります。

キーを追加すると代替キーとして登録され、既存のすべてのキーが自動的に置き換わるわけではありません。キーを削除する際は、名前とマスクされたプレビューを確認してください。接続を削除しても、暗号化ストア内にキーが再利用可能な状態で残る場合があります（アカウント設定の削除は、認証情報の完全消去を保証するものではありません）。

送信先の確認とテスト

エンドポイントを変更すると、認証情報とプロンプトの両方が別の送信先へ送られる可能性があります。接続する前に、提供元と意図したリージョンであることを確認してください。キーを使用するリモートエンドポイントには暗号化通信（HTTPS）が必須です（同一マシン上のローカルエンドポイントは例外として扱われます）。

接続テストおよびモデルテストは実際のリクエストを送信するため、コストが発生する場合があります。アカウントテストの成功は、そのテストリクエストが通ったことを示すものであり、すべてのモデル、ツール、コンテキスト長、または利用権限を保証するものではありません。まずはログで正確なエラーを確認したうえで、最小限のテストを行ってください。
