RuneAgent の役割

RuneAgent はターミナル内で動作するコーディングエージェントです。あなたが達成したい結果を伝えると、モデルが作業手順を提案し、RuneAgent がファイルの読み取りやツールの実行を行って、その結果を同じ会話画面に表示します。Atoryn が提供するサブスクリプションやバンドルモデルではなく、あなたが接続したモデルアカウントを使って動作します。

プログラム本体とセッションデータはお使いの PC 上に保存されます。ただし、これはすべての処理がオフラインで完結することを意味しません。選択したプロバイダには、リクエストに必要なプロンプト、コンテキスト、および対応する添付ファイルが送信されます。また、実行するコマンドや接続した外部サービスがネットワークを使用する場合もあります。機密性の高いデータを扱う前に、プライバシーとデータ管理をお読みください。

プロジェクトフォルダで起動する

ホームページのコマンドで RuneAgent をインストールします（各ステップの詳細はインストールとアップデートをご覧ください）。続いて、RuneAgent に作業させたいフォルダを開きます。まずはバージョン管理された小さなプロジェクトを選び、既存の未コミット変更がないか確認してから始めることを推奨します。

cd path/to/your-workspace
rune

rune path/to/your-workspace のようにフォルダを直接指定して起動することもできます。起動時の作業フォルダが、ファイルアクセス、セッション管理、およびプロジェクト指示ファイルの基準となるワークスペースになります。ホームディレクトリ全体で起動すると、1 つのリポジトリで起動する場合に比べてはるかに広い範囲をワークスペースとして許可することになるため注意してください。

モデルの接続と選択

  1. Ctrl+G を押し、Connections → Add connection を開きます。
  2. 使用するモデルプロバイダを選択します。接続先を確認し、必要なアドレスを入力したうえで、マスク表示される API キー欄にキーを入力します（接続時には疎通確認のため実際のリクエストが送信され、課金対象となる場合があります）。
  3. Models を開き、接続したプロバイダを選んで Enter でモデルを選択します（一覧を閲覧・検索しただけではセッションのモデルは切り替わりません）。
  4. タスクを送信する前に、コンポーザーの横に表示されているモデル名と権限モードを確認します。

プロバイダのプリセットは初期設定用の情報であり、アカウントの利用権そのものではありません。利用できるモデルはアカウント、エンドポイント、カタログによって決まります。詳しくはモデルプロバイダ、接続管理、およびモデルと機能定義をご覧ください。

範囲を絞ったタスクを 1 つ依頼する

最初はデフォルトの Ask モードで始めましょう。ワークスペース内のファイル読み取りはそのまま進み、ファイル編集とコマンド実行の前には必ず承認が求められます。期待する結果、制約条件、および確認方法を具体的に伝えると効果的です：

インポーターが空の日付を受け入れてしまう原因を調べてください。原因を説明し、回帰テストを追加し、コマンドを実行する前に修正案を提示してください。

権限確認カードが表示されたら、実際に実行されるコマンド、ファイルパス、または差分を確認してください。承認はそのカードに明記された範囲にのみ適用され、作業全体の安全性を保証するものではありません。実行中の AI 作業を停止するには Esc を 2 回押します。作業中に補足説明を送ることも可能で、送信済みのリクエストを書き換えるのではなく後続のステップで順番に処理されます。

結果を確認する

最終レポートとツールの実行結果を通読し、変更されたファイルを確認し、あなた自身の手で動作を検証してください。モデルがタスクを誤解したり、テストが証明している以上の成果を主張したりすることがあります。サイドパネルには追跡されたファイルの実際の差分が表示され、/logs や /context では失敗の原因やモデルに渡されたコンテキストを確認できます。

/undo を使えば、対象ファイルをセッション開始前の状態に復元できます。ただし、外部へのデプロイ、サービスへ送信したメッセージ、その他あらゆる外部の副作用を取り消せるわけではありません。Git やバックアップの代わりではなく、ローカルファイルの復元ツールとして活用してください。
