最小限で的確な診断情報を集める

rune -version の出力、正確なエラーメッセージ、表示されているフッター、該当するコマンドまたは設定キー、および問題が特定の 1 セッションか全セッションのどちらで起きているかを記録します。該当する /logs の項目を読み、explain で設定値を 1 つずつ確認してください。外部に共有する際は非公開の作業内容を伏せ字にしてください。

rune -version
rune -config check
rune -config explain network.stream_idle_timeout

これらのコマンドはバージョンと設定ファイルを確認します。設定ファイルが正しくてもプロバイダへの接続が機能するとは限りません。なお、-doctor、プロバイダテスト、モデルテストは実際のネットワークリクエストを送信する場合があります。

インストールに関する問題

rune: command not found
インストーラが表示した配置先フォルダを確認し、フルパスで rune を実行するか、インストールとアップデートの手順に従ってそのフォルダを PATH に追加してから新しいターミナルを開いてください。
お使いのシステム向けのビルドがない
その OS、プロセッサ、または C ライブラリ向けの署名付きビルドが現在のリリースに含まれていません。ホームページのインストールコマンドの下に対応ビルドが記載されています（環境には何もインストールされていません）。
SIGNATURE CHECK FAILED または CHECKSUM MISMATCH
ダウンロードされたファイルが公式の公開リリースと一致していません。何もインストールされていないため、それらのファイルは使用しないでください。信頼できるネットワークから時間をおいて再試行し、繰り返す場合は報告してください。
一般ユーザーでの実行を求められる
プログラムはユーザー自身のホームフォルダ内に配置されるため、Linux・macOS のインストーラは root での実行を拒否します。通常のユーザーターミナルを開いて再実行してください。Windows でも管理者 PowerShell は不要です。
このシステムでプログラムが起動しない
OS のバージョンがサポート対象より古いか、プロセッサが一致していません。対応プラットフォームで対応バージョンを確認してください。

キー操作、マウス、配色、コピーの問題

ショートカットが効かない場合、多くはターミナル側がそのキー入力を保持しています。Konsole ではプロファイルを変更しない限り Ctrl+ホイールがズームになり、一部のターミナルでは Alt+ホイールが横スクロールになります。Rune が認識するキーは /help で確認できます。明るい背景や暗い背景で配色が不自然に見える場合は、ターミナルが背景色を報告していない可能性があります。環境変数 RUNE_THEME に dark、light、または 16 進カラーコードを設定してください。

Linux ではコピーはターミナル経由で行われるため、ターミナル側でクリップボード操作が許可されている必要があります（SSH 経由や tmux 内ではオフになっていることがよくあります）。tmux の場合は set -g set-clipboard on で有効にするか、Shift を押しながらドラッグしてターミナル標準の選択機能を使用してください。

Auto モードでもコマンドが毎回確認を求める

Auto モードで確認なしにコマンドを実行できるのは、コマンドをサンドボックスで隔離できる環境に限られます。古い Linux カーネルなどでサンドボックスが利用できない場合は毎回確認が表示されます（サンドボックスが有効かどうかは /help の This machine 欄で確認できます）。Windows で専用サンドボックスアカウントを設定していない場合、Git Bash などの MSYS2／Cygwin プログラムはコマンドごとに確認を求めます。rune -sandbox で状態を確認し、rune -sandbox setup で設定してください。また、コンテナエンジンやキーエージェントなど、すでに稼働しているローカルプログラムへアクセスするコマンドは、別途個別の権限確認を求めます。

バックグラウンドコマンドが止まっているように見える

停止や入力送信を行う前に、まずそのコマンドのレポートとログを確認してください。Linux ではキー入力待ちを自動検知しますが、macOS はパスワード入力などの非表示入力待ちのみを検知し、Windows は入力待ちを通知しません。そのため、出力がないコマンドは入力を待っているか処理を続けているかのどちらかです。静かだからといって当て推量でパスワードを入力したりプロンプトを確定したりしないでください。すべての Rune ウィンドウを閉じると、切り離されたセッションの保持期間（初期値 60 秒）が経過した後にバックグラウンドコマンドも終了します。

コンテキストが大きすぎると表示される

Rune はプロバイダが報告するトークン使用量、またはコンテキスト超過エラーを受けて古い履歴を自動でコンパクションします。安全に要約できる古い履歴がもう残っていない場合は、同じリクエストを再送せずプロバイダのエラーを表示します。Models → Alt+C でモデルのコンテキストウィンドウ設定を確認し、無関係な新しい作業であれば /new で別セッションを開始するか、/compact を実行してください。小規模な要約モデルがバッチを拒否する場合は compact.max_batch_size を下げてください。

API キーが利用不可（Unavailable）と表示される

Key missing はデータフォルダにそのアカウントのキーが登録されていない状態ですので、Connections で追加してください。Unavailable は暗号化ストアは存在するものの開けない状態（鍵ファイルの欠損や別バックアップとの不整合など）です。まずはバックアップから一致するペアを復元してください。新しい認証情報ストアの開始（new-store）は古いストアを退避してすべてのキーを再登録する最終手段であり、接続テストではありません。各状態の詳細は認証情報の保護をご覧ください。

メッセージが待機中のまま進まない

キューに入った入力待ち、未回答の権限確認・質問フォーム、データ未着の生成処理中、再試行の待機中、および Compacting（要約中）のいずれであるかをフッターやログで区別してください。コンポーザーが空であることだけでは状態を特定できません。診断目的で「Continue」などのメッセージを繰り返し送ると余分なタスクが積み重なるため避けてください。

少しずつデータが届いている低速なストリームと、完全に無応答のストリームは別です。タイムアウトを変更する前にまず報告されているタイムアウト値を確認してください。また、ターミナルコマンドがバックグラウンドへ移行したのは失敗や強制終了を意味するものではないため、タスクのレポートを確認してください。

アカウントまたはモデルのエラー

選んだプロバイダーとモデル、意図したエンドポイントを確認してください。Key missing と Unavailable は別の状態で、失敗した鍵は休止として扱われず、リングの順に再試行されます。カタログの項目は利用権を、モデル ID の語は推論モードの提供を証明しません。

無効な認証情報や非対応のパラメータは再試行しても解決しません。まずは正確なエラー内容を確認し、むやみに認証情報ストアを作り直したり、プロバイダを切り替えたり、課金対象となるテストを繰り返したりしないでください。

出力や検索結果が途中で切れている

画面上の 4 行折りたたみ表示、返却テキスト上限（Output cap）、スキャン上限による検索停止、およびモデルのコンテキスト上限超過を区別してください。折りたたみを展開し、保存済み出力の案内や継続通知を確認したうえで、読み取り範囲や検索パスを絞り込んでください。検索が途中で上限に達した場合、他に一致する箇所が存在しないことの証明にはなりません。

コンテキストサイズは最大回答サイズではありません。画面上の機能定義の数値だけを大きくしてもプロバイダ側の制限は広がらず、逆に出力上限を小さくしすぎると推論の後に最終回答用のトークンが残らなくなることがあります。

ポリシー審査や Web ツールの状態がおかしい

Classifier が Enabled になっていても、実際に Active とは限りません。権限モード、有効なポリシーファイルの有無、除外設定、および待機中の再読み込み（reload）が必要かどうかを確認してください。審査の失敗は承認にはなりません。また、明示的に指定した Web プロバイダが見つからない場合は利用不可となり、勝手に別のサードパーティサービスへ切り替わることはありません。

Web 検索とページ取得はそれぞれ独立した選択項目です。Connections で Web アカウントを保存しただけではツールのプロバイダは選択されないため、Tools 画面で選択してください。

再試行と 2 つの割当

Rune は 1 つの鍵を retry.attempts_per_key 回（既定は 10）試してから、そのアカウントのリングの次の鍵を使います。呼び出し全体は retry.max_attempts を使い切ると止まります。割当を使い切った鍵はすぐに交代し、曲線（3、6、9... 秒）は同じ鍵での試行間の待ち時間です。フッターは鍵と 2 つの回数を示し、鍵の切り替えは記録にも残ります。

エンジンが拒否する設定

設定は使うときではなく rune.toml の読み込み時に検査されます。未知のキー、型の違う値、範囲外の数値や時間、存在しないモデルや接続は、そのキーを名指しする文とともにエンジンを停止します。推測値で動くことはありません。ファイルを直すか rune -config reset でキーを消し、rune -config check で確認してください。すべてのキーと既定値、受け付ける値は設定リファレンスにあります。

アップグレード後の挙動

Linux・macOS のセッションは、強制的に再起動しなくても待機状態になった時点で新しいビルドへ移行します。Windows では開いているウィンドウは起動時のビルドのまま動作し、新しく開いた Rune から新ビルドが使われます。再開時に一時的なエラーが出たからといって、セッションを削除する必要はありません。

データの更新に失敗したと表示された場合は、ディスク空き容量や書き込み権限など示された原因を解消してから再試行してください。1 つの項目が未変更と報告されても、他のすべての項目が失敗したとは限りません。原因を確認しないまま実行中のランタイムファイルを削除したり、審査を無効化したり、Full モードに切り替えたり、ストレージを消去したりしないでください。
