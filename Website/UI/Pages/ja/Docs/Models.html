接続済みアカウントのモデルを探す

Models 画面には、設定済みのプロバイダとそのカタログから取得した利用可能なモデル、およびあなたが手動で追加したモデル ID が一覧表示されます。検索はこの一覧を絞り込むものであり、あらゆるベンダーの全モデルを横断検索するものではありません。実際に利用できるかどうかは、アカウント、エンドポイント、権限、およびカタログの更新状態に依存します。

左側で特定のプロバイダまたは All providers を選択します。一覧を閲覧しているだけでは現在の会話の設定は変わりません。モデルを選んで Enter を押すと、そのプロバイダ／モデルのペアが適用されます。Ctrl+F で検索欄に戻ります。現在アクティブなペアは、カーソルでハイライトされている項目とは区別して表示されます。

カタログの更新とカスタム ID

Refresh catalog を実行すると、ネットワークリクエストを送信して利用可能なモデル ID と公開情報を取得します（アクティブなモデルは切り替わりません）。Enter model ID では正確な識別子を直接追加できますが、ID を追加しただけではそのアカウントで実行できることの証明にはなりません。

不明なコンテキスト長、出力上限、および価格は不明のまま表示されます。モデル名に含まれる単語から性能を推測したり、ローカルの表示値を書き換えてプロバイダ側の上限が広がったとみなしたりしないでください。検索結果の上で T を押すと実際のモデルテストリクエストが送信され、コストが発生する場合があります。

Alt+C でモデルの機能定義を設定する

モデルを選択して Alt+C を押すと、そのモデルの永続的な設定が開きます。ここでの機能定義（Capabilities）は「モデルが何を受け入れられるか」を記述するものであり、「現在のセッションで何を要求するか」は Generation 画面で設定します。最大出力トークン数の定義は、要求する回答の長さそのものではありません。

Context / output
既知のモデル上限を記録します。ここで値を上書きしても、上流サービスの実際の制限を広げることはできません。
Reasoning
開始時の推論動作と選択可能な推論レベルを設定します。Thinking バッジはモデルが推論に対応していることを示し、現在のセッションで推論が有効であることを意味しません。
Media / controls
エンドポイントが実際にサポートしている機能を指定します。非対応の制御項目は表示されないか、推論の有効時に使用できなくなる場合があります。
Pricing
ローカルでのコスト計算用に、既知の入力・出力・キャッシュ単価を設定します。価格が不明な場合は「0」ではなく未算出として扱われ、またキャッシュ単価を設定してもエンドポイントがプロンプトキャッシュに対応している証明にはなりません。

フォールバックとモデルの削除

New-session fallback は、既存のセッションを上書きすることなく、今後新しく開始するセッションの初期プロバイダを選択します。モデル上で Delete を押すとその項目が一覧から非表示・削除され、カスタム設定も消去されます（上流のプロバイダ上のモデル自体が削除されるわけではありません）。再度追加した際は最新のカタログメタデータが使われ、削除前のカスタム設定が自動的に戻るとは限りません。

コスト集計の仕組みと注意点

Spend（消費額）は、使用量と単価の両方が判明しているリクエストを集計します。単価未設定だったリクエストに後からモデル単価が設定された場合はその時点で計算され、すでに計算済みのリクエストは記録された時点のコストを保持します。端数処理、キャッシュ、割引、またはプロバイダ側の使用量報告の不足により、実際の請求額と異なる場合があります。

利用額の警告（Spending warning）は強制的な利用停止上限ではありません。単価はプロバイダの公式情報で確認し、確実な予算上限が必要な場合はプロバイダ側のアカウント制限機能を使用してください。1 回の回答を調整したい場合は、モデルの機能定義を書き換えるのではなく、生成と推論で現在のセッション設定を調整してください。
