権限付与ではなく、ポリシー審査

分類器（Classifier）は、提案された対象アクションをあなたが記述した CLASSIFIER.md のポリシーに照らして審査します。動作には有効なポリシーファイルと対象の権限モードが必要です。Ask モードでは動作せず、Auto／Full モードでも除外設定や人間の明示的な承認によって審査の有無が変わります。「Enabled」と「Active」を同一視せず、実際の Classifier ステータス表示を確認してください。

審査モデルも誤判断をする可能性があります。ポリシー審査はアクセス制御チェック、適切なタスク境界、およびあなた自身の判断に代わるものではなく、Full モードを低リスクにするものでもありません。

ポリシーの優先順位

ポリシーは、選択中の Rune ホーム内のグローバル設定として配置するか、ワークスペースルートのプロジェクトローカル設定として配置できます。グローバルルールはプロジェクトルールより優先され、プロジェクトルールはタスクに対してユーザーが明示した制限事項より優先されます。書かれていない許可をモデルが推測することに頼るのではなく、必須条件、禁止事項、例外を明確に記述してください。

CLASSIFIER.md はプロジェクト案内用の AGENTS.md とは別物です。ポリシーファイルの管理者はあなた自身であり、その変更はプロジェクトまたはグローバルのポリシー決定そのものです。アシスタントが作成した説明文やツールの出力結果によって、あなたの承認が勝手に作られることはありません。

スナップショットと再読み込み

セッションは、最初の作業を受け付けた時点のポリシー状態（ポリシーの未設定や無効状態を含む）を固定します。途中でファイルを編集しても、進行中のセッションのポリシーが勝手に置き換わることはありません。セッションの待機中に Generation 設定内の Reload classifier policy または /classifier reload を実行してください。再読み込みに失敗した場合は前のポリシーが維持され、新しいホストやセッションではその時点で有効なポリシーが読み込まれます。

再読み込み後はステータスを確認してください。有効なポリシーがない場合、審査は行われません。評価が失敗したからといって、安易に分類器を無効化したりモードを切り替えたりしないでください。

審査材料と上限

審査には、提案された正確な引数、関連するユーザーの元の指示と補足説明、明示的なテキスト・画像添付ファイル、および選択された直近のツール入力が使用されます。コマンド内にファイル名が含まれているからといって、任意のスクリプトやリポジトリの中身を自動的に収集することはありません。

テキスト証拠の初期上限は整形後で 256 KiB であり、提案された引数は省略されず完全に渡されます。ポリシーファイル自体には 1 ファイルあたり 64 KiB の上限があります。画像やプロバイダ側のリクエスト全体サイズの上限はこれとは別に適用されます。初期設定では審査のタイムアウトは 120 秒、要求出力上限は 1,024 トークン（モデルの上限に従う）です。

Excluded tools（除外ツール）は、該当ツールの呼び出しを分類器の審査からスキップするだけのものであり、他の権限チェックをバイパスするものではありません。Context tools（コンテキスト対象ツール）は、除外設定とは独立して、どの直近ツール入力を審査の参考コンテキストに含めるかを制御します。明示的な空リスト [] は「すべて対象外」を意味し、設定のリセットではありません。

サニタイザーと失敗時の扱い

初期設定で有効になっているサニタイザーは、審査のためにユーザーの元の入力から指示内容を抽出します。ユーザーのメッセージを書き換えたりソースファイルをクリーニングしたりするものではありません。抽出が利用できない場合でも、元の制限事項が使用されます。補助モデルによる処理が増えるため、レイテンシやコストが増加したり、別のプロバイダへデータが送信されたりする場合があります。

審査での拒否、サービスの利用不可、および無効な評価結果はそれぞれ異なる結果として報告され、自動的に承認されることは決してありません。報告された結果を確認してください。審査モデル、証拠サイズ、除外ツールを変更すると保護範囲が変わるため、グローバル設定を変更する前にリスクを確認してください。
