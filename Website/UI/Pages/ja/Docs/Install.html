必要な環境

Linux
x86_64 または arm64（該当プロセッサ向けの署名付きビルドが公開されている環境）。各リリースで対応ビルドが明記されます。glibc ビルドは glibc 2.17 以降のディストリビューションで動作し、CentOS 7、Debian 11・12、Ubuntu 24.04 で動作確認されています。静的リンクされた musl ビルドはシステム側の C ライブラリを必要とせず、Alpine で動作確認されています。
macOS
Apple silicon または Intel 上の macOS 11 以降（macOS 対応はベータ版です）。
Windows
x64 または ARM64 上の Windows 10 バージョン 1809 以降、または Windows 11（Windows 対応はベータ版です）。
インストーラ
Linux・macOS では署名検証と展開のために curl、tar、gzip、openssl（OpenSSL または macOS 標準搭載の LibreSSL）が必要です。Windows では対応バージョンの Windows に標準搭載されている PowerShell のみが必要です。Linux・macOS では root ではなく一般ユーザーとして実行してください。Windows でも管理者権限は不要です。
モデルアカウント
選択したプロバイダのアカウント、またはご自身の PC 上で動作するモデルサービスが必要です。詳しくはモデルプロバイダをご覧ください。

現在のリリースでどのシステム向けの署名付きビルドが公開されているかは、ホームページの各インストールコマンドの下に記載されています。OS ごとの動作の違いについては対応プラットフォームをご覧ください。

インストール

インストールコマンドはホームページに掲載されています。Linux・macOS では sh で実行する install.sh、Windows では PowerShell で実行する install.ps1 を使用します。事前にスクリプトの内容を確認したい場合は、コマンドが受け取るものとまったく同じプレーンテキストの install.sh および install.ps1 を閲覧できます。各スクリプトは以下のステップを順番に実行し、1 つでも失敗した場合は環境を一切変更せずに停止します：

  1. OS とそのバージョン、一般ユーザーで実行されていること、および必要なツールが揃っていることを確認します。
  2. プロセッサ（Linux ではさらに C ライブラリの glibc／musl）を検出します。
  3. リリースのチェックサム一覧をダウンロードし、スクリプト内に記載されたリリース公開鍵で署名を検証します。
  4. お使いのマシン向けのアーカイブをダウンロードし、署名済みの一覧と照合します。
  5. アーカイブ内にプログラム本体とライセンスファイルのみが含まれていること、およびプログラムが起動して期待どおりのバージョンを返すことを確認します。
  6. アトミックなリネーム操作でプログラムを所定の位置に配置し、ライセンスおよびサードパーティ表記をユーザーデータ領域に保存します。
システムプログラムの配置先ライセンス表記の保存先
Linux, macOS~/.local/bin/rune~/.local/share/runeagent（または $XDG_DATA_HOME/runeagent）
Windows%USERPROFILE%\.local\bin\rune.exe%LOCALAPPDATA%\RuneAgent

インストーラがシェルの設定ファイルや PATH を勝手に書き換えることはありません。配置先フォルダが PATH に含まれていない場合は、PATH にあるフォルダへ Rune をリンクしてその旨を伝え、それができない場合は、いま開いているウィンドウで実行できる1行を表示します。署名によって何が証明され何が証明されないか、および手動でダウンロードを検証する手順については、リリースの署名検証をご覧ください。

インストールコマンドは curl や PowerShell を使用してダウンロードするため、プログラムにインターネット経由の隔離マークは付きません。一方、ブラウザでアーカイブをダウンロードした場合はマークが付きます。そのため macOS では Gatekeeper によって rune の起動がブロックされます。アーカイブを検証した後、xattr -d com.apple.quarantine rune で隔離属性を解除してください。Windows では、エクスプローラーから開いた際に SmartScreen の警告が表示されることがあります。

インストーラのオプション

環境変数を指定しない場合、インストーラは最新の公開バージョン、ユーザー用の bin フォルダ、および（Linux では）自動検出された C ライブラリを使用します。Linux・macOS ではスクリプトを install.sh として保存して内容を確認したうえで、以下の環境変数を付けて実行してください。Windows では、同じ PowerShell ウィンドウ内で先に環境変数を設定してからインストールコマンドを実行します。

RUNE_VERSION
{{.DocVersion}} などの公開済みバージョン番号を指定します。過去のバージョンも番号指定でインストールできます。
RUNE_INSTALL_DIR
デフォルトの代わりにプログラムを配置する絶対パスを指定します。
RUNE_LIBC
Linux 専用：自動検出の代わりに gnu または musl を指定します。公開されていない組み合わせは拒否されます。
RUNE_VERSION={{.DocVersion}} sh install.sh
RUNE_INSTALL_DIR="$HOME/bin" sh install.sh
$env:RUNE_VERSION = "{{.DocVersion}}"
irm {{.Origin}}{{url "install.ps1"}} | iex

PATH を通す

多くの Linux ディストリビューションでは、ログイン時に ~/.local/bin が存在していれば自動的に PATH に含まれますが、macOS では含まれません。rune が見つからない場合は、ご自身でフォルダを PATH に追加してください。bash または zsh（macOS のデフォルトシェル）の場合は、~/.bashrc または ~/.zshrc に次の行を追加し、新しいターミナルを開きます：

export PATH="$HOME/.local/bin:$PATH"

fish の場合は fish_add_path ~/.local/bin を 1 回実行します。Windows では、次の PowerShell コマンドでユーザー PATH にフォルダを追加し、その後新しいターミナルを開いてください：

[Environment]::SetEnvironmentVariable("Path", [Environment]::GetEnvironmentVariable("Path", "User") + ";$HOME\.local\bin", "User")

RUNE_INSTALL_DIR を設定した場合は、そのフォルダのパスに置き換えてください。

初回起動

プロジェクトフォルダでターミナルを開き、rune を実行します。初回起動時に、ホームフォルダ内の .rune（Windows では %USERPROFILE%\.rune）、または RUNE_HOME で指定した場所にデータフォルダが作成されます。この中には以下が保存されます：

  • 設定ファイル rune.toml。あなたが変更した項目のみが記録され、その他の値は実行中のバージョンから引き継がれます。
  • 暗号化された API キー。
  • プロジェクトごとに管理されるセッション履歴、プロジェクトメモリ、および undo が使用するスナップショット。

Windows では、初回起動時に一度だけ、Rune がコマンドを実行するための専用アカウントを作成する管理者確認が表示されます。ここで拒否しても、起動のたびに確認が出ることはありません。後から作成したい場合は rune -sandbox setup を実行してください。専用アカウントがない場合の違いについてはセキュリティで説明しています。

使用中のデータフォルダの場所は、rune -config の出力の 1 行目に表示されます。Rune は自身のデータをプロジェクト内ではなくこのデータフォルダに保存するため、プロジェクト内のファイルが変更されるのは、選択したモードの下で AI がツールを実行したとき、あなた自身が ! コマンドを実行したとき、またはプロジェクトスコープを指定してスキルや MCP 設定を保存したときだけです。続いて、「概要」のモデルの接続と選択へ進んでください。

アップデート

目的のバージョンに対してインストーラを再度実行してください（RUNE_INSTALL_DIR を設定していた場合は同じパスを指定します）。ダウンロードの検証とプログラムの置き換えが一括で行われます。完了後に rune -version で結果を確認してください。

すでに開いている Rune ウィンドウはそのまま動作を続けます。Linux・macOS では、セッションが待機状態になると自動的に新しいビルドへ切り替わり、新バージョンの初回起動時にデータフォルダも更新されます。Windows では実行中のプログラムをその場で置き換えられないため、開いているウィンドウは起動時のバージョンのまま動作し、次に新しく開いた Rune から新しいバージョンが使われます。切り替えのために実行中の作業を強制終了しないでください。

アンインストール

作業を完了または停止し、すべての Rune ウィンドウを閉じてから、プログラムとライセンス表記ファイルを削除します。Linux・macOS の場合：

rm ~/.local/bin/rune
rm -r ~/.local/share/runeagent

Windows（PowerShell）の場合：

rune -sandbox reset
Remove-Item "$HOME\.local\bin\rune.exe"
Remove-Item -Recurse "$env:LOCALAPPDATA\RuneAgent"

Windows では、まず rune -sandbox reset を実行することで、Rune のコマンドサンドボックスに付与されたフォルダへのアクセス権を解除し、専用アカウントを削除します（管理者確認が表示される場合があります）。データフォルダはご自身で削除しない限りそのまま残ります。このフォルダには履歴、設定、キー、復元ポイントが保存されており、通常のアンインストールでは削除する必要はありません。削除する場合は、先に rune -config で場所を確認し、Rune の実行中には絶対に削除しないでください。

環境変数

RUNE_HOME
ホームフォルダ内の .rune の代わりに別のデータフォルダを使用します（設定、キー、セッションが独立して管理されます）。
NO_COLOR
--no-color と同様に、色なしで出力します。
RUNE_THEME
ターミナルが背景色を報告しない場合に、ターミナルの背景（dark、light、または 16 進カラーコード）を Rune に伝えます（Appearance にあるテーマ選択とは異なります）。
RUNE_VERSION, RUNE_INSTALL_DIR, RUNE_LIBC
インストーラのみが参照する変数です。詳しくはインストーラのオプションをご覧ください。
