フォアグラウンド実行とバックグラウンド実行

エージェントはタスクの依存関係に応じてコマンドの起動方法を選択します。次のステップでコマンドの出力結果が必要な場合は、通常のフォアグラウンド実行で結果を直接受け取ります。独立して並行作業を進められる場合は、最初からバックグラウンドとして起動し、即座にタスク ID を受け取ります（コマンドの名前だけでどちらが正しいかが決まるわけではありません）。

フォアグラウンドで起動したコマンドが設定された待機時間を過ぎても実行中の場合、再起動されることなく同じプロセスのままバックグラウンドへ移行します。初期設定の待機時間は 120 秒です。OS によってキー入力待ちが検知された場合は、設定時間を待たずに早い段階で引き継がれることがあります（単に出力がないというだけでは入力待ちの証明にはなりません）。

シェルと作業ディレクトリ

コマンド呼び出しのたびに新しいシェルが起動されるため、前の呼び出しで行った cd は引き継がれません。作業ディレクトリはその呼び出しごとに指定されます。自動選択（auto）では OS に適した対応シェルが使われ、詳細設定ではインストール済みシェルの絶対パスを指定できます。

コマンドボックスには実際に実行したシェルが示されます（bash・zsh は $、PowerShell は PS>、コマンドプロンプトは >）。シェルを変更するとコマンド構文も変わります。シェルコマンドは現在の権限モードと承認されたスコープの下で実行され、ターミナル設定自体が実行権限やローカルサービスへのアクセス権を付与することはありません。

実行レポートの見方

Running
プロセスはまだ実行中であり、正常完了した状態ではありません。
Waiting for input
システムが入力待ちを検知しました。応答する前にプロンプトの内容を確認してください。
Completed / Failed
プロセスが終了しました。終了コードと出力内容を確認してください（終了コード 0 は、そのコマンド自身のチェックが通ったことのみを意味します）。
Killed
プロセスが停止されました。途中まで行われた処理が自動的にロールバックされたと想定しないでください。
Lost
追跡していたランタイムを見失うなどして、Rune が正常な最終結果を確認できなかった状態です（成功ではありません）。

タスクが終了するか入力待ちが検知されると、Rune はどのタスクがどう終了したか、PID、実行時間、ログファイルのパス、およびまだエージェントに渡していなかった出力を含むレポートを自動的にエージェントへ通知します。出力を回収するために同じコマンドを再実行する必要はなく、出力が省略または切り詰められた場合はその行に明記されます。

保存されるログファイル

各バックグラウンドコマンドは、PC 上に 1 つのログファイルを書き出します。このファイルには確定した出力と、末尾に現在の画面状態が記録されるため、末尾に改行が出力されていない質問プロンプトもそのまま含まれます。ログはターミナルのカーソル移動を反映した後のプレーンテキストとして保存されるため、1 行を上書き更新するプログレスバーは 1 行に保たれ、質問行に入力した回答も重複せずその行に反映されます。

エージェントがバックグラウンドコマンドから最初に受け取るレポートは（一部がすでに表示されていたとしても）ログの先頭から始まり、以降のレポートでは新しく追加・変更された出力のみが返されます。プロセス名とログパスのみが記載されたレポートは、新しい出力がなかったことを意味します。コマンドが入力待ちになったことを通知する前には必ずログがディスクへ書き出されるため、Rune を再起動した場合でも古い会話履歴に頼らずログを読み取れます（ただしディスク障害や書き込み中のクラッシュに対する保証ではありません）。

キー入力の送信

process_control は、既知のバックグラウンドタスクへ文字列を入力するか、起動した子プロセスごとタスクを停止します。完了を待機したり次の出力を直接返したりはしません。送信オプションでは、末尾に自動で Enter を付けるか、強制的に Enter を送るか、テキストのみを入力するかを選べます（空のテキストに Enter を指定すると Enter キーのみが押されます）。

入力待ちの検知はプラットフォームによって異なります。Linux はキー入力待ち全般を検知し、macOS はパスワード入力などの非表示入力待ちのみを検知し、Windows はこれらを検知しません。macOS や Windows で出力が止まっているタスクは、入力を待っている可能性も処理を続けている可能性もあります。プロセスが静かだからといって、パスワードを推測して送ったり破壊的な操作の確認プロンプトに同意したりしないでください。

出力上限とプロセスの生存期間

モデルへ返されるテキストの初期上限は 30,000 文字です。これとは別に、フォアグラウンド出力のキャプチャ上限は 8 MiB、バックグラウンドログは 1 タスクあたり 100 MiB に制限されており、この上限を超えたコマンドは停止されます。トランスクリプト上の 4 行プレビューは単なる画面表示の折りたたみです。

最後の Rune ウィンドウを閉じると、アクティブな AI 作業は停止します。バックグラウンドタスクは切り離されたセッションの保持期間（初期値 60 秒）の間は残りますが、経過後に終了します。独立して長時間稼働させたいサービスがある場合は OS 側のサービス管理機構を使用し、Rune のバックグラウンドタスクが永続的に動き続けると想定しないでください。
