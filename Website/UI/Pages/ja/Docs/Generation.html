現在のセッションに対する生成制御

Settings → Generation は、現在アクティブなセッションとモデルの動作を制御します。任意指定の項目は、値をクリアすることでプロバイダ側または開始時の既定値に戻せます。rune.toml 内のグローバルな初期値は、既存セッションでの選択とは別に管理されます。モデルがサポートしていない項目は画面に表示されない場合があります。

推論（Reasoning）と推論レベル

選択中のモデルが提供する推論レベルは、Generation 画面、/thinking、または Alt+T で切り替えられます。一方、Models → Alt+C では永続的な開始時の動作と選択可能なオプションを設定します。モデル一覧の Thinking バッジは「そのモデルが推論に対応していること」を示し、現在のセッションで有効になっていることを示すものではありません。

Off
推論の無効化を要求します。ただし、上流のプロバイダやルーターが思考を一切行わないことを保証するものではありません。
On / effort
対応する推論を有効にするか、提供されている推論レベルを選択します。レベルを高くするとレイテンシやトークンコストが増加する場合がありますが、必ずしもより良い回答が保証されるわけではありません。
Route default
選択肢として提供されている場合、推論の制御を経路（ルート）側の既定動作に委ねます。これは明示的な Off でも特定の推論レベルでもありません。

9router では Off でレベルを送信しないため、ルートは自身の既定値を使います。上書きされるのは思考を有効にしてレベルを選んだときだけです。

テキストとして表示される思考過程は単語数（words）でカウントされ、思考トークン数を報告するルートではその報告されたトークン数が表示されます。Rune が独自の推測でトークン数を算出することはありません。また、思考過程を返さないエンドポイントもあるため、画面に思考が表示されないことは推論が無効であることの証明にはなりません。

サンプリング

項目目的と一般的な範囲
Temperature出力のランダム性を調整します（一般的には 0〜2）。値を低くしても常に同一の回答になるわけではありません。
Top PNucleus サンプリング（一般的には 0.01〜1）。通常は Temperature とこれの両方ではなく、どちらか一方を調整します。
Frequency penalty同じトークンの繰り返しを抑えます（一般的には −2〜2。負の値は繰り返しを促します）。
Presence penalty同じ話題の繰り返しを抑えます（一般的には −2〜2）。

実際に受け付けられる値の範囲はモデルやエンドポイントに依存します。推論が有効な間は、一部のサンプリング設定が使用できなくなる場合があります。ペナルティやランダム性を極端に大きくすると、回答の質が低下することがあります。

最大出力と停止シーケンス

Max output は、モデルの既知の上限内で 1 回の回答に許可する正の整数トークン上限です。推論を行うモデルでは、最終回答の前にこの枠の一部が推論で消費されることがあります。値が小さすぎると回答が途中で切れる原因になり、逆に大きくするとコストが増える可能性があります。値を省略しても無制限の出力にはなりません。

生成を終了させる停止文字列（Stop sequences）は最大 4 つまで指定できます。セッション内のエディタではカンマ区切りで入力しますが、TOML の配列ではカンマを含む文字列も 1 つの要素としてそのまま保持されます。通常のコードに含まれる文字列を停止文字列に指定すると、意図せず回答が途中で切断されるため注意してください。

/set temperature=0.2
/set temperature=

1 行目の例はセッションの設定を変更し、2 行目はその任意設定をクリアします。Generation 画面の下部にある補助モデル（Auxiliary models）の設定はグローバル設定であり、次の記事で説明します。
