信頼境界

モデルはアクションを提案するだけであり、自ら実行権限を承認することはありません。リポジトリ内のテキスト、Web ページ、添付ファイル、外部ツールのレスポンスには、誤解を招く指示が含まれている可能性があります。Rune の実行制御とアクセスチェックは、「モデルに正しく振る舞うようお願いする」のではなく、プログラム自体によって強制されます。

いかなるツールや権限モードも、任意のコードを無条件に安全にするわけではありません。コマンド、通信先、パス、意図された副作用を必ず確認してください。コンテナエンジン、SSH キーエージェント、その他のローカルサービスは隔離されたコマンドより広い権限で動作する場合があり、承認した外部ツールにも固有のリスクが存在します。

権限モード

Ask · デフォルト
ワークスペース内の読み取りはそのまま実行できます。すべてのファイル編集、すべてのコマンド実行、およびワークスペース外へのアクセスは毎回確認を求めます。提示されたスコープに対する記憶オプション（Always）が選べる場合があります。
Auto
ワークスペース内の読み書きは確認なしで進められます。ワークスペース外へのアクセスやリスクの高いコマンドは引き続き確認を求めます。この自律性を意図する場合にのみ使用してください。
Full
権限確認や通常のコマンド隔離境界なしで、OS アカウントの権限のままワークスペース内外でアクションを実行できます。基本的な検証や該当するポリシー審査は残りますが、Full モードが無害になるわけではありません。

フォームやパレットの外で Tab を押すとモードが順番に切り替わり、/mode ask、/mode auto、/mode full で明示的に選択できます。これはセッションごとの選択であり、グローバルな permissions.mode キーではありません。トラブルシューティングの近道として安易に Full へ切り替えないでください。

設計上、これらのチェックを意図的にスキップする入力が 1 つだけあります。先頭に ! を付けてあなた自身が直接入力する手動コマンドです。Enter を押すと、権限確認やポリシー審査を行わず、あなたの OS アカウントのフルアクセス権限でそのスクリプトを 1 回実行します。AI がこの入力を生成することはできず、セッションのモードも変わりません。詳しくは手動シェルコマンドをご覧ください。

承認には適用範囲がある

Allow once（今回のみ許可）はモード自体の変更ではありません。Always（常に許可）が表示される場合も、そこに明記されたスコープにのみ適用されます。拒否、キャンセル、タイムアウトは実行されません。質問フォーム、Settings の確認、または「承認済み」と書かれた文書が実行承認の代わりになることはありません。

コマンドは自身が起動したサービスを利用できますが、すでに稼働しているローカルサービス（コンテナエンジンやキーエージェントなど）へアクセスしようとした場合は、個別の権限確認が発生することがあります。対象サービスとスコープを確認してください（許可するとファイルアクセス以上の権限を与えることになります）。

コマンド隔離とプラットフォーム上の制限

Rune はエンジン側のアクセスチェックと、OS が提供するコマンド隔離機能を組み合わせて使用します。ディストリビューション名やディレクトリ構成を決め打ちするのではなく、実行時に機能の利用可否を検出します。意図したモードの制限内にコマンドを閉じ込められない場合は、隔離されているふりをするのではなく、明示的な承認を求めます。

モードの基本ルールは Linux、macOS、Windows で共通ですが、OS 基盤の保証内容は異なります。Windows では専用のサンドボックスアカウントを使うことでより強力な隔離が行われます。専用アカウントが利用できない場合の制限付きトークンによるフォールバックには、全ユーザーが読み取れる一部の場所や特定の読み取り専用名前付きパイプへアクセスできるなどの既知の制限があります。実際の状態は rune -sandbox で確認でき、セットアップには管理者の確認が必要です。

各 OS が何を制限し、何を検知できないかの詳細は対応プラットフォームに記載されています。なお、これらの説明はアプリケーションの設計を示すものであり、すべてのプラットフォーム向けに常に署名付きビルドが公開されていることを保証するものではありません（現在公開中のビルドはホームページの各インストールコマンドの下に明記されています）。

ポリシー審査とファイルの復元

Auto／Full モードでは、任意の AI 分類器（Classifier）を使って対象アクションを CLASSIFIER.md に照らして審査できます。これは誤判定もあり得る追加のチェックであり、サンドボックス隔離、人間による確認、またはバックアップの代わりにはなりません。人間による承認を求める呼び出しでは人間の明示的な判断が使われます。表示されるステータスと分類器（Classifier）ポリシーを確認してください。

対象のファイル変更はセッションのスナップショットから復元できますが、外部への副作用がすべて元に戻せるわけではありません。それぞれの制限については、差分の確認・元に戻す・やり直す、認証情報の保護、およびプライバシーとデータ管理をご覧ください。

セキュリティ問題の報告

公開の診断情報には、有効な API キー、非公開ファイル、悪用可能な攻撃コードを掲載しないでください。該当する Rune のバージョン、期待される境界、最小限の再現手順、および実際の結果を記録し、検証済みの非公開メンテナ連絡先が案内されている場合はそちらを使用してください（このページでは未検証のセキュリティ窓口や回答期限の保証は掲げていません）。
