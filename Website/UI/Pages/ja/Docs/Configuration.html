保存場所と適用範囲

グローバル設定ファイルは、選択されている Rune データホーム（通常は ~/.rune/）内の rune.toml です。設定リファレンスに設定可能なすべてのキーが記載されています。環境変数 RUNE_HOME で別のデータホームを選択できます。プロジェクト内に rune.toml という名前のファイルを置いても自動的に設定ファイルとして読み込まれることはなく、また -project は設定ホームではなくワークスペースを選択するフラグです。

実際の設定ファイルの場所は rune -config で確認できます。このファイルにはあなたが保存した設定のみが記録され、記載のない項目は現在の既定値を引き継ぎます。ファイル先頭の version = 1 は設定ファイルのフォーマットバージョンを表すものであり、アプリケーションのバージョンではありません（アップグレード目的でこの数値を書き換えないでください）。

1 項目ずつ確認する

-config explain <key>
指定したキーの有効な値、説明、および反映タイミングを確認します。
-config defaults
保存済みの設定とは別に、初期設定値（Factory defaults）を確認します。
-config check
設定ファイルの構文と指定可能な値を検証します（API キーの有効性、クレジット残高、通信疎通はテストしません）。
-config show
現在有効な設定全体を確認します。非公開のアカウントメタデータが含まれる場合があるため、共有する前に伏せ字処理を行ってください。
-settings
選択したワークスペースのモデル制御設定を確認します。

変更とリセット

rune -config explain terminal.command_timeout
rune -config set terminal.command_timeout 2m
rune -config reset terminal.command_timeout
rune -config check

set コマンドは、グローバル設定を変更する明確な意図がある場合にのみ実行してください。reset は上書き設定を削除するものであり、既定値をファイルに書き写すものではありません。Settings 画面の Use default もグローバル値に対して同じ働きをします。存在しないキーや廃止されたキーはエラーとなり、別名として暗黙に処理されることはありません。

TOML にはネイティブの null 型がありません。任意のキーを解除する際は null と記述するのではなく、そのキー自体を削除するか、対応する reset コマンドを使用してください。空文字列、"auto"、"none"、または空リストがすべての設定項目でリセットを意味するとは限らないため注意してください。

データ型と単位

真偽値（Boolean）
TOML 内で引用符なしの true または false を指定します。
回数・トークン数（Count / tokens）
各設定の許容範囲内の整数です。トークン数、文字数、バイト数はそれぞれ異なる単位です。
時間（Duration）
"500ms"、"60s"、"2m" のように単位を明示した文字列です。"unlimited" を指定できるのは権限確認と質問フォームの待機時間のみです。
サイズ（Size）
"16MiB" のように 2 進単位を明示してください。単位なしの数値はバイトではなく KiB として解釈されます。
リスト（List）
ドキュメントに記載された正確な文字列を指定します。[] は明示的な「空の選択」であり、必ずしもリセットを意味しません。
[terminal]
command_timeout = "2m"

[generation]
temperature = 0.2
stop = ["END,EXACT", "STOP"]

上記は構文の例であり、あらゆる環境に推奨される設定というわけではありません。stop 配列ではカンマを含む文字列もそのまま厳密に保持されます（一方、セッション内の設定エディタではカンマ区切りで複数の文字列を入力します）。グローバルな生成設定の初期値を変更しても、現在開いているすべてのセッションの設定が上書きされるわけではありません。

反映タイミングと注意点

設定の変更は通常、再起動なしで反映されます。即時反映される項目と次の操作から反映される項目があるため、個別の設定については explain で確認してください。CLASSIFIER.md を編集しても、すでに固定されたセッションのポリシーは自動更新されないため、待機中に再読み込み操作を実行してください。

公開するサンプルにはアカウントのエンドポイントや認証情報を含めないでください。手動で編集した場合は、無関係な設定を書き換えていないか確認し、検証を行ってください。上限値を引き上げるとメモリ、ディスク、コンテキスト、およびコストの消費が増える場合がありますが、それによってアクセス権限が付与されたり非対応モデルが動作するようになったりすることはありません。
