Web 検索とページ取得は別々のツール

web_search はクエリから Web ページを検索し、web_fetch は公開されている 1 つの HTTP(S) ページをテキストとして読み取ります。検索クエリに URL を渡しても検索が行われるだけで、自動的にそのページが開かれるわけではありません。また、組み込みのページリーダーは対話型ブラウザではないため、ログイン認証の背後にあるコンテンツや JavaScript のみで描画されるページの取得は保証されません。

検索には設定済みの外部サービスが必要です。一方、ページ取得（Fetch）は初期設定で Rune 組み込みのページリーダーを使用します。この 2 つのツールはそれぞれ独立したプロバイダ指定（ピン留め）、タイムアウト、および出力上限を持っており、片方のサービスを有効にしてももう片方に自動適用されることはありません。

まずアカウント接続を追加する

Settings → Connections で、目的の Search & Fetch アカウントのアドレスと認証情報を追加します。接続情報を保存しただけではサービスが正常に動作する証明にはなりません。同一ベンダーであっても、モデル用エンドポイントと Web 用エンドポイントは別サービス・別契約となっている場合があります。

プロバイダを追加して選択する

  1. Settings → Tools → Web search または Web fetch → Provider を開きます。
  2. Add provider を選び、接続済みのアカウントを選択します。
  3. ゲートウェイサービスの場合は、空欄に使用する正確なルート名を入力します（サンプルやモデル名からルート名を推測しないでください）。
  4. Rune はプロバイダを登録する前に実際のリクエストを送信してテストします（クエリやページアドレスが送信され、コストが発生する場合があります）。
  5. 一覧に戻り、使用するプロバイダを選択します。選択操作によってテストと保存が行われ、明示的にピン留めされます（追加しただけでは選択状態にはなりません）。

追加や選択に失敗した場合は、前の設定がそのまま維持されます。テストの成功はそのリクエストが通ったことを示すものであり、今後あらゆるページやサービスに無制限にアクセスできることを保証するものではありません。

各サービスを利用するには、そのサービスのご自身のアカウントが必要です。Rune はここに記載された検索またはページ読み取り機能のみを使用し、各ベンダーが販売するすべての製品を使うわけではありません。特記がない限り、各サービスは固定のアドレスを持ち、API キーが必要です。

デフォルト動作と明示的なピン留め

検索のデフォルト
未指定の場合、追加順で最初に有効化された検索プロバイダを使用します。そのため、最初のプロバイダを追加するとそれがデフォルトの検索先になります。
ページ取得のデフォルト
組み込みのページリーダーを使用します。外部リーダーを追加しただけでは自動的に切り替わりません。
明示的な選択（ピン留め）
特定のアカウントまたは account:route を固定します。指定先が見つからないか利用不可の場合、勝手に別のプロバイダへリクエストを送ることはありません。

ピン留めを解除するには、Use default を選ぶか web_search.provider／web_fetch.provider をリセットします。使用中のプロバイダを削除する場合は、先に別の選択へ切り替えてください。ここでの削除はツールのプロバイダ登録を外すだけで、Connections のアカウントやキー自体は削除されません。ゲートウェイサービスには最大 32 個のルートを保存できます。

上限とプライバシー

初期設定は、検索結果が最大 8 件、各ツールリクエストのタイムアウトが 60 秒、返却文字数が各ツール 100,000 文字です。呼び出しごとの件数指定で検索結果の上限を減らすことはできます。出力文字数上限を大きくしても、アクセス制限がバイパスされることはありません。

外部の検索サービスには検索クエリが送信され、外部のページリーダーには対象ページのアドレスが送信されます（課金対象となる場合があります）。組み込みのページ取得は対象サイトへ直接アクセスし、プライベート IP や内部ネットワーク宛ての通信は拒否されます。リダイレクト時の Cookie 処理はその 1 回の読み取りに限定され、永続的なブラウザログイン状態を作ることはありません。
