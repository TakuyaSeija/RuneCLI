シークレットは専用の認証情報欄へ入力する

名前付きの API キーを追加するには、Settings → Connections → 対象アカウントを開きます。Personal や Work などの名前を付けると複数のキーを区別しやすくなります。キーの値そのものは会話欄ではなく、必ずマスク表示される認証情報フィールドに入力してください。

コマンドライン引数でキーを渡すと、シェルの履歴やプロセス情報に残る恐れがあります。また、サンプルコードや設定の出力結果を誤って公開してしまうケースにも注意が必要です。アカウント設定内に記録される認証情報の参照名は、キーの値そのものではありません。

保存と通信の保護

Rune は保存時に認証情報ストアを暗号化し、ローカルの鍵ファイルを所有ユーザーのアカウントのみがアクセスできるよう制限します。これは平文での偶発的な露出を防ぐものであり、侵害されたユーザーアカウントやあなた自身の権限で動作する無制限のプロセスから保護するものではありません。バックアップを取る際は、暗号化されたストアと対応する鍵ファイルをセットで安全に保管してください。

既知の認証情報は、リクエストやログの出力境界で伏せ字（Redact）処理されます。ただし、これによってあらゆる会話や診断出力をそのまま安全に公開できるわけではありません（チャット欄に手動で貼り付けたテキストは会話内容として扱われます）。Rune は平文の HTTP で別のマシンへ API キーを送信することを拒否します（ループバック接続のローカルサービスは別扱いとなります）。

未設定（Missing）と利用不可（Unavailable）の違い

Key missing
選択中のデータホームにそのアカウントの認証情報が存在しないか、認証情報ストア自体がまだ作成されていません。正規の手順で目的のキーを追加してください。
Unavailable
ストアは存在するものの開けない状態です。鍵ファイルの欠損・破損、バックアップ元が異なるペアの不整合、ファイルの読み取り権限不足、またはデータの破損が原因として考えられます。
キーリングのローテーション
アカウントに複数のキーがある場合、各キーは割り当てられた試行回数を使い切ると即座に次のキーへ引き継ぎます。Rename key を使えば、秘密値を再入力せずにキーの名前を直接変更できます。

認証情報が Unavailable の状態でも Rune 自体は起動でき、認証情報を必要とする処理を実行した時点でエラーが報告されます。Rune が勝手にストアを空だとみなしたり、黙って新しいストアで上書きしたりすることはありません。

慎重な復旧手順

まずは意図した Rune ホームが選択されているかを確認し、利用可能な場合は一致する認証情報バックアップのペアを復元してください。診断の近道として安易にストアを削除したり、無関係な鍵ファイルを作成したりしないでください。

復旧が不可能な場合は、Connections 内の Start a new credential store または rune -provider new-store --yes を実行すると、古いペアを退避したうえでキーが空の状態から新しく開始できます。その後、すべての認証情報を再登録する必要があります。これは明確な判断のもとで行う復旧操作であり、日常的な接続テストではありません。

キーのローテーションと削除

名前付きキーを追加すると代替キーが増えます。別のキーを削除する前には、キー名とマスクされたプレビューを必ず確認してください。接続設定を削除しても、キー自体は再利用可能な状態で残る場合があります。万一キーが漏洩した場合は、ローカルの参照を削除するだけでなく、プロバイダ側でもキーの失効・再発行を行ってください（すでに外部へコピーされたトークンをローカルの削除だけで無効化することはできません）。

Configured の表示や登録キー数は、認証の有効性やクレジット残高を証明するものではありません。テストを実行すると課金対象となり得る実際のリクエストが送信されます。エンドポイントを変更した後にテストする際は、あらかじめ送信先を確認してください。
