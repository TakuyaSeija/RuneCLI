検証によって確認されること

インストーラは、チェックサム一覧に対するリリース署名を検証したうえで、ダウンロードしたアーカイブをその署名済み一覧と照合してからインストールを行います。これらはそれぞれ役割が異なります。チェックサムだけでは配布元の真正性は証明できず、また有効な署名があってもリリースにバグや意図しない動作がないことまでは証明できません。

さらにインストーラは、選択されたプラットフォーム、期待されるアーカイブ名、およびバイナリが正常に起動するかどうかを確認し、コピー途中の実行ファイルが露出しないようアトミックなリネーム操作で配置します。正確な処理内容を確認したい場合は、実行前にインストーラのソースコード（install.sh または install.ps1）をお読みください。

ダウンロードしたファイルを手動で検証する

ダウンロード一覧から、目的のアーカイブ、SHA256SUMS、SHA256SUMS.sig、および確認済みの公開鍵を取得します。リリースは SHA-256 上の ECDSA P-256 鍵で署名されており、OpenSSL および macOS 標準の LibreSSL のどちらでも検証できます。ファイルを保存したディレクトリで、まず署名を検証し、続いてアーカイブのチェックサムを検証します。Linux の場合：

openssl dgst -sha256 -verify signing-key.pem -signature SHA256SUMS.sig SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS

macOS でも署名検証コマンドは同じです。続けてダウンロードしたアーカイブ名を明示してチェックサムを照合します：

openssl dgst -sha256 -verify signing-key.pem -signature SHA256SUMS.sig SHA256SUMS
grep ' rune-VERSION-macos-aarch64.tar.gz$' SHA256SUMS | shasum -a 256 --check

Windows ではインストーラが自動で署名を検証します。ダウンロードしたアーカイブを署名済み一覧と手動で照合する場合は、PowerShell でハッシュ値を出力し、SHA256SUMS 内の該当アーカイブの行と一致するか確認します：

(Get-FileHash .\rune-VERSION-windows-x86_64.zip -Algorithm SHA256).Hash.ToLower()

VERSION はダウンロードしたリリース番号に置き換えてください。署名チェックで Verified OK と出力され、かつチェックサム照合で実際に使用するアーカイブの名前が表示される必要があります（一覧内の別のファイルが通過したからといって、存在しないアーカイブが検証されたことにはなりません）。不一致がある場合は実行を中止してください。

検証の限界とアップデート

デジタル署名はバイト列が特定のリリース鍵によって署名されたことを証明しますが、ソースコードの第三者監査、再現可能ビルド（Reproducible builds）の証明、依存ライブラリの安全性保証、あるいは万一署名鍵自体が漏洩した場合の保護を行うものではありません。検証手順を共有する際も、この信頼範囲を明確に保ってください。

目的の署名付きリリースをインストールしたら、rune -version で確認します。Linux・macOS では、互換性のある起動中セッションは待機状態になった時点で新しいビルドへ移行できます。Windows では新しく Rune を開いたときから新ビルドが使われます。バージョン表示を変えるためだけに実行中の作業を強制終了しないでください。
