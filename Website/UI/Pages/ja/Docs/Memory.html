メモリとは

メモリは、エージェントがプロジェクトごとに保持するフォルダです。MEMORY.md というインデックスファイルと、その横に並ぶ個別のノートファイルで構成されます。モデル自身が既存のファイルツールを使ってプレーンテキストとして読み書きし、セッションが終了してもそのまま残ります。覚えるべき専用のメモリコマンドや特別なストレージ操作はありません。

異なるプロジェクト間でノートが共有されることはありません。各プロジェクトのメモリは、リポジトリの内部ではなく、選択中の Rune ホーム下にあるそのプロジェクト専用のフォルダ内に保管されます。

モデルに渡される内容

セッション開始時に参考資料としてモデルへ渡されるのは、インデックス（MEMORY.md）のみです。個別のノートは、モデルがそのノートを必要だと判断して @memory/ パス経由で開いたときに初めてモデルへ届きます。フォルダ内のその他のノートは読み込まれないため、長いノートが 1 つあるだけでプロジェクトの以降すべてのリクエストで毎回トークンを消費するといったことはありません。

インデックスはセッション開始時と履歴のコンパクション時に読み込まれ、実行中に常時監視されるわけではありません。その間に別のセッションが保存したノートは次回セッションを開いたときに反映され、現在のセッション自身が保存したノートは書き込んだモデル自身がすでに把握しています。

ノートの読み書き

メモリ専用のツールはありません。モデルは inspect_file でノートを読み取り、find_files や search_text で探し、create_file や patch_file で追加・編集します。@memory エイリアスは Rune によって解決されるため、マシン固有の絶対パスでノートを指定する必要がなく、プロジェクト内の通常ファイルとノートを取り違えることもありません。

Rune はメモリファイルを書き込む際、ファイル全体を一度に書き込むか全く書き込まないかのいずれかで処理し、読み書きの間は他のセッションからの変更をブロックします。そのため、あるセッションが書き込み中に別のセッションが開いた場合でも、古いインデックスか新しいインデックスのどちらか一方が完全に読み取られ、書きかけの状態で読まれることはありません。

インデックスのサイズ上限

インデックスには memory.recall_size（初期値 20 KiB）のバイト数上限のみが適用されます。インデックスがこのサイズを超えると、古い項目から省略されてその旨が通知され、モデルにはインデックスを肥大化させるのではなく整理・圧縮することが求められます。上限を引き上げるとセッション開始時のリクエストでより多くのコンテキストを消費しますが、ノートの内容の正確性が高まるわけではありません。

メモリにはできないこと

Rune が強制するいかなる制御も、メモリから読み取られることはありません。メモリはエージェント自身が書き込んだテキストであり、誤解を招く指示が紛れ込む可能性があるため、権限、パス、上限、設定値などがノートから決まることは一切ありません。メモリはモデル向けのメモ書きにすぎず、Rune 本体のシステム指示を模倣できない形式で渡されます。

また、メモリはバックアップでもコマンド実行ログでもありません。次のセッションに引き継ぐ価値のある決定事項、修正点、未完了の作業を記録するための場所であり、認証情報や一時的なコマンド出力を保存する場所ではありません。

保存場所

メモリは Rune ホーム下のプロジェクト専用フォルダに置かれ、コマンドサンドボックスからのアクセスは許可されません。つまり、AI が実行するシェルコマンドからはメモリを見ることはできず、Rune のファイルツールを通じてのみアクセスできます。リポジトリの外に置かれているのは意図的な設計であり、エージェント向けのメモが Git のコミットに紛れ込むことはありません。
