外部機能の接続

MCP（Model Context Protocol）は、ツール、リソース、プロンプトを提供する外部サーバーを接続します。操作には /mcp または rune -mcp を使用します（現在の Settings 画面に独立したタブがあるわけではありません）。サーバーの接続と、ツールを通じて行われる各タスクの実行承認は別々に管理されます。

リモートサーバーにはあなたが送信したデータが渡され、ローカルサーバーはこの PC 上でプログラムを起動します。サーバーから返されたテキストは、たとえ「公式の指示である」と主張していても、信頼できないタスクデータとして扱われます。

スコープと承認

User
複数のプロジェクトにわたって利用できる個人用の定義です。
Project
プロジェクトの MCP 設定に保存される共有定義です。内容を確認して明示的に承認する必要があります。共有定義が変更された場合は再承認が必要になることがあります。
Private project
特定の 1 プロジェクトでのみ使う個人用の定義で、MCP 変更時のデフォルトスコープです。同じ ID の共有プロジェクト定義を上書きでき、共有プロジェクト定義は個人用の User 定義を上書きできます。

接続する前に list／status で確認し、定義を validate で検証してください（検証は実際の接続テストではありません）。追加（add）にはサーバー ID と、接続先のリモート URL または引数付きのローカル実行ファイルの絶対パスを指定します。正確な構文についてはインストール済みコマンドのヘルプを確認してください。

アクセス権限の確認

サーバーを追加または有効化する前に、実行ファイルと引数またはリモート接続先、認証方式、環境変数、プロジェクトへの書き込み権限、追加の読み書きフォルダ、および起動中のローカルサービスへのアクセス権を確認してください。タスクに必要な最小限の権限のみを付与してください。

リモートエンドポイントには HTTPS が必須です（平文の HTTP はループバック接続に限定されます）。共有 URL や環境変数のリテラル値にシークレットを直接埋め込まず、正規の認証情報フローを使用してください。ローカルの実行ファイルや追加フォルダの指定は単なるラベルではなく、実際のアクセス権限の付与そのものです。

ワークスペース外の追加フォルダを指定した場合、Ask／Auto モードではローカルサーバーの起動前に承認が求められることがあります。ローカルサービスへの広範なアクセスを許可すると、あなたのアカウント権限で動作しているプログラムに到達できる場合があります。接続エラーを消すためだけにこれらの権限を安易に広げないでください。

接続、テスト、削除

list · status
設定済みのサーバーと現在の接続状態を確認します。
validate
定義の書式や設定値を検証します（接続の成功を保証するものではありません）。
connect <id> · test <id>
実際に接続を行い、ローカルコードの起動やリモートサービスへの通信を実行します。
approve <id>
内容を確認した共有定義を承認します。中身を確認していないファイルに対して承認を与えないでください。
disconnect <id>
その接続を閉じます（保存されている定義自体は削除されません）。
enable|disable|remove <id>
正しい設定スコープを指定して、対象定義の有効・無効の切り替えや削除を行います。
reload
設定済みの接続を再読み込みします。
login <id> · login-status <id>
該当する認証フローを開始するか、認証状態を確認します。

これらの操作は rune -mcp status のように rune -mcp に続けて指定します。変更時は必ず対象のスコープと ID を確認してください。トークンやシークレットを扱うコマンドには機密値を渡せるものがありますが、シェル履歴に残さないよう正規の認証 UI の使用を推奨します。

認証にはベアラートークンまたは OAuth フローが使われます。トークンを会話欄に貼り付けないでください。サーバーへの接続に成功しても、すべてのツールが安全で、元に戻せて、正常に動作することの証明にはなりません。モデルは宣言された正確なツール入力を確認し、通常の実行制御の下でツールを呼び出します。
