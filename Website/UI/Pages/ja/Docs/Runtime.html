適切な待機時間を設定する

Settings → Runtime は、モデルリクエストのタイミング、共通ネットワーク待機時間、および再試行（Retry）を管理します。ターミナルのフォアグラウンド待機時間、Web ツールのタイムアウト、権限確認カードの有効期限はここではなく Tools 側の個別設定です。あらゆるタイムアウトをむやみに延ばしても、原因を解決しないまま症状を長引かせるだけになることがあります。

アカウントごとの任意のリクエストタイムアウトには、5〜3,600 の整数（秒）を指定できます。空欄または default にすると上書き設定が解除されます。補助ジョブには個別のタイムアウトを設定できます。なお、「通信が継続しているストリーム」と「データが一切届いていない無応答のストリーム」は区別して扱われます。

再試行は線形の間隔で動作する

キー初期値意味
retry.max_attempts5初回リクエスト後の再試行回数（合計で最大 6 回試行）。0 にすると再試行を行いません。
retry.initial_delay3s基本ステップ時間。待機時間は 3 秒、6 秒、9 秒…と線形に増えていきます。
retry.max_delay1m最大待機時間。次の待機時間がこれを超える場合は、基本ステップ時間に戻って繰り返します（指数バックオフではありません）。
retry.credit_cooldown15m残高不足となったキーが再び使用可能になるまでの休止時間（クレジット残高自体を補充するものではありません）。

すべての失敗が再試行されるわけではありません。誤った認証情報、非対応のパラメータ、間違ったエンドポイントは再試行しても直りません。再試行回数を極端に大きくすると、失敗確定までの時間が延びたり余分な課金が発生したりするため、まずはログで分類されたエラー内容を確認してください。

ネットワーク待機時間

ストリーム無応答上限（Stall limit）
network.stream_idle_timeout：応答データが一切届かない状態の最大許容時間（初期値 5 分）。継続してデータを受信しているストリーム全体の制限時間ではありません。
接続タイムアウト（Connect timeout）
network.connect_timeout：接続確立までの制限時間（初期値 10 秒）。
プローブタイムアウト（Probe timeout）
network.probe_timeout：明示的なプロバイダテストの制限時間（初期値 45 秒）。
カタログ（Catalog）
詳細設定：リクエストタイムアウト 10 秒、キャッシュ有効期間 1 時間、1 回の更新あたり最大 100 ページ（カタログの有効期間はプロンプトキャッシュの寿命とは無関係です）。

その他の詳細設定では、ストリーミングおよび非ストリーミング応答の最大サイズを制限します（トークン数ではなくバイト単位です）。network.token_saver 互換オプションを有効にすると、対応ルーター側にツール結果の圧縮を委ねることができますが、圧縮が保証されるわけではなく、返される詳細情報が減る場合があります。

切り離されたセッションの保持期間

host.idle_lifetime はグローバルな詳細設定で、初期値は 60 秒です。最後のウィンドウを閉じると AI のアクティブな作業は停止しますが、バックグラウンドコマンドはこの保持期間中も実行を続けます。時間内に再び開けば監視を再開できます。これはアカウントのログアウトタイマーではなく、また無期限に動き続けるサーバーを保証するものでもありません。

変更とリセットの注意点

Runtime 画面の目的の行を開いて編集し、Apply を選択します。Use default で上書き設定を解除でき、rune -config explain <key> で有効な値と反映タイミングを確認できます。stream_idle_timeout の変更はすでに待機中のリクエストにも反映されますが、その他の項目は原則として次の操作から適用されます。

設定を変更する前に、処理の遅い正常なサービス、無応答で停止した接続、残高切れのキー、非対応のリクエストのいずれであるかを見極めてください。設定の保存に成功しても、ネットワーク接続が成功したことにはなりません。
