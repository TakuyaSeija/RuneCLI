対応状況の一覧

Rune はどのシステムでも同じモード、ツール、設定、データ構造で動作する単一のプログラムです。OS ごとに異なるのは、実行中のプログラムの置き換え方法、コマンドの隔離（サンドボックス）方式、およびコマンドの入力待ちを OS がどこまで検知できるかという点です。Linux がプライマリプラットフォームであり、macOS と Windows はベータ対応です（実機でビルド・テストされていますが、Linux に比べて日常的な稼働実績が少ない段階です）。

現在のリリースでどのシステム向けの署名付きビルドが公開されているかは、ホームページの各インストールコマンドの下に記載されています。

Linux

現在の一般的なディストリビューションのようにカーネルがサンドボックス機能を備えている環境では、コマンドはカーネル自身のサンドボックスによって制限されます。古いカーネルなどでサンドボックスが利用できない場合はその旨が表示され、Auto モードでもすべてのコマンドが実行前に確認を求めるようになります（Full モードでは確認を行いません）。サンドボックスが有効かどうか、およびサンドボックスの制限外となる項目は、/help の This machine 欄で確認できます。

テキストのコピーはターミナル経由で行われるため、ターミナル側でプログラムによるクリップボード操作が許可されている必要があります。SSH 経由や tmux、screen の内部ではこの許可がオフになっていることがあります。その場合はターミナルまたはマルチプレクサの設定でオンにするか、Shift キーを押しながらドラッグしてターミナル標準の選択機能を使用してください。リンクを開くにはデスクトップ環境に備わっている xdg-open が必要です。

NixOS や Guix のようにプログラムを読み取り専用のパッケージストアに保持するシステムでは、コマンドからそのストア内のプログラムの読み取りと実行が可能です。

macOS

コマンドは macOS 標準のサンドボックス内で実行され、Linux と同じ範囲に制限されます。テキストのコピーはシステムのクリップボードを直接更新するため、ターミナル経由のクリップボード操作を無視する macOS 標準の「ターミナル（Terminal.app）」でもそのままコピーが機能します。

macOS が Rune に通知するのは、パスワードプロンプトなどの非表示入力待ちのみです。通常の文字入力を静かに待っているバックグラウンドコマンドは、処理継続中のコマンドと同じように見えます。応答や停止を行う前に必ずログを確認し、出力が静かだからといって安易にパスワードを推測して入力したりプロンプトを確定したりしないでください。

コマンドは macOS に同梱されている bash で実行されます（macOS の標準ログインシェルである zsh など、ターミナルが開いているシェルと一致するとは限りません）。別のインストール済みシェルを使う場合は、terminal.shell に絶対パスを指定してください。

インストールにはホームページのコマンドを使用してください。ブラウザでダウンロードしたファイルにはインターネット経由の隔離マークが付き、解除するまで Gatekeeper が起動をブロックします（解除手順はインストールとアップデートをご覧ください）。

Windows

Windows では、Rune は専用のローカルアカウントを使ってコマンドを隔離します。Rune の初回起動時に一度だけ、そのアカウントを作成するための管理者確認が表示されます。拒否した場合でも起動のたびに確認が出ることはありません。後から設定する場合は rune -sandbox setup を実行し、アカウントとフォルダのアクセス権をすべて削除する場合は rune -sandbox reset を実行します。現在の隔離方式と付与されているアクセス権は rune -sandbox で確認できます。

専用アカウントを使用しない場合、Rune はあなた自身のアカウントの制限付きトークンを使ってコマンドを制限しますが、以下の制約があります：

  • ドライブルートのフォルダ、他のドライブ、ProgramData など、Windows がすべてのユーザーに読み取りを許可している場所を読み取れるほか、ProgramData 内にファイルを作成できます（あなた自身のユーザープロファイルフォルダは保護されます）。
  • 他のプログラムが Windows の既定のセキュリティ設定で作成した名前付きパイプを読み取り専用で開くことができます（書き込みは拒否されます）。
  • Git Bash やその他の MSYS2／Cygwin プログラムは、コマンドごとに事前の確認を求めたうえでフルアクセス権限で実行されます。また、curl.exe や Invoke-WebRequest が使用する Windows 標準の HTTPS 通信は失敗します（Git 付属の HTTPS は動作します）。

専用アカウントを設定すれば、隔離されたコマンド内でも Git Bash や Windows 標準の HTTPS が正常に動作します。Rune は Windows のシステムフォルダ、ドライブのルート、または全ユーザーのプロファイルを収める親フォルダにはアクセス権を追加しないため、それらの場所で直接開いたプロジェクトでは Ask モード・Auto モードともに毎回コマンドの確認を求めます。

Windows はコマンドのキー入力待ちを Rune に通知しません。静かなバックグラウンドコマンドは、入力を待っているか処理を続けているかのどちらかですので、応答する前に必ずログを確認してください。また、Windows では実行中のプログラムを置き換えられないため、アップデートはすでに開いているウィンドウではなく、次に新しく開いた Rune から反映されます。

ターミナルの挙動

キーボードショートカットやマウス操作は、ターミナルがそれらを Rune に転送した場合にのみ機能します。Konsole ではプロファイルを変更しない限り Ctrl+ホイールでズームが行われ、一部のターミナルでは Alt+ホイールが横スクロールになります（通常のホイール操作とキー操作はどの環境でも使えます）。なめらかなホイールスクロールは、フレーム全体を一括描画して速度を維持できるターミナルでのみ動作し、それ以外の環境ではノッチ単位で即座に移動します。配色、透過、フォントはターミナル側の設定に従います。お使いの環境で認識されるキーは /help で確認できます。
