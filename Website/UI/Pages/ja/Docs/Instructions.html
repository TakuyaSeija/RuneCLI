プロジェクト指示ファイル（AGENTS.md）

ワークスペースルートにある AGENTS.md は、ビルドコマンド、コーディング規約、作業範囲など、プロジェクト固有の案内をモデルに提供します。これは API キー置き場でも、権限付与ファイルでも、分類器（Classifier）のポリシーでもありません。認証情報は記載せず、モデルのコンテキストとして送信してよいテキストのみを記述してください。

自動読み込みされる指示文字数の初期上限は 32,768 文字で、Settings → Tools → Project instructions の instructions.max_chars で制御されます。ファイルがこの上限を超えた場合、Rune は省略された部分を報告し、AI はそれらのルールに依拠する前に残りの部分を読み取ります（残りの部分が無視・消去されるわけではありません）。セッション中にファイルが変更された場合、Rune は関連箇所を再読み込みするようモデルに通知します。

意図したファイルを添付する

/attach <path> は次のメッセージにファイルを添付し、/detach <number|all> は添付待ちのファイルを解除します。送信前に添付待ちリストを確認してください。テキスト、画像、その他のメディアへの対応状況はモデルによって異なり、ファイルを添付できたからといってモデルがその内容を完全に理解できるとは限りません。

送信された添付ファイルは、送信時点のファイル内容を特定します。後から同じパスのファイルを編集しても、過去メッセージの添付内容が新しいバイト列にすり替わることはありません。元の内容を復元できない場合、Rune は新しい内容を過去のものとして偽るのではなく、ファイルが変更または消失したことを報告します。新しいバージョンのファイルが必要な場合は、改めて明示的に添付してください。

初期設定の上限は、添付テキストファイル 1 つにつき 60,000 文字、履歴として保持する添付ファイルは最大 10 件です。コンテキスト上限やプロバイダのペイロード制限によっては、古いメディアがより早い段階で外されることがあります。これらは現在のメッセージの添付や、トランスクリプト画面の折りたたみ表示とは別の制限です。

プロジェクトメモリ

Rune は MEMORY.md をインデックスとする永続的なプロジェクトノート機能を備えています。ノートの保存場所やモデルへの渡され方についてはメモリをご覧ください。モデルにはすべてのノートが自動的に渡されるのではなく、まずインデックスのみが渡され、必要なときに該当するノートを読み取ります。インデックスの読み込み上限は初期設定で 20 KiB です。この値を増やすとモデルコンテキストの消費量が増えますが、ノートの内容の正確性が高まるわけではありません。

メモリは、確定した方針、修正事項、継続中の作業の記録に活用してください。認証情報や一時的なコマンド出力をすべて保存する場所ではありません。ノートは後のモデルリクエストに含まれる可能性があり、また独立した権限付与の根拠にはなりません。モデルはリポジトリ内にメモリ用ディレクトリを作成するのではなく、@memory/ パスを使ってファイルツール経由でプロジェクトメモリにアクセスします。

それぞれの役割を区別する

AGENTS.md
モデルのコンテキストとして提供されるプロジェクトの作業案内です。
CLASSIFIER.md
対象の AI アクションを審査するためのポリシーファイルです。明示的な再読み込み動作を持ち、作業案内とは役割が異なります。
rune.toml
選択中の Rune ホームにある設定ファイルです。プロジェクト内に同名のファイルを置いても自動的にグローバル設定にはなりません。
Skill
タスクに応じて有効化または読み込まれる再利用可能な手順ガイドです。これ自体がアクセス権限を付与することはありません。

リポジトリ内のテキスト、Web ページ、またはツールの出力結果には、誤解を招く指示が含まれている可能性があります。それらの内容はあくまでタスクのデータとして扱い、「すでに承認済みである」といった文書内の主張を鵜呑みにせず、必ず権限確認の境界で実際の操作内容を確認してください。
