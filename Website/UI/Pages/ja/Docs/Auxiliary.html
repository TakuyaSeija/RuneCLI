グローバルな補助ジョブ

Settings → Generation の下部にある補助モデルの各項目は、選択中の Rune ホームを使用するすべてのセッションに適用されます。現在アクティブなモデルをそのまま引き継ぐことも、特定のプロバイダとモデルのペアを明示的に指定することも可能です。設定を変更すると、コスト、レイテンシ、および関連データの送信先プロバイダが変わる場合があります（設定変更の確認は、無関係なアクションへの承認ではありません）。

設定した最大出力トークン数は、選択したモデル本来の性能上限およびプロバイダ側のリクエスト全体サイズ上限の範囲内に制限されます。Settings で大きな数値を指定しても、サービス側の上限を超えることはできません。仮のモデル名を適当に入力するのではなく、上書き設定をリセットしてアクティブなモデルを引き継ぐようにしてください。

推論（Reasoning）が必須のモデルを補助ジョブに使う場合、より大きな実効出力枠が必要になることがあります。詳細設定 auxiliary.mandatory_reasoning_output_tokens の初期値は 4,096 ですが、これはすべてのジョブに一律で加算される値ではありません。要求される出力結果は、選択したモデルの上限内に収まる必要があります。

Sanitizer（サニタイザー）

サニタイザーは、分類器（Classifier）がユーザーの元の指示や制限事項を正確に識別できるよう補助します。ファイルを書き換えたり、すべてのメッセージから特殊な Unicode 文字を除去したり、会話履歴を改変したりするものではありません。分類器による審査が対象となる場面でのみ動作します。抽出が利用できない場合は元のユーザー指示がそのまま参照され、制限事項が消えることはありません。

初期値
有効（Enabled）、アクティブモデルの継承、リクエストタイムアウト 120 秒、出力上限 4,096 トークン、ソーステキストの最大バッチサイズ 64 KiB。
設定キー
sanitizer.enabled、sanitizer.model、sanitizer.timeout、sanitizer.max_output_tokens、sanitizer.max_batch_size。

バッチサイズはトークン数ではなくテキストのバイト数で測られます。バッチを小さくするとリクエスト回数が増える可能性があり、逆にプロバイダの受け入れ上限を超えるバッチはそのプロバイダに拒否されます。

Classifier（分類器）

ポリシー審査モデルは、提案されたアクションを CLASSIFIER.md のルールに照らして評価します。Ask モードでは動作せず、Auto または Full モードで有効なポリシーファイルが存在する場合に機能します。人間による承認を求める呼び出しでは、AI 審査ではなくあなたの明示的な判断が使われます。設定が有効（Enabled）になっていても、特定のアクションが実際に審査されたことの証明にはなりません。

初期値は、有効（Enabled）、アクティブモデルの継承、タイムアウト 120 秒、出力上限 1,024 トークン、テキスト証拠の合計上限 256 KiB、ポリシーファイル 1 つあたりの上限 64 KiB です。除外ツールのリストと直近入力コンテキストのリストは個別に設定します。優先順位、再読み込み、失敗時の挙動については分類器（Classifier）ポリシーをご覧ください。

Compaction（コンパクション）

コンパクションは古い会話履歴を要約し、モデルのコンテキストウィンドウに空きを作ります。/compact で手動実行できるほか、プロバイダが報告する入力トークン使用量に達したとき、またはリクエストがサイズ超過でプロバイダに拒否されたときに Rune が自動で実行します。Rune がテキストや思考過程、画像のサイズからトークン数を推測することは一切ありません。要約はあらゆる詳細を完全に残すコピーではなく、またディスク上の保存済みセッションを削除するものでもありません。

キー初期値と意味
compact.modelアクティブなモデルを継承します。
compact.max_output_tokens要約に要求する最大出力トークン数（初期値 32,768、モデルの上限に従います）。
compact.max_batch_size要約リクエスト 1 回あたりに引用する履歴テキストの最大サイズ（128 KiB）。トークン数ではなくバイト単位です。小規模な要約モデルがバッチを拒否する場合は値を下げてください。
compact.keep_recent_turns要約せずそのまま残す直近のターン数（初期値 5、利用可能なコンテキスト量によっては少なくなります）。
compact.fallback_context_tokensモデルがコンテキストウィンドウ長を公開していない場合に自動コンパクションを開始する報告入力トークン数（初期値 200,000）。既知の上限を拡張したり、文字数からトークン数を推測したりするものではありません。
compact.message_chars過去の各アシスタント応答・ツール結果メッセージから考慮する最大文字数（32,000 文字）。
compact.tool_chars過去のツール呼び出し 1 回あたりから保持する引数の最大文字数（2,000 文字）。

ユーザーの元の指示は、アシスタントやツールの抜粋とは別に扱われ、必要に応じてバッチに分割されます（勝手に切り詰められることはありません）。要約モデルがコンテキスト長超過でリクエストを拒否した場合は、より大きなアクティブモデルが代わりに使われることがあります。必須のコンパクションが失敗した場合は再試行するかどうかの確認が表示され、キャンセルまたは拒否すると試行を中止します（失敗した要約が完了として扱われることはありません）。

タイトル生成とリセット

タイトル生成ジョブは、会話の序盤の内容からセッションに名前を付けます。初期設定ではアクティブなモデルを継承し、最大 256 出力トークンを要求して 60 文字以内のタイトルを生成します。これらの設定を変更すると以降のタイトル生成に適用されますが、既存のタイトルが一括で書き換わることはありません。個別のタイトルを変更するにはセッションの名前変更機能を使用してください。

各キーの詳細は rune -config explain <key> で確認できます。Settings の Use default または rune -config reset <key> を実行するとグローバルな上書き設定が解除されます。審査用の予算を減らすとカバー範囲が狭まり、補助ジョブの処理量を増やすとコストが増加する可能性があります。グローバル設定を変更する前に、具体的な影響を確認してください。
