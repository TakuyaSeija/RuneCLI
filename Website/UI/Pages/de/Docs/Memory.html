Was das Projektgedächtnis ist

Das Projektgedächtnis (Memory) ist ein Ordner, den der Agent für ein einzelnes Projekt führt: eine Indexdatei namens MEMORY.md und daneben jeweils eine eigene Datei für jede Notiz. Geschrieben wird es als normaler Klartext vom Modell selbst – mit genau denselben Dateiwerkzeugen, die es ohnehin nutzt –, und es bleibt über das Ende der Sitzung hinaus erhalten. Es gibt keinen separaten Memory-Befehl und kein eigenes Speichersystem, das du erst erlernen müsstest.

Zwei Projekte teilen sich niemals Notizen. Jedes Projekt bewahrt sein Gedächtnis in einem eigenen projektspezifischen Ordner innerhalb des gewählten Rune-Home-Verzeichnisses auf, niemals innerhalb deines Repositorys.

Was beim Modell ankommt

Beim Öffnen einer Sitzung wird dem Modell lediglich der Index als Nachschlagewerk übergeben. Eine einzelne Notiz erreicht das Modell erst dann, wenn es diese Notiz gezielt über ihren Pfad @memory/ öffnet – also genau in dem Moment, in dem das Modell entscheidet, dass die Notiz für die aktuelle Aufgabe relevant ist. Der Rest des Ordners bleibt ungelesen, sodass eine lange Notiz nicht bei jeder künftigen Anfrage des Projekts das Kontextbudget belastet.

Der Index wird beim Öffnen einer Sitzung sowie nach einer Komprimierung des Verlaufs eingelesen, nicht fortlaufend während des Betriebs. Speichert eine andere Sitzung in der Zwischenzeit eine Notiz, steht diese beim nächsten Öffnen der Sitzung bereit; speichert die aktuelle Sitzung selbst eine Notiz, kennt das schreibende Modell deren Inhalt ohnehin bereits.

Notizen lesen und schreiben

Es gibt keine speziellen Memory-Werkzeuge. Das Modell liest Notizen mit inspect_file, sucht in ihnen mit find_files oder search_text und erstellt oder ändert sie mit create_file und patch_file. Den Alias @memory löst Rune intern auf, sodass eine Notiz niemals über einen rechnerspezifischen absoluten Pfad angesprochen wird und keine Projektdatei mit einer Notiz verwechselt werden kann.

Rune schreibt eine Memory-Datei entweder vollständig oder gar nicht und sperrt parallele Zugriffe anderer Sitzungen während des gesamten Lese- bzw. Schreibvorgangs. Öffnet sich eine Sitzung, während eine andere gerade schreibt, liest sie daher entweder den alten oder den neuen Index – niemals einen halb geschriebenen Stand.

Das Budget

Der Index wird durch memory.recall_size begrenzt (standardmäßig 20 KiB); dieses Byte-Budget ist die einzige geltende Obergrenze. Wächst der Index darüber hinaus, werden die ältesten Einträge beim Laden ausgelassen und ein entsprechender Hinweis eingefügt; vom Modell wird erwartet, den Index selbst kompakt zu halten, statt ihn endlos anwachsen zu lassen. Eine Erhöhung des Budgets verbraucht beim Start jeder Sitzung mehr Kontext, macht den Inhalt der Notizen aber nicht zutreffender.

Was das Projektgedächtnis nicht kann

Keine einzige Regel, die Rune durchsetzt, stammt jemals aus dem Projektgedächtnis. Weder Berechtigungen noch Pfade, Limits oder Konfigurationswerte werden aus einer Notiz gelesen – denn Memory besteht aus vom Agenten verfasstem Text, in dem sich auch irreführende Anweisungen verbergen könnten. Es handelt sich ausschließlich um Arbeitsnotizen für das Modell, die so übergeben werden, dass sie niemals die Systemanweisungen von Rune nachahmen können.

Das Projektgedächtnis ist außerdem weder ein Backup noch ein Befehlsprotokoll. Es bewahrt Entscheidungen, Korrekturen und offene Punkte auf, die in die nächste Sitzung übernommen werden sollen; Zugangsdaten und flüchtige Befehlsausgaben haben dort nichts zu suchen.

Wo es gespeichert wird

Das Projektgedächtnis liegt im Rune-Home-Verzeichnis im jeweiligen Projektordner, und die Befehls-Sandbox gewährt keinen Zugriff darauf: Ein von der KI ausgeführter Shell-Befehl kann diese Dateien nicht sehen. Erreichbar sind sie ausschließlich über die integrierten Dateiwerkzeuge von Rune. Dass sie außerhalb des Repositorys liegen, ist volle Absicht – so landet niemals versehentlich eine interne Arbeitsnotiz des Agenten in einem Git-Commit.
