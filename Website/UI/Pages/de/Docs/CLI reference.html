Starten und prüfen

Führe diese Befehle in der Shell deines Betriebssystems aus. Nutze rune -help für deinen installierten Build. Befehle, die Anbieter kontaktieren, Konten ändern, Daten löschen oder Server starten, führen echte Aktionen aus und sind keine bloßen Diagnose-Flags.

rune [dir]
Öffnet den interaktiven Agenten im aktuellen oder angegebenen Workspace.
rune -p "prompt"
Führt einen einzelnen Prompt aus und gibt die Antwort sowie den Tool-Fortschritt ohne Vollbild-Oberfläche aus. Berechtigungsanfragen werden abgelehnt statt stillschweigend freigegeben, wenn niemand antworten kann.
-project <dir>
Wählt den Workspace für einen anderen Befehl aus.
-version · -help
Gibt die Programmversion oder die Befehlsreferenz aus.
-settings · -tools
Zeigt die wirksamen Modellparameter oder die dem Agenten angebotenen Werkzeuge an.
-read-only
Schränkt schreibende Werkzeuge ein. Dies garantiert jedoch nicht, dass keine Datei gelesen oder keine Daten gesendet werden.
--no-color
Deaktiviert Farben. Die Umgebungsvariable NO_COLOR wird ebenfalls unterstützt.

Konfiguration

-config
Zeigt den Pfad der aktiven Einstellungsdatei an.
-config show|defaults|check
Zeigt die wirksamen Werte, die Standardwerte ab Werk oder validiert die Datei. Die Ausgabe von show kann private Kontometadaten enthalten; check prüft keine Netzwerkverbindung.
-config explain <key>
Erklärt den wirksamen Wert eines Schlüssels und ab wann Änderungen greifen.
-config set <key> <value>
Speichert eine globale Einstellung. Beispiel: rune -config set terminal.command_timeout 2m.
-config reset <key>
Entfernt eine globale Überschreibung, sodass wieder der aktuelle Standardwert oder die Vererbung gilt.
-config format
Formatiert gruppierte Einstellungen neu, ohne ihre Bedeutung zu verändern.
-set key=value
Ändert eine unterstützte Workspace- oder Modelleinstellung, keinen beliebigen globalen Konfigurationsschlüssel.

Konten und Modelle

Nutze nach Möglichkeit das maskierte Eingabefeld unter Connections. Echte Schlüssel in Kommandozeilenargumenten können im Shell-Verlauf und in Prozesslisten landen. Die folgende Syntax verwendet bewusst Platzhalter.

rune -provider add <name> -key <key> [-preset <p>] [-base <url>] [-model <id>]
-provider list
Listet Konten, Vorlagen (Presets) und die Verfügbarkeit von Webdiensten auf.
-provider key <name> <key>
Fügt dem Schlüsselbund eines Kontos einen Schlüssel hinzu. Dies ändert gespeicherte Zugangsdaten.
-provider keys <name>
Zeigt maskierte Schlüssel-Metadaten an.
-provider dropkey <name> <n>
Entfernt den nummerierten Schlüssel nach Prüfung seiner Identität.
-provider default <name>
Legt den Standardanbieter für neue Sitzungen fest; bestehende Unterhaltungen werden dadurch nicht umgeschaltet.
-provider remove <name>
Entfernt die Anbieterkonfiguration. Gehe nicht davon aus, dass damit jeder gespeicherte Schlüssel unwiderruflich überschrieben wird.
-provider test <name>
Sendet eine echte, möglicherweise kostenpflichtige Anfrage, um das Konto zu testen.
-provider models <name>
Fragt den Modellkatalog des Kontos ab. Führt eine Netzwerkanfrage aus.
-provider dryrun <name> [model]
Zeigt die Vorschau einer Anfrage an, ohne sie abzusenden. Die Vorschau kann privaten Kontext enthalten; teile sie nicht ungeprüft.
-provider timeout <name> <seconds>
Legt ein optionales Anfrage-Timeout für das Konto fest (5–3600 Sekunden); default entfernt die Überschreibung.
-provider new-store --yes
Legt ein nicht mehr lesbares Schlüsselpaar beiseite und beginnt mit einem leeren Speicher. Nutze dies nur nach einer bewussten Wiederherstellungsentscheidung; jeder Schlüssel muss danach neu eingetragen werden.
-model list · -model set <id>
Listet Modelle auf oder wählt ein Modell für den angegebenen Workspace aus.

Sitzungen und Speicher

-session · -resume <id>
Öffnet die Sitzungsauswahl (bzw. gibt bei einer Pipe eine Liste aus) oder setzt eine bekannte Sitzung fort.
-session rename <id> <title>
Benennt eine einzelne Sitzung um.
-session delete <id>
Löscht eine einzelne Sitzung dauerhaft. Prüfe zuvor, um welche Sitzung es sich handelt.
-storage [list|prune]
Prüft den Projektspeicher oder entfernt geeignete Daten von Projekten, die nicht mehr vorhanden sind.
-sandbox [setup|reset]
Prüft den Status der Befehlsisolierung unter Windows, richtet das zugehörige dedizierte Konto explizit ein oder entfernt die Sandbox-Einrichtung von Rune. Andere Plattformen nutzen diese Einrichtung nicht.

Erweiterungen und Diagnose

-skills [operation]
Listet wiederverwendbare Anleitungen auf, zeigt sie an, aktiviert, deaktiviert, installiert oder lädt sie neu. Die Installation übernimmt einen geprüften Ordner oder ein ZIP-Archiv und legt ihn im aktuellen Projekt ab, sofern --scope user ihn nicht benutzerweit speichert.
-mcp [operation]
Verwaltet, genehmigt, validiert und testet externe Tool-Definitionen. Eine Verbindung kann einen lokalen Prozess starten oder einen entfernten Dienst kontaktieren; eine reine Validierung ist noch keine erfolgreiche Verbindung.
--scope user|project|private-project
Wählt den unterstützten Konfigurationsbereich für eine Erweiterungsänderung. Geteilte Projektänderungen wirken sich auch auf andere Nutzer dieses Projekts aus.
-doctor
Führt Diagnosen einschließlich Verbindungsprüfungen aus. Kann Netzwerkanfragen senden; prüfe die Ausgabe vor dem Weitergeben.
-db <path>
Verwendet eine alternative Engine-Datenbank. Dies ist unabhängig von der Auswahl eines gesamten Einstellungsverzeichnisses über RUNE_HOME.
-host
Nutzt zeilengetrenntes JSON für die Frontend-Integration anstelle der interaktiven Oberfläche. Dies ist kein öffentlicher Netzwerkserver.
-script <file>
Spielt ein geschriebenes Modellskript ab. Ein Skript kann echte Tool-Aufrufe vorschlagen; führe niemals ein ungeprüftes Skript in einer produktiven Arbeitsumgebung aus.

Wie du Erweiterungen einrichtest und freigibst, erfährst du unter Skills und MCP-Verbindungen. Wechsle nicht in den Modus Full und lösche keine lokalen Daten, nur um eine Fehlermeldung zu umgehen.
