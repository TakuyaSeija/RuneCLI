Einstellungen für diese Sitzung

Unter Settings → Generation steuerst du die aktive Sitzung bzw. das aktive Modell. Optionale Werte lassen sich leeren, damit wieder die Vorgabe des Anbieters oder der Standardwert beim Start greift. Globale Startwerte in rune.toml sind unabhängig von den Entscheidungen einer bereits laufenden Sitzung. Nicht unterstützte Regler werden unter Umständen ausgeblendet.

Reasoning und Denkaufwand

Wähle unter Generation, über /thinking oder mit Alt+T aus den angebotenen Reasoning-Stufen des gewählten Modells. Über Models → Alt+C konfigurierst du hingegen das dauerhafte Startverhalten und die verfügbaren Optionen. Ein Thinking-Abzeichen in der Modellliste bedeutet grundsätzliche Unterstützung, nicht dass Reasoning in der aktuellen Sitzung aktiv ist.

Off
Fordert deaktiviertes Reasoning an. Dies ist jedoch keine Garantie dafür, dass ein übergeordneter Anbieter oder Router intern keinerlei Denkaufwand betreibt.
On / effort
Aktiviert unterstütztes Reasoning oder wählt eine angebotene Stufe aus. Ein höherer Denkaufwand kann Latenz und Token-Kosten steigern, ohne automatisch eine bessere Antwort zu garantieren.
Route default
Überlässt – sofern angeboten – die Reasoning-Steuerung der jeweiligen Route. Dies entspricht weder festem Off noch einer bestimmten festen Stufe.

Bei 9router erhält eine Route, die ausdrücklich meldet, dass Thinking nicht deaktiviert werden kann, bei einer Off-Anfrage den Wert Low; Minimal wird aus den wirksamen Auswahlmöglichkeiten ausgeschlossen, selbst wenn eine ältere gespeicherte Option diesen Wert enthält. Routen, bei denen Thinking abschaltbar ist, erhalten eine Deaktivierungsanfrage, wobei der ausführende Dienst dies dennoch abweichend handhaben kann. Lies den Hinweistext neben dem Regler, statt das Verhalten aus der Modell-ID abzuleiten.

Als Text angezeigtes Thinking wird in Wörtern gezählt; meldet eine Route stattdessen Thinking-Tokens, werden diese gemeldeten Tokens angezeigt. Rune erfindet keine eigenen Token-Schätzungen. Dass kein Gedankengang sichtbar ist, beweist nicht, dass Reasoning deaktiviert war: Manche Endpunkte geben den Denkprozess schlicht nicht zurück.

Sampling

ReglerZweck und üblicher Bereich
TemperatureZufälligkeit, üblicherweise 0–2. Ein niedrigerer Wert garantiert keine identischen Antworten.
Top PNucleus-Sampling, üblicherweise 0,01–1. Passe in der Regel entweder diesen Wert oder Temperature an, nicht beide gleichzeitig.
Frequency penaltyVerringert wiederholte Tokens, üblicherweise −2 bis 2; negative Werte fördern Wiederholungen.
Presence penaltyVerringert das Wiederholen derselben Themen, üblicherweise −2 bis 2.

Der tatsächlich akzeptierte Wertebereich hängt vom jeweiligen Modell bzw. Endpunkt ab. Aktives Reasoning kann einzelne Sampling-Regler vorübergehend unzugänglich machen. Extreme Strafen (Penalties) oder zu hohe Zufälligkeit können die Qualität der Antworten deutlich verschlechtern.

Ausgabelänge und Stoppsequenzen

Max output legt eine positive ganzzahlige Token-Obergrenze für die Antwort innerhalb des bekannten Modelllimits fest. Reasoning kann bereits vor der eigentlichen Antwort einen Teil dieses Budgets verbrauchen. Ein zu niedriger Wert kann zu unvollständigen Antworten führen; ein höheres Limit kann höhere Kosten zulassen. Ein leer gelassener Wert bedeutet keine unbegrenzte Ausgabe.

Bis zu vier Stopp-Zeichenfolgen können die Generierung vorzeitig beenden. Das Sitzungsmenü akzeptiert kommagetrennte Einträge; ein TOML-Array bewahrt dagegen exakte Zeichenfolgen einschließlich enthaltener Kommas innerhalb eines Eintrags. Eine Stopp-Zeichenfolge, die in normalem Programmcode vorkommt, kann eine Antwort unerwartet abschneiden.

/set temperature=0.2
/set temperature=

Das erste Beispiel setzt eine Einstellung für die laufende Sitzung; das zweite löscht diese optionale Vorgabe wieder. Die weiter unten unter Generation aufgeführten Regler für Hilfsmodelle gelten global und werden im nächsten Artikel beschrieben.
