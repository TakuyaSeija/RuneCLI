Websuche und Seitenabruf sind getrennt

Das Werkzeug web_search sucht anhand einer Anfrage nach passenden Webseiten. web_fetch liest eine einzelne öffentliche HTTP(S)-Seite als Text ein. Übergibst du eine URL an die Websuche, wird nach dieser Adresse gesucht – sie wird dadurch nicht automatisch direkt abgerufen. Der integrierte Seitenleser ist kein interaktiver Browser und kann keine Inhalte hinter Logins oder aus reinen JavaScript-Anwendungen abrufen.

Für die Websuche musst du einen Suchdienst einrichten. Der Seitenabruf nutzt standardmäßig den integrierten Leser von Rune. Beide Werkzeuge besitzen voneinander unabhängige Anbieterauswahlen, Timeouts und Ausgabebudgets; wenn du einen Dienst für das eine Werkzeug aktivierst, wird er nicht automatisch auch für das andere ausgewählt.

Zuerst die Zugangsdaten hinterlegen

Füge unter Settings → Connections das gewünschte Konto unter Search & Fetch samt Adresse und API-Schlüssel hinzu. Das bloße Speichern der Zugangsdaten beweist noch nicht, dass der Dienst funktioniert. Zudem können der Modell-Endpunkt und der Web-Endpunkt eines Anbieters technisch getrennte Dienste mit unterschiedlichen Berechtigungen und Tarifen sein.

Anbieter hinzufügen und auswählen

  1. Öffne Settings → Tools → Web search bzw. Web fetch → Provider.
  2. Wähle Add provider und danach das verbundene Konto aus.
  3. Gib bei einem Gateway die exakt vorgesehene Route in das leere Feld ein. Rate keine Route anhand von Beispielen oder Modellnamen.
  4. Rune sendet vor dem Übernehmen des Anbieters eine echte Testanfrage. Dabei wird eine Suchanfrage bzw. Seitenadresse übertragen, was Kosten verursachen kann.
  5. Kehre zur Liste zurück und wähle den gewünschten Anbieter aus. Erst diese Auswahl testet und speichert ihn als aktiven Dienst; das bloße Hinzufügen legt ihn noch nicht als festen Anbieter fest.

Schlägt das Hinzufügen oder Auswählen fehl, bleibt deine bisherige Einstellung unverändert aktiv. Ein erfolgreicher Test bestätigt die getestete Anfrage, garantiert aber keinen uneingeschränkten Zugriff auf jede künftige Webseite oder jeden Tarif.

Standardverhalten und feste Auswahl

Standard bei der Suche
Ist kein fester Anbieter gesetzt, nutzt Rune den ersten aktivierten Suchanbieter in der Reihenfolge des Hinzufügens. Das Hinzufügen des ersten Suchanbieters macht ihn daher automatisch zum aktiven Standard.
Standard beim Seitenabruf
Standardmäßig wird der integrierte Seitenleser genutzt. Das Hinzufügen eines externen Abrufdienstes schaltet diesen noch nicht automatisch aktiv.
Feste Auswahl (Pin)
Legt ein bestimmtes Konto bzw. eine bestimmte Kombination aus konto:route fest. Fehlt dieser Dienst oder ist er nicht erreichbar, sendet das Werkzeug die Anfrage niemals stillschweigend an einen anderen Anbieter.

Nutze Use default oder setze web_search.provider bzw. web_fetch.provider zurück, um die feste Zuordnung aufzuheben. Wähle zuerst eine andere Option aus, bevor du einen aktuell genutzten Anbieter aus der Tool-Liste löschst. Das Löschen dort entfernt nur die Zuordnung beim Werkzeug, nicht das Konto oder die Schlüssel unter Connections. Für einen Gateway-Dienst lassen sich höchstens 32 Routen speichern.

Limits und Datenschutz

Die Standardwerte ab Werk liegen bei acht Suchergebnissen, 60 Sekunden Timeout pro Anfrage und 100.000 zurückgegebenen Zeichen je Werkzeug. Ein Parameter beim einzelnen Aufruf kann die Trefferanzahl der Suche verringern. Ein höheres Ausgabelimit umgeht keine Zugriffsbeschränkungen.

Externe Suchdienste erhalten deine Suchanfrage; externe Abrufdienste erhalten die Zieladresse der Webseite und können dafür Gebühren berechnen. Der integrierte Seitenabruf kontaktiert den Zielserver direkt. Zugriffe auf private oder interne Netzwerkadressen werden verweigert. Die optionale Cookie-Verarbeitung gilt nur innerhalb eines einzelnen Lesevorgangs bei Weiterleitungen und speichert keine dauerhafte Browser-Sitzung.
