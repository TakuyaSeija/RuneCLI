Zugang ist nicht gleich Auswahl

Connections verwaltet Kontoadressen und API-Schlüssel. Es legt weder das aktuelle Modell noch das Anfrage-Timeout, den Websuchdienst oder den Seitenabruf fest. Diese Einstellungen befinden sich unter Models, Runtime bzw. Tools.

Eine angezeigte Schlüsselanzahl oder der Status Configured bedeutet lediglich, dass Zugangsdaten hinterlegt sind – nicht, dass eine Anfrage erfolgreich war oder Guthaben vorhanden ist. Der Status Resting kann bedeuten, dass ein Schlüssel vorübergehend pausiert. Prüfe die konkrete Fehlermeldung, statt das Konto wiederholt neu anzulegen.

Modellkonto hinzufügen

Jede Anbietervorlage (Preset) samt Schlüsselformat und Adresse ist unter Modellanbieter aufgeführt.

  1. Öffne Settings → Connections → Add connection und wähle den gewünschten Modellanbieter aus.
  2. Prüfe das Formular, das zunächst als Not connected yet markiert ist. Eine Vorlage mit fester Adresse fragt nach dem Schlüssel; eine kontoabhängige oder benutzerdefinierte Adresse muss explizit angegeben werden.
  3. Kontrolliere den Verbindungsnamen und den Schlüsselnamen. Gib Geheimnisse ausschließlich im maskierten Feld für Zugangsdaten ein.
  4. Wähle Connect. Rune testet ein neues Modellkonto vor der Übernahme; diese Testanfrage kann Kosten verursachen. Mit Cancel brichst du ab, ohne zu speichern.
  5. Wähle nach dem Verbinden unter Models das gewünschte Paar aus Anbieter und Modell aus.

Eine Vorlage liefert kompatible Standardeinstellungen für die Einrichtung. Sie ist weder ein eigenes Konto noch eine API-Berechtigung oder eine Garantie dafür, dass sämtliche Produkte eines Anbieters funktionieren. Tarifabhängige Abonnements und regionale Adressen können von der regulären API eines Anbieters abweichen.

Webdienst-Konto hinzufügen

Wähle einen Anbieter unter Search & Fetch, gib die erforderliche Adresse bzw. den Schlüssel ein und speichere das Konto. Das bloße Speichern der Zugangsdaten aktiviert noch keinen Such- oder Abrufdienst und beweist auch nicht dessen Funktion. Wechsle anschließend zu Tools → Web search oder Web fetch → Provider, um den gewünschten Dienst hinzuzufügen, zu testen und auszuwählen.

Websuche und Seitenabruf werden unabhängig voneinander ausgewählt. Ein Konto für lokale Modelle und der Webdienst desselben Anbieters benötigen unter Umständen unterschiedliche Adressen oder Schlüssel. Siehe Websuche & Abruf.

Bearbeiten und entfernen

Öffne eine bestehende Verbindung, um ihre Base URL zu ändern oder benannte Schlüssel zu verwalten. Änderungen an Modell-Endpunkten werden vor der Übernahme getestet. Use default stellt die vom Anbieter vorgesehene Standardadresse wieder her, statt eine Adresse aus dem Kontonamen zu erraten.

Das Hinzufügen eines Schlüssels legt eine zusätzliche Alternative an und ersetzt bestehende Schlüssel nicht automatisch. Prüfe vor dem Entfernen den Namen und die maskierte Vorschau eines Schlüssels. Beim Entfernen einer Verbindung können deren Schlüssel zur Wiederverwendung erhalten bleiben; das Löschen eines Kontoeintrags ist keine Garantie für eine kryptografische Datenvernichtung.

Zieladresse und Tests

Das Ändern eines Endpunkts kann sowohl Zugangsdaten als auch Prompts an eine andere Gegenstelle senden. Prüfe vor dem Verbinden den Betreiber und die beabsichtigte Region. Entfernte Endpunkte mit Schlüsselauthentifizierung erfordern eine verschlüsselte Übertragung; ein Endpunkt auf demselben Rechner (Loopback) wird als lokaler Sonderfall behandelt.

Verbindungs- und Modelltests sind echte Anfragen und können Kosten verursachen. Ein erfolgreicher Kontotest gilt für die getestete Anfrage, garantiert aber nicht die Verfügbarkeit jedes Modells, Werkzeugs, Kontextfensters oder Tarifs. Führe nach einem Blick auf die genaue Fehlermeldung in den Logs lieber einen gezielten kleinen Test durch.
