Was die Verifizierung sicherstellt

Das Installationsskript überprüft zuerst die kryptografische Release-Signatur der Prüfsummenliste und gleicht anschließend das heruntergeladene Archiv vor der Installation mit dieser signierten Liste ab. Diese beiden Prüfungen erfüllen unterschiedliche Zwecke: Eine Prüfsumme allein beweist noch nicht, von wem sie stammt, und eine gültige Signatur garantiert nicht, dass eine Software frei von Fehlern oder unerwünschtem Verhalten ist.

Darüber hinaus prüft das Installationsskript die erkannte Plattform, die erwarteten Dateinamen im Archiv und ob sich die Binärdatei starten lässt. Es installiert das Programm über ein atomares Umbenennen, sodass niemals eine halb kopierte Programmdatei ausführbar herumliegt. Lies bei Bedarf vor dem Ausführen den Quelltext des Installationsskripts (install.sh bzw. install.ps1), um jeden Prüfschritt im Detail nachzuvollziehen.

Heruntergeladene Dateien manuell prüfen

Lade aus der Download-Liste das gewünschte Archiv, SHA256SUMS, SHA256SUMS.sig sowie den verifizierten öffentlichen Schlüssel herunter. Releases werden mit einem ECDSA-P-256-Schlüssel über SHA-256 signiert – ein Verfahren, das sowohl OpenSSL als auch das mit macOS ausgelieferte LibreSSL prüfen können. Prüfe im Download-Ordner zuerst die Signatur und danach die Prüfsumme des Archivs. Unter Linux:

openssl dgst -sha256 -verify signing-key.pem -signature SHA256SUMS.sig SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS

Unter macOS läuft die Signaturprüfung identisch; prüfe anschließend die Prüfsumme deines heruntergeladenen Archivs anhand seines Dateinamens:

openssl dgst -sha256 -verify signing-key.pem -signature SHA256SUMS.sig SHA256SUMS
grep ' rune-VERSION-macos-aarch64.tar.gz$' SHA256SUMS | shasum -a 256 --check

Unter Windows übernimmt das Installationsskript die Signaturprüfung automatisch. Um ein heruntergeladenes Archiv selbst mit der signierten Liste abzugleichen, gibst du seine Prüfsumme in PowerShell aus und vergleichst sie mit der entsprechenden Zeile in SHA256SUMS:

(Get-FileHash .\rune-VERSION-windows-x86_64.zip -Algorithm SHA256).Hash.ToLower()

Ersetze VERSION durch die heruntergeladene Versionsnummer. Die Signaturprüfung muss Verified OK ausgeben, und die Prüfsummenkontrolle muss exakt das Archiv bestätigen, das du verwenden willst. Ein fehlendes Archiv gilt nicht schon deshalb als geprüft, weil eine andere Datei aus der Liste bestanden hat. Brich bei jeder Abweichung sofort ab und führe den Download nicht aus.

Grenzen und Updates

Eine Signatur bestätigt, dass die vorliegenden Bytes mit dem privaten Release-Schlüssel signiert wurden. Sie ersetzt weder ein unabhängiges Code-Audit noch beweist sie reproduzierbare Builds, fehlerfreie Abhängigkeiten oder den Schutz vor einem kompromittierten Signaturschlüssel. Behalte diesen Unterschied im Hinterkopf, wenn du Prüfanleitungen weitergibst.

Installiere das gewünschte signierte Release und kontrolliere anschließend die Ausgabe von rune -version. Unter Linux und macOS wechseln kompatible offene Sitzungen im Leerlauf automatisch auf den neuen Build. Unter Windows behalten geöffnete Fenster ihren bisherigen Build, bis du ein neues Rune-Fenster startest. Brich niemals laufende Aufgaben hart ab, nur damit sich die Versionsanzeige sofort aktualisiert.
