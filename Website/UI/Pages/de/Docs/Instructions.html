Projektanweisungen

AGENTS.md im Wurzelverzeichnis des Workspace liefert Projektanweisungen: Build-Befehle, Konventionen und Rahmenbedingungen für die Arbeit. Die Datei ist weder ein Speicherort für API-Schlüssel noch eine Berechtigungsfreigabe oder die Klassifiziererrichtlinie. Halte Zugangsdaten daraus fern und schreibe nur Text hinein, der als Modellkontext gesendet werden soll.

Das Standardlimit ab Werk für automatisch geladene Anweisungen liegt bei 32.768 Zeichen und wird über instructions.max_chars unter Settings → Tools → Project instructions gesteuert. Überschreitet eine Datei dieses Limit, meldet Rune den ausgelassenen Teil, und die KI liest den Rest bei Bedarf nach, bevor sie sich auf diese Regeln stützt; der restliche Dateiinhalt geht also nicht verloren. Ändern sich die Projektanweisungen während einer Sitzung, kann Rune das Modell darauf hinweisen, die Quelle neu einzulesen.

Die richtige Datei anhängen

/attach <path> fügt eine Datei zur nächsten Nachricht hinzu; /detach <number|all> entfernt vorgemerkte Anhänge. Prüfe vor dem Absenden die Liste der vorgemerkten Dateien. Je nach Modell werden Text, Bilder oder andere Medien unterschiedlich unterstützt; dass sich eine Datei anhängen lässt, bedeutet noch nicht, dass das Modell ihren Inhalt verarbeiten kann.

Ein gesendeter Anhang ist fest mit der Dateiversion verknüpft, die zum Sendezeitpunkt vorlag. Wird die Datei unter diesem Pfad später geändert, darf eine alte Nachricht im Verlauf nicht stillschweigend die neuen Bytes widerspiegeln. Lässt sich der ursprüngliche Inhalt nicht mehr rekonstruieren, meldet Rune, dass die Datei geändert oder gelöscht wurde, statt neuen Inhalt als alten auszugeben. Hänge die neue Version explizit erneut an, wenn die Aufgabe sie benötigt.

Zu den Werkslimits gehören 60.000 Textzeichen pro angehängter Textdatei und bis zu zehn historische Anhänge. Kontext- und Größenlimits des Anbieters können ältere Medien schon früher aus dem aktiven Kontext entfernen. Diese Grenzen gelten unabhängig von den Anhängen der aktuellen Nachricht und von der optischen Einklappung im Protokoll.

Projektgedächtnis (Memory)

Rune unterstützt dauerhafte Projektnotizen mit einem Index in MEMORY.md; Memory beschreibt, wo die Notizen liegen und was davon an das Modell übergeben wird. Das Modell erhält automatisch nur den Index, nicht jede einzelne Notiz, und liest relevante Notizen bei Bedarf gezielt nach. Das Abrufbudget für den Index beträgt standardmäßig 20 KiB; eine Erhöhung belegt mehr Modellkontext, macht den Inhalt der Notizen aber nicht verlässlicher.

Nutze das Projektgedächtnis für dauerhafte Architekturentscheidungen, Korrekturen und laufende Aufgaben. Speichere dort weder Zugangsdaten noch flüchtige Befehlsausgaben. Notizen können in späteren Modellanfragen mitgesendet werden und stellen keine eigene Berechtigungsquelle dar. Das Modell greift über Dateiwerkzeuge mit dem Präfix @memory/ auf das Projektgedächtnis zu und legt keinen eigenen Memory-Ordner in deinem Repository an.

Zwecke sauber trennen

AGENTS.md
Projektanweisungen, die als Modellkontext mitgegeben werden.
CLASSIFIER.md
Deine Richtlinie für die KI-gestützte Aktionsprüfung. Sie besitzt ein eigenes Verhalten beim Neuladen und ist nicht mit allgemeinen Projektanweisungen gleichzusetzen.
rune.toml
Einstellungen im gewählten Rune-Home-Verzeichnis. Eine gleichnamige Datei in einem Projektordner wird nicht automatisch zur globalen Einstellungsdatei.
Skill
Eine wiederverwendbare Anleitung, die für eine Aufgabe aktiviert oder gelesen wird. Sie kann von sich aus keine Berechtigungen erteilen.

Texte im Repository, Webseiten oder Tool-Antworten können irreführende Anweisungen (Prompt Injections) enthalten. Behandle solche Inhalte als reine Aufgabendaten und prüfe Aktionen an der Berechtigungsgrenze, statt der Behauptung eines Dokuments zu vertrauen, eine Freigabe liege bereits vor.
