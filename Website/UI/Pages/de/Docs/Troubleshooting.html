Die wichtigsten Diagnosedaten zusammentragen

Notiere dir die Ausgabe von rune -version, den genauen Wortlaut der Fehlermeldung, den sichtbaren Text in der Fußzeile, den betroffenen Befehl bzw. die Einstellung sowie ob das Problem nur in einer Sitzung oder in jeder Sitzung auftritt. Lies den passenden Eintrag unter /logs und prüfe die betreffende Einstellung mit explain. Schwärze vertrauliche Projektdaten, bevor du Auszüge weitergibst.

rune -version
rune -config check
rune -config explain network.stream_idle_timeout

Diese Befehle prüfen lediglich Programmversion und lokale Konfiguration. Eine formal gültige Konfigurationsdatei beweist noch keine funktionierende Anbieterverbindung. -doctor, Anbietertests und Modelltests senden hingegen echte Netzwerkanfragen.

Installation

rune: command not found
Das Installationsskript gibt den verwendeten Zielordner aus. Starte rune von dort über den vollständigen Pfad oder füge den Ordner – wie unter Installieren & aktualisieren beschrieben – zu deinem PATH hinzu und öffne danach ein neues Terminal.
No build for your system
Das aktuelle Release enthält keinen signierten Build für diese Kombination aus Betriebssystem, Prozessor oder C-Bibliothek. Die Zeile unter dem Installationsbefehl auf der Startseite nennt alle vorhandenen Builds. Am System wurde nichts verändert.
SIGNATURE CHECK FAILED oder CHECKSUM MISMATCH
Der Download stimmt nicht mit dem veröffentlichten Release überein. Es wurde nichts installiert; verwende diese heruntergeladenen Dateien auf keinen Fall. Versuche es später über ein vertrauenswürdiges Netzwerk erneut und melde den Vorfall, falls der Fehler bestehen bleibt.
Run as your normal user
Unter Linux und macOS verweigert das Installationsskript die Ausführung als root, da das Programm in deinem eigenen Home-Verzeichnis abgelegt wird. Öffne ein normales Benutzerterminal und führe den Befehl erneut aus. Unter Windows wird keine Administrator-PowerShell benötigt; das Programm landet im Profil des Kontos, unter dem das Fenster läuft.
Das Programm startet auf diesem System nicht
Das Betriebssystem ist älter als von Rune unterstützt oder die Prozessorarchitektur passt nicht. Plattformunterstützung listet die unterstützten Versionen auf.

Tasten, Maus, Farben und Kopieren

Wenn ein Tastenkürzel nichts bewirkt, wird es meist vom Terminal selbst abgefangen. Konsole zoomt bei Ctrl+Mausrad (sofern im Profil nicht anders eingestellt), und manche Terminals nutzen Alt+Mausrad für horizontales Scrollen; /help zeigt alle Kürzel an, auf die Rune reagiert. Wirken Farben auf einem hellen oder dunklen Hintergrund falsch, hat das Terminal seine Hintergrundfarbe meist nicht gemeldet: Setze in diesem Fall RUNE_THEME auf dark, light oder einen Hex-Farbwert.

Unter Linux läuft das Kopieren über das Terminal, das Programmen das Beschreiben der Zwischenablage erlauben muss; über SSH oder innerhalb von tmux ist dies oft standardmäßig deaktiviert. Schalte es frei (in tmux mit set -g set-clipboard on) oder halte beim Ziehen mit der Maus Shift gedrückt, um die native Textauswahl des Terminals zu verwenden.

Befehle fragen im Modus Auto immer wieder nach

Der Modus Auto führt Befehle nur dort ohne Rückfrage aus, wo sie technisch in einer Sandbox isoliert werden können. Bietet das System keine Sandbox an – etwa auf einem älteren Linux-Kernel –, fragt jeder Befehl vorab um Erlaubnis; /help zeigt unter This machine an, ob die Sandbox aktiv ist. Unter Windows fragen ohne eingerichtetes Sandbox-Konto Git Bash sowie andere MSYS2- oder Cygwin-Programme vor jedem Befehl nach; rune -sandbox nennt den Grund und rune -sandbox setup richtet das Konto ein. Auch ein Befehl, der auf einen bereits laufenden lokalen Dienst (wie eine Container-Engine oder einen Schlüsselagenten) zugreifen will, fragt gesondert um Erlaubnis.

Ein Hintergrundbefehl scheint zu hängen

Lies den Statusbericht und die Log-Datei des Befehls, bevor du ihn abbrichst oder eine Eingabe sendest. Unter Linux erkennt Rune automatisch, wenn ein Befehl auf eine Tastatureingabe wartet. macOS meldet nur verdeckte Abfragen wie Passworteingaben, und Windows meldet Wartezustände gar nicht – dort kann ein stiller Befehl also entweder auf eine Antwort warten oder noch rechnen. Rate niemals auf Verdacht ein Passwort und bestätige keine Abfrage, nur weil ein Befehl gerade keine Ausgabe liefert. Wenn du alle Rune-Fenster schließt, enden laufende Hintergrundbefehle nach Ablauf der Haltezeit für getrennte Sitzungen (standardmäßig 60 Sekunden).

Das Modell meldet, dass der Kontext zu groß ist

Rune komprimiert älteren Verlauf automatisch anhand der vom Anbieter gemeldeten Token-Zahlen oder nachdem der Anbieter eine Anfrage als zu groß abgelehnt hat. Lässt sich kein älterer Teil mehr sinnvoll zusammenfassen, zeigt Rune den Fehler des Anbieters an und sendet dieselbe Anfrage nicht erneut. Prüfe das eingetragene Kontextfenster des Modells unter Models → Alt+C, starte für unabhängige Aufgaben eine neue Sitzung mit /new oder führe /compact aus. Lehnt ein kleines Zusammenfassungsmodell einen Stapel ab, verringere compact.max_batch_size.

Schlüssel sind nicht verfügbar

Key missing bedeutet, dass im Datenordner kein Schlüssel für dieses Konto hinterlegt ist; füge ihn unter Connections hinzu. Unavailable bedeutet, dass der verschlüsselte Schlüsselspeicher zwar existiert, aber nicht entsperrt werden kann – etwa weil die zugehörige Schlüsseldatei fehlt oder aus einem anderen Backup stammt. Stelle in diesem Fall zuerst das zusammenpassende Paar aus deinem Backup wieder her. Das Anlegen eines neuen Schlüsselspeichers legt den alten Speicher beiseite und erfordert das erneute Eintragen sämtlicher Schlüssel; nutze diesen Schritt nur als letzten Ausweg, niemals als bloßen Test. Zugangsdaten erläutert jeden Zustand im Detail.

Eine Nachricht scheint nicht weiterzugehen

Unterscheide zwischen einer eingereihten Folgemeldung, einer offenen Berechtigungs- oder Rückfragekarte, einer laufenden Generierung ohne eingehende Daten, einem Wiederholungs-Countdown und einer laufenden Komprimierung (Compacting). Ein leeres Eingabefeld allein verrät noch nicht den genauen Zustand. Sende zur Diagnose nicht wiederholt „Continue“-Nachrichten – diese werden als zusätzliche Arbeitsaufträge eingereiht.

Ein langsam, aber stetig tröpfelnder Stream ist etwas anderes als eine komplett abgerissene Übertragung. Prüfe das gemeldete Timeout, bevor du den Wert veränderst. Wechselt ein Terminalbefehl nach Ablauf der Vordergrundzeit in den Hintergrund, ist er damit weder fehlgeschlagen noch abgebrochen; lies dazu den Statusbericht des Prozesses.

Ein Konto oder Modell schlägt fehl

Prüfe den gewählten Anbieter, das Modell und den gemeinten Endpunkt. Key missing und Unavailable sind verschiedene Zustände; ein fehlgeschlagener Schlüssel wird nicht als ruhend markiert, er wird in Ring-Reihenfolge erneut versucht. Ein Katalogeintrag beweist keinen Anspruch, und ein Wort in einer Modell-ID beweist keinen verfügbaren Denkmodus.

Automatische Wiederholungsversuche können weder ungültige Schlüssel noch nicht unterstützte Parameter reparieren. Lies zuerst die genaue Fehlermeldung; ersetze nicht vorschnell den Schlüsselspeicher, wechsle nicht blind den Anbieter und starte keine wiederholten kostenpflichtigen Testanfragen.

Ausgabe oder Suche ist unvollständig

Unterscheide zwischen einer vierzeiligen optischen Einklappung im Protokoll, einem Rückgabelimit für das Modell, einer am Arbeitslimit gestoppten Suche und einem vollen Modellkontext. Klappe die Ansicht auf, lies eventuelle Hinweise auf gespeicherte Ausgaben oder übersprungene Zeilen und grenze den Zeilenbereich bzw. Suchpfad gezielt ein. Eine vorzeitig beendete Suche beweist nicht, dass es keine weiteren Treffer gibt.

Die Größe des Kontextfensters ist nicht gleich der maximalen Antwortlänge. Das Erhöhen eines lokalen Fähigkeitswerts erweitert nicht das technische Limit beim Anbieter. Setzt du das Ausgabelimit zu niedrig an, bleibt nach dem Reasoning möglicherweise kein Platz mehr für die eigentliche Antwort.

Richtlinien- oder Web-Status wirkt unstimmig

Dass der Klassifizierer auf Enabled steht, heißt noch nicht, dass er in der Sitzung aktiv prüft: Kontrolliere den Berechtigungsmodus, ob eine gültige Richtlinie vorliegt, welche Werkzeuge ausgeschlossen sind und ob im Leerlauf ein Reload nötig ist. Eine fehlgeschlagene Richtlinienprüfung gilt niemals als Zustimmung. Fehlt ein fest eingestellter Webdienst, wird das Werkzeug als nicht verfügbar gemeldet und weicht niemals stillschweigend auf einen anderen Drittanbieter aus.

Websuche und Seitenabruf werden getrennt voneinander ausgewählt. Das bloße Speichern eines Webdienst-Kontos unter Connections wählt noch keinen aktiven Anbieter für das Werkzeug aus; nimm diese Zuordnung unter Tools vor.

Wiederholung und ihre zwei Kontingente

Rune versucht einen Schlüssel retry.attempts_per_key Mal (standardmäßig zehn), bevor der nächste im Ring des Kontos genutzt wird; der ganze Aufruf endet, wenn retry.max_attempts verbraucht ist. Ein aufgebrauchter Schlüssel übergibt sofort; die Kurve (3, 6, 9... Sekunden) ist die Wartezeit zwischen Versuchen mit demselben Schlüssel. Die Fußzeile nennt Schlüssel und beide Zähler, und ein Schlüsselwechsel steht auch im Verlauf.

Eine Einstellung, die die Engine ablehnt

Eine Einstellung wird beim Laden von rune.toml geprüft, nicht bei der Nutzung. Ein unbekannter Schlüssel, ein Wert falschen Typs, eine Zahl oder Dauer außerhalb des Bereichs oder ein Modell bzw. eine Verbindung, die es nicht gibt, halten die Engine mit einem Satz an, der den Schlüssel nennt; nichts läuft mit einem geratenen Wert. Korrigiere die Datei oder entferne den Schlüssel mit rune -config reset, und prüfe mit rune -config check. Alle Schlüssel, Standardwerte und akzeptierten Werte stehen in der Einstellungsreferenz.

Nach einem Update

Unter Linux und macOS übernehmen offene Sitzungen den neu installierten Build automatisch im Leerlauf, ohne dass du das Fenster schließen musst. Unter Windows arbeiten bereits geöffnete Fenster mit ihrer Startversion weiter; erst neu geöffnete Rune-Fenster nutzen den neuen Build. Schlägt das Fortsetzen einer Sitzung aus einem klar benannten Grund fehl, musst du die Sitzung deshalb nicht löschen.

Meldet Rune, dass der Datenordner nicht aktualisiert werden konnte, behebe die genannte Ursache – etwa fehlenden Speicherplatz oder fehlende Schreibrechte – und versuche es erneut. Wird ein einzelnes Element als unverändert gemeldet, bedeutet das nicht, dass alle übrigen Schritte fehlgeschlagen sind. Lösche niemals laufende Laufzeitdateien, deaktiviere keine Sicherheitsprüfungen, wechsle nicht blind auf Full und lösche nicht deinen Datenordner als unüberlegten Workaround.
