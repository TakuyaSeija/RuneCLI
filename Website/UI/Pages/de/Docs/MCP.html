Externe Fähigkeiten

MCP bindet externe Server an, die Werkzeuge, Ressourcen oder Prompts bereitstellen. Nutze dafür /mcp oder rune -mcp; einen eigenen Reiter in den interaktiven Einstellungen gibt es dafür aktuell nicht. Das Herstellen einer Verbindung ist getrennt von der Freigabe einzelner Aufgaben, die über ein solches Werkzeug ausgeführt werden.

Ein entfernter Server empfängt die Daten, die du an ihn sendest. Ein lokaler Server startet Programmcode auf deinem Rechner. Zurückgegebener Text gilt als nicht vertrauenswürdige Aufgabendaten – selbst dann, wenn er behauptet, verbindliche Anweisungen zu enthalten.

Geltungsbereich und Freigabe

User
Persönliche Definitionen, die projektübergreifend zur Verfügung stehen.
Project
Geteilte Definitionen in der MCP-Konfiguration des Projekts. Prüfe sie sorgfältig und gib sie explizit frei; ändert sich eine geteilte Definition, ist eine erneute Freigabe erforderlich.
Private project
Persönliche Definitionen für ein einzelnes Projekt (der Standardbereich bei MCP-Änderungen). Sie überschreiben geteilte Projektdefinitionen mit derselben ID, welche wiederum persönliche Benutzerdefinitionen überschreiben.

Prüfe Server mit list/status und validiere Definitionen vor dem Verbinden. Eine Validierung ist kein Live-Verbindungstest. Der Befehl add erwartet eine Server-ID sowie eine entfernte Ziel-URL oder eine lokale ausführbare Datei mit absolutem Pfad und Argumenten. Die genaue Befehlssyntax zeigt die Hilfe deines installierten Builds.

Zugriffsrechte prüfen

Prüfe vor dem Hinzufügen oder Aktivieren eines Servers dessen ausführbare Datei samt Argumenten bzw. die entfernte Zieladresse, die Authentifizierung, Umgebungsvariablen, Schreibrechte im Projekt, zusätzliche Lese-/Schreibordner sowie den Zugriff auf bereits laufende lokale Dienste. Gewähre nur die Rechte, die für die jeweilige Aufgabe wirklich benötigt werden.

Entfernte Endpunkte erfordern HTTPS; unverschlüsseltes HTTP ist nur auf Loopback-Adressen erlaubt. Bette keine Geheimnisse direkt in geteilte URLs oder ungeschützte Umgebungsvariablen ein. Nutze den vorgesehenen Weg für Zugangsdaten. Lokale Programme und zusätzliche Wurzelverzeichnisse sind echte Sicherheitsentscheidungen, keine bloßen Beschriftungen.

Zusätzliche Ordner außerhalb des Workspace können in den Modi Ask und Auto vor dem Start eines lokalen Servers eine Freigabe erfordern. Ein weitreichender Zugriff auf lokale Dienste kann Programme erreichen, die mit den Rechten deines Benutzerkontos laufen. Erweitere diese Rechte niemals pauschal, nur um einen Verbindungsfehler zu umgehen.

Verbinden, testen und entfernen

list · status
Zeigt konfigurierte Server und den aktuellen Verbindungsstatus an.
validate
Prüft die Definitionen formal, ohne eine echte Verbindung aufzubauen.
connect <id> · test <id>
Baut eine echte Verbindung auf und startet dabei gegebenenfalls lokalen Code oder kontaktiert einen entfernten Dienst.
approve <id>
Gibt eine geprüfte geteilte Projektdefinition frei. Gib niemals eine Datei frei, die du zuvor nicht selbst geprüft hast.
disconnect <id>
Trennt die aktive Verbindung; die gespeicherte Definition bleibt dabei erhalten.
enable|disable|remove <id>
Ändert die Verfügbarkeit der gewählten Definition oder entfernt sie unter Angabe des passenden Geltungsbereichs (Scope).
reload
Lädt die konfigurierten Verbindungen neu.
login <id> · login-status <id>
Startet einen unterstützten Authentifizierungsablauf oder prüft dessen Status.

Diese Unterbefehle folgen auf rune -mcp, zum Beispiel rune -mcp status. Kontrolliere bei jeder Änderung den gewählten Geltungsbereich und die ID. Erweiterte Befehle für Zugangsdaten wie token oder secret nehmen sensible Werte entgegen; nutze nach Möglichkeit den vorgesehenen Authentifizierungsdialog, statt Geheimnisse im Shell-Verlauf zu hinterlassen.

Die Authentifizierung kann über ein Bearer-Token oder einen OAuth-Ablauf erfolgen. Füge niemals Tokens in den Chat ein. Ein erfolgreich verbundener Server ist kein Beweis dafür, dass jedes seiner Werkzeuge sicher, umkehrbar oder unterstützt ist. Das Modell liest die exakten Tool-Parameter aus und unterliegt denselben Ausführungskontrollen wie bei integrierten Werkzeugen, statt eine fremde Server-API zu erraten.
