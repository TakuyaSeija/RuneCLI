Choose the right wait

Settings → Runtime owns model request timing, shared network waits and retries. A terminal foreground wait, a web-tool deadline and a permission-card expiry are different settings under Tools. Raising every timeout can hide the symptom without fixing the cause.

An account's optional request timeout accepts whole seconds from 5 to 3,600. Blank/default removes that override. Auxiliary jobs can have their own operation deadline. An active stream and a stream receiving no data are not the same condition.

Retries are linear

KeyFactory valueMeaning
retry.max_attempts5Retries after the first attempt: up to six attempts in total. Zero disables retries.
retry.initial_delay3sBase step: waits increase 3, 6, 9… seconds.
retry.max_delay1mA next wait beyond this restarts the sequence at the base step. It is not exponential backoff.
retry.attempts_per_key10How many attempts one key gets before the next key in its ring is used — 10 attempts by default. A spent key hands over at once, and the ring starts over once every key has spent its allowance.

Not every failure is retried. Retrying cannot fix a wrong credential, unsupported control or incorrect endpoint. Very high counts can prolong a failure and add charges; read the classified error in logs first.

Network waits

Stall limit
network.stream_idle_timeout: 5 minutes with no response data. This is not a five-minute total limit on a continuously active stream.
Connect timeout
network.connect_timeout: 10 seconds to establish a connection.
Probe timeout
network.probe_timeout: 45 seconds for an explicit provider test.
Catalog
Advanced values: 10-second request timeout, 1-hour freshness period and at most 100 pages per refresh. Catalog freshness is not a prompt-cache lifetime.

Other advanced limits bound streaming and non-streaming response sizes. They measure bytes, not tokens. The token-saver compatibility option can leave compression to a supported router; enabling it does not guarantee compression and can reduce returned detail.

Detached-session lifetime

host.idle_lifetime is an advanced global setting, 60 seconds by default. When the last window leaves, active AI work stops; background commands can continue during this retention period. Reopen in time to resume watching. It is not an account logout timer or a promise of an indefinitely running server.

Change and reset deliberately

Open the relevant Runtime row, edit and Apply. Use default removes an override; rune -config explain <key> shows effective value and timing. Stream-idle changes can affect a request already waiting, while other choices generally apply to later operations.

First distinguish a slow working service, a silent stalled connection, an exhausted key and an unsupported request. A successful configuration save is not a successful network test.
