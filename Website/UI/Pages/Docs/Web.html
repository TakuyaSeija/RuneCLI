Search and read are separate

web_search finds pages from a query. web_fetch reads one public HTTP(S) page as text. A URL supplied as a search query is searched, not automatically fetched. The built-in reader is not an interactive browser and cannot promise content behind authentication or a script-only application.

Search needs a configured service. Fetch defaults to Rune's built-in page reader. The two tools have independent provider pins, timeouts and output budgets; enabling one service does not silently choose it for the other.

Add access first

In Settings → Connections, add the intended Search & Fetch account with its address and credentials. Saving access alone is not proof that the service works. A provider's model endpoint and web endpoint may be different services with different entitlements.

Add and select a provider

  1. Open Settings → Tools → Web search or Web fetch → Provider.
  2. Choose Add provider and the connected account.
  3. For a gateway, enter the exact intended route into the empty field. Do not infer a route from an example or a model name.
  4. Rune tests a real request before keeping the provider. This can send a query/page address and incur cost.
  5. Return to the list and select the intended provider. Selection tests and saves that exact choice; adding alone does not explicitly pin it.

A failed add or selection leaves the previous choice in place. A successful test proves the tested request, not unrestricted future access to every page or service.

Default and explicit pins

Search default
When unset, use the first enabled search provider in addition order. Adding the first provider can therefore make it the default in use.
Fetch default
Use the built-in reader. Adding an external reader does not automatically select it.
Explicit choice
Pin one account or one account:route. If missing or unavailable, the tool does not silently send the request to a different provider.

Use default or reset web_search.provider/web_fetch.provider to remove the corresponding pin. Select another choice before deleting a provider in use. Deletion removes that tool provider, not the account or keys. A gateway service can keep at most 32 saved routes.

Limits and privacy

Factory defaults are eight search results, 60 seconds per tool request and 100,000 returned characters for each tool. A per-call count can lower the search maximum. A larger output cap does not bypass access restrictions.

Third-party search receives the query; an external reader receives the page address and can charge for its work. Built-in fetching contacts the requested site. Private/internal targets are refused. The optional cookie handling is limited to one redirected read and does not create a persistent browser login.
