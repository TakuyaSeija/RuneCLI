Controls for this session

Settings → Generation controls the active session/model. Optional values can be cleared to return control to the provider or starting default. Global starting values in rune.toml are separate from existing session choices. Unsupported controls may not appear.

Reasoning and effort

Use Generation, /thinking or Alt+T to choose from the selected model's offered reasoning levels. Models → Alt+C instead configures persistent starting behavior and available options. A Thinking badge in a model list means support, not current activation.

Off
Request disabled reasoning. It is not a guarantee of zero thinking by an upstream provider or router.
On / effort
Enable supported reasoning or choose an offered level. Greater effort can increase latency and token cost without guaranteeing a better answer.
Route default
Where offered, leave reasoning control to the route. This is neither Off nor a particular positive effort level.

On 9router, a route explicitly reporting that thinking cannot be disabled receives Low for an Off request; Minimal is excluded from the effective choices, even if an older saved option contains it. Routes that can disable thinking receive a disable request, but executors may still change it. Check the explanation beside the control instead of inferring behavior from the model ID.

Thinking shown as text is counted in words; a route reporting thinking tokens can show those reported tokens instead. Rune does not invent a token estimate. No visible thought does not prove reasoning was disabled: some endpoints do not return it.

Sampling

ControlPurpose and usual range
TemperatureRandomness, commonly 0–2. Lower is not a promise of identical answers.
Top PNucleus sampling, commonly 0.01–1. Usually adjust this or temperature rather than both.
Frequency penaltyDiscourage repeated tokens, commonly −2–2; negative values encourage repetition.
Presence penaltyDiscourage repeated subjects, commonly −2–2.

The actual accepted range belongs to the model/endpoint. Reasoning can temporarily make some sampling controls unavailable. Excessive penalties or randomness can make results less useful.

Output and stop sequences

Max output is a positive whole-token reply ceiling within the model's known limit. Reasoning can consume part of it before a final answer. Too little can leave an incomplete answer; a larger allowance can permit more spending. An omitted value is not unlimited output.

Up to four stop strings can end generation. The session editor takes comma-separated entries; a TOML array preserves exact strings, including commas within one entry. A stop string that matches ordinary code can cut an answer unexpectedly.

/set temperature=0.2
/set temperature=

The first example sets a session preference; the second clears that optional choice. Auxiliary-model controls lower on Generation are global, described in the next article.
