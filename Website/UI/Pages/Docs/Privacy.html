Local does not mean offline

Rune runs on your computer and keeps local settings, sessions and project data. The application does not require an Atoryn account and has no product telemetry collection. It still makes the network requests needed by the accounts, catalogs, models and tools you use.

Using a remote model sends relevant request content to that provider. Running the program locally is not a promise that all code stays on the machine. For sensitive work, review the destination, model configuration, attached files and provider's own retention policy.

What can be sent

Main model
Your prompt, selected conversation context, tool declarations/results and supported attachments needed for the request.
Auxiliary models
Relevant material for policy review, instruction extraction, summaries or titles. A separate configured provider can receive that subset.
Search and page services
A search query, or the target page address and service-specific request. Built-in fetching contacts the target site directly.
MCP and commands
Data passed to external tools or programs. Their own network behavior and retention are not controlled by a blanket “local agent” claim.
Account tests and catalogs
Authentication/test requests and model information requests. Tests can be billed.

Choosing another endpoint is a data-routing decision. An unavailable explicit web pin does not silently fall back to another third party.

What is kept locally

The selected Rune home holds configuration, encrypted credentials, conversation/project data, memory and eligible file-restoration data. A workspace change does not delete its history. A session can therefore retain private prompts and tool output after you stop working.

Compaction changes model context, not a secure-erasure policy. Session deletion and storage pruning are explicit maintenance actions. Deleting a connection is not a promise that all its credentials or historical request metadata have been erased.

Sharing diagnostics

Logs, context views, request dry runs and effective configuration can contain private code, paths, account names or work descriptions. Credential redaction helps with known secrets; it is not a guarantee every private string has been removed.

Share the smallest relevant excerpt after reviewing it. Never paste a real key into chat, source control or a public bug report. Prefer masked key metadata and a minimal reproduction over a full data-folder dump.

Your controls

Choose the intended workspace and mode, attach only needed files, review account endpoints and use provider-side retention/budget controls when required. A local model can reduce remote-model disclosure, but separate web tools, auxiliary routes or commands may still contact services.

-read-only restricts mutating tools; it does not mean no reading or network transmission. A spending warning is not a hard cap. An undo restores eligible local files; it cannot retract information already sent.
