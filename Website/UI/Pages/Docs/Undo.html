Inspect actual changes

The side panel reports current differences for files tracked by the session. Added and removed counts compare content; they are not a total of every edit title. Repeated edits can cancel each other out, and a tool's line count alone is not a complete review.

Review a diff and rerun the relevant checks before keeping the result. A passing command only proves what that command tested. Rune does not automatically commit your work, and file restoration is not a replacement for version control or a consistent backup.

Restore a file

  1. Wait for the work affecting the file to settle.
  2. Open /undo and select the intended file. Use the offered diff action, including Alt+S in the list, to read what will change.
  3. Start confirmation with Enter and confirm within the displayed interval only after checking the current contents.
  4. Verify the restored file and any dependent work.

Undo restores the file to before this session first changed it, not merely before the last patch. It may overwrite edits made outside Rune after that snapshot. A restore is a real mutation and is recorded as such.

Redo is limited

/redo can put back what the latest undo replaced. Review it in the same way. It is not an independent, unlimited timeline of arbitrary versions and should not be used as your only recovery plan.

What restoration cannot promise

File snapshots do not reverse a remote deployment, database transaction in an external service, email, package installation or every action of an arbitrary command. Files outside the protected/tracked scope and changes made by other programs need their own recovery strategy. Check the actual file list rather than assuming an entire machine is covered.

The factory protected-file allowance is 64 MiB. An oversized eligible write can fail before mutation instead of proceeding without protection. Increasing that limit uses more storage; lowering it can stop writes. Do not describe an unprotected external side effect as undoable.

Advanced options

checkpoint.max_file_size
64 MiB factory maximum for an eligible file snapshot.
checkpoint.refresh_interval
1 second factory refresh cadence for already tracked files, configurable from 100 ms to 1 minute.
checkpoint.diff.context
Three surrounding context lines by default, configurable from 0 to 100.
checkpoint.diff.max_cells
Comparison work allowance, 1,000,000 by default. This affects comparison strategy, not file access or the number of permitted changes.

These are advanced configuration keys, not extra current Settings rows. Inspect an option with rune -config explain <key>; reset with rune -config reset <key>.
