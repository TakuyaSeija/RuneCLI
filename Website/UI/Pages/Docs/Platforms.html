Support at a glance

Rune is one program with the same modes, tools, settings and data on every system. What differs is what each operating system lets a program do: how a running program is replaced, how commands are confined, and what the system can tell about a waiting command. Linux is the primary platform. macOS and Windows are in beta: built and tested on real machines, with less everyday use behind them.

Linux

Commands are confined by the kernel's own sandbox where the kernel provides it, as most current distribution kernels do. Where it does not, such as on an old kernel, Rune says so: in Auto every command then asks first, and Full stops asking. /help shows under This machine whether the sandbox is active and anything that can get past it.

Copying text goes through your terminal, which must allow programs to set the clipboard. Over SSH, or inside tmux or screen, that permission can be off; turn it on in the terminal or the multiplexer, or hold Shift while dragging to use the terminal's own selection. Opening a link needs xdg-open, which desktop systems provide.

On a system that keeps its programs in a read-only package store, such as NixOS or Guix, commands may read and run what is in that store.

macOS

Commands run in macOS's own sandbox, held to the same places as on Linux. Copying text sets the system clipboard directly, so it works in Terminal, which ignores a program's request to set the clipboard through the terminal.

macOS tells Rune only about hidden entries, such as a password prompt. A background command that waits quietly for another kind of answer looks like a command that is still working; read its log before deciding, and never guess a password or confirm a prompt just because a command is quiet.

Commands run in bash, which macOS includes, not necessarily in the shell your terminal opens: macOS's own login shell is zsh. Choose another installed shell with an absolute path in terminal.shell.

Install with the command on the home page. A copy downloaded in a browser is marked as coming from the internet, and Gatekeeper refuses to start it until the mark is removed; Install & update shows how.

Windows

Rune confines commands with a separate local account of its own. The first time you open Rune it asks once for Administrator confirmation to set that account up. If you decline, it does not ask at every start; run rune -sandbox setup when you want it, and rune -sandbox reset to remove it and every access Rune's commands were given on your folders. rune -sandbox lists that access and says which way of confining is in use.

Without that account, Rune confines commands with a restricted form of your own account, with these limits:

  • A command can still read what Windows lets every user read, such as folders at a drive's root, other drives and ProgramData, and can create files in ProgramData. Your profile folder stays out of its reach.
  • A command can open, to read only, a named pipe another program created with Windows's default security. Writing to such a pipe is refused.
  • Git Bash and other MSYS2 or Cygwin programs ask before each command and then run that call with full access. Windows's own HTTPS, used by curl.exe and Invoke-WebRequest, fails; Git's HTTPS still works.

With the account in place, Git Bash and Windows's own HTTPS work inside a confined command. Rune does not add access to Windows's own folders, to a drive's root or to the folder that holds every user's profile, so a project opened in one of those asks before each command in Ask and Auto.

Windows does not tell Rune when a command waits for typed input. A quiet background command may be waiting for an answer or still working: read its log before answering. A running program cannot be replaced on Windows, so an update reaches the next Rune you open, not the windows already open.

Terminals

Keys and mouse gestures only reach Rune when the terminal passes them on. Konsole zooms on Ctrl+wheel unless its profile says otherwise, and some terminals turn Alt+wheel into horizontal scrolling; plain wheel and keys always work. The wheel glides smoothly only in a terminal that draws whole frames at once and keeps up; elsewhere each notch moves at once. Colours, transparency and fonts belong to the terminal. Run /help to see what your build answers to.
