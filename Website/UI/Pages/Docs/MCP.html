External capabilities

MCP connects external servers that offer tools, resources or prompts. Use /mcp or rune -mcp; it is not a separate current Settings tab. Connecting is different from approving each task performed through a tool.

A remote server receives data you send it. A local server starts code on this computer. Returned text is untrusted task data, even when it claims to contain authoritative instructions.

Scope and approval

User
Personal definitions available across intended projects.
Project
Shared definitions in the project's MCP configuration. Review and explicitly approve them; a changed shared definition can require approval again.
Private project
Personal definitions for one project, the default MCP change scope. They can override shared project definitions of the same ID, which can override personal user definitions.

Inspect with list/status and validate definitions before connecting. Validation is not a live connectivity test. Add takes a server ID and an intended remote URL or absolute local executable with arguments. Consult the installed command's help for the exact operation syntax.

Review the access

Before adding or enabling a server, inspect its executable/arguments or remote destination, authentication, environment, project-write permission, additional read/write folders and access to already-running local services. Grant only what the task needs.

Remote endpoints require HTTPS; plain HTTP is limited to loopback. Do not embed secrets in a shared URL or literal environment values. Use the supported credential flow. Local executables and extra roots are real access decisions, not merely descriptive labels.

Additional outside folders can require approval in Ask/Auto before a local server starts. Broad local-service access can reach programs acting with your account's rights. Do not expand these options just to silence a failed connection.

Connect, test and remove

list · status
Inspect configured servers and current connection state.
validate
Check definitions without claiming a successful connection.
connect <id> · test <id>
Make a real connection, potentially starting local code or contacting a remote service.
approve <id>
Approve a reviewed shared definition. Do not manufacture approval for a file you have not inspected.
disconnect <id>
Close that connection; this does not remove its saved definition.
enable|disable|remove <id>
Change the intended definition's availability or remove it, using the correct configuration scope.
reload
Refresh configured connections.
login <id> · login-status <id>
Start an applicable authentication flow or inspect its state.

These operations follow rune -mcp, for example rune -mcp status. Review the selected scope and ID for every change. Advanced credential commands such as token/secret accept sensitive values; prefer the supported authentication UI rather than placing credentials in shell history.

Authentication may use a bearer credential or an OAuth flow. Do not paste tokens into the conversation. A successfully connected server is not proof every tool is safe, reversible or supported. The model discovers exact tool inputs and uses the normal execution controls rather than inventing another server's API.
