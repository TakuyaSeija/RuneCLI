Three different kinds of limit

A display fold controls what you see initially. A returned-output cap controls how much text the AI receives. A capture/work limit can stop a command or end a search. Increasing one does not increase the others, and none grants file or network access.

Open Settings → Tools, choose the relevant group, edit and Apply. Use default removes the global override. The factory values below describe Rune {{.DocVersion}}, not your saved choices; inspect one with rune -config explain <key>.

File tools

inspect_file
One file, with inclusive line ranges for text. Factory maximum file size 16 MiB and returned text 30,000 characters. A supported non-text file can be attached to a capable model.
find_files
Glob search for paths. Factory maximum 200 returned paths and 20,000 characters. A smaller per-call limit can reduce, not raise, that maximum.
search_text
Content search. Factory maximum 100 matching lines, 2,000 characters per line and 30,000 total characters. It shares the individual-file size limit with inspect_file.
create_file
Create a file, overwriting an existing one if present. The action must still pass permissions and file protection.
patch_file
Replace one exact piece of text. The old text must occur exactly once; an ambiguous match is not an instruction to replace every occurrence.

Path and text searches include hidden and ignored names but skip .git and .rune. Shared scan limits are 200,000 entries, depth 32 and 200,000 regex-work steps per line. A stopped or shortened search can have more results. Narrow the path or pattern before raising a limit.

Terminal and process tools

terminal_use runs a command in a fresh shell. Factory foreground wait is 120 seconds, returned text 30,000 characters and per-background log 100 MiB. The wait normally hands work to background; exceeding an output/log capture limit can stop it. manage_process reports status/new output, with 30,000 returned characters by default. terminal_send_input types a response rather than waiting for its result.

Read Terminal & background work for launch intent, platform input detection and task lifetime.

Web and extension tools

web_search
Search with a query and optional lower result count. Factory maximum eight results, 60-second request timeout and 100,000 output characters.
web_fetch
Read one public page. Factory timeout 60 seconds and 100,000 returned characters. Separate provider selection belongs to this tool.
discover_capabilities
Find skills, MCP tools and resources not already listed. Factory returned-text allowance 30,000 characters.
call_mcp_tool
Call a discovered external tool using that server's exact declared inputs; the server's operations and risks are its own.
read_mcp_resource
Read a discovered resource. Factory returned-text allowance 50,000 characters.

Plans, questions and orchestration

track_tasks replaces the task list, up to 20 tasks with 120 characters each by default. ask_user_questions requests decisions in an explicit form. Question waits are unlimited by default; permission waits expire after 10 minutes. Unlimited means no expiry, not automatic approval.

tools.max_actions_per_response defaults to 20 proposed tool calls in one model response. It is not a total task budget, worker count or promise that calls run in parallel. Each call still has its own permission and validation.

Change responsibly

Not every tool has a dedicated numeric editor. Higher limits can expose more content and consume more time, disk, memory or model context. Lower limits can omit needed evidence or stop work. Read notices about incomplete output instead of claiming a truncated result is complete.
