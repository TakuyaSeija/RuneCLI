The conversation

User messages, the model's responses and tool steps share one transcript. A tool step names the action and shows its outcome. A failed, refused or not-executed call is not a completed action; read the notice rather than inferring success from the presence of a box.

Long user messages and tool results are visually folded. A footer such as “lines cut. Click to open all” opens the displayed result. This is different from a tool output limit: opening a fold cannot recover text that was never returned. A saved-output notice may tell the agent where to read the remaining text.

A collapsed command box shows its command on one row, while it streams, runs and after it ends. Each line break of a longer script appears there as ↵, and … marks a rest that does not fit the width; both are only display marks, never part of the command that runs. Its output shows up to four rows, and the count of hidden command and output lines sits at the bottom. Click the box to open the whole command, with its original lines, and all of its output.

Clicking a link in the conversation opens a REFERENCE panel with its complete address. For a web address, Open in browser or Enter hands it to your system browser; Copy complete destination or C copies it; Esc closes the panel. A file path can only be copied: Rune never opens or runs a file from a link.

The composer

The box at the bottom holds your next message and shows the current model, reasoning choice where applicable, and mode. Enter sends it; Alt+Enter inserts a newline. A growing multiline input is bounded so some conversation space remains visible.

Type / to open the command palette and filter by command or description. Tab completes while the palette is active; outside a form or palette it cycles permission modes. Your terminal may reserve modified keys, so consult /help if a shortcut does not reach Rune.

Starting the input with ! turns it into a command you run yourself; the composer then shows Shell · full access once. Read Manual commands before you use it.

The side panel

Sessions
Title, start time, activity, context, input/output/cache usage and spend. Unknown limits or prices stay unknown; they are not zero.
Plan
The task list recorded by the agent, with todo, doing and done states. A marked task is the agent's progress report, not independent proof of correctness.
Files changed
Current differences for files tracked by this session, with added and removed line counts. Counts reflect content, not the sum of every edit title.

Use Ctrl+O or /panel to toggle the panel. It can be hidden automatically when the terminal is too narrow. The preference does not stop accounting or delete information. Ctrl+T opens the plan.

Questions and permissions

A permission card asks whether one proposed action may run. A question form asks for a decision or missing requirement. Neither is a completed tool result. Read the scope, select an answer and confirm it. A remembered approval, when offered, applies only to the scope named by that control.

Large cards have their own scrollable reader and pinned answer controls. Scrolling does not answer the card. A deadline expiring is not automatic approval. The default permission wait is 10 minutes; a user question waits without expiry unless configured otherwise.

Status and reading

The footer distinguishes working, waiting on you, retrying and compacting. A blank composer after sending is not proof that a provider has received the request. Use the status and /logs together when investigating a delay.

A temporary footer message stays 8 seconds. When another message or a retry countdown is waiting, it gives way after 3 seconds; a retry keeps counting meanwhile. The confirmations of Esc and Ctrl+C always show over it: press Esc again within 3 seconds to stop the AI, or Ctrl+C again within 4 seconds to leave.

Scrolling away from the latest message holds your reading position. Ctrl+↓ jumps to the latest chat. Settings, logs, context and restore views own their navigation independently; Esc leaves a view when idle.
