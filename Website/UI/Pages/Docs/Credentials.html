Enter secrets in the credential field

Use Settings → Connections → account to add a named API key. A name such as Personal or Work helps distinguish keys; the value belongs in the masked credential field, not in the conversation.

Command-line key arguments can appear in shell history or process information. Source examples and configuration dumps are also easy to publish accidentally. A reference to a credential in account configuration is not the key value itself.

Storage and transport

Rune encrypts its credential store at rest and restricts local key material to the owning account. This protects against casual plaintext exposure, not a compromised user account or unrestricted process running with your rights. Keep the encrypted store and its corresponding key material together in a secure backup.

Known credentials are redacted at request/log boundaries. This does not make an arbitrary conversation or diagnostic dump safe to share: text you manually paste into chat is conversation content. Rune refuses sending an API key over plain HTTP to another machine; loopback services are a separate local case.

Missing and unavailable are different

Key missing
The selected data home has no credential for that account, or no credential store. Add the intended key through the supported flow.
Unavailable
The store exists but cannot be opened. The cause can be missing/damaged key material, an unmatched backup pair, unreadable files or damaged content.
Resting
A credential can be temporarily ineligible, for example after credit exhaustion. Cooldown does not replenish credit.

Rune can still start when credentials are unavailable; only work needing them reports the failure. It does not pretend the store is empty or silently replace it with a new one.

Recover deliberately

First verify the intended Rune home and restore a matching credential backup if available. Do not delete the store or create unrelated replacement key material as a diagnostic shortcut.

If recovery is impossible, Start a new credential store in Connections, or rune -provider new-store --yes, sets the old pair aside and begins with no keys. Every credential must be added again. This is a deliberate recovery action, not a routine connection test.

Rotation and removal

Adding a named key adds an alternative; inspect the name and masked preview before removing another one. Removing a connection can leave keys available for reuse. If a credential was exposed, revoke/rotate it at the provider as well—removing a local reference cannot revoke a token already copied elsewhere.

Configured/key count is not proof of valid authentication or credit. A test makes a real, potentially billed request. Verify the destination before testing after an endpoint change.
