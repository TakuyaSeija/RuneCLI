01

Check your system

The installer detects your system and processor, and on Linux the C library, glibc or musl. It installs only a signed build published for that combination.{{with .Latest}} The line under each install command names what release {{.Version}} has.{{end}}

Linux and macOS need curl, tar, gzip and openssl, which macOS ships; Windows needs only PowerShell. macOS 11 or later and Windows 10 version 1809 or later are supported, both in beta. On Linux and macOS run the installer as your normal user, not root; on Windows it needs no Administrator rights.

02

Verify before installing

The install command above verifies the signature and archive checksum before replacing the program.

Read the installer source, install.sh or install.ps1, before running it. To review offline, save the script, inspect it, then run sh install.sh, or .\install.ps1 in PowerShell.

Walk through your first session

What changes on your machine

One program
Rune is placed at ~/.local/bin/rune, or .local\bin\rune.exe in your profile on Windows. No root or Administrator needed.
Your shell, untouched
Your shell profile and PATH are never edited. If that folder isn't on your PATH, the installer tells you.
License notices
Saved beside your other user data, in ~/.local/share/runeagent, or %LOCALAPPDATA%\RuneAgent on Windows.
Your Rune data
Settings, sessions and encrypted keys live in one data folder in your home, created the first time Rune starts.
Your own model access
Bring a provider account or a supported local endpoint. Rune comes with no API credit.

Installer options

Environment variables choose a version, an absolute destination or, on Linux, the C library. Leaving them unset uses the published latest version, your user bin folder and automatic detection. For an inspected script saved as install.sh:

RUNE_VERSION=X.Y.Z sh install.sh
RUNE_INSTALL_DIR="$HOME/bin" sh install.sh
RUNE_LIBC=musl sh install.sh

In PowerShell, set the variable first, then run the install command:

$env:RUNE_VERSION = "X.Y.Z"
irm {{.Origin}}{{url "install.ps1"}} | iex

Replace X.Y.Z with a published version. These examples are alternatives, not required sequential steps. A missing system, processor or library archive is refused.

Update an existing installation

Run the installer again for the intended release, with the same RUNE_INSTALL_DIR if you chose one. It verifies the download and replaces the program in one step. Check rune -version afterward.

On Linux and macOS, compatible open sessions adopt the newly installed build when idle; on Windows the next Rune you open uses it. Do not kill active work to force it. Keep independent backups of important projects and Rune data.

“rune: command not found”

The installer names the folder it used. Run rune from there by its full path, or add that folder to your PATH yourself; the installer never edits your shell profile or PATH. For the default folder, add this line to ~/.bashrc or ~/.zshrc:

export PATH="$HOME/.local/bin:$PATH"

In fish, run fish_add_path ~/.local/bin once. On Windows, Install & update has the PowerShell line. Then open a new terminal.

Remove Rune

Finish or stop your work and close every Rune window, then remove the program and its license notices. Use your own folder instead of ~/.local/bin if you chose one.

rm ~/.local/bin/rune
rm -r ~/.local/share/runeagent

On Windows, Install & update lists the PowerShell steps, including taking back the access of Rune's command sandbox. Your settings, sessions, encrypted keys and restore data stay in Rune's data folder until you delete it yourself. Its location is the first line rune -config prints; read it before removing the program. Deleting that folder loses your history and restore points, and is not needed just to uninstall.
