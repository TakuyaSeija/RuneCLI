Qué es la memoria

La memoria es una carpeta que el agente mantiene para cada proyecto: contiene un archivo índice llamado MEMORY.md y un archivo independiente por cada nota junto a él. La escribe el propio modelo en texto plano usando las mismas herramientas de archivos que emplea habitualmente, y persiste más allá de la sesión que la escribió. No existe ningún comando especial de memoria ni un sistema de almacenamiento aparte que tengas que aprender.

Dos proyectos nunca comparten notas. Cada proyecto guarda su memoria dentro de su propia carpeta bajo el directorio de datos de Rune seleccionado, nunca dentro de tu repositorio.

Qué llega al modelo

Al abrir una sesión, al modelo se le entrega únicamente el índice como material de referencia. Una nota concreta solo llega al modelo cuando este la abre a través de su ruta @memory/, en el momento en que decide que esa nota es relevante. El resto de la carpeta permanece sin leer, de modo que una nota extensa no consume tokens en cada solicitud durante toda la vida del proyecto.

El índice se lee al abrir una sesión y de nuevo cuando se compacta su historial, no de forma continua mientras se ejecuta. Si otra sesión guarda una nota mientras tanto, esta llegará a la sesión actual la próxima vez que se abra; una nota guardada por la propia sesión actual ya es conocida por el modelo que la escribió.

Leer y escribir notas

No existen herramientas exclusivas para la memoria. El modelo lee las notas con inspect_file y las busca con find_files o search_text; las crea o edita con create_file y patch_file. Rune traduce el alias @memory internamente, por lo que una nota nunca se referencia mediante una ruta absoluta dependiente de la máquina y un archivo del proyecto no puede confundirse con una nota.

Rune escribe cada archivo de memoria de forma íntegra o no lo escribe, y bloquea el acceso frente a otras sesiones durante toda la operación de lectura o escritura. Así, si una sesión se abre mientras otra está escribiendo, leerá el índice anterior completo o el nuevo completo, nunca una versión a medias.

El presupuesto

El índice está limitado por memory.recall_size (20 KiB por defecto), y ese presupuesto en bytes es el único límite que se aplica. Cuando el índice lo supera, se omiten las entradas más antiguas y un aviso lo indica; se espera entonces que el modelo compacte el índice en lugar de dejarlo crecer indefinidamente. Aumentar ese presupuesto consume más contexto en cada solicitud que abre una sesión y no hace que las notas sean más ciertas.

Qué no puede hacer la memoria

Ninguna regla que Rune aplique procede jamás de la memoria. Ningún permiso, ruta, límite ni valor de configuración se lee de una nota, ya que la memoria es texto escrito por el agente y podría albergar instrucciones engañosas. Es únicamente texto informativo para el modelo, y se le entrega en un formato que no puede imitar las instrucciones internas de Rune.

La memoria tampoco es una copia de seguridad ni un registro de comandos. Sirve para conservar decisiones, correcciones y tareas pendientes que merezca la pena llevar a la siguiente sesión; las credenciales y la salida transitoria de comandos no deben guardarse ahí.

Dónde reside

La memoria se almacena dentro del directorio de datos de Rune, en la carpeta propia de cada proyecto, y el entorno aislado de comandos no tiene acceso a ella: un comando de shell ejecutado por la IA no puede verla. Solo es accesible mediante las herramientas de archivos internas de Rune. Mantenerla fuera del repositorio es una decisión deliberada para evitar que un commit incluya por accidente notas destinadas únicamente al agente.
