Ubicación y alcance

La configuración global se guarda en rune.toml dentro del directorio de datos de Rune seleccionado, normalmente ~/.rune/. La Referencia de ajustes enumera todos los ajustes que puedes cambiar: una fila en Settings o una clave del archivo. RUNE_HOME permite seleccionar otro directorio de datos. Un archivo llamado rune.toml dentro de un proyecto no actúa automáticamente como archivo de configuración, y -project elige un espacio de trabajo, no un directorio de ajustes.

Ejecuta rune -config para ver la ubicación exacta en uso. El archivo guarda únicamente tus opciones personalizadas; los valores ausentes heredan los valores predeterminados vigentes. La clave superior version = 1 describe el formato del archivo de configuración, no la versión de la aplicación. No la cambies para intentar actualizar el programa.

Inspecciona un ajuste cada vez

-config explain <key>
Consulta el valor efectivo de una clave, su descripción y cuándo entra en vigor.
-config defaults
Consulta los valores de fábrica por separado de tus opciones guardadas.
-config check
Valida la sintaxis de la configuración y que los valores estén admitidos. No comprueba claves de API, saldo ni conectividad.
-config show
Inspecciona la configuración efectiva. Puede contener metadatos privados de cuentas; oculta los datos sensibles antes de compartirla.
-settings
Inspecciona los controles del modelo para el espacio de trabajo seleccionado.

Modificar y restablecer

rune -config explain terminal.command_timeout
rune -config set terminal.command_timeout 2m
rune -config reset terminal.command_timeout
rune -config check

Ejecuta el comando set únicamente cuando quieras aplicar ese cambio global. Reset elimina el valor personalizado sin escribir una copia del valor predeterminado. En Settings, la opción Use default cumple la misma función para los valores globales. Las claves desconocidas o retiradas generan un error y no se aceptan en silencio como alias.

TOML no tiene un valor nulo nativo. Elimina una clave opcional o utiliza el comando de restablecimiento en lugar de escribir null. No des por sentado que una cadena vacía, «auto», «none» o una lista vacía significan restablecer en todos los ajustes.

Tipos de datos y unidades

Booleano
true o false, sin comillas en TOML.
Recuento / tokens
Un número entero dentro del rango admitido por el ajuste. Los tokens, los caracteres y los bytes son medidas distintas.
Duración
Una cadena con unidades explícitas como "500ms", "60s" o "2m". Solo los tiempos de espera de permisos y preguntas admiten unlimited.
Tamaño
Usa unidades binarias explícitas como "16MiB". Un tamaño sin unidad se interpreta como KiB, no como bytes.
Lista
Usa las entradas exactas documentadas. [] representa una selección vacía explícita, no necesariamente un restablecimiento.
[terminal]
command_timeout = "2m"

[generation]
temperature = 0.2
stop = ["END,EXACT", "STOP"]

Este ejemplo muestra la sintaxis y no constituye una configuración recomendada universalmente. El array stop conserva las cadenas exactas, incluidas las comas; en cambio, el editor de la sesión acepta entradas separadas por comas. Los valores globales de generación no sobrescriben todas las sesiones actuales.

Momento de aplicación y riesgos

Por lo general, los cambios se propagan sin necesidad de reiniciar. Usa explain para consultar cada ajuste concreto: los valores en vivo y los valores que se aplican en la siguiente operación entran en vigor en momentos distintos. Editar CLASSIFIER.md no recarga una política de sesión ya fijada; utiliza para ello la acción de recarga cuando la sesión esté inactiva.

Mantén los puntos de conexión y las credenciales fuera de los ejemplos públicos. Valida las ediciones manuales sin reemplazar preferencias no relacionadas. Aumentar los límites puede incrementar el consumo de memoria, disco, contexto y coste, pero no concede permisos de acceso ni hace funcionar un modelo incompatible.
