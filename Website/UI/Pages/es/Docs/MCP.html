Capacidades externas

MCP conecta servidores externos que ofrecen herramientas, recursos o plantillas de instrucciones. Usa /mcp o rune -mcp; no existe una pestaña dedicada en Settings. Conectar un servidor es distinto de aprobar cada tarea realizada mediante una herramienta.

Un servidor remoto recibe los datos que le envíes. Un servidor local inicia código en este ordenador. El texto devuelto se trata como datos de tarea no confiables, incluso aunque afirme contener instrucciones con autoridad.

Ámbito y aprobación

User
Definiciones personales disponibles en los proyectos donde trabajes.
Project
Definiciones compartidas en la configuración MCP del proyecto. Revísalas y apruébalas explícitamente; si una definición compartida cambia, volverá a requerir aprobación.
Private project
Definiciones personales para un único proyecto (es el ámbito predeterminado al modificar MCP). Tienen prioridad sobre las definiciones compartidas del proyecto con el mismo identificador, y estas a su vez prevalecen sobre las definiciones personales del usuario.

Inspecciona con list/status y valida las definiciones antes de conectar. La validación no es una prueba de conectividad en vivo. La operación add recibe un identificador de servidor y una URL remota o un ejecutable local con ruta absoluta y sus argumentos. Consulta la ayuda del comando instalado para ver la sintaxis exacta de cada operación.

Revisa los permisos de acceso

Antes de añadir o activar un servidor, inspecciona su ejecutable y argumentos (o su destino remoto), la autenticación, las variables de entorno, el permiso de escritura en el proyecto, las carpetas adicionales de lectura/escritura y el acceso a servicios locales que ya estén en ejecución. Concede únicamente lo necesario para la tarea.

Los puntos de conexión remotos requieren HTTPS; HTTP sin cifrar solo se permite hacia la interfaz local (loopback). No incrustes secretos en una URL compartida ni en valores literales de entorno; usa el flujo de credenciales compatible. Los ejecutables locales y las carpetas raíz adicionales son decisiones reales de acceso, no simples etiquetas descriptivas.

Las carpetas adicionales fuera del espacio de trabajo pueden requerir aprobación en los modos Ask y Auto antes de que se inicie un servidor local. Conceder un acceso amplio a servicios locales puede permitir llegar a programas que actúan con los permisos de tu cuenta. No amplíes estas opciones solo para silenciar un fallo de conexión.

Conectar, probar y eliminar

list · status
Inspecciona los servidores configurados y el estado actual de sus conexiones.
validate
Comprueba la validez de las definiciones sin dar por establecida la conexión.
connect <id> · test <id>
Realiza una conexión real, lo que puede iniciar código local o contactar con un servicio remoto.
approve <id>
Aprueba una definición compartida que hayas revisado. Nunca apruebes a ciegas un archivo que no hayas inspeccionado.
disconnect <id>
Cierra esa conexión sin eliminar su definición guardada.
enable|disable|remove <id>
Cambia la disponibilidad de la definición indicada o la elimina, utilizando el ámbito de configuración correspondiente.
reload
Actualiza las conexiones configuradas.
login <id> · login-status <id>
Inicia un flujo de autenticación compatible o consulta su estado.

Estas operaciones se ejecutan tras rune -mcp, por ejemplo rune -mcp status. Revisa el ámbito seleccionado y el identificador en cada cambio. Los comandos avanzados de credenciales como token o secret aceptan valores sensibles; utiliza preferiblemente la interfaz de autenticación integrada para no dejar credenciales en el historial de la shell.

La autenticación puede emplear una credencial bearer o un flujo OAuth. Nunca pegues tokens en la conversación. Que un servidor se conecte correctamente no demuestra que todas sus herramientas sean seguras, reversibles o compatibles. El modelo descubre los parámetros exactos de cada herramienta y aplica los controles habituales de ejecución en lugar de inventar la API de otro servidor.
