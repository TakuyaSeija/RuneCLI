Ejecutar un comando tú mismo

Escribe ! como primer carácter en el cuadro de entrada, seguido de un comando, y pulsa Enter. Rune ejecuta ese script por ti, sin pasar por la IA. Antes de que pulses Enter, el cuadro de entrada muestra Shell · full access once para que veas claramente que vas a ejecutar un comando y no a enviar un mensaje.

! git status --short
npm test

El ejemplo anterior es un único script de dos líneas: se ejecutan ambas. Solo la primera línea lleva el signo !; un segundo ! sería interpretado por la propia shell (en bash y sh invierte el código de salida del comando siguiente). Úsalo para hacer una comprobación rápida, vigilar una compilación o ejecutar un paso que no hayas permitido dar a la IA. Al terminar, tanto el comando como su resultado pasan a formar parte de la conversación y la IA responde a continuación.

Qué se considera un comando

  • Solo un signo ! en la primera posición inicia un comando. hello ! echo test, un ! después de un espacio o un ! en una línea posterior de un mensaje normal se tratan como texto normal.
  • Cuando el texto empieza por !, todas las líneas siguientes forman parte del mismo script. Un ! posterior se interpreta como sintaxis de la shell, no como un segundo comando de Rune.
  • Pegar texto nunca ejecuta nada por sí solo. Enter ejecuta todo el script actual, incluidas las líneas que hayas pegado.
  • Un signo ! aislado no ejecuta nada. Borra el ! inicial para que el texto vuelva a ser un mensaje normal.

Qué nivel de acceso tiene

Pulsar Enter constituye tu autorización. El script se ejecuta una sola vez con el acceso completo de tu cuenta del sistema operativo: fuera de los límites del espacio de trabajo y del entorno aislado de comandos, sin revisión del clasificador ni del saneador, y sin ninguna pregunta adicional de permiso.

No se ejecuta como administrador ni como root, no cambia el modo de permisos de la sesión y tampoco autoriza ninguna acción posterior de la IA. Lee el script completo antes de pulsar Enter, sobre todo si lo has pegado.

Mientras la IA está trabajando

Si envías un comando manual mientras hay un turno en curso, el comando espera a que termine ese turno y luego se ejecuta en el orden en que lo enviaste. Su salida en vivo se muestra mientras se ejecuta. Cuando termina —o cuando pasa a segundo plano por haber alcanzado el tiempo de espera configurado o por estar esperando entrada por teclado—, Rune añade a la conversación el comando y lo que haya impreso, y la IA responde. Esa respuesta es una solicitud normal al modelo y puede tener coste.

Si una ventana se reconecta, Rune reenvía la misma entrada sin llegar a ejecutarla dos veces. Tras un cierre inesperado, Rune nunca vuelve a ejecutar automáticamente un comando que pudiera haberse ejecutado ya.

Cuando se rechaza una acción de la IA

Cuando se rechaza un comando propuesto por la IA, el aviso de rechazo puede mencionar esta opción manual. Rune nunca envía un comando con ! en tu nombre ni reintenta por su cuenta una acción rechazada. El resto de herramientas no disponen de ningún atajo equivalente.

Qué shell lo ejecuta

La shell viene determinada por terminal.shell. Con el valor de fábrica auto, Rune utiliza bash si está disponible en el ordenador y /bin/sh en caso contrario; en Windows utiliza PowerShell 7, o en su defecto Windows PowerShell, o Símbolo del sistema. Cada shell interpreta los comandos en su propio lenguaje.

El recuadro del comando indica qué shell lo ejecutó realmente: $ para bash y zsh, PS> para PowerShell y > para el Símbolo del sistema. Cuando el recuadro está plegado muestra la primera línea del script; haz clic en él para desplegar el script completo con sus líneas originales.

Privacidad

Tanto el comando como todo lo que imprima se envían a la IA en la siguiente solicitud. No imprimas secretos, claves ni archivos privados que no pegarías directamente en un mensaje. Rune oculta las claves que tiene registradas, pero eso no garantiza el filtrado de cualquier valor privado.
