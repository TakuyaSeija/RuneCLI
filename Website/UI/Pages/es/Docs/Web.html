Buscar y leer páginas son herramientas separadas

web_search busca páginas a partir de una consulta. web_fetch lee como texto una página pública HTTP(S). Si pasas una URL como consulta de búsqueda, se realizará una búsqueda sobre ella en lugar de abrir directamente la página. El lector integrado no es un navegador interactivo y no puede acceder a contenido tras un inicio de sesión ni a aplicaciones que dependan exclusivamente de la ejecución de scripts.

La búsqueda requiere configurar un servicio. La lectura de páginas utiliza por defecto el lector integrado de Rune. Ambas herramientas tienen proveedores fijados, tiempos de espera y límites de salida independientes; activar un servicio para una de ellas no lo selecciona automáticamente para la otra.

Añade primero la cuenta de acceso

En Settings → Connections, añade la cuenta de Search & Fetch que quieras usar junto con su dirección y sus credenciales. Guardar el acceso por sí solo no demuestra que el servicio funcione. El punto de conexión de modelos y el punto de conexión web de un mismo proveedor pueden ser servicios distintos con permisos y planes diferentes.

Añadir y seleccionar un proveedor

  1. Abre Settings → Tools → Web search o Web fetch → Provider.
  2. Elige Add provider y selecciona la cuenta conectada.
  3. Si se trata de una pasarela, escribe la ruta exacta deseada en el campo vacío. No deduzcas el nombre de una ruta a partir de un ejemplo o del nombre de un modelo.
  4. Rune realiza una solicitud de prueba real antes de guardar el proveedor. Esto puede enviar una consulta o dirección de página y generar costes.
  5. Vuelve a la lista y selecciona el proveedor deseado. Al seleccionarlo se prueba y se guarda esa elección exacta; el simple hecho de añadirlo no lo fija explícitamente.

Si falla la adición o la selección, se mantiene la opción que estuviera activa anteriormente. Superar la prueba demuestra que esa solicitud concreta funcionó, pero no garantiza el acceso futuro sin restricciones a cualquier página o servicio.

Selección predeterminada y fijación explícita

Predeterminado en búsqueda
Cuando no se define ninguno explícitamente, se utiliza el primer proveedor de búsqueda habilitado según el orden en que se añadieron. Por tanto, añadir el primer proveedor puede convertirlo en el proveedor activo por defecto.
Predeterminado en lectura
Utiliza el lector integrado. Añadir un lector externo no lo selecciona automáticamente.
Elección explícita
Fija una cuenta o un par cuenta:ruta concreto. Si deja de existir o no está disponible, la herramienta no envía la solicitud en silencio a otro proveedor distinto.

Usa Use default o restablece web_search.provider/web_fetch.provider para quitar la fijación correspondiente. Selecciona otra opción antes de eliminar un proveedor que esté en uso. Eliminarlo quita ese proveedor de la herramienta, pero no borra la cuenta ni sus claves en Connections. Un servicio de pasarela puede guardar hasta 32 rutas.

Límites y privacidad

Los valores de fábrica son ocho resultados de búsqueda, 60 segundos por solicitud de herramienta y 100.000 caracteres devueltos en cada herramienta. En una llamada concreta puede solicitarse un número menor de resultados. Aumentar el límite de salida no evita las restricciones de acceso de los sitios web.

Un servicio de búsqueda de terceros recibe la consulta; un lector externo recibe la dirección de la página y puede cobrar por procesarla. El lector integrado contacta directamente con el sitio solicitado y rechaza direcciones privadas o internas. El manejo opcional de cookies se limita a seguir las redirecciones de una única lectura y no mantiene ninguna sesión iniciada de forma persistente.
