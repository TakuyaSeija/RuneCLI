# Rune architecture contracts

Read together with `AGENTS.md` / `CLAUDE.md`. This file retains the detailed cross-layer contracts; the root instructions carry the mandatory gates and workflow.

## Text input contract

The CLI's `ui/editing.rs` is the single canonical keymap/transaction implementation for composer, Questions custom answers, Settings/search (secrets included), MCP fields and picker search/rename. Display and hit-testing still use `ui/editor.rs` and `ansi` glyph projection. The frontend sends only the resulting composer text/cursor through the existing command path; selection, desired column, undo/redo and the bounded kill ring are private transient field state, never protocol/history/credential data. A same-text ACK preserves local edit history; a different authoritative text invalidates it rather than undoing another window's work. A Composer event whose per-window `operations` receipt covers the edit in flight is that edit's acceptance too: the CLI settles it through the same ACK reducer, so Enter does not wait for a second unicast confirmation; a late ACK no longer owns the edit, and a different window's receipt never confirms it. Elapsed time alone never settles that edit or authorizes consumption of its composer; the former three-second abandonment path is removed. Closing or submitting a field, recalling history, or switching sessions also clears it; merely moving focus never shares one field's history with another. All edit entry points, including paste, yank and case expansion, obey the surface's limits atomically. Secret input keeps masked geometry and no automatic clipboard copy.

One key chord owns each editing action, with no Readline alias table or discarded modifiers: Ctrl+A/E logical-line boundaries, Home/End whole-buffer boundaries, Ctrl+K forward kill (at newline remove that newline, at EOF no-op), Ctrl+U backward line kill, Ctrl+Left/Right word motion, Ctrl+W/Alt+D word kills, Ctrl+Y/Alt+Y yank/cycle, Ctrl+_/Alt+R undo/redo, Alt+X/W transpose glyph/word, Alt+U/L/V word case; Shift arrows and Ctrl+Shift Left/Right extend source selection. A mouse drag copies on release and immediately clears its transient highlight on every ordinary text surface; it never places the caret or creates an edit selection. Input copy uses the renderer-published glyph/source geometry (preserving original tabs/newlines), leaves text/cursor/focus intact, and excludes masked secrets; a plain click still places the caret, and keyboard selection still edits. `ui/selection.rs` owns the drag range projection: renderer-owned content spans and origin-pane identity travel with `draw::Sink` through caches, scrolling, overlays and clipping. The same spans govern highlight and clipboard extraction, excluding UI box borders, timeline gutters and adjacent panes without stripping literal source glyphs; table cells are tab-separated. Resize, keyboard/wheel navigation or replacement of selected content cancels the unfinished gesture and swallows its release, never activating the control now under it. Terminal-owned selection (mouse off or terminal Shift-drag) remains the terminal's behavior. Composer Up/Down move visible rows with a sticky desired column, falling back to buffer start/end at the top/bottom row, and repeating at the start/end recalls prompt history (owner exception, 2026-10-16); PageUp/Down also navigate its per-session history. Soft-wrap boundary affinity is field-local and width-bound: a caret at a shared source offset keeps the visual row it moved or clicked to; paint and motion use that same side. PageUp/Down recall composer history directly; only an explicit navigation index identifies recalled input, never text equality. Questions Up/Down leave custom text only at buffer start/end after visible-row motion; Shift motion stays selection. Alt+Left/Right alone switches questions from any form control, preserving each answer; Tab remains form focus, never a hidden mode change. Application shortcuts are not repurposed as Readline actions. Unsupported prefix sequences and terminal reports must never become destructive edits or user prose. Tests cover unique chords/actions, every surface's real dispatcher, Unicode/control/paste geometry, cross-window history invalidation and PTY submitted answers.

## Screen navigation contract

The visible slash palette owns its choice/confirm keys before a reader behind it, never while the composer is hidden by a form. Settings/picker own their whole surface; otherwise the foreground panel gets first refusal before a pending form gets its own keys, with unmatched text still editable in the visible footer. No navigation changes a hidden composer or mode. The wheel uses renderer-owned row and column geometry: Settings, palette, sidebar, form document or foreground reader; spent directions remain on their surface. `Modifiers::wheel_multiplier` applies the same Ctrl/Alt 3× factor to each surface's ordinary notch (item, row or document page), never keyboard focus transitions or a second surface; controls that do not scroll remain unchanged. Lists with a chevron (Logs, Undo/Redo) move selection and reveal together, centred like Settings and clamped at the document ends; plain readers such as Context scroll rows without inventing selection. Logs page keys can read long open details. One panel replaces another through `ui/navigation.rs`; leaving/replacing it invalidates pending presentation replies (including capability/picker loads), never acknowledgements of operations. A late response cannot reopen an older screen. Escape dismisses a visible palette first, otherwise the current screen; Settings ancestry and explicit Undo/Redo diff-to-list navigation remain local.

## Footer status and confirmation lifetime

`ui/footer.rs` arbitrates the main footer on the existing UI thread: ordinary messages use `ui.status_lifetime` (8s default) when unopposed, or at most `ui.status_replace_lifetime` (3s default) of visible time when another message or live retry is waiting. One latest pending notice coalesces superseded updates; countdown ticks update the same retry source rather than creating new notices or resetting its display interval. Confirmations take precedence over undo countdown, ordinary status and retry, and pause the covered source's visible time. Esc acceptance, hint rendering and expiry all use `ui.stop_lifetime` (3s default), including Questions; Ctrl+C uses `ui.quit_lifetime` (4s). A nonmatching key disarms its confirmation. Stop/end control outcomes and session/view replacement discard obsolete messages. On narrow footers the active status or confirmation keeps its space before work/project metadata is shortened. Retry/network deadlines are not delayed or reset by presentation. The optional contested-message setting comes from FIELDS, with a format26 barrier that changes no saved choice or history.

## Frame pacing (measured)

How a frame is paced follows from measurements of real terminals (`ui/draw.rs` `Screen`, CLAUDE.md CLI UI): Konsole 25.04 answers no DEC 2026, draws 10 ms after data arrives or 40 ms into a stream, and takes 35–80 ms for a 169×50 page with its event loop shut. Sending it one frame at a time, then `Screen::QUIET` with nothing new, then a lone `ESC [ 5 n` it answers only once done drawing (`Screen::next_at`), was measured under gdb in a real Konsole: torn repaints 8/736 → 0/711, about 1–1.5 frames a second fewer.

## Session work visibility and ordering

Manual compaction is work even between inference turns: `compact::Activity` publishes `Event::Compacting` (PROTOCOL 21) through Bus for the actual summary lifetime, clearing it on success, error, cancellation or unwind. The latest status is part of `session.view`; the CLI's `working()` drives its spinner, elapsed clock, stop controls and handover eligibility without inventing a user turn. A released admission with a backlog gives a newer prompt the queue to run, its own message last (`Admitted::Backlog`), never a chance to overtake older submissions. A run writes its unanswered messages, active time and `Done` under `settle_with` before admission opens again, so its terminal event cannot clear a newer run. No network wait belongs in that terminal critical section. A boundary flush (exit/session switch) refuses while `composition.submits` still holds an Enter snapshot, leaving the event loop to send it normally; handover waits too, so a submitted message is never saved back as a draft and glued to text typed after resume. A queued prompt's existing ID comes from the message counter: `work::for_queued` compares that acceptance order with the last final row, keeping a pre-final steer on its work and opening new work for a post-final submission (manual compaction and pending-journal recovery included), without rewriting history or adding a stored field. Anthropic's `message_stop` ends that response without waiting for HTTP EOF; an OpenAI finish reason still leaves room for its trailing usage and `[DONE]`.

A synchronous startup `session.resume` has no event loop yet to follow a retiring host. If its authenticated connection ends, says `HostUpgrading`, or refuses with `retry: true` before the resume ACK, `Driver` reconnects to that same session and reissues the same read-only resume ID within the original `RESUME_DEADLINE`. The wait is not restarted; a silent host still times out and an ordinary semantic refusal is returned unchanged. No mutating command is retried by this path, no socket is removed, and no second engine or host is started to displace an existing owner.

## Model instruction ownership

Within one request, each built-in behavioral instruction has one owner (owner, 2026-10-29). The static system prompt owns cross-tool agent workflow, `action` writing, common path/search conventions, trusted message interpretation, recovery, memory and communication. Each tool declaration owns its operation and tool-specific contract; each argument description owns that argument's meaning. Common required/type/enum/length schema constraints remain structural validation, not duplicated prose; `action` stays the first required bounded string, and its one shared schema description names what the field is for without restating the writing rule (owner, 2026-10-31: with no description at all, models read only the JSON schema and filled `action` with a bare verb — `run`, `read`, `create` — in 517 of 518 calls of one measured session). Runtime context, attachment metadata, process notifications and notices report facts, identities and limits rather than reissuing those rules. Specific continuation ranges or errors remain facts needed for recovery. Original user/project/skill/MCP content and immutable old rows are never rewritten or deduplicated by text matching. Independently requested title/classifier/sanitizer/compact roles each retain their own trust and task instructions; their output-call/field contracts live only in the auxiliary tool schema, and quoted input wrappers supply provenance, not another instruction. Regression tests cover ownership, required action validation, auxiliary policy boundaries and both provider wire shapes.

## Model output repetition

A model that begins repeating one short unit is stopped by the engine *while it streams*, not after it finishes (owner, 2026-11-02; session 698: a gateway leaked its raw tool syntax into the text and then sent `}"` 66,818 times — 134,018 bytes in one row, paid for token by token, and wider than the terminal's own column arithmetic). `session/degeneration.rs` watches only the tail of the answer and of the reasoning: an *exact* unit of 1–64 bytes repeated immediately at the end of the stream, covering at least 4 KiB (16 KiB when the unit is only whitespace) and at least 16 repeats. A base64 data URI, a minified line, a hash, a path, a Markdown rule, a table separator, an indented block, blank lines between paragraphs and a repetition that has already ended are never touched: the rule sets no ceiling on how long a single token may be, so a legitimate unbroken run is not its business. The finding is a byte fact about the stream, so live, view and replay agree, and a retried attempt starts over (`Chunk::Reset` clears it).

The turn then settles on the person's answer, asked through the clarification form every frontend already draws (`questions_request` — the same one `ask_user_questions` and a failed compaction use), never a dialog of its own: `Keep up to the repeat (Recommended)` stores the text written before the repeat as an ordinary assistant row, `Discard` stores nothing and leaves the session as if the message never ran. That form's `id` names no tool call, because the engine stopped the stream itself. Only an explicit `Discard` throws text away; a dismissed, blank, cancelled or timed-out form keeps it, since discarding output someone paid for is their decision. Everything streamed is void at that point: the engine emits `StreamReset` and re-emits the kept text, so what the screen holds equals the stored row. A turn cancelled while the form waits stays cancelled and keeps its partial row exactly as a stop during any other stream. The thresholds are internal constants (`limits::REPETITION_*`), not configuration.

The renderer keeps its own guarantee, independent of the engine: `markdown::chop` wraps an unbreakable run at the measure on every row it produces, so any row — a data URI, or a degenerate 134 KB run stored by an older build — is drawn whole and never wider than the screen. It is never truncated to achieve that.

A one-shot run (`rune -p`) prints each segment of answer text once it is the text the session keeps, and drops the segment a `StreamReset` voids: a pipe cannot take bytes back, so an attempt that is retried, or a response this guard stops, is never printed twice or half-way (the segment is flushed before a tool line, so the order of what is printed is unchanged).

## Tool selection and command execution

The model chooses the inspection tool and whether the task can proceed without a command's result; it weighs capabilities, bounded output, safety, total work and dependencies, not call count alone or command-name categories. Independent bounded reads may share a response; the existing gate decides whether they may execute concurrently. An immediate background launch is the explicit `run_in_background: true` intent, not a prediction the engine derives from a program name. Omitted or false retains the result in the same call, with the existing automatic handoff if the foreground wait expires or an input wait is detected. Uncertain duration does not require a background launch. `session/status.rs` publishes the current shell, foreground wait and `platform::INPUT_WAIT_DETECTION` capability through the existing append-only status path; static tool declarations explain the mechanics and the system prompt explains the task-level choice once.

The execution engine owns observed exit, output/capture bounds, input-wait facts, cancellation, the one `to_background` transition and the task journal/wakes. No duration classifier, new scheduler, subprocess probe, polling loop or grace period is added. An explicit launch keeps its immediate-return contract even for a fast command; a failed log setup starts nothing, and a failed automatic handoff retains the existing bounded termination path. A background result reaches the model in that task's own `<system_notification>` — Rune's line (which task, how it ended, its PID, how long it ran, the path of its log) and, below the tag, the output the model has not been given yet, neutralised so a process cannot speak as Rune — never by re-executing or repeatedly checking to wait (owner, 2026-11-03); dependencies resume only from observed results. The system prompt alone teaches the task-level waiting strategy; terminal declarations retain execution mechanics. Its guidance explains the reason: prefer independent work or ending the turn for the notification; a new shell sleep/status/log-wait loop does not advance the tracked task and can itself become another background process, adding work and model cost. Purposeful progress/diagnostic checks and loops that perform actual work remain valid; this is guidance, not a command classifier or blanket ban on loops. The same permission, confinement, process-tree and recovery contracts apply in both modes.

## Manual shell and reference links

`!` is an interactive frontend submission mode, recognized only at byte zero, before trimming; mid-prompt/newline markers are not scanned for execution. All subsequent lines are one shell script and paste waits for Enter. A visible composer label warns `Shell · full access once`. Only `shell.submit` / `draft.shell_promote` can construct its engine provenance; ordinary `prompt`, model `terminal_use` args, external output and stored history cannot. PROTOCOL 22 carries these commands and `tool_shell` metadata. `manual_shell` on immutable user/pending rows records provenance, not a replay request. Format23 explicitly marks old messages/pending as nonmanual without interpreting their text; old audit bytes and unknown shell identities stay unchanged.

A manual submission shares session admission and its ordered queue. It is a barrier to mid-turn steering and runs only after prior work ends, one script/result/AI response before the next entry. The exact bytes receive one `perm::Gate::authorize_manual_shell` decision, lifted by the ordinary `Widened` RAII guard: classifier/sanitizer and AI permission questions skipped, jail/sandbox lifted for that one call, no OS privilege elevation, no persisted grant, no session-mode change. The same terminal executor owns PTY, limits, cancellation and background handoff. Input/result go to append-only `ContextKind::ManualShell` with quoted data and recorded UI metadata, never invented model tool calls or classifier authority. AI inference starts only after the result settles/moves; wakes retain their ordinary lifecycle. A stable random frontend submission token (not a PID-derived request id) and exact script hash in composer prevent a reconnect re-run; a host recovery stores pending without executing it. A crash after acceptance may leave execution unknown: never auto-replay a potentially executed script. Terminal refusal guidance matches Error codes, limited to the resolved built-in terminal_use (aliases included), and never becomes an automatic bypass. Model and frontend tool.invoke results use Finished::for_call for the same user/classifier/jail refusal guidance; repeated failures reapply it idempotently. Ordinary errors, cancellation, nonterminal and external tools do not acquire that manual option. Only the terminal command-field description explains preserved script newlines and ! as a frontend-only mode; the classifier never treats a prefix as authorization.

A terminal call pins its executable for risk/reach/permission and launch. PROTOCOL 23 carries an engine-observed shell preview in `ToolArgs`, never read from model arguments; `ToolShell` confirms the execution's pinned identity and audit metadata records that fact. The bus retains preview identity through argument folding and the ToolCall boundary, then retains ToolShell for joining windows. UI title/prompt/highlight use this engine identity, or Terminal when unknown, never a platform guess or an unproven Administrator claim. A configuration change before execution may change the preview shell to the newly pinned shell; preview metadata never authorizes a call. Assistant response prose uses `Role::Response` (neutral white/dark endpoint), not global Text; thinking/tool output/syntax/chrome remain unchanged. Every wrapped action row uses the same Text ink. Closed terminal commands fill one visual row through `ui/terminal_preview.rs`: each source newline is displayed as a neutral `↵` boundary, never silently changed to a space, semicolon or conditional shell operator. A glyph-safe `…` appears only when the projected suffix cannot fit; streaming, running and finished calls share that limit, independent of the separate four-row output preview. Renderer-owned optional source pieces on selection spans map display-only newline marks back to original newlines and exclude added ellipses from Rune drag-copy; literal source glyphs remain literal and terminal-native selection still copies the display. Open All uses the original multiline source and existing highlighter, including blank rows and indentation. The single bottom omitted-row count covers only command source suffix rows not represented in the compact preview plus hidden output rows, never source newlines already visible as marked boundaries. A wake reads the saved log itself: the first telling after an input-wait handoff carries only what followed the handoff's result (that result gave the output so far, and `to_background` registers the task with that `Reported`), later tellings only new or changed output, a wake taken back unread gives its ledger back so the next telling carries what it held, and a wake with no body has nothing new to say. Its text — Rune's line in the tag, then the output in a `<process_output>` block, data defused by `frame::block` — is bounded by `process_control.max_output_chars` with the head/tail kept, read line by line so memory holds no more than that ceiling, the cut said in Rune's own line (`N lines cut, read the log with inspect_file`), a part that could not be read said there too, and the whole of it always readable at the path that line names. A log includes final scrollback and the current terminal screen while the process runs or waits; before any detected wait is announced it is synchronized to disk, independently of conversation/compaction. The live suffix is replaced in place, not appended twice when echoed answers or redraws change it. This is terminal-interpreted plain text, not raw PTY escapes and not an immutable archive of every intermediate frame; capture errors, disk failures, power loss during a write and configured limits remain explicit bounds. Format24 adds the final-prefix/published-end positions to live handover while preserving old log/journal bytes.

The finished renderer frame publishes OSC-8 label ranges for Rune mouse hit-testing, after wrapping/clipping/sidebar composition. A click opens a REFERENCE panel with the full destination, a drag stays copy. Only explicit Open/Enter on a valid HTTP(S) URL sends `ui.open_url`, handled asynchronously by the engine and platform's browser opener (no shell). File/path destinations remain copy-only: no file read, viewer, executable or OS association. Invalid schemes, controls, credentials and bidi spoofing are refused; Linux needs an available desktop opener and says when absent, macOS uses its desktop opener, Windows ShellExecuteExW with the ordinary `open` verb only for a validated web URL. Native terminal modifier-click remains the terminal's own interaction for web URLs; file/path OSC targets are stripped from outgoing terminal bytes after Rune captures its own hit map, so they cannot launch an OS file association outside the copy-only panel.

## Context counts and source-byte budgets

Provider-reported usage is the only token accounting and automatic-compaction input. Rune never converts text length, thinking, native continuation envelopes, image bytes or base64 to tokens, and never learns an admission ratio from historical estimates. Unknown usage stays unknown. A model's published/manual context, input and output limits are metadata, not a measurement of a new request. The latest reported input is scoped to that session/route and after its newest compaction. Manual compaction and a real provider `ContextOverflow` may compact safe older groups; after overflow, no safe cut returns that provider error without resending the unchanged request, and a second overflow after one successful compaction stops. Original user instructions and the newest complete assistant/tool group stay verbatim; tool execution is never replayed.

`compact.max_batch_size` (128KiB) and `sanitizer.max_batch_size` (64KiB) bound quoted source text in bytes, not model capacity. Every original user source is split before quoting, never silently elided; generated carry-forward prose may be shortened with a bounded progress check. Small models may reject a byte-bounded batch: the provider's failure remains a failure, not a guessed pre-send context error. A selected compact model falls back once to a distinct active route with larger metadata capacity only after an actual context rejection. Classifier evidence retains its own byte cap and full proposed arguments; failed review stays fail-closed. Full serialized provider payload-byte limits, media limits, jail and permission gates are unchanged and independent for every request. Logs say source/message/byte facts, never estimated token savings.

Skill summary listings use `skills.max_catalog_size` (8KiB), overridden only by an explicit `capabilities.catalog_bytes`. Format25 converts saved `capabilities.catalog_tokens` to its former byte allowance once, preserving comments and other choices; invalid items do not abort an upgrade. No runtime legacy key or fallback exists. Historical `token_usage.estimated_in` values remain immutable, unused; new usage rows leave that retired column zero. Configured output-token allowances are sent as tokens, never translated to an invented word/byte capacity.

## Architecture — single gates that must not be bypassed

```
frontend ─Command─► engine ─► session ─► provider
         ◄─Event──             ├─► perm   (Gate: the only path that executes a tool)
                              ├─► tools  (write_guard: the only path that writes files)
                              │    ├─► jail     (engine tool paths; lexical + symlink)
                              │    └─► sandbox  (Landlock / Seatbelt / restricted token; the child process)
                              ├─► checkpoint    (pre-write undo)
                              └─► store         (SQLite + per-session JSONL)
```

- `perm::Gate`, `ToolCtx::write_guard`, `net` = three single gates; do not add parallel paths. The enforcer is the engine, not the model/prompt/server; the prompt **deliberately** does not mention permission limits (reason in `session/prompt.rs`).
- `panic.rs`: a panic inside a tool = 1 failed call, not a dead engine; the workspace is **deliberately not** `panic="abort"`.
- Platform (`Engine/src/platform/`, 2026-10-16): the only code that speaks to the operating system, for the whole workspace — the CLI included, which has no `libc` dependency at all. `platform/mod.rs` is the contract (every item and its meaning, the same on every OS); `platform/unix/` answers what Linux and macOS share (POSIX: files, console, stdio, sockets, pty, process, home, time), `platform/linux/` and `platform/macos/` what only one of them has (reached from `unix/` as `os::` — Landlock, seccomp and `/proc`; Seatbelt, `sysctl` and libproc), `platform/windows/` all of Windows (2026-10-17: ConPTY, `CreateProcess(AsUser)W` in job objects, restricted tokens and ACL entries, named pipes, the console's VT modes), one file per capability. Where an OS cannot give a fact the contract says so by a value — `INPUT_WAIT_DETECTION`, `REPLACES_IN_PLACE` — never by a stub that pretends; policy tables are chosen by `platform::OS` at run time. The contract is shaped by meaning, not by Unix: a process is started by the platform — `spawn_on_terminal` (its own session, the terminal its own), `spawn_piped` (an MCP server over pipes, stopped when dropped), `spawn_detached` (a session host outliving its window) — from a `Launch` (program, arguments, a command-line tail written as is for `cmd /S /C` on Windows, folder, environment) and a `Placement` (its confinement, Unix sockets allowed or refused, its tree's mark) rather than given `pre_exec` closures; what crosses an `exec` is `Handed` (its JSON the bare descriptor number every earlier build wrote, so the handover record is unchanged); a socket peer is `peer_is_same_user`, never a uid; a file is a `FileIdentity`, never `(dev, ino)` at a call site; a path is spelt by `platform::canonical` (every link resolved; on Windows without `\\?\` where it reads the same — cmd cannot run in a verbatim folder), never `canonicalize` outside the platform; a file that must be this user's alone is made so as it is created (`open_private` with `Private::{Lock, New, Append}`: `0600`, or an owner-only ACL), never tightened after; the terminal is `ConsoleMode` + `Typed::Keep`/`Discard` (TCSADRAIN/TCSAFLUSH). A file is replaced whole by `replace(from, to)`; on Windows it waits up to `REPLACE_PATIENCE` (2 s) while another program holds `to` without letting it be deleted (an antivirus, the indexer, a backup tool: `ERROR_ACCESS_DENIED`/`SHARING_VIOLATION`/`LOCK_VIOLATION`), never failing a configuration, credential or composer save on that. A lock is a `lock::Lock`, never a bare file: its descriptor is noted (`platform::keep_from_children`, a fixed table of atomics) from open to just before close, and the first thing every child Rune forks does is close the noted ones (`unix/kept.rs` `close_in_child`, in `in_child` and the services probe) — `flock` belongs to the open file, so a child still starting (Landlock, seccomp, the listener handoff: up to a minute) held every lease, host, configuration, credential and drafts lock its parent let go (a closed session read as open elsewhere and kept its scratch, macOS CI 2026-10-18); Windows lists the handles a child gets (`PROC_THREAD_ATTRIBUTE_HANDLE_LIST`), so there is nothing to note; a lock handed across an `exec` leaves the table first (`Lock::into_file`) and is noted again when adopted (`Lock::adopt`). `boundary::os_specific_code_lives_only_in_platform` fails the gate on `libc::`, `windows_sys::`, `std::os::`, `extern "C"`, an OS `cfg`, a `/proc` read or a `canonicalize` anywhere else — engine, CLI, unit and integration tests alike, with no exceptions list; what a test must observe of the OS (a process's state or parent, a link, a descriptor kept across exec, a resize signal) is `platform::fixture`, compiled only for tests (`test-support` feature). Security policy that names an OS's paths (`sandbox::Policy` reads/writes, `perm::denylist`, `perm::reach::Forbidden`) stays with its owner: decisions, not mechanisms — one table per OS in the owner's module, chosen by `platform::OS` at run time and never by a `cfg`, so every table is compiled and unit-tested on every machine. The shell a command runs in is read in its own language (`shell.rs` `ShellKind` by the program's name: a POSIX shell takes `-c`; PowerShell `-NoLogo -NoProfile -EncodedCommand` with a UTF-8 preamble and an exit-code epilogue, so no quoting can change the command; cmd `/D /S /C "<command>"` as a tail written as is), and the risk rules and path reach read it the same way (`perm::windows_shells`, `denylist::classify_for`, `reach::in_command_for`); `terminal.shell = auto` is bash else `/bin/sh`, on Windows PowerShell 7 on `PATH`, else Windows PowerShell, else cmd (owner, 2026-10-17). Paths compare without case where the OS does (`jail::starts_with_folded`: Windows, macOS), and a Windows name the OS would read as something else — a device, a stream, a trailing dot or space — is refused (`platform::windows_name_trouble`). A skill package's files are read with no link anywhere on the way, the package root's own path included (`LinkFreeDir`, component by component with `O_NOFOLLOW`; never `openat2`, which kernels before 5.6 and container profiles refuse — 0.6.7 failed every skill there). The Rune home is spelt as the filesystem names it wherever it is chosen (`store::Db::home_dir` → `jail::canonical_spelling`, `$RUNE_HOME` and `$HOME` alike), and an empty or relative `$HOME` is no home.
- Locks (`Engine/src/lock.rs`): every cross-process hold — a session's lease and host lock, the configuration, the vault, drafts, memory, help in use, an upgrade — is `lock::exclusive`/`lock::shared` with `Wait::No` (held elsewhere = `Io` of kind `WouldBlock`) or `Wait::Yes` (the kernel's wait, woken by the release, at most `lock::PATIENCE` = 10 s, then `TimedOut`): std's whole-file locks, `flock` on Linux — the lock earlier builds took, so builds side by side during a handover exclude each other.
- Retry lives only in `retry/`: one loop around the whole attempt (open + stream), `retry.max_attempts` retries (any number) on the owner's curve — retry k waits `retry.initial_delay` × k (default 3 s) and a wait past `retry.max_delay` (default 1 m) starts the series again from the step, so the defaults wait 3/6/9/12/15 s; no floor or ceiling of the code's own — every error except user cancel, `Incomplete`, `ContextOverflow` (the turn compacts instead) and Rune's own `Invalid`/`NotFound`. The server's `Retry-After` is never read (owner: Rune's retry is not steered by the provider's) — a key a server refused rests on the same curve (out of credit: `retry.credit_cooldown`). A stream on which nothing arrives for `network.stream_idle_timeout` (default 5 m; hot-reloaded, it reaches a request already waiting; any byte — thinking, a keep-alive — starts it again) is abandoned as `Error::Stalled` and retried like any other error (`net/Interrupt.rs`, the transport's one wait). A failure after output was shown emits `Chunk::Reset` → `Event::StreamReset` (the frontend drops the partial) before the repeat. Tools never run inside the loop. `net` never retries by itself. Every secret is registered in `net/redact` — it must never appear in errors/logs.

Whether a program waits is a fact read by `platform::Pty::input_wait` (Linux: the terminal's termios — `ECHO` off = hidden, `ICANON` = a line read — and `/proc/<pid>/syscall` of each process of the terminal's foreground group: blocked in a read of this terminal or `/dev/tty`; a process this user may not inspect, e.g. set-user-ID `sudo`, counts only when the terminal is set for a hidden line), never parsed from output; `platform::INPUT_WAIT_DETECTION` says how much a platform can tell (`Every` on Linux; `HiddenOnly` on macOS — a terminal set for a hidden line while every thread of the foreground group waits, XNU giving no wait channel; `Never` on Windows — no public interface tells that a console program waits to read) — what it cannot tell moves only at the timeout, and on those systems alone the notices say a quiet command may be waiting for input or really still running (owner, 2026-10-17; Linux's words unchanged). Every wait of one task is told in the same words, so a wait's wake is taken back by identity, never by matching its text later (that took the next wait's wake, word for word the same, with it): `SessionWakeNotifier::withdraw` removes it from the session's queue while unread (`SessionState::withdraw_queued`) the moment its wait is over (typed into, gone, the task ended or was stopped) or a stop said it, sending and taking back under one lock (`background::Waits`); a wake taken back unread restores the ledger it advanced (`background::Wake`), so what it carried is told by the next wake and never lost, and a wake is queued only while its task still runs and waits, checked under that lock, so a stop that lands while its report is read adds no second `Killed`. `process_control` (`tools/process_control.rs`: `process_id`, `do` = `type`|`stop`, `text`, `submit` = `auto`|`enter`|`none`, blank = `auto`) types into a running task's terminal, or stops it together with its whole tree; `process_id` has no `all` (owner, 2026-11-03) and every launch notice and wake names the id it belongs to, the still-running ones listed in `<status>` — through the gate as a command (`runs_commands`, its text classified by the deny-list: the process may be a shell) — with Enter after the text when `submit` says so or, on `auto`, when the terminal reads a line (`Pty::line_mode`; Enter when unknown; empty text with no Enter is refused, since nothing would be typed), and returns at once with one sentence (`notice::typed`: `Typed …`, never the text itself — it may be a password). It neither waits nor reports: what the process does next — its next wait or its end — arrives as a `<system_notification>`, as the sentence says. Waiting has one contract (session 570: a tool that could block beside a prompt that said "do not wait" made the model poll, wait in slices and end its turn, by turns): the model does other work, then ends its turn, and the notification starts the next; a wake never waits and holds only what the model was not given (`background::Reported`: the log offset and the screen as reported — the rows of that screen are not sent again, whether it grew in place or scrolled into the log, and a redrawn screen is sent from its first changed row, `background_report::without_seen_rows`; that a wake holds only what the model was not given is said once, in the system prompt, and its own line names the log the rest of it is in). A wake's line keeps its facts apart with `;` (`input hidden (what is typed is not shown)`, `N lines cut, read the log with inspect_file`, `part of its output could not be read (…), read the log with inspect_file`, `lost: <why>`). Only a result the model reads tells it anything (`tools::Reader`, on `ToolCtx`): a call a frontend runs directly (`tool.invoke`, `call::run_direct`) is `Reader::Person` — its result joins no history the model reads, so its kills and a wait its command met change nothing of what the model was told (`Reported`, told waits) and still reach the model by wakes. Every process a command starts carries its tree's random mark (`platform::TREE_VAR`, `new_tree_mark`), kept with the task and in its start record; a stop (kill, cancel, timeout, output limit, capture failure, a session let go) is `platform::terminate_tree`: the group and every live process carrying the mark — so what left the group (`setsid`, a daemon's double fork) stops too; a process that clears its environment or runs as another user is out of reach (Linux reads `/proc/<pid>/environ`, macOS a process's environment through `KERN_PROCARGS2`; Windows holds the tree in a job object named by the mark, which a child cannot leave unless allowed to break away). - Session: draft registry + cross-process flock/lease; detached host via a socket in `~/.rune/run/`, bound and reached only through `platform::LocalListener::bind`/`LocalStream::connect` (a home of any length — a path past the socket address's bytes is spelt through `/proc/self/fd` on Linux, through a short link in the user's private temporary folder on macOS); a connection is heard only after it proves itself (`access.rs`, the socket's single gate — Landlock does not mediate `connect()` and a socket's mode comes from the umask): the peer runs as this user (`LocalStream::peer_is_same_user` — the kernel's word: `SO_PEERCRED` on Linux, `getpeereid` on macOS; on Windows a named pipe met through a meeting file at the socket's path, the client known by impersonating it — the same user, and no less elevated than the host; a host's end lets a window go only once it has read what it was sent, `FlushFileBuffers` then disconnect within a bounded linger, since a plain disconnect throws unread bytes away — `HostUpgrading` among them) and its first line is a `session.hello` carrying the host's key — random, issued per host into a 0600 `run/session_<id>.key` before it binds, withdrawn on drop under the ownership lock; a confined command cannot read `run/` unless the person granted it, and — the kernel's own fence, whatever it can read — reaches no socket without local services (above); whoever can do both was let by the person, and could already rewrite the home. Until admitted a connection is in no fan-out, counts as no window and reaches no engine (`session_ipc.rs` `admit` → `serve`); a window of the build before keys gets, for its `session.resume`, only this host's protocol and version (`resumed: false`) — the mismatch is what makes that build hand itself over to the installed one at once, carrying its input, so no window is ever relaunched — and "newer build" for any other command (`answer_older_window`, for the previous release only); a window finding no key file sends its hello without one, which such a host answers as an unknown command (`Answer::Older`); **one** place executes a tool call (`session/call.rs`) — the model path and the frontend path are identical. A session runs one piece of work at a time — a turn, a compaction, a restore, a direct tool call, a background task's wake — through one admission (`SessionState::admit`/`begin_guarded`/`settle_with`, `session/mod.rs`) — every user message (`prompt` and `prompt.steer` alike, `engine.rs`) is admitted there: it begins a turn or waits for the work in progress, never refused for the session being busy, so no frontend decides by what it believes about busy (a window that had seen `Done` before the turn let go was refused and put the message back; `a_prompt_while_the_session_is_busy_is_admitted_never_refused`); a window draws each message it sent as waiting until the engine's `TurnStart` for it and never sends one again (the engine holds the queue), and a refused one leaves the screen with its words back in the composer ahead of anything typed since: the busy flag and the queue of messages for the work in progress live under one lock, so a steer or a wake that arrives while busy is taken at the work's next decision point or when it settles (`turn.rs` `settle` → `Continue`/`Released`; `run_queued` for work that is not a turn), never stored for nobody; a compaction asked for while busy runs at the next request boundary. Consecutive calls of one response run together only when their tool is `Tool::concurrent` (reads and nothing else: `inspect_file`, `find_files`, `search_text`, `web_search`, `web_fetch`), the classifier does not judge them and the Gate's own `verdict` allows them without a question (`call::concurrent`, the same functions the run goes through); `turn.rs` `together`/`run_together` runs them all at once — no width of its own (owner, 2026-10-11: `tools.max_parallel` is retired; `tools.max_actions_per_response` bounds a response) — and records every result in the model's order. `find_files` and `search_text` walk every file of the project — an ignore file or a hidden name hides nothing (owner, 2026-10-11: `scan.respect_ignore` and `scan.hidden` are retired) — save `.git` and `.rune`, which no walk enters (`walk::Options::configured`) unless the pattern names a folder inside one. A walk starts in the folders the pattern (`find_files`) or `include` (`search_text`) names before its first wildcard (`tools::Scope`, `glob::split_walk_root`): it finds what a walk of the whole workspace filtered by that pattern would, without spending its entry budget elsewhere first; a pattern that is one existing file's path reads that file alone, and one that names a place outside the workspace reaches it like any path argument (`reaches`: `find_files`' pattern, `search_text`'s include — never its search text, which names no place). How far a walk goes (`scan.max_entries`, `scan.max_depth`) and the per-line regex fuse (`scan.regex_steps`) are the person's, in Settings → Tools → FILE SCAN, and a walk that stops at either bound says so in a notice (`tools::walk_stopped`: `The search stopped at …`) instead of a result that only looks complete. - Store: JSONL = source of truth, append-only (one write per record, newline included; a file a crash left without a final newline is closed off before the next record, so damage costs only the record it cut; `session.jsonl` is parsed incrementally by `JsonlStore::read_messages_shared`, a replaced or shorter file is re-read in full; the turn reads it once per round via `Db::history_shared` and copies only the rows it sends). SQLite = registry/grants/checkpoint manifests/usage/provider catalogue — no conversation history; a session's spend is the engine's (owner, 2026-10-23): `Db::session_usage_before` sums the rows' recorded costs and prices each measured row recorded without one at its model's rates now (`Settings::prices`, a snapshot taken before the store's lock), never rewriting a row, so a price filled in later prices the history it was missing from while a request priced when it ran keeps its charge; `session/spend.rs` sends it whole as `Event::Spend` (spend, priced, unpriced) after each recorded request and at every `SettingsGet` (a window asks on every configuration change, any process), serialized so totals arrive in the order the store moved; replay keeps only the latest; the sidebar shows `$X` with `N requests not priced` beside it, or `not priced` when nothing has a price; a schema change = bump `SCHEMA_VERSION` + a migration path (a copy goes to `backups/` first). The provider model catalogue (`provider_models`) is reached only through `store/catalogue.rs`, which opens the database with the store's own connection settings (`store::connect`, never the store's start-up work) at the path it is given — settings never assume a database beside `rune.toml`; a database whose schema another process is still laying reads as empty, and a write to it opens the store first (`catalogue::laid`).
- Rune memory: index-only injection (`MEMORY.md`, in the opening context) from the project folder's `memory/`; no memory tools by design. The static prompt states why a note exists — experience a later session inherits (a failure and its cause, a correction, a decision and its reasoning, a measured limit) rather than a summary of the code — and that the index is a report of what was true when written, to be verified before it is relied on (owner, 2026-11-01). - Checkpoint: content-addressed blobs in the project folder's `objects/` (engine home, not inside the project); every write is captured first, one manifest per turn, never trimmed on its own (owner, 2026-10-11: `checkpoint.keep_turns` is retired; only `checkpoint.prune` with an explicit `keep` trims, and a deleted session's blobs are collected). Undo is per file (owner): the session's file ledger (`session_files`: each path's state before the session first touched it — blob and mode —, kept past pruning, and when the session last changed it) is the undo list (`checkpoint.files`, the same rows and `+N −N` as the side panel's FILES CHANGED) and what is put back (`checkpoint.restore { file }`: the file as it was before the session, or no file when the session created it); `checkpoint.diff { file }` shows that state against the file now. Redo is undo the other way (owner): an undo keeps what it overwrote (A) in the ledger (`redo_blob`/`redo_mode`/`redo_at`, kept past pruning, the latest undo's); `/redo` (`checkpoint.redos`, `checkpoint.redo_diff { file }`, `checkpoint.redo { file }`; the same panel, `undo::Side::Redo`) lists only files that were undone, measures the file now against A, puts A back whatever became of the file since, and is used up — the file leaves the list until its next undo. Undo and redo (`Engine::put_back`) hold the session's admission (refused while work runs), capture what they overwrite under a turn of their own and are told to the model (`context::restored`). The diff (`checkpoint/diff.rs`) never refuses: Myers within `checkpoint.diff.max_cells`, past it patience anchors (lines unique on both sides) and Myers per piece, the whole bounded by `diff::TOTAL_WORK` budgets — every count shown is a real diff's; only a blob gone from `objects/` (`Change::Missing`) falls back to the write ledger's tally and cannot be undone.
- Realtime file counts have one publisher (`session/file_changes.rs`). - Upgrade (`Engine/src/upgrade/`, `Cli/src/build.rs`): every release is taken over live. A running host/window that sees a new build installed asks it `rune -upgrade-check` (config, database and layout checked without changes) and, when idle, `exec`s it in place; the window carries its input, cursor and panel. Where a process cannot become another program (`platform::REPLACES_IN_PLACE` false: Windows) nothing `exec`s: a window says once that a newer build is installed and is used the next time Rune is opened, and hosts and the picker keep the build they run (owner, 2026-10-17). A window still on the build before starts any session host from the build installed now (`Driver::launcher` → `build::installed`, never its own replaced `… (deleted)` file), and never `exec`s while it holds a draft's first message not yet handed to its host (`App::handover_waits`). The picker parks the same way. The session picker (`rune -session`) does the same while its list is idle (`picker.rs` `release_to_activate`: `build::replaced` + `build::ready`, then `exec` with its own arguments, back on the list). The version a window shows (footer, banner) is the build it runs, `runeengine::VERSION` — never its host's, which is kept apart as `App::host_version` for this rule: a window also follows a host that runs a later release (one installed in place, under the same file) — never an earlier one, which takes the installed build over by itself (`build::later`; a window that followed any difference exec'd itself in a loop until its host moved). Rune starts Rune the way it was started (`platform::program_launch`/`program_command`, the one way for the session host, the upgrade check, the window/host/picker exec and the way back): on Linux a program may be started by naming it to a dynamic loader (`ld-linux… --library-path <dir> ./rune`, how a build runs on a system whose glibc is too old), where `/proc/self/exe` is the loader — the program's path, its identity (`running_program`) and the way back (`own_program`) are then what the kernel mapped this code from, read as the process starts (`platform/linux/started.rs`), and every start goes through the same loader with the options it was given (0.7.7 started the loader as the host: exit 127). The Linux release is built for glibc 2.17 in the manylinux2014 image and as a static musl file (`scripts/build_linux_release.sh`, checked by `check_linux_binary.py` and `smoke_linux_release.sh`; owner, 2026-10-21): a build made on a new system asks for that system's glibc. The first process of the new build upgrades the home before anything reads it: `version.json` names the home's format, each `upgrade/vN.rs` step runs once (configuration → layout → database schema), under `run/Upgrade.lock`, after every session lease and host lock of the previous build is free. Nothing is deleted — what the new format drops is moved into `backups/UpgradeN-<time>/` with a `plan.json` of every change; a failed step is undone in reverse — the version marker included (`Plan.marker`, saved before the step starts) —, a crash part way is undone by the next start (`run/Upgrade.active`). The goal of a release is that every person reaches it, on any machine (owner, 2026-10-16): before changing anything the upgrade checks it may write and has room (`preflight`, `platform::free_space`); one damaged item (a session file that does not read, a torn line, a broken pending promotion, a drafts registry, a format-1 folder still holding something) is left as it was or set aside, noted in `Plan.skipped` and told (`Progress::LeftAsItWas`), never a reason to stop — session record files change only through `rewrite_sessions`/`rewrite_lines`; an I/O failure keeps its kind and path so the person is told what to do (`build::failure`). Rune never replaces the installed build — whoever installed it owns that file, and no `rune.prev` exists on a person's machine: a process another build handed over carries that build's program across the exec (`Handover.program`, `platform::own_program`, written only by `handover::exec`, the one exec path of window, host and picker) and goes back to it when the home is still older after a failure (`build::go_back`); a fresh start that fails says why and exits, the home as it was. A failure is noted in the home (`run/Upgrade.refused`: build, attempts, time, reason) and `-upgrade-check` of that build answers not ready for 1/5/15/60 minutes after the 1st/2nd/3rd/later failure, so the windows of the build before do not each fail the same way; a person's start always tries; success removes the note. A not-ready verdict is asked again a minute later (`build::ASK_AGAIN`), only a ready one is kept per installed file. `-upgrade-check` also prints `format N`. The engine refuses a home still in an older format. A release that changes stored data adds one step and bumps `upgrade::VERSION`. The barrier passes over ownership locks carried across an exec by processes of the new build: each such process notes the locks it carries (`run/session_<id>.carried`: its pid and start, `platform::process_started`) before it queues for the upgrade and removes the notes after (`upgrade::Carrying`) — waiting on them deadlocked every host that took 0.2.8 over at once. A window whose host is away while the home is upgraded waits for it as long as the upgrade lock is held (`driver::find_host_through_upgrade`, `upgrade::underway`) instead of starting a host that would queue behind the same upgrade and then closing.

## Contracts moved verbatim from AGENTS.md (binding)

These rules lived in `AGENTS.md`/`CLAUDE.md` until that file outgrew its opening-context budget (`scripts/check_git_policy.py`). The text below is unchanged; `AGENTS.md` points here.

### Classifier policy

- Classifier policy (`CLASSIFIER.md`) is the owner's editable file: normal tools may write/rewrite/delete it, still through Gate/jail/write_guard (owner, 2026-10-13). The first admitted work pins global/project/missing/invalid rules in any mode; pre-work status previews disk without pinning. Only explicit idle `classifier.reload` replaces a live snapshot; failed reload retains it, and a new host reads disk again. Classifier input is the exact proposed arguments plus original user work/steering/clarification and explicit text/image attachments — never file/script/manifest contents collected from command paths. `classifier.context_tools` independently selects the last three settled matching call inputs, not outputs or authorization. One text evidence budget (`classifier.max_evidence_size`, default256KiB) includes formatting; proposed arguments stay complete, image bytes do not consume it but obey the selected model's media/payload limits. Review authority is global CLASSIFIER.md > project CLASSIFIER.md > explicit sourced user restrictions in their work/standing scope; no conflict allows, and missing context/unsupported media alone is not a denial. Human-permission calls skip classifier and sanitizer per call (Gate facts only), never the other gates. Sanitizer is enabled by default for eligible classifier review (explicit false opts out), uses Auxiliary and an append-only source/work/hash ledger, reuses settled extraction/raw fallback across calls/restart, and falls back custom→distinct active→original sources without sanitizing its own output. No user-message-count key. Provider failures/invalid partitions remain failed evaluations. Every outside value is quoted/label-safe. Work source/final metadata on immutable rows survives failure/restart; new work after a final has a new source. Every API request separately obeys its provider's complete serialized-body payload cap; main/classifier/compact quotas are never summed. Compaction keeps original user instructions/steers whole before summarizing in budgeted quoted batches; assistant/tool-result excerpts count32000 Unicode chars/row and call arguments2000chars/call with identity retained. Defaults recent5/output32768/fallback200000; effective model output clamps the instruction length too. Compaction uses auxiliary route/model budget, runtime fallback when larger, and a retry question on needed failures; no stops Failed, cancel stops Cancelled. Sidebar diffs publish after each settled mutation and refresh tracked files only via `session/file_changes.rs` (default1s, `checkpoint.refresh_interval`); content is authority. Stops/resume/upgrade own the watcher lifecycle.

### Composer

- Composer: an empty input stays one editable row; multiline input grows to at most 11 editable rows, clamped to preserve conversation space on short terminals. Keyboard, mouse and soft wrap use the same plain editor projection and glyph-width measure (tabs shown as four spaces, control/escape sequences never styles; combining suffixes, variation selectors and ZWJ sequences never split between visual rows), translating display positions back to original UTF-8 source bytes. A message leaves the composer at its Enter: one sent while the host has an edit unconfirmed waits in `composition.submits` (the composer as it stood at its Enter, the host brought to exactly that, sent in order once it holds it), and what is typed meanwhile is the next message's — never glued on (`a_message_is_what_was_there_at_its_enter_whatever_the_host_still_confirms`). A late prompt ACK never rolls the authoritative composer revision back; the renderer publishes row hit geometry, so a click places the caret on that visual row and blank space goes to its end. Mouse presses/drags/releases reach the shared click/selection handler even in Settings and MCP input; wheel events retain their surface-specific routing. Mouse drags copy on release and clear their highlight, never moving the input caret or selecting for replacement; plain clicks still place the caret, keyboard selection still edits, and masked secrets never auto-copy. Renderer-owned content spans (carried with Sink through caches/cuts/overlays) govern both highlight and extraction: no UI borders, timeline gutters or adjacent pane; literal source glyphs survive. Resize or replacement of selected content cancels the gesture without a release-click. Settings/navigation tolerate one-cell release jitter; real drags select rather than activating controls. The session picker publishes its own rendered card hits: a click selects, a click on the selected card resumes. Sent user messages are display-folded to the same four visual rows and `lines cut` footer as tool previews; clicking the box opens/refolds it. Their complete content is stored and sent unchanged, with fold state only in CLI blocks and cache fingerprints.

### Transcript scroll

- Transcript scroll (`draw.rs` `chat_top`): the reader is held by an `Anchor` — the first non-blank row's text plus its `Place` (drawn group, row inside it, the group's height, the width): the same row of the same group when the width held (the text searched near it), the same fraction of the group after a reflow (side panel toggled, terminal resized), never a bare row number. An overlay that replaces the chat (`/help`, `/logs`, `/context`, `/undo`, …) scrolls in its own `PanelView` (`ui/panel_view.rs`) and never touches the chat's place. `/undo` and `/context` start at the top and keep semantic item/source-line anchors through split/resize; only navigation/preview requests reveal the chosen rendered range, so page/wheel reads never snap back. `/undo` draws one file per row, turn/time in fixed columns, hanging path continuations, counts against the right edge and the Rune `›` chevron; `/context` separates tools/messages and their metadata with headings and rules; source text is plain, indented four columns, without a decorative left gutter. Renderer-owned ranges govern scrolling; stale panel/preview responses never reopen or re-arm a superseded choice. Scrolled away from the newest row, the centred hint `Press Ctrl+↓ Jump to latest` is laid over the chat's last row, covering only its own columns and a blank each side (`ansi::overlay`; `JUMP_HINT`; hidden under an overlay, a card, a form or the slash palette; a click on it jumps); `Key::CtrlDown` jumps from anywhere. A wheel notch moves `ui.scroll_lines` (default 2) rows whatever the pace (no acceleration — owner); with Ctrl or Alt held `FAST_WHEEL` (3×) as far through the same glide (`wheel_scroll_at`); terminals may keep these combinations for themselves (Konsole zooms on Ctrl+wheel unless its profile says otherwise; Qt turns Alt+wheel sideways), so they are extras, never the only way.

### Main-chat previews

- Main-chat previews (`Cli/src/ui/viewport.rs`) and permission readers are different surfaces. Non-open tool previews start at minimal height (command only when no output yet) and grow as content arrives up to at most four visual content lines, cutting the remaining suffix below with `… N lines cut. Click to open all`. The fold marker is always AFTER the entire preview (head preview), never between a tool notice and its output or at the top; it is a display fold, not deletion. Explicit Open All click expands to full output. `↑/↓ N rows above/below · wheel here` belongs only to genuinely scrollable readers such as permissions and the sidebar. Counts come from rendered visual lines. Terminal input previews fill one visual row when closed, during streaming/running/finished alike: explicit `↵` marks each source newline, and glyph-safe `…` appears only for a suffix beyond the width. These are display marks, never shell separators; Rune drag-copy restores original newlines and omits added ellipses via renderer-owned source pieces. Open All restores original multiline source/indentation. A cut command says only that it was cut (`…`); it never contributes a count to the output footer, and the footer's `N lines cut` counts only unseen output rows — a one-line output under a multiline command therefore has no footer at all (owner, 2026-10-31: a fold count beside the command's own ellipsis read as if output had been hidden). Streaming title/prompt/highlight use engine-supplied ToolArgs shell metadata; ToolShell confirms the pinned execution shell and survives reconnect. Terminal output box does not reserve blank padding: before output arrives it has no divider and no output rows; once output arrives it grows line-by-line up to 4 lines, retaining only the live rows actually occupied so erase frames do not flicker. Permission/question readers retain their separate larger height allowance, pinned controls and scroll geometry. Ask-user custom answer caret renders after the final character without right-margin truncation.

### Foreground terminal output

- Foreground terminal output (`Engine/src/terminal_screen.rs`): AVT interprets the PTY stream incrementally in a private grid shared by the CLI and the final model-visible result, including backspace, CR, cursor movement, erase and alternate-screen operations. The screen gets the grid's rows; the model gets the command's lines — a row the grid wrapped (AVT's own wrap mark, never guessed from width) is joined back, so a narrow box never splits a line the model reads (`terminal_screen.rs` `Row`). Only plain screen rows leave the adapter; command escapes cannot resize the grid, set the outer window title, or access the clipboard. `ToolOutput` carries the actual PTY rows/cols; a live session keeps complete geometry segments (bounded by `terminal.max_output_size`) until the result replaces them, never an arbitrary raw-byte tail that loses cursor state. The CLI sizes the PTY for its terminal box at session start and on layout changes, and output revisions invalidate same-length spinner redraws in the transcript cache. The non-open box starts command-only, grows monotonically with output up to four rows, and retains live occupied row slots during erase frames to avoid height flicker. Output is head-previewed, and `lines cut` appears below. Ask→Allow/Full use identical preview geometry. A background log uses that same grid: final scrollback plus the live screen are saved in one file, with `background_log::Position` separating its immutable prefix from the replaced suffix. All publications share the cap/error path; detected waits sync before wake. the wake reads the saved file from where the model was last given it, never appending another in-memory copy. Handover carries the prefix position and `Shown`; format24 preserves old log/journal bytes.
