# Rune architecture contracts

Read together with `AGENTS.md` / `CLAUDE.md`. This file retains the detailed cross-layer contracts; the root instructions carry the mandatory gates and workflow.

## Text input contract

The CLI's `ui/editing.rs` is the single canonical keymap/transaction implementation for composer, Questions custom answers, Settings/search (secrets included), MCP fields and picker search/rename. Display and hit-testing still use `ui/editor.rs` and `ansi` glyph projection. The frontend sends only the resulting composer text/cursor through the existing command path; selection, desired column, undo/redo and the bounded kill ring are private transient field state, never protocol/history/credential data. A same-text ACK preserves local edit history; a different authoritative text invalidates it rather than undoing another window's work. Closing or submitting a field, recalling history, or switching sessions also clears it; merely moving focus never shares one field's history with another. All edit entry points, including paste, yank and case expansion, obey the surface's limits atomically. Secret input keeps masked geometry and no automatic clipboard copy.

One key chord owns each editing action, with no Readline alias table or discarded modifiers: Ctrl+A/E logical-line boundaries, Home/End whole-buffer boundaries, Ctrl+K forward kill (at newline remove that newline, at EOF no-op), Ctrl+U backward line kill, Ctrl+Left/Right word motion, Ctrl+W/Alt+D word kills, Ctrl+Y/Alt+Y yank/cycle, Ctrl+_/Alt+R undo/redo, Alt+X/W transpose glyph/word, Alt+U/L/V word case; Shift arrows and Ctrl+Shift Left/Right extend source selection. A field-local mouse drag selects editable source, while transcript selection remains clipboard copy. Composer Up/Down move visible rows with a sticky desired column, falling back to buffer start/end at the top/bottom row, and repeating at the start/end recalls prompt history (owner exception, 2026-10-16); PageUp/Down also navigate its per-session history. Soft-wrap boundary affinity is field-local and width-bound: a caret at a shared source offset keeps the visual row it moved or clicked to; paint and motion use that same side. PageUp/Down recall composer history directly; only an explicit navigation index identifies recalled input, never text equality. Questions Up/Down leave custom text only at buffer start/end after visible-row motion; Shift motion stays selection. Alt+Left/Right alone switches questions from any form control, preserving each answer; Tab remains form focus, never a hidden mode change. Application shortcuts are not repurposed as Readline actions. Unsupported prefix sequences and terminal reports must never become destructive edits or user prose. Tests cover unique chords/actions, every surface's real dispatcher, Unicode/control/paste geometry, cross-window history invalidation and PTY submitted answers.

## Screen navigation contract

The visible slash palette owns its choice/confirm keys before a reader behind it, never while the composer is hidden by a form. Settings/picker own their whole surface; otherwise the foreground panel gets first refusal before a pending form gets its own keys, with unmatched text still editable in the visible footer. No navigation changes a hidden composer or mode. The wheel uses renderer-owned row and column geometry: Settings, palette, sidebar, form document or foreground reader; spent directions remain on their surface. `Modifiers::wheel_multiplier` applies the same Ctrl/Alt 3× factor to each surface's ordinary notch (item, row or document page), never keyboard focus transitions or a second surface; controls that do not scroll remain unchanged. Lists with a chevron (Logs, Undo/Redo) move selection and reveal together, centred like Settings and clamped at the document ends; plain readers such as Context scroll rows without inventing selection. Logs page keys can read long open details. One panel replaces another through `ui/navigation.rs`; leaving/replacing it invalidates pending presentation replies (including capability/picker loads), never acknowledgements of operations. A late response cannot reopen an older screen. Escape dismisses a visible palette first, otherwise the current screen; Settings ancestry and explicit Undo/Redo diff-to-list navigation remain local.

## Frame pacing (measured)

How a frame is paced follows from measurements of real terminals (`ui/draw.rs` `Screen`, CLAUDE.md CLI UI): Konsole 25.04 answers no DEC 2026, draws 10 ms after data arrives or 40 ms into a stream, and takes 35–80 ms for a 169×50 page with its event loop shut. Sending it one frame at a time, then `Screen::QUIET` with nothing new, then a lone `ESC [ 5 n` it answers only once done drawing (`Screen::next_at`), was measured under gdb in a real Konsole: torn repaints 8/736 → 0/711, about 1–1.5 frames a second fewer.

## Architecture — single gates that must not be bypassed

```
frontend ─Command─► engine ─► session ─► provider
         ◄─Event──             ├─► perm   (Gate: the only path that executes a tool)
                              ├─► tools  (write_guard: the only path that writes files)
                              │    ├─► jail     (engine tool paths; lexical + symlink)
                              │    └─► sandbox  (Landlock / Seatbelt / restricted token; the child process)
                              ├─► checkpoint    (pre-write undo)
                              └─► store         (SQLite + per-session JSONL)
```

- `perm::Gate`, `ToolCtx::write_guard`, `net` = three single gates; do not add parallel paths. The enforcer is the engine, not the model/prompt/server; the prompt **deliberately** does not mention permission limits (reason in `session/prompt.rs`).
- `panic.rs`: a panic inside a tool = 1 failed call, not a dead engine; the workspace is **deliberately not** `panic="abort"`.
- Platform (`Engine/src/platform/`, 2026-10-16): the only code that speaks to the operating system, for the whole workspace — the CLI included, which has no `libc` dependency at all. `platform/mod.rs` is the contract (every item and its meaning, the same on every OS); `platform/unix/` answers what Linux and macOS share (POSIX: files, console, stdio, sockets, pty, process, home, time), `platform/linux/` and `platform/macos/` what only one of them has (reached from `unix/` as `os::` — Landlock, seccomp and `/proc`; Seatbelt, `sysctl` and libproc), `platform/windows/` all of Windows (2026-10-17: ConPTY, `CreateProcess(AsUser)W` in job objects, restricted tokens and ACL entries, named pipes, the console's VT modes), one file per capability. Where an OS cannot give a fact the contract says so by a value — `INPUT_WAIT_DETECTION`, `REPLACES_IN_PLACE` — never by a stub that pretends; policy tables are chosen by `platform::OS` at run time. The contract is shaped by meaning, not by Unix: a process is started by the platform — `spawn_on_terminal` (its own session, the terminal its own), `spawn_piped` (an MCP server over pipes, stopped when dropped), `spawn_detached` (a session host outliving its window) — from a `Launch` (program, arguments, a command-line tail written as is for `cmd /S /C` on Windows, folder, environment) and a `Placement` (its confinement, Unix sockets allowed or refused, its tree's mark) rather than given `pre_exec` closures; what crosses an `exec` is `Handed` (its JSON the bare descriptor number every earlier build wrote, so the handover record is unchanged); a socket peer is `peer_is_same_user`, never a uid; a file is a `FileIdentity`, never `(dev, ino)` at a call site; a path is spelt by `platform::canonical` (every link resolved; on Windows without `\\?\` where it reads the same — cmd cannot run in a verbatim folder), never `canonicalize` outside the platform; a file that must be this user's alone is made so as it is created (`open_private` with `Private::{Lock, New, Append}`: `0600`, or an owner-only ACL), never tightened after; the terminal is `ConsoleMode` + `Typed::Keep`/`Discard` (TCSADRAIN/TCSAFLUSH). `boundary::os_specific_code_lives_only_in_platform` fails the gate on `libc::`, `windows_sys::`, `std::os::`, `extern "C"`, an OS `cfg`, a `/proc` read or a `canonicalize` anywhere else — engine, CLI, unit and integration tests alike, with no exceptions list; what a test must observe of the OS (a process's state or parent, a link, a descriptor kept across exec, a resize signal) is `platform::fixture`, compiled only for tests (`test-support` feature). Security policy that names an OS's paths (`sandbox::Policy` reads/writes, `perm::denylist`, `perm::reach::Forbidden`) stays with its owner: decisions, not mechanisms — one table per OS in the owner's module, chosen by `platform::OS` at run time and never by a `cfg`, so every table is compiled and unit-tested on every machine. The shell a command runs in is read in its own language (`shell.rs` `ShellKind` by the program's name: a POSIX shell takes `-c`; PowerShell `-NoLogo -NoProfile -EncodedCommand` with a UTF-8 preamble and an exit-code epilogue, so no quoting can change the command; cmd `/D /S /C "<command>"` as a tail written as is), and the risk rules and path reach read it the same way (`perm::windows_shells`, `denylist::classify_for`, `reach::in_command_for`); `terminal.shell = auto` is bash else `/bin/sh`, on Windows PowerShell 7 on `PATH`, else Windows PowerShell, else cmd (owner, 2026-10-17). Paths compare without case where the OS does (`jail::starts_with_folded`: Windows, macOS), and a Windows name the OS would read as something else — a device, a stream, a trailing dot or space — is refused (`platform::windows_name_trouble`). A skill package's files are read with no link anywhere on the way, the package root's own path included (`LinkFreeDir`, component by component with `O_NOFOLLOW`; never `openat2`, which kernels before 5.6 and container profiles refuse — 0.6.7 failed every skill there). The Rune home is spelt as the filesystem names it wherever it is chosen (`store::Db::home_dir` → `jail::canonical_spelling`, `$RUNE_HOME` and `$HOME` alike), and an empty or relative `$HOME` is no home.
- Locks (`Engine/src/lock.rs`): every cross-process hold — a session's lease and host lock, the configuration, the vault, drafts, memory, help in use, an upgrade — is `lock::exclusive`/`lock::shared` with `Wait::No` (held elsewhere = `Io` of kind `WouldBlock`) or `Wait::Yes` (the kernel's wait, woken by the release, at most `lock::PATIENCE` = 10 s, then `TimedOut`): std's whole-file locks, `flock` on Linux — the lock earlier builds took, so builds side by side during a handover exclude each other.
- Retry lives only in `retry/`: one loop around the whole attempt (open + stream), `retry.max_attempts` retries (any number) on the owner's curve — retry k waits `retry.initial_delay` × k (default 3 s) and a wait past `retry.max_delay` (default 1 m) starts the series again from the step, so the defaults wait 3/6/9/12/15 s; no floor or ceiling of the code's own — every error except user cancel, `Incomplete`, `ContextOverflow` (the turn compacts instead) and Rune's own `Invalid`/`NotFound`. The server's `Retry-After` is never read (owner: Rune's retry is not steered by the provider's) — a key a server refused rests on the same curve (out of credit: `retry.credit_cooldown`). A stream on which nothing arrives for `network.stream_idle_timeout` (default 5 m; hot-reloaded, it reaches a request already waiting; any byte — thinking, a keep-alive — starts it again) is abandoned as `Error::Stalled` and retried like any other error (`net/Interrupt.rs`, the transport's one wait). A failure after output was shown emits `Chunk::Reset` → `Event::StreamReset` (the frontend drops the partial) before the repeat. Tools never run inside the loop. `net` never retries by itself. Every secret is registered in `net/redact` — it must never appear in errors/logs.
- Structured stream failures are protocol data: a top-level `error`, JSON `type`/`event = error` or `response.failed`, and SSE `event: error` are provider failures even on HTTP 200. Never infer an error from `choices[].delta.content`, an `[Error]` prefix, or text quoting JSON. Both dialects pass failures through the one `retry/` loop; the SSE reader keeps event names separately from data, reset per dispatch.
- Classifier rules (`perm/Classifier.rs`) are a session snapshot: the global/project file contents and their combined digest, a missing-policy state, or a failed read, pinned when the session's first work starts whatever the mode (session admission calls `classifier::pin_config`; status before work previews disk without pinning). Reading Settings, mode switches and edits/deletion on disk do not silently adopt new policy. The policy file is the owner's and any tool may write, rewrite or delete it — no policy-specific write prohibition; the ordinary Gate/jail/write_guard remain (owner, 2026-10-13); a new session or host reads what disk holds then. Explicit `classifier.reload` holds session admission, reads and validates a replacement, then swaps it and clears tickets atomically; a failed reload retains the old snapshot and reports failure. A restarted/upgraded host reads current disk policy again (owner, 2026-10-12). Session status is derived from the same snapshot used to judge actions; draft status previews disk. Neither policy reload nor status rewrites main-model history or its prompt prefix.
- Settings has one editable home per global key (regression in `ui/settings.rs`): Runtime = retry and shared network request timing; Tools = terminal command wait, question and permission timeout plus tool limits; Appearance = theme/layout, with no mock conversation preview implementation. `ui/editor.rs` supplies plain display-to-source geometry to Composer, Questions, Settings/search and MCP; renderer-owned rows and the same glyph measures govern caret clicks/wrap/scroll, not independently reconstructed text. Secret field geometry uses bullets mapped to source bytes, never plaintext display.
- What the model is told is append-only. The system prompt (`session/prompt.rs` `SYSTEM`) is a static text — no live value, no workspace/OS/date/config; it explains every Rune tag (`frame::TAGS`) and status and how to work. Tool declarations are byte-static built-ins (`Registry::declared` memoizes them) — no configured value in them; every limit is enforced live by the engine (hot-reloaded config) and named in the tool result when it bites. Everything live reaches the model as `Role::Context` rows (`session/context.rs`; user-role on the wire, never read as the user's words): the opening context (memory index, AGENTS.md, skill catalogue, `<status>`), written as a turn starts when the model holds none — once per session — and placed before that turn's request (`reading_order`); a `<status_update>` row at the next API call — mid-turn too — when a value in `session/status.rs` changed; a `<context_update>` row at the next API call — mid-turn too — when a file-born part of the opening context (memory index, `AGENTS.md`, skill list) changed since the model was handed it (fingerprints kept in each row's `ContextMeta.sources` and in the compaction record; what the session's own tools wrote is not news, `context::written`); the memory-index notice at the next API call after the index was written; a `<system_notice>` row after the person undid or redid a file (`context::restored`). A draft holds no context row: the opening context is written as its first turn starts. Every context row is announced to every window as it is told (`Event::Context`), but the CLI draws none of them in the conversation, live or replayed (owner: the transcript is the person's and the model's words) — `/context` and `/logs` show them; only a background task's `<system_notification>` is drawn, since it is why the model speaks unasked. A row is never edited; compaction is the only sanctioned rewrite and stores the context snapshot in its record, so the request after it is summary + fresh context. Untrusted text inside a Rune block goes through `frame::block`, which neutralizes Rune tag names. Every stored attachment — prompt or tool result — is sealed when stored (`Attachment::seal`: the file's SHA-256, size and modification time, and the text budget in force; nothing is copied — owner, 2026-10-11). Each request settles it (`Attachment::settle`, `media::Fingerprints`, verifying the full content SHA independently of size/time, and `Attachment::read_verified` checks the actual bytes at rendering too): while the file still has that hash it is read from its path; once it changed or is gone, what was sent is read from a copy in the session's `attachments/` named by the hash — made only then, from the project's undo store when Rune's own write captured it (`Checkpoints::original`), or the copy an earlier build kept — and with no copy the attachment says `status="changed"` or `status="not_found"`, the same words on every request. New bytes are never rendered under an old message, so the cached prefix holds; the model is told once per path and state by a `<context_update>` (`context::attachment_changes`, `sources` key `attachment:<path>` = `changed`|`removed`, judged on the newest attachment of the path). A row an earlier build wrote keeps its hash under the stored key `snapshot` and reads its path while unchanged. History media evictions are permanent (`media.jsonl`).
- What a failed call is told and recorded follows from its `Error` variant, never from its wording: the classifier fails as `Error::Classifier(Supervision)` — `Refused` (status `denied`, code `classifier_denied`) or `Undecided { code }` (status `service_unavailable`, its own `classifier_*` code) — and `call.rs` `Finished::of` matches variants only. Preflight preserves the `Error` variant, not a string; the audit row records `status` and `code`, and replay restores both. Rows before the additive code field keep unknown causes unknown: never infer them from wording or rewrite old JSONL. The classifier judges a call as one action (`Ticket.decision`; tool arguments are atomic, so there is no per-item batch) and its refusal is that call's own result, so a judged call reports its tool's own detail and status like any other.
- Classifier evidence is assembled by `perm/classifier_context.rs`, `classifier_input.rs` and `classifier_media.rs`: exact proposed tool arguments, all original user sources/steering and validated clarification with durable work scope, and user-attached text/images. There is no message-count key. No command token causes a file/manifest read. Work identity is immutable `Message.work` metadata (`source`, `finished`), carried across failures/steers and reconstructed after host restart; a request after a completed final opens new work. `classifier.context_tools` selects the last three settled matching call inputs independently of review exclusions; historical tool outputs and agent prose are not user authorization. The combined final formatted text fits `classifier.max_evidence_size` (default256KiB); proposed arguments are never shortened, context keeps bounded ends. Binary images are separate media with selected model/dialect/payload rules, unsupported types are notices, never invented content. Labels/paths/control characters cannot introduce a new Rune label. Refusal authority is global CLASSIFIER.md > project CLASSIFIER.md > explicit original-user restrictions in their work/standing scope; lower sources never relax higher rules, policy silence does not erase additional user restrictions, and missing context alone allows unless an applicable rule expressly requires it. Every denial reason names its source and immediate conflict; model rationale never substitutes for actual authorization. Invalid or unavailable evaluations are errors, never allows. The decision tool schema is byte-stable, with exact-current-ID partition enforced by engine decode; prompt caching reuses the stable policy prefix, not decisions or a changing suffix. Tickets bind policy/mode/args and selected context; changed context is reevaluated before execution.
- Compaction failure (owner, 2026-10-13): the summary is sized for the model that runs it (`auxiliary::route`, shared with the job itself); when `compact.model` cannot hold the history and the active model holds more, the active model summarises (log `compact_fallback`). A compaction a turn needs that still fails is logged and asked about with a clarification form (`compact::ask_retry`, the `questions_request` every frontend answers; a one-shot run answers `Unavailable`): yes retries and the turn goes on, anything else stops the turn with the failure's own error and the next message compacts again. A compaction asked for while a response's calls wait that fails is asked for again at the next request boundary. A manual compaction (`session.compact`) that fails is logged only. Compact excerpts count Unicode characters: assistant/tool-result body default32000 per row; historical tool arguments default2000 per call, with every call ID/name/target kept visible. Original user instructions/steering and valid clarification are never excerpted before summarizing: quoted fragments are processed in budgeted batches, with prior generated summary carried forward. Attachment media stays separate from body excerpts and is not silently loaded into the summarizer. Byte evidence/payload budgets remain separate; marker/indent overhead is budgeted. Default recent retention is5 (group/budget safety may keep fewer), output32768 tokens bounded by the selected route, unknown usable-context fallback200000. Transcript role labels are Rune-owned column-zero rows, message bodies indented, so external tool output cannot forge a USER row. Small models receive only their actual remaining input room, never a 2000-token minimum above their budget.
- Auxiliary jobs (title, classifier, sanitizer, compaction) run only through `session/Auxiliary.rs`: they honour `Chunk::Reset` like the turn, and a job offering exactly one tool is forced to call it (`RequestControl::force_tool`; the providers never name a tool themselves). A title is the `set_title` call's argument, not prose; every stored title passes `store::sessions::title_of` (one line, printable, no control or invisible characters), because a title is model output steered by untrusted text and is never fed back to a model.
- Provider payload enforcement (`provider/live.rs::shape`) measures the entire rendered JSON body against that request's selected provider `max_payload_size`, including system/policy/tools/evidence/media base64 and syntax. Each main, classifier, title or compact request is independent; no shared cumulative byte allowance and no metadata-only decision. Oversized bodies fail before the single `net` send path.
- Tool output is the tool's own output; Rune's word about it is one leading `<tool_notice>`, written and read only through `tools/notice.rs`: tidy data (the `manage_process` report) is a block of `Key: value` lines. `manage_process` has exactly one report envelope: `Additional information` appears only for truncation or incomplete reading/saving, or to say Rune no longer tracks the process, while `Capture` remains a separate conditional capture-failure field; raw output and head/tail previews stay outside it. Capture retains the information separately until the envelope is chosen, never by parsing command output as notices. Everything else is ONE line holding one sentence with no label colon (`<tool_notice>Exit code 101</tool_notice>`). No `Status:` line — the status is only a label in the audit row (`toolcalls.jsonl`, event `detail`), never in the payload. Only where it says something: an empty successful output or a failed command carries its exit code; a failure carries its own per-kind sentence (denied, cancelled, timed out, output cut, repeated…), whose meaning lives in the system prompt (`<messages_from_rune>`; a contract test keeps every tag and field the engine writes explained, and the reverse). A command becomes a background task one way (`tools/terminal.rs` `to_background`): launched with `run_in_background`; still running at `terminal.command_timeout` — then it moves to the background with the notice alone as the call's result (`Moved to the background as`; its output, from the start, is `manage_process`'s first report — owner, 2026-10-11), never killed (stopped only when it cannot move: no log); or seen blocked reading its terminal — waiting for typed input — once it has printed nothing for `terminal.input_wait_delay` (asked once per quiet spell, re-armed by new output or typed input; never a timer that reports), when it moves at once with the notice and its output so far (`Waiting for input in the background as`; `Its input is hidden (what is typed is not shown)` for an entry the terminal does not echo — nothing more: whether to ask the person is the model's call). Whether a program waits is a fact read by `platform::Pty::input_wait` (Linux: the terminal's termios — `ECHO` off = hidden, `ICANON` = a line read — and `/proc/<pid>/syscall` of each process of the terminal's foreground group: blocked in a read of this terminal or `/dev/tty`; a process this user may not inspect, e.g. set-user-ID `sudo`, counts only when the terminal is set for a hidden line), never parsed from output; `platform::INPUT_WAIT_DETECTION` says how much a platform can tell (`Every` on Linux; `HiddenOnly` on macOS — a terminal set for a hidden line while every thread of the foreground group waits, XNU giving no wait channel; `Never` on Windows — no public interface tells that a console program waits to read) — what it cannot tell moves only at the timeout, and on those systems alone the notices say a quiet command may be waiting for input or really still running (owner, 2026-10-17; Linux's words unchanged). A background task's monitor asks the same question in the same way and, when a wait begins, wakes the session once (`<system_notification>Background task … is waiting for input. … Call manage_process with process_id: … for what it asks, then answer it with terminal_send_input.`), unless a result already told the model (the moving `terminal_use`, a `manage_process` report) or no window watches (held, then told by `deliver_pending`). Every wait of one task is told in the same words, so a wait's wake is taken back by identity, never by matching its text later (that took the next wait's wake, word for word the same, with it): `SessionWakeNotifier::withdraw` removes it from the session's queue while unread (`SessionState::withdraw_queued`) the moment its wait is over (typed into, gone, the task ended or was stopped) or a report said it, sending and taking back under one lock (`background::Waits`). `terminal_send_input` (`tools/send_input.rs`: `process_id`, `text`, `submit` = `auto`|`enter`|`none`, blank = `auto`) types into a running task's terminal — through the gate as a command (`runs_commands`, its text classified by the deny-list: the process may be a shell) — with Enter after the text when `submit` says so or, on `auto`, when the terminal reads a line (`Pty::line_mode`; Enter when unknown; empty text with no Enter is refused, since nothing would be typed), and returns at once with one sentence (`notice::typed`: `Typed …`, never the text itself — it may be a password). It neither waits nor reports (owner, 2026-10-11): typing is its one job, reading the process is `manage_process`'s, and what the process does next — its next wait or its end — arrives as a `<system_notification>`, as the sentence says. Waiting has one contract (session 570: a tool that could block beside a prompt that said "do not wait" made the model poll, wait in slices and end its turn, by turns): the model does other work, then ends its turn, and the notification starts the next; `manage_process` never waits (no `block`/timeout field) and a report holds only what the model was not given (`background::Reported`: the log offset and the screen as reported — the rows of that screen are not sent again, whether it grew in place or scrolled into the log, and a redrawn screen is sent from its first changed row, `monitoring::without_seen_rows`; that a report holds only what is new is said once, in the declaration, never as a field beside `Output log`). A report's values carry no label colon of their own (`Input: hidden (what is typed is not shown)`, `Capture: Output capture failed (…)`, a Lost task's `Additional information`). A kill the model makes is told by its own result: `BackgroundTaskManager::stop` marks the end Killed and told in the one step that ends it, so the monitor that sees the process go wakes nobody (the bug of 2026-10-11: "finished: Killed" after a kill), and a wait it had is over, its wake taken back; a kill that finds its task ended answers with that task's report. Only a result the model reads tells it anything (`tools::Reader`, on `ToolCtx`): a call a frontend runs directly (`tool.invoke`, `call::run_direct`) is `Reader::Person` — its result joins no history the model reads, so its kill, its reports and a wait its command met change nothing of what the model was told (`Reported`, answered wakes, told waits) and still reach the model by wakes. The registry keeps the first end as the journal does (`update_status` never replaces an end), and every end — Lost included — is a wake. That promise survives the process that made it: a session's `background.jsonl` records each task's start, end and whether the model was told (`background::BackgroundRecord`), and a session host (`Engine::settle_background`, after it took over what the build before handed on — never a window's own engine) tells the model, once, of every task it started and never heard the end of — one that ended while no window was open, or one lost to a crash or a power cut. The registry a host opens a session with is the journal's projection (`settle_unreported`): every task it records, with the last state it saw — a task that ended keeps that end (Completed with its exit code stays Completed after any restart), one whose end nobody saw is `Lost`, recorded once with why (`LostReason`: `Restart` — another boot; `RuneStopped` — this boot, and what is left of it is stopped: its group only when the leader is the very process its start's `Identity` (boot + `platform::process_started`) names, its tree by mark; `Unknown` — a start an earlier build wrote without an identity, or an exit status that could not be read); the model is told each end it was never told, once. States are one capitalised word on every surface (`background::state_of`: `Running`, `Waiting for input`, `Completed`, `Failed (exit code N)`, `Killed`, `Lost`); a Lost task's PID is `unknown` unless Rune stopped it in this boot. `manage_process` on an id with a log but no journal record reports `Process: Lost`, `PID: unknown`, why, and what the log kept (an id is `background::is_task_id`, never a path). Every process a command starts carries its tree's random mark (`platform::TREE_VAR`, `new_tree_mark`), kept with the task and in its start record; a stop (kill, cancel, timeout, output limit, capture failure, a session let go) is `platform::terminate_tree`: the group and every live process carrying the mark — so what left the group (`setsid`, a daemon's double fork) stops too; a process that clears its environment or runs as another user is out of reach (Linux reads `/proc/<pid>/environ`, macOS a process's environment through `KERN_PROCARGS2`; Windows holds the tree in a job object named by the mark, which a child cannot leave unless allowed to break away). A background log grows on disk, streamed, up to `terminal.max_background_log_size` (default 100 MiB), then the task is stopped; `terminal.max_output_size` (8 MiB) bounds only what a foreground command prints while it runs, held in memory. A monitor reads its limits live (`Watch` holds the shared configuration, never a snapshot). A background log is read through the same AVT grid as a foreground command (`terminal_screen::Screen::log`): a row is written once it has scrolled off the top (`Screen::drain`, as a terminal's scrollback), the rows still on the grid — which a program may yet redraw, e.g. Gradle's status block — are the task's `tail`, shown after the log, kept exactly (`terminal_screen::Shown`) and resumed by the build that takes the task over (`Screen::resume`), and written to the log when the task ends; the same text `manage_process` reads. - Session: draft registry + cross-process flock/lease; detached host via a socket in `~/.rune/run/`, bound and reached only through `platform::LocalListener::bind`/`LocalStream::connect` (a home of any length — a path past the socket address's bytes is spelt through `/proc/self/fd` on Linux, through a short link in the user's private temporary folder on macOS); a connection is heard only after it proves itself (`access.rs`, the socket's single gate — Landlock does not mediate `connect()` and a socket's mode comes from the umask): the peer runs as this user (`LocalStream::peer_is_same_user` — the kernel's word: `SO_PEERCRED` on Linux, `getpeereid` on macOS; on Windows a named pipe met through a meeting file at the socket's path, the client known by impersonating it — the same user, and no less elevated than the host; a host's end lets a window go only once it has read what it was sent, `FlushFileBuffers` then disconnect within a bounded linger, since a plain disconnect throws unread bytes away — `HostUpgrading` among them) and its first line is a `session.hello` carrying the host's key — random, issued per host into a 0600 `run/session_<id>.key` before it binds, withdrawn on drop under the ownership lock; a confined command cannot read `run/` unless the person granted it, and — the kernel's own fence, whatever it can read — reaches no socket without local services (above); whoever can do both was let by the person, and could already rewrite the home. Until admitted a connection is in no fan-out, counts as no window and reaches no engine (`session_ipc.rs` `admit` → `serve`); a window of the build before keys gets, for its `session.resume`, only this host's protocol and version (`resumed: false`) — the mismatch is what makes that build hand itself over to the installed one at once, carrying its input, so no window is ever relaunched — and "newer build" for any other command (`answer_older_window`, for the previous release only); a window finding no key file sends its hello without one, which such a host answers as an unknown command (`Answer::Older`); **one** place executes a tool call (`session/call.rs`) — the model path and the frontend path are identical. A session runs one piece of work at a time — a turn, a compaction, a restore, a direct tool call, a background task's wake — through one admission (`SessionState::admit`/`begin_guarded`/`settle`, `session/mod.rs`) — every user message (`prompt` and `prompt.steer` alike, `engine.rs`) is admitted there: it begins a turn or waits for the work in progress, never refused for the session being busy, so no frontend decides by what it believes about busy (a window that had seen `Done` before the turn let go was refused and put the message back; `a_prompt_while_the_session_is_busy_is_admitted_never_refused`); a window draws each message it sent as waiting until the engine's `TurnStart` for it and never sends one again (the engine holds the queue), and a refused one leaves the screen with its words back in the composer ahead of anything typed since: the busy flag and the queue of messages for the work in progress live under one lock, so a steer or a wake that arrives while busy is taken at the work's next decision point or when it settles (`turn.rs` `settle` → `Continue`/`Released`; `run_queued` for work that is not a turn), never stored for nobody; a compaction asked for while busy runs at the next request boundary. Consecutive calls of one response run together only when their tool is `Tool::concurrent` (reads and nothing else: `inspect_file`, `find_files`, `search_text`, `web_search`, `web_fetch`), the classifier does not judge them and the Gate's own `verdict` allows them without a question (`call::concurrent`, the same functions the run goes through); `turn.rs` `together`/`run_together` runs them all at once — no width of its own (owner, 2026-10-11: `tools.max_parallel` is retired; `tools.max_actions_per_response` bounds a response) — and records every result in the model's order. `find_files` and `search_text` walk every file of the project — an ignore file or a hidden name hides nothing (owner, 2026-10-11: `scan.respect_ignore` and `scan.hidden` are retired) — save `.git` and `.rune`, which no walk enters (`walk::Options::configured`); how far a walk goes (`scan.max_entries`, `scan.max_depth`) and the per-line regex fuse (`scan.regex_steps`) are the person's, in Settings → Tools → FILE SCAN. A call running alongside others never asks: `Gate::authorize_silently` fails it closed if its verdict turned into a question — no second card, no widened jail while others read.
- Layout (`Project.rs`): everything Rune keeps about a project lives in one folder, `~/.rune/projects/<name>/` — `project.json` (its identity: the path), `memory/` (+ `memory.lock` beside it), `objects/`, `sessions/<id>/`, `scratch/<id>/`. `<name>` is the path with every non-alphanumeric character turned into `-`; a `-<hash8>` suffix only when that name already belongs to another path or the path is too long. One root: the store's (`JsonlStore::root`, the database's directory) holds the project folders and `run/`. `project_key` stays an internal identity (drafts, `run/<key>.gen`, MCP vault entries). `storage.list`/`storage.prune` (`store/storage.rs`) prune only a folder whose path the filesystem reports missing and that no session holds open — rows first, then the project's MCP logins in the vault (`mcp::credential_prefix`), folder and identity last. What a tool writes to disk for a session (long output, a background log) goes in that session's `tools_result/` (`ToolCtx::results`), never a path of the tool's own making. `scratch/<id>/` is the session's private `TMPDIR` (the sandbox grants it, never `/tmp`); it goes when the session closes — whichever process lets go last (`Engine::shutdown`, a host releasing a session, `Driver::shutdown` after the host's locks are gone) removes exactly that folder once the session's lease and host lock are both free (`engine.rs` `remove_scratch_if_closed`: renamed under the locks, deleted after; a host carrying its lock across an upgrade's `exec` keeps it); what a crash left is swept at start after `storage.scratch_lifetime`. `drafts.json` that does not read is set aside into `backups/Drafts-<time>.json` and a fresh registry started, so a damaged file never stops a window (owner, 2026-10-16). `drafts.json` keeps no composition that holds nothing (`Composer::holds_nothing`): an emptied one drops its entry and moves the project's `cleared` order, so a new window is not handed older words; every write folds an empty entry an older build's window wrote across a live upgrade (`Registry::drop_empty`).
- Store: JSONL = source of truth, append-only (one write per record, newline included; a file a crash left without a final newline is closed off before the next record, so damage costs only the record it cut; `session.jsonl` is parsed incrementally by `JsonlStore::read_messages_shared`, a replaced or shorter file is re-read in full; the turn reads it once per round via `Db::history_shared` and copies only the rows it sends). A session's folder holds `meta.json` (its index — no central index), `toolcalls.jsonl`, `background.jsonl`, `sanitizer.jsonl`, `tasks.json`, `logs.jsonl`, `media.jsonl`, `composer.json`, `capabilities.json`, `attachments/`, `tools_result/`; the small JSON state files a person may open (`drafts.json`, `composer.json`, `capabilities.json`) are written indented (`jsonl::pretty`). - Rune memory: index-only injection (`MEMORY.md`, in the opening context) from the project folder's `memory/`; no memory tools by design. - Checkpoint: content-addressed blobs in the project folder's `objects/` (engine home, not inside the project); every write is captured first, one manifest per turn, never trimmed on its own (owner, 2026-10-11: `checkpoint.keep_turns` is retired; only `checkpoint.prune` with an explicit `keep` trims, and a deleted session's blobs are collected). Undo is per file (owner): the session's file ledger (`session_files`: each path's state before the session first touched it — blob and mode —, kept past pruning, and when the session last changed it) is the undo list (`checkpoint.files`, the same rows and `+N −N` as the side panel's FILES CHANGED) and what is put back (`checkpoint.restore { file }`: the file as it was before the session, or no file when the session created it); `checkpoint.diff { file }` shows that state against the file now. The CLI `/undo` panel (`Cli/src/ui/undo.rs`) is the only CLI entry point — no `-undo`/`-checkpoint`, no file-undo shortcut and no checkpoint hint on the composer; Ctrl+U edits input only: one header, one key line and a warning that every later change is lost; rows `N  time  path  +N −N  [undo]` in first-touch order, the cursor kept mid-screen (`Document::centre`, as Settings › Models); Alt+S opens the file's diff (old | new line numbers, `checkpoint.diff.context` lines around each change, a rule between hunks); Enter starts a `undo::CONFIRM` (3 s) countdown in the state line and only a second Enter inside it restores (one after it starts it again); an undone file stays listed at `+0 −0`. Redo is undo the other way (owner): an undo keeps what it overwrote (A) in the ledger (`redo_blob`/`redo_mode`/`redo_at`, kept past pruning, the latest undo's); `/redo` (`checkpoint.redos`, `checkpoint.redo_diff { file }`, `checkpoint.redo { file }`; the same panel, `undo::Side::Redo`) lists only files that were undone, measures the file now against A, puts A back whatever became of the file since, and is used up — the file leaves the list until its next undo. The diff (`checkpoint/diff.rs`) never refuses: Myers within `checkpoint.diff.max_cells`, past it patience anchors (lines unique on both sides) and Myers per piece, the whole bounded by `diff::TOTAL_WORK` budgets — every count shown is a real diff's; only a blob gone from `objects/` (`Change::Missing`) falls back to the write ledger's tally and cannot be undone.
- Realtime file counts have one publisher (`session/file_changes.rs`). Settled mutating calls (model and frontend), restore/redo and SessionView refresh actual diffs through Bus; a bounded portable watcher samples only ledger paths at `checkpoint.refresh_interval` (FIELDS default 1s, 100ms–1m), including external editor/Bash changes. Timestamps or sums of write titles are never freshness proof. Content-hashed diff tallies avoid repeated diff computation; the watcher neither acquires admission, resets cancel, resumes tasks nor triggers inference. A write barrier excludes local file-tool/restore writes in flight, never a long terminal/MCP call; failures preserve the last known tally and log once per changed reason. Last-window suspension, deletion, reap and shutdown stop/join the watcher; a resume starts it again. - Upgrade (`Engine/src/upgrade/`, `Cli/src/build.rs`): every release is taken over live. A running host/window that sees a new build installed asks it `rune -upgrade-check` (config, database and layout checked without changes) and, when idle, `exec`s it in place; the window carries its input, cursor and panel. Where a process cannot become another program (`platform::REPLACES_IN_PLACE` false: Windows) nothing `exec`s: a window says once that a newer build is installed and is used the next time Rune is opened, and hosts and the picker keep the build they run (owner, 2026-10-17). A window still on the build before starts any session host from the build installed now (`Driver::launcher` → `build::installed`, never its own replaced `… (deleted)` file), and never `exec`s while it holds a draft's first message not yet handed to its host (`App::handover_waits`). What is typed does not hold a window back — input, cursor and attachments travel in the handover record — only hands still typing do, until they rest `HANDOVER_IDLE` (3 s; not under a protocol skew); before the `exec` the key reader is parked between two reads (`input::park`) and the window goes only when every key it read was applied (`input::sent` = `App::keys_applied`; the reader counts per taker — the picker, then the window it opens, each from zero, and keys read while no taker has it are held for the next, `input::take_reader`/`release`/`HELD`; a numbered OSC reply arriving after the colour probe gave up is dropped, never typed, `input::decode_osc`), and the terminal is set with TCSADRAIN, never TCSAFLUSH, on handover and on entry, so a key typed meanwhile waits in the terminal for the next build. The picker parks the same way. The session picker (`rune -session`) does the same while its list is idle (`picker.rs` `release_to_activate`: `build::replaced` + `build::ready`, then `exec` with its own arguments, back on the list). The version a window shows (footer, banner) is the build it runs, `runeengine::VERSION` — never its host's, which is kept apart as `App::host_version` for this rule: a window also follows a host that runs a later release (one installed in place, under the same file) — never an earlier one, which takes the installed build over by itself (`build::later`; a window that followed any difference exec'd itself in a loop until its host moved). The first process of the new build upgrades the home before anything reads it: `version.json` names the home's format, each `upgrade/vN.rs` step runs once (configuration → layout → database schema), under `run/Upgrade.lock`, after every session lease and host lock of the previous build is free. Nothing is deleted — what the new format drops is moved into `backups/UpgradeN-<time>/` with a `plan.json` of every change; a failed step is undone in reverse — the version marker included (`Plan.marker`, saved before the step starts) —, a crash part way is undone by the next start (`run/Upgrade.active`). The goal of a release is that every person reaches it, on any machine (owner, 2026-10-16): before changing anything the upgrade checks it may write and has room (`preflight`, `platform::free_space`); one damaged item (a session file that does not read, a torn line, a broken pending promotion, a drafts registry, a format-1 folder still holding something) is left as it was or set aside, noted in `Plan.skipped` and told (`Progress::LeftAsItWas`), never a reason to stop — session record files change only through `rewrite_sessions`/`rewrite_lines`; an I/O failure keeps its kind and path so the person is told what to do (`build::failure`). Rune never replaces the installed build — whoever installed it owns that file, and no `rune.prev` exists on a person's machine: a process another build handed over carries that build's program across the exec (`Handover.program`, `platform::own_program`, written only by `handover::exec`, the one exec path of window, host and picker) and goes back to it when the home is still older after a failure (`build::go_back`); a fresh start that fails says why and exits, the home as it was. A failure is noted in the home (`run/Upgrade.refused`: build, attempts, time, reason) and `-upgrade-check` of that build answers not ready for 1/5/15/60 minutes after the 1st/2nd/3rd/later failure, so the windows of the build before do not each fail the same way; a person's start always tries; success removes the note. A not-ready verdict is asked again a minute later (`build::ASK_AGAIN`), only a ready one is kept per installed file. `-upgrade-check` also prints `format N`. The engine refuses a home still in an older format. A release that changes stored data adds one step and bumps `upgrade::VERSION`. The barrier passes over ownership locks carried across an exec by processes of the new build: each such process notes the locks it carries (`run/session_<id>.carried`: its pid and start, `platform::process_started`) before it queues for the upgrade and removes the notes after (`upgrade::Carrying`) — waiting on them deadlocked every host that took 0.2.8 over at once. A window whose host is away while the home is upgraded waits for it as long as the upgrade lock is held (`driver::find_host_through_upgrade`, `upgrade::underway`) instead of starting a host that would queue behind the same upgrade and then closing.
