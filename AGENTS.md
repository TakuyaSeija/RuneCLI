# Rune — development instructions

> Deploying the site (`/Studio/`) or the `rune` CLI release: read `docs/deploy.md` first, then run `DeployStudio.sh` at the project root (every sub-command takes `--dry-run`).

Rust workspace for **Rune**, a local coding agent for Linux, macOS (11+) and Windows (10 1809+/11), x64 and arm64. Two crates: `Engine/` (`runeengine` — agent loop, tools, permissions, jail, sandbox, checkpoint, store) and `Cli/` (`runecli` — the `rune` binary: interactive UI, `-p` one-shot, `-host` JSON stdio). The GUI (RuneStudio/Flutter) has no code yet.

## Commands

```bash
cargo build --workspace
cargo test  --workspace --no-fail-fast
cargo test  -p runeengine <filter>               # one module/test (CLI: -p runecli)
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt   --all -- --check
scripts/build_linux_release.sh [gnu|musl]        # release build (Docker) → background
```

- Tests keep their temporary folders under `target/test-tmp/` (`.cargo/config.toml` forces `TMPDIR` there), never in `/tmp` (tmpfs) nor in the scratch of a Rune session that runs them; an in-memory `Db` and the engine test `Harness` remove their own folder. `rm -rf target/test-tmp` clears what is left. CLI unit tests read no `rune.toml` (`ui::settings_home`): they run on the `FIELDS` defaults, never on the owner's live settings.
- `RUNE_HOME` (default `~/.rune/`) = the owner's live data. Tests and manual binary runs must use `RUNE_HOME=$(mktemp -d)` / an isolated HOME (pattern of the Python fixtures `Cli/tests/Rune*.py`).
- Known parallel flakes: `store::drafts` (Engine) and the CLI `session_ipc` child-host tests (`child_client_keeps_parent_host_owned_after_new`, `child_session_receives_new_ack_and_multi_hop_handover_succeeds`: a 1 s child-socket wait) — rerun alone, then the whole gate, before calling it a regression. Under load (≳ 8, e.g. after a release build) the `agent.rs` 10 s-wait tests fail at random — `configure_model_while_turn_runs_never_deadlocks_and_cancel_stops_instantly`, `prompt_steer_while_busy_is_accepted_and_injected_into_next_step`, `three_rapid_steers_become_three_separate_user_messages`, `mode_can_be_switched_while_a_turn_is_running`, and `a_hidden_entry_is_said_to_be_hidden_and_can_be_answered` (60 s deadline): measured, they fail only under load.
- Runtime config: `rune -config check|explain`. Per-project data: `rune -storage [list|prune]`.

## Release & install (binding)

Every future product release MUST build and publish for all target platforms without exception (Linux x86_64/arm64 gnu/musl, macOS Apple Silicon/Intel, Windows x64/arm64 via CI; owner, 2026-11-05). Builds come from GitHub Actions, never from hand-made per-platform builds: commit, push `crossplatform` with `[ci macos]`, wait for every job of `studio-ci.yml` green, then publish with `Ops/Release/PublishRune.sh --ci-run <run-id>`, which refuses a run that is not `completed success` of HEAD. A local Linux build is only an early test. Every release's changelog entry is layered, never a bare bullet list (owner, 2026-11-06): a title, then a paragraph saying what changed and why, then short to-the-point detail lines, in all ten languages. On the website/downloads, any older archive version lacking a build on a platform must explicitly display that platform as unavailable, never omitting it silently. After a product change is complete and verified, release and install automatically without waiting for another owner request, unless the owner explicitly says not to (owner, 2026-10-29). The safety gates and defer conditions below still apply; audit-only, docs-only and local experiments do not create a product release. This does not authorize Git commit/push, remote publication or Website deployment.  Build release and install to `~/.local/bin/rune`. Installers never edit a shell profile (docs/website.md); on Linux and macOS they never edit PATH either: a piped child cannot change its parent's PATH, so to make `rune` run at once they place or link the binary in a folder already on PATH, print the one line that finishes the job when none can be written, and add the folder to the calling shell when the script is sourced; on Windows they set the running window's PATH and the user PATH (registry), leaving no setup step:

**Proof before a version (owner, 2026-11-08: absolute).** No version is raised, no release is built, no binary is installed and nothing is published while any platform is unproven: green local gate → push `crossplatform` `[ci macos]` with the version untouched → every job of `studio-ci.yml` green → bump the version → build, smoke, dry-run, back up, install → push the bump and publish only from that run's green result. A failed job never raises the version; the same unreleased version is fixed and pushed again. The numbered steps, with every command and its reasoning, are in `docs/deploy.md`.

Skip or defer (state it in the memo) when: the build is not green; it is not a release (local experiment, docs only); the owner declines; or live work makes it safer to wait for an idle handover.

## Upgrade safety (binding)

Every release must reach every person on any machine (owner, 2026-10-16): no `rune.prev`, install path or this-machine assumptions. Contracts: `docs/architecture.md`.

- Nothing optional (official help, drafts, credentials) may stop a start, upgrade check or turn; Rune never replaces the installed binary. Only no room/no write access stops an upgrade, found by `preflight` before any change.
- A stored-shape change = one `upgrade/vN.rs` step + `VERSION` bump; one damaged item never fails a step (`rewrite_sessions`, `Plan::skip`); a changed `FIELDS` default goes in `defaults.rs` `PAST`. Test the step, `every_older_format_reaches_this_build`, a damaged item, and the release dry run.
- A test that may fail an upgrade runs a copied binary, isolated `HOME`/`RUNE_HOME`, never `~/.local/bin/rune`.

## Versioning (binding)

`X.Y.Z`, all plain integers without leading zeros (SemVer/Cargo reject `0.01.0`). While the project is not yet stable, or without an owner instruction, `X` is always 0.

- `Y` 0–99, `Z` 0–9. Routine release: `Z+1`; if `Z=9` → `Y+1`, `Z=0`.
- `X+1` only on owner instruction; `Y` and `Z` reset to 0.
- `Y=99` and `Z=9` → stop and ask the owner.

## Architecture — binding overview

Detailed contracts: **read `docs/architecture.md` before changing engine, protocol, provider, store, sandbox, session, or UI interactions**. Those rules remain binding; this split prevents the opening instruction injection from truncating the owner's rules.

- Frontend uses only `proto::Command` / `Event` through the driver. `perm::Gate` is the sole tool-execution gate; `ToolCtx::write_guard` the sole file-write gate; `net` the sole network gate. Never add a bypass.
- Model, frontend, MCP, file, and network inputs are untrusted. Enforce at the engine, not by prompt; preserve jail, sandbox, checkpoints and secret redaction. A tool panic is a failed call, not a dead engine.
- Built-in instruction ownership and footer status/confirmation lifetimes follow `docs/architecture.md` (§ Model instruction ownership, § Footer status and confirmation lifetime); keep one behavioral owner per request, preserve structural validation, and never let retry hide an armed confirmation.
- Prompt/tool declarations are static. Live values are append-only context rows. Store history as immutable rows. An attachment is its path plus the SHA-256 it had when sent (owner, 2026-10-11): read from its path while it still matches; once it changed or is gone, what was sent is read from a copy made only then (from the undo store when Rune changed it), else the attachment says `changed`/`not_found` — never new bytes under an old message — and the model is told by a `<context_update>`. JSONL is conversation/audit truth, SQLite stores registries and ledgers.
- Failures are classified by `Error` variant, never wording. Live/view/replay must agree on status and codes. Write titles are `+N` of the body only (overwrite too); Patch titles measure replaced/replacement text. Sidebar counts are the actual session-start snapshot diff, never sums of titles. Spend = the engine's total (`Event::Spend`): an unpriced request takes its model's price now; rows never rewritten (owner, 2026-10-23).
- Retry lives only in `retry/`, retaining the owner's configured curve and exclusions; no provider-directed delay or extra retry loop. Auxiliary work goes through `session/Auxiliary.rs`.
- Model output repetition (owner, 2026-11-02): a response that repeats one exact unit (1–64 bytes, at least 4 KiB and 16 repeats; only-whitespace units 16 KiB) at the end of its answer or reasoning is stopped while it streams, by a byte rule with no ceiling on token length — base64 data URIs, minified lines, hashes, Markdown rules, table separators and indented blocks are never mistaken for a loop. The person then keeps the text written before the repeat or discards the message, asked through the existing clarification form (`questions_request`), never a new dialog; unanswered, dismissed or cancelled keeps it, only an explicit `Discard` throws it away. Does not authorize a tool, a new dialog or a config key: thresholds stay in `limits::REPETITION_*`. Contracts: `docs/architecture.md`.
- One session admission and one event bus. Preserve multi-window parity, idle upgrade handover, queued input and background tasks; never kill a live host to install a release. A released backlog precedes any newer prompt; a run's unanswered rows/accounting/Done precede the next admission. Manual compaction has explicit live/view status and stop controls even between turns (`Event::Compacting`); no network wait holds admission's terminal critical section.
- Commands: the model chooses launch intent by task dependencies, not name categories; the engine owns runtime waits/handoff (`docs/architecture.md`). Background tasks (`session/BackgroundTask.rs`): the journal-projected registry keeps seen ends, otherwise `Lost` with reason; states capitalised (`state_of`); stops reach the marked tree (`platform::terminate_tree`); typed-input waits are platform facts (`Pty::input_wait`, `INPUT_WAIT_DETECTION`: Linux every, macOS hidden, Windows none), answered with `process_control` (`do` = `type`|`stop`, `process_id` without `all`; it never reports and never waits); every wait and every end arrives as one `<system_notification>` that carries Rune's line (task, how it ended, PID, run time, log path) and, after it in a `<process_output>` block (data, defused), the output the model was not given yet, bounded by `process_control.max_output_chars` (a wake taken back unread gives it to the next); a stop is told only by its result. Last window leaving stops runtime at once, tasks after `host.idle_lifetime`.
- Context truth (owner, 2026-10-29): never convert bytes/characters/thinking/media into token counts or a learned admission ratio. Provider-reported usage or a real context rejection drives automatic compaction; unknown stays unknown. Source batching/catalogues use explicit byte limits, never guessed model capacity. Keep payload/evidence/media security limits and history unchanged; see `docs/architecture.md` Context counts. Terminal guidance explains why polling/shell wait loops for already-backgrounded work waste time/cost and may themselves background; prefer independent work or ending the turn for the notification, without banning purposeful checks or actual-work loops.
- Provider differences are settings/capability data, not model-name branches. Cache prices are accounting, not capability. Preserve prefix shape, tool IDs/content/media, and each dialect's legal cache carrier. 9router thinking: OpenAI door: one field, `reasoning_effort` (a level, or `none`), no `reasoning` object (Claude routes redact thinking); Anthropic door (`dialect_for`: `owned_by` `cc`; owner, 2026-10-23): same choices, Claude's controls (`router_thinking`). Thinking shows text words or Anthropic-reported tokens, never estimates. 9router offers `ROUTER_LEVELS` (minimal…max) less `ROUTER_REFUSED` (`claude-budget` minimal), or the person's Alt+C options; explicit `thinkingCanDisable:false` excludes Minimal even from retained/manual options and Off requests Low (`thinking_off_requests_low`), never a guessed minimum. True/unknown Off requests disabled (`none` on OpenAI); Off is a request, not a zero-thinking guarantee—router executors may change it (owner, 2026-10-25). No model-name tables. `ProviderConfig::settle_thinking` settles every entry; Alt+C/session/payload share effective `effort_choices`, stored overrides not erased. Starts Off unless chosen otherwise (`ModelInfo::starts_thinking`, new session/model/provider switch); mandatory/default only if person set; On without a level is "Route default" (`ROUTE_DEFAULT`), nothing sent.
- Web search/fetch are served through accounts (`[services]`, `settings/services.rs`; one vendor per file in `web/`), sharing the vault ring and eligible model endpoint by account name. Connections manages access only (endpoint/URL, adapter identity, keys), with no Quick Actions, Configuration, route/service switches or payload controls (owner, 2026-10-15). An account may be saved without tool providers (`service.account`), with URL/security validation but no request or claim it works. Tools › Web search/fetch › Provider owns Add/Delete and one exact choice (`service.select`): a direct account or `9router:provider`, like model choices. Add route is an empty field only — no catalog candidates, examples, prefill or default additions. Added providers and explicit selections must each pass one real request through net; adding only keeps, selecting atomically writes the exact pin and service route with revision checks. Deleting a provider keeps its account/keys; choose another before deleting the one in use. `web_search.provider`/`web_fetch.provider` pin account or account:route; missing pin target is unavailable, never another. Unset search = first switched on; unset fetch = built-in reader (a third-party reader is never automatic). Kept gateway routes survive being switched off, are capped by `services::MAX_ROUTES`, and use the vendor spelling its door accepts (`exa`, never `exa/search`); format19 resolves old gateway pins once, no runtime legacy fallback. Provider timeout belongs to Runtime, fallback/catalog controls to Models. Vendor output stays as read — snippet markup reduced to words (`web/text.rs`), returned HTML read by the built-in parser. Tool schemas remain query+count / url(+cookies); who serves is a status value; every actual tool step is a session log line; a key never travels over plain http to another machine.
- Credentials: disk is truth; an unopenable store is `Unavailable` + cause — never no keys, never overwritten, no new `master.key` beside it; all surfaces show `Secrets::key_state`.
- MCP tools remain behind the static discovery/proxy path; their external schemas are exact and are never relaxed by built-in default normalization.
- Official help: `.rune/skills/rune-settings-guide/`, offline bundled, user-facing only; no internals. Compiled copy is authority and owns its name (install/update refuse it; any other copy of that name is shadowed), repair never fatal, personal skills untouched. Changes require help+coverage updates; full contract: `docs/architecture.md` Product help.
- Website (`Website/`): public product information only — no private deployment paths, ports, hosts, credentials or defense internals; reading works without JS, assets are local, illustrations show only what the CLI draws and say what is simulated, and motion appears only where it fits (no AI-slop effects). **Read `docs/website.md` before changing anything under `Website/`**: it holds the binding hero, install, replay, reading-page, docs, license, light and test contracts (owner decisions through 2026-10-28).
- Configuration is hot-reloaded; every default belongs to `FIELDS`. Layout/schema/config changes require an ordered upgrade step and version bump; no runtime legacy fallback.
- `rune.toml` holds the person's choices only — a save never writes a default, "Use default" removes the key so the newest `FIELDS` default holds, and an upgrade changes a default only where the file holds a default, never a choice (owner, 2026-10-14; format 16 `upgrade/defaults.rs` tells them apart by meaning). Every process follows the file: `configuration::Shared` re-reads it at most every `FOLLOW_EVERY`, every engine command checks it first, and whatever must happen on a change keys on `Shared::generation`, never on which reader noticed — a draft window, a windowless host and `-host` included.
- Settings: Appearance owns themes/layout (no conversation preview code); Runtime owns retry/shared network timing; tool-specific command/question/permission timeouts live only in Tools. Editable global keys have one UI home. All text fields consume renderer-published source geometry (`ui/editor.rs`), including Questions, Settings/search and MCP.
- Classifier policy: the binding contract (CLASSIFIER.md ownership, pinning/reload, evidence, sanitizer, compaction and sidebar-diff rules) lives verbatim in `docs/architecture.md` § Classifier policy (moved for the opening-context budget); read it before changing those areas.

## Conventions

- No emoji/emoticons outside test data, including production comments/messages; escapes are no loophole. Technical UI glyphs and Unicode input handling remain allowed (owner, 2026-10-16).
- A new dependency only if almost all of it is used and writing it ourselves would be worse. Glob/regex/walk/pty/landlock/SSE stay in-tree; the list of legitimate crates is in `Cargo.toml`.
- One file per tool; `tools/mod.rs` holds only trait/registry/ctx/helpers. Tool schema: `action` is **always the first field**, with atomic top-level arguments (not arrays — streaming reason in the doc comment). Some providers decode strictly and send **every declared property, optional or not** (every `cx/*` model, measured 2026-10-10: unused text fields arrive as `""`, a blank, or an invented value), so no two optional fields may exclude each other, every optional field needs a value meaning "the default", and a tool reads optional text through `field_given_str` (empty or blank = not given). Built-in validation canonicalizes optional blank text against its static schema (nested items too), never required payloads or external MCP schemas; provider declarations contain no empty/blank enum sentinel. One identical call made or failed again in a turn is compared without its `action` sentence (`turn.rs` `same_call`): tool results stay pure; loop warnings are sent via `<system_notice>` on Cadence B (3, 6, 9, 12, 18, 24, ...) instructing how to break the loop (stop polling & await notification for bg tasks, switch approach or ask for others) — always guidance to the model, never a brake (owner, 2026-11-01). `patch_file` requires `old_str` to occur exactly once; `create_file` overwrites an existing file (owner decision; the result says `Overwrote`); a path a tool cannot find is `Error::NotFound` — a structured not-executed notice naming the path and the next step, not an I/O failure; misspelled tool names go through the alias map.
- Some modules are deliberately PascalCase via `#[path]` (check: `grep -rn '#\[path' Engine/src Cli/src`); new files are snake_case unless they join a PascalCase group.
- `//!` doc comments explain **why**, not what.
- Configuration hot-reloads via arc-swap (`settings/Configuration.rs`); never snapshot by value. Every default lives in `FIELDS` — no in-code fallback; a key the code reads but `FIELDS` lacks (or reads as the wrong kind) is a hard failure in test/debug builds and returns the `FIELDS` default plus one session log line in release (scanner test `every_literal_key_the_code_reads_is_a_field_of_the_right_kind`); a retired key is an unknown key (the engine refuses to start), never silently mapped. A provider is the adapter its `api` names (`compatible` when none), never guessed.
- No legacy compatibility at runtime: an older layout, config or schema is upgraded once by an ordered step in `upgrade/` (removable once no install can still be at that format), never read by a fallback.
- CLI UI: one `Msg` channel = the single place state changes (no cross-thread locks); frames are built whole and sent as per-line diffs — a row beside the side panel in two pieces split at its seam (`draw::beside`/`seam`), and a page move done by the terminal's scroll when that sends fewer bytes, the panel's displaced cells included (`Shift`, `repaint_cost`) — beside the panel only on a terminal that answered DEC 2026 (synchronized output; `Screen::ask`), since one that draws mid-frame (Konsole) shows the panel jump; colour codes are sent only when the style changes (`ui/sgr.rs`); a changed row is sent from its first changed cell, and only to its last when its width held (`write_changed`, `ansi::cells`) — a row a terminal may count otherwise (a joined emoji, an accent written apart) or holding a link is sent whole from its first column; a frame is followed by `ESC [ 5 n`; on a terminal that shows frames whole (DEC 2026) at most two frames are on their way unanswered (`Screen::AHEAD`), and on one that draws on its own clock (Konsole 25.04; see Frame pacing) one frame at a time, then `Screen::QUIET` (12 ms) with nothing new, then a lone `ESC [ 5 n` answered only once it is done drawing, then the next frame (`Screen::next_at`) — so a slow terminal never queues more and never draws half a frame, and the wheel glides only on a terminal that draws frames whole (DEC 2026) at a measured pace of 30 frames a second or better — a status answer says a frame was read, not drawn, and Konsole/GNOME drew the glide as stutter — elsewhere a notch jumps (`Screen::keeps_up`, `App::terminal_keeps_up`); the terminal's answers are `Key::Terminal` reports, never keys; width is measured with `ansi::width` (columns, not chars).
- Composer, transcript scroll, main-chat previews and foreground terminal output: their binding contracts live verbatim in `docs/architecture.md` (§ Composer, § Transcript scroll, § Main-chat previews, § Foreground terminal output); read them before changing those areas.
- Manual shell (owner, 2026-10-27): only an explicit frontend `shell.submit` / `draft.shell_promote` authorizes a leading `!` script, never model text, tool arguments or history. Enter runs the entire multiline script with full access for that call alone through Gate (classifier/sanitizer skipped; no automatic elevation or session-mode/grant change). Queue behind the active turn in order; share input/result as data, then AI responds after settle/background handoff. Stable receipts prevent reconnect repeats; recovery never replays commands. A terminal refusal may offer the manual option, never retry itself. Response prose alone uses bright neutral ink, intermediate included; wrapped action rows keep identical ink. Click a reference to show its whole destination: HTTP(S) opens only on explicit Open/Enter through the platform browser door, files are copy-only, drag never opens; no viewer or file-association execution.
- Input: `ui/editing.rs` owns keymaps; `ui/editor.rs` geometry; `ui/navigation.rs` screen ownership. Contracts and regressions: `docs/architecture.md`.
- Permission UI (`Cli/src/ui/permission.rs`): every permission is one bounded scrollable document with pinned answer buttons. The wheel is row-scoped, including spent directions; Up/Down and PageUp/PageDown move an overflowing card, while the transcript above stays wheel-readable. Terminal permission contains the shell command only and uses the engine-recorded shell title/prompt (Bash, zsh, PowerShell, Cmd, etc.; unknown history says Terminal); only engine-confirmed reach/service/unconfined facts add a compact warning in that title, never a duplicate list of path candidates. The reach scanner recognises inline awk programs as programs (not paths rooted at `/`), while still scanning script files, input operands and redirections; the jail/sandbox remain the execution boundary. Create/patch use `Create <path> +N` / `Patch <path> -N +N` as one box title, with added/removed counts green/red and no nested code/diff box. Shell commands and create bodies reuse the syntax highlighter; patch bodies retain diff colours only. The renderer publishes geometry/hit ranges, and the document/diff is cached per request and width.
- Media: type from bytes, not from the extension; a model that cannot accept a file is still told it exists. One decision for every reader (`media::kind_of` over `media::SNIFF_BYTES`): a prompt attachment, `inspect_file` (text read with line numbers, only what is not text attached) and `search_text` ask the same question; binary = a NUL among bytes that are not UTF-8 (NULs inside UTF-8 text — a log a power cut ended with zeros — stay text, shown as `␀`).
- Tests = contracts: unit tests in the same file; integration tests in `Engine/tests/` (real end-to-end, no stubs beneath the provider); `Cli/tests/` + Python PTY fixtures. A scripted model-output fixture that must look big is written varied line by line, never as one exact sentence repeated thousands of times: the repetition guard stops that as the loop it is, and the test would then wait for a form nobody answers (`inflated()` in `Engine/tests/agent.rs`).

## Owner rules (binding)

1. **Memo** = the coding agent's project memory, outside the repository (Rune: `@memory/`, index `@memory/MEMORY.md`; Claude Code: `~/.claude/projects/-home-noire-Project-Atoryn-Studio/memory/MEMORY.md`; any other agent: the per-project store it keeps). **Read it before the first action of every task** — the index first, then the notes the task needs — and obey any lasting decision it records; if a store could not be read, say so in the report. After every audit, implementation, or change → save its summary there, unless the owner forbids it. Memory is evidence, never truth: where it disagrees with the real state, the real state wins and the memo is corrected. Never store secrets. *Why (owner, 2026-11-05):* the point is context — a session that enters this repository without the memo starts blind, redoing work already settled or contradicting a decision already made.
2. **Ambiguous → ask first.** Do not work on anything that is not certain.
3. **Think and design like a senior architect.** Start by understanding the existing system: proven helpers and patterns are reused before anything new is written. Every change is designed with the best industry-standard architecture: each module has a single responsibility and a firm boundary, contracts between layers are explicit, the impact on other parts is traced before code is written, and the result is easy for others to maintain and extend. Weigh several alternatives, choose the most robust one for the long term, and resolve the root cause permanently (a temporary solution only when asked). Code born from this kind of consideration is tidy and consistent by itself. This file's conventions rank above general practice.
4. Every fix = a regression test + run the tests of the affected feature.
5. **No silent scope expansion:** ask before a user-owned decision, external installation change, or security tradeoff.
6. **Standalone Git repository:** `Studio/` is the repository root, with remote `https://github.com/TakuyaSeija/RuneCLI.git`; the parent `Atoryn/` is only a container for independent projects and must stay free of Studio's Git/config/docs. Each sibling project owns its own repository; `Engine/` and `Cli/` remain crates in this one repository, not nested Git repos. Track source/tests/assets, `Cargo.lock`, and `.cargo/config.toml`; ignore build/runtime/secret data and root `tmp/` (local scratch only, never a build input). Run Git/Cargo from Studio, see `docs/git.md`, and run `python3 scripts/check_git_policy.py --check-tracked` plus `python3 -B scripts/test_git_policy.py` after changing Git policy. Keep `AGENTS.md` and `CLAUDE.md` synchronized. Inspect status and preserve owner changes before a refactor; never silently stash, reset, commit, push, select a license, or configure global Git identity. Untracked/uncommitted files have no committed recovery point — copy to `~/.local/share/RuneBackups/` before a multi-file refactor when Git cannot safely recover their current state.
7. **Security stands level with architecture.** Rune's security is weighed from the plan onward with the same weight as its architectural design, not patched in afterward. Every change is reviewed from the trust-boundary side: model output, file contents, MCP/network responses, and frontend input are treated as untrusted until they pass the single gates (`perm::Gate`, `write_guard`, `net`); access is granted at the minimum needed; failure ends in denial, not in relaxation; secrets stay in the vault and `net/redact`. If a change widens the attack surface or weakens a layer of defense, say so and ask the owner before continuing (rule 2).
8. **Cross-platform from the design stage.** Rune targets Linux, Windows, and macOS across many versions, so its behavior must not depend on the user's system configuration (e.g. `fstab`, mount points, shell profiles, distro directory layout, system tools assumed to be installed). The engine brings everything it needs; OS capabilities are detected at runtime, not assumed from a distro name or version. OS-specific code is confined behind `platform/` (gate: `platform::boundary`) with the same contract on every OS, and the core guarantees (`perm::Gate`, `write_guard`, jail) stay held by the engine so they are identical on every OS; kernel mechanisms such as Landlock are a per-platform layer on top of them.
9. **CLAUDE.md is a living document.** Update this file together with the change when a rule or piece of project information is permanent and long-lived, e.g. a workspace that had no Git now uses it; the owner explicitly asks for this file to change; or a thorough refactor of a feature makes the description here no longer true. Its content is always the current state, not a change history. Anything temporary, task-specific, or fast-changing goes in the memo only (rule 1).
10. **Speak the owner's language.** Every reply, question, and report to the owner is written in the language the owner is using, and follows when the owner switches. If a message mixes languages (e.g. a question in one language about pasted text in another), use the language of the owner's own words.
11. **Many problems, one approved plan.** When a task holds several problems and some already have a settled solution while others do not (the agent has found no good answer, or the owner has not decided), fix none of them yet. Report the whole set: what is solved, what is open and why, and the options for the open ones; then wait for the owner's explicit approval. Never decide alone to apply the solved part first, to choose an answer for an open item, or to skip, defer, or reorder any item (rule 2, rule 5). A general go-ahead ("proceed", "kerjakan") does not cover an item without an agreed solution; only the owner naming that item does. After approval, the set is applied as one planned change, built and checked one step at a time, each fix with its regression test (rule 4). Why: a partial fix changes the ground the remaining solutions stand on, so the rest is redone or contradicts it.

## Known pitfalls

- The engine reads project instructions from the workspace's **`AGENTS.md`** (`AGENTS_FILE` in `session/prompt.rs`), not from this CLAUDE.md.
- Live `~/.rune/`: do not delete `rune.db-wal`/`-shm` and `*.lock` (active, not junk); tests must not mutate it; never read or print `master.key` and `secrets.vault`.
- macOS/Windows: verified only by CI on real machines (`studio-ci.yml`; on `crossplatform` macOS needs `[ci macos]` in the commit), type-checked by `scripts/xcheck.sh <triple> clippy …`; Wine is a smoke test, never a reason for a weaker design (owner, 2026-10-17). Windows ACL grants are recorded before written (`rune -sandbox reset`), never on Windows's own folders.
