# Rune — development instructions

Rust workspace for **Rune**, a local coding agent for Linux, macOS (11+) and Windows (10 1809+/11), x64 and arm64. Two crates: `Engine/` (`runeengine` — agent loop, tools, permissions, jail, sandbox, checkpoint, store) and `Cli/` (`runecli` — the `rune` binary: interactive UI, `-p` one-shot, `-host` JSON stdio). The GUI (RuneStudio/Flutter) has no code yet.

## Commands

```bash
cargo build --workspace
cargo test  --workspace --no-fail-fast
cargo test  -p runeengine <filter>               # one module/test (CLI: -p runecli)
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt   --all -- --check
cargo build --release -p runecli                 # may take minutes → background; notification on completion
```

- Tests keep their temporary folders under `target/test-tmp/` (`.cargo/config.toml` forces `TMPDIR` there), never in `/tmp` (tmpfs) nor in the scratch of a Rune session that runs them; an in-memory `Db` and the engine test `Harness` remove their own folder. `rm -rf target/test-tmp` clears what is left. CLI unit tests read no `rune.toml` (`ui::settings_home`): they run on the `FIELDS` defaults, never on the owner's live settings.
- `RUNE_HOME` (default `~/.rune/`) = the owner's live data. Tests and manual binary runs must use `RUNE_HOME=$(mktemp -d)` / an isolated HOME (pattern of the Python fixtures `Cli/tests/Rune*.py`).
- Known parallel flakes: `store::drafts` (Engine) and the CLI `session_ipc` child-host tests (`child_client_keeps_parent_host_owned_after_new`, `child_session_receives_new_ack_and_multi_hop_handover_succeeds`: a 1 s child-socket wait) — rerun alone, then the whole gate, before calling it a regression. Under load (≳ 8, e.g. after a release build) the `agent.rs` 10 s-wait tests fail at random — `configure_model_while_turn_runs_never_deadlocks_and_cancel_stops_instantly`, `prompt_steer_while_busy_is_accepted_and_injected_into_next_step`, `three_rapid_steers_become_three_separate_user_messages`, `mode_can_be_switched_while_a_turn_is_running`, and `a_hidden_entry_is_said_to_be_hidden_and_can_be_answered` (60 s deadline): measured, they fail only under load.
- Check runtime configuration: `rune -config check|explain`. What Rune keeps per project: `rune -storage [list|prune]`.

## Release & install (binding)

Once a release is done, build release and install to `~/.local/bin/rune`:

1. Fully green quality gate (fmt + clippy + test).
2. Bump the version in `[workspace.package]` of the root `Cargo.toml` — the only place the version lives.
3. `python3 scripts/upgrade_dry_run.py --bin target/release/rune` prints only PASS (credential-free copy of the live home + homes written by every old binary in RuneBackups); review each `rune.toml` diff.
4. Back up to `~/.local/share/RuneBackups/<Label>-<timestamp>/`: the old binary (+ a SQLite snapshot if the change touches the store, via `sqlite3 ... ".backup"` / `VACUUM INTO`, not `cp` — the DB is in WAL mode).
5. Atomic install: copy the new build to `~/.local/bin/rune.new`, then `mv -f` onto `rune` (same filesystem); the previous binary lives only in the backup. Running windows and session hosts take the new build over by themselves when idle — no kill, no relaunch — and the first process of the new build upgrades the home (see Upgrade safety); never force-kill a live host/session.

Skip or defer (state it in the memo) when: the build is not green; it is not a release (local experiment, docs only); the owner declines; or live work makes it safer to wait for an idle handover.

## Upgrade safety (binding)

Every release must reach every person on any machine (owner, 2026-10-16): no `rune.prev`, install path or this-machine assumptions. Contracts: `docs/architecture.md`.

- Nothing optional (official help, drafts, credentials) may stop a start, upgrade check or turn; Rune never replaces the installed binary. Only no room/no write access stops an upgrade, found by `preflight` before any change.
- A stored-shape change = one `upgrade/vN.rs` step + `VERSION` bump; one damaged item never fails a step (`rewrite_sessions`, `Plan::skip`); a changed `FIELDS` default goes in `defaults.rs` `PAST`. Test the step, `every_older_format_reaches_this_build`, a damaged item, and the release dry run.
- A test that may fail an upgrade runs a copied binary, isolated `HOME`/`RUNE_HOME`, never `~/.local/bin/rune`.

## Versioning (binding)

`X.Y.Z`, all plain integers without leading zeros (SemVer/Cargo reject `0.01.0`). While the project is not yet stable, or without an owner instruction, `X` is always 0.

- `Y` 0–99, `Z` 0–9. Routine release: `Z+1`; if `Z=9` → `Y+1`, `Z=0`.
- `X+1` only on owner instruction; `Y` and `Z` reset to 0.
- `Y=99` and `Z=9` → stop and ask the owner.

## Architecture — binding overview

Detailed contracts: **read `docs/architecture.md` before changing engine, protocol, provider, store, sandbox, session, or UI interactions**. Those rules remain binding; this split prevents the opening instruction injection from truncating the owner's rules.

- Frontend uses only `proto::Command` / `Event` through the driver. `perm::Gate` is the sole tool-execution gate; `ToolCtx::write_guard` the sole file-write gate; `net` the sole network gate. Never add a bypass.
- Model, frontend, MCP, file, and network inputs are untrusted. Enforce at the engine, not by prompt; preserve jail, sandbox, checkpoints and secret redaction. A tool panic is a failed call, not a dead engine.
- Prompt/tool declarations are static. Live values are append-only context rows. Store history as immutable rows. An attachment is its path plus the SHA-256 it had when sent (owner, 2026-10-11): read from its path while it still matches; once it changed or is gone, what was sent is read from a copy made only then (from the undo store when Rune changed it), else the attachment says `changed`/`not_found` — never new bytes under an old message — and the model is told by a `<context_update>`. JSONL is conversation/audit truth, SQLite stores registries and ledgers.
- Failures are classified by `Error` variant, never wording. Live/view/replay must agree on status and codes. Write titles are `+N` of the body only (overwrite too); Patch titles measure replaced/replacement text. Sidebar counts are the actual session-start snapshot diff, never sums of titles.
- Retry lives only in `retry/`, retaining the owner's configured curve and exclusions; no provider-directed delay or extra retry loop. Auxiliary work goes through `session/Auxiliary.rs`.
- One session admission and one event bus. Preserve multi-window parity, idle upgrade handover, queued input and background tasks; never kill a live host to install a release.
- Background tasks (`session/BackgroundTask.rs`): the registry is the journal's projection (an end once seen is kept; an unseen one is `Lost` with its reason), states are one capitalised word everywhere (`state_of`), a stop reaches the whole tree by its mark (`platform::terminate_tree`), a wait for typed input is a platform fact (`Pty::input_wait`; `INPUT_WAIT_DETECTION`: every one on Linux, hidden only on macOS, none on Windows) answered with `terminal_send_input`, which only types and returns (its next wait or its end is a wake, read with `manage_process`), a kill is told by its own result and never by a wake after it, and a last window leaving stops the runtime at once but the tasks only after `host.idle_lifetime`. Contracts: `docs/architecture.md`.
- Provider differences are settings/capability data, not model-name branches. Cache prices are accounting, not capability. Preserve prefix shape, tool IDs/content/media, and each dialect's legal cache carrier. 9router thinking is one field, `reasoning_effort` (a level, or `none`); no `reasoning` object (it makes Claude routes redact thinking). Every 9router model — the adapter's fact, never a row's — offers the router's whole level table `ROUTER_LEVELS` (minimal…max, read from its source 2026-10-15; never a hardcoded subset, a per-model list or the upstream's own list) less what its format turns into a request the upstream refuses (`ROUTER_REFUSED`, by format: `claude-budget` `minimal`, HTTP 400 live), or the person's Alt+C options, settled at every door by `ProviderConfig::settle_thinking`; starts Off (`none`, no level beside a name that may carry one) unless the person turned it on (Settings › Models › Alt+C › Reasoning) or chose otherwise on it (`ModelInfo::starts_thinking`, one reading for new session, model and provider switch — `Engine::start_on_model`); is mandatory-thinking or has a default level only where the person set it; Off is always a choice — on `thinkingCanDisable: false` it asks for the least, said beside the switch (`thinking_off_asks_least`); on with no level is "Route default" (`ROUTE_DEFAULT`): nothing sent, the route decides (owner, 2026-10-15).
- Web search/fetch are served through accounts (`[services]`, `settings/services.rs`; one vendor per file in `web/`), sharing the vault ring and eligible model endpoint by account name. Connections manages access only (endpoint/URL, adapter identity, keys), with no Quick Actions, Configuration, route/service switches or payload controls (owner, 2026-10-15). An account may be saved without tool providers (`service.account`), with URL/security validation but no request or claim it works. Tools › Web search/fetch › Provider owns Add/Delete and one exact choice (`service.select`): a direct account or `9router:provider`, like model choices. Add route is an empty field only — no catalog candidates, examples, prefill or default additions. Added providers and explicit selections must each pass one real request through net; adding only keeps, selecting atomically writes the exact pin and service route with revision checks. Deleting a provider keeps its account/keys; choose another before deleting the one in use. `web_search.provider`/`web_fetch.provider` pin account or account:route; missing pin target is unavailable, never another. Unset search = first switched on; unset fetch = built-in reader (a third-party reader is never automatic). Kept gateway routes survive being switched off, are capped by `services::MAX_ROUTES`, and use the vendor spelling its door accepts (`exa`, never `exa/search`); format19 resolves old gateway pins once, no runtime legacy fallback. Provider timeout belongs to Runtime, fallback/catalog controls to Models. Vendor output stays as read — snippet markup reduced to words (`web/text.rs`), returned HTML read by the built-in parser. Tool schemas remain query+count / url; who serves is a status value; every actual tool step is a session log line; a key never travels over plain http to another machine. Contracts: `docs/architecture.md`.
- Credentials: disk is truth; an unopenable store is `Unavailable` + cause — never no keys, never overwritten, no new `master.key` beside it; all surfaces show `Secrets::key_state`.
- MCP tools remain behind the static discovery/proxy path; their external schemas are exact and are never relaxed by built-in default normalization.
- Official help: `.rune/skills/rune-settings-guide/`, offline bundled, user-facing only; no internals. Compiled copy is authority, repair never fatal, personal skills untouched. Changes require help+coverage updates; full contract: `docs/architecture.md` Product help.
- Configuration is hot-reloaded; every default belongs to `FIELDS`. Layout/schema/config changes require an ordered upgrade step and version bump; no runtime legacy fallback.
- `rune.toml` holds the person's choices only — a save never writes a default, "Use default" removes the key so the newest `FIELDS` default holds, and an upgrade changes a default only where the file holds a default, never a choice (owner, 2026-10-14; format 16 `upgrade/defaults.rs` tells them apart by meaning). Every process follows the file: `configuration::Shared` re-reads it at most every `FOLLOW_EVERY`, every engine command checks it first, and whatever must happen on a change keys on `Shared::generation`, never on which reader noticed — a draft window, a windowless host and `-host` included.
- Settings: Appearance owns themes/layout (no conversation preview code); Runtime owns retry/shared network timing; tool-specific command/question/permission timeouts live only in Tools. Editable global keys have one UI home. All text fields consume renderer-published source geometry (`ui/editor.rs`), including Questions, Settings/search and MCP.
- Classifier policy (`CLASSIFIER.md`) is the owner's editable file: normal tools may write/rewrite/delete it, still through Gate/jail/write_guard (owner, 2026-10-13). The first admitted work pins global/project/missing/invalid rules in any mode; pre-work status previews disk without pinning. Only explicit idle `classifier.reload` replaces a live snapshot; failed reload retains it, and a new host reads disk again. Classifier input is the exact proposed arguments plus original user work/steering/clarification and explicit text/image attachments — never file/script/manifest contents collected from command paths. `classifier.context_tools` independently selects the last three settled matching call inputs, not outputs or authorization. One text evidence budget (`classifier.max_evidence_size`, default256KiB) includes formatting; proposed arguments stay complete, image bytes do not consume it but obey the selected model's media/payload limits. Review authority is global CLASSIFIER.md > project CLASSIFIER.md > explicit sourced user restrictions in their work/standing scope; no conflict allows, and missing context/unsupported media alone is not a denial. Human-permission calls skip classifier and sanitizer per call (Gate facts only), never the other gates. Sanitizer is enabled by default for eligible classifier review (explicit false opts out), uses Auxiliary and an append-only source/work/hash ledger, reuses settled extraction/raw fallback across calls/restart, and falls back custom→distinct active→original sources without sanitizing its own output. No user-message-count key. Provider failures/invalid partitions remain failed evaluations. Every outside value is quoted/label-safe. Work source/final metadata on immutable rows survives failure/restart; new work after a final has a new source. Every API request separately obeys its provider's complete serialized-body payload cap; main/classifier/compact quotas are never summed. Compaction keeps original user instructions/steers whole before summarizing in budgeted quoted batches; assistant/tool-result excerpts count32000 Unicode chars/row and call arguments2000chars/call with identity retained. Defaults recent5/output32768/fallback200000; effective model output clamps the instruction length too. Compaction uses auxiliary route/model budget, runtime fallback when larger, and a retry question on needed failures; no stops Failed, cancel stops Cancelled. Sidebar diffs publish after each settled mutation and refresh tracked files only via `session/file_changes.rs` (default1s, `checkpoint.refresh_interval`); content is authority. Stops/resume/upgrade own the watcher lifecycle.

## Conventions

- No emoji/emoticons outside test data, including production comments/messages; escapes are no loophole. Technical UI glyphs and Unicode input handling remain allowed (owner, 2026-10-16).
- A new dependency only if almost all of it is used and writing it ourselves would be worse. Glob/regex/walk/pty/landlock/SSE stay in-tree; the list of legitimate crates is in `Cargo.toml`.
- One file per tool; `tools/mod.rs` holds only trait/registry/ctx/helpers. Tool schema: `action` is **always the first field**, with atomic top-level arguments (not arrays — streaming reason in the doc comment). Some providers decode strictly and send **every declared property, optional or not** (every `cx/*` model, measured 2026-10-10: unused text fields arrive as `""`, a blank, or an invented value), so no two optional fields may exclude each other, every optional field needs a value meaning "the default", and a tool reads optional text through `field_given_str` (empty or blank = not given). Built-in validation canonicalizes optional blank text against its static schema (nested items too), never required payloads or external MCP schemas; provider declarations contain no empty/blank enum sentinel. The repeated-failure notice compares calls without their `action` sentence (`turn.rs` `same_call`) and stays advisory (owner). `patch_file` requires `old_str` to occur exactly once; `create_file` overwrites an existing file (owner decision; the result says `Overwrote`); a path a tool cannot find is `Error::NotFound` — a structured not-executed notice naming the path and the next step, not an I/O failure; misspelled tool names go through the alias map.
- Some modules are deliberately PascalCase via `#[path]` (check: `grep -rn '#\[path' Engine/src Cli/src`); new files are snake_case unless they join a PascalCase group.
- `//!` doc comments explain **why**, not what.
- Configuration hot-reloads via arc-swap (`settings/Configuration.rs`); never snapshot by value. Every default lives in `FIELDS` — no in-code fallback; a key the code reads but `FIELDS` lacks (or reads as the wrong kind) is a hard failure in test/debug builds and returns the `FIELDS` default plus one session log line in release (scanner test `every_literal_key_the_code_reads_is_a_field_of_the_right_kind`); a retired key is an unknown key (the engine refuses to start), never silently mapped. A provider is the adapter its `api` names (`compatible` when none), never guessed.
- No legacy compatibility at runtime: an older layout, config or schema is upgraded once by an ordered step in `upgrade/` (removable once no install can still be at that format), never read by a fallback.
- CLI UI: one `Msg` channel = the single place state changes (no cross-thread locks); frames are built whole and sent as per-line diffs — a row beside the side panel in two pieces split at its seam (`draw::beside`/`seam`), and a page move done by the terminal's scroll when that sends fewer bytes, the panel's displaced cells included (`Shift`, `repaint_cost`) — beside the panel only on a terminal that answered DEC 2026 (synchronized output; `Screen::ask`), since one that draws mid-frame (Konsole) shows the panel jump; colour codes are sent only when the style changes (`ui/sgr.rs`); a changed row is sent from its first changed cell, and only to its last when its width held (`write_changed`, `ansi::cells`) — a row a terminal may count otherwise (a joined emoji, an accent written apart) or holding a link is sent whole from its first column; a frame is followed by `ESC [ 5 n`; on a terminal that shows frames whole (DEC 2026) at most two frames are on their way unanswered (`Screen::AHEAD`), and on one that draws on its own clock (Konsole 25.04; see Frame pacing) one frame at a time, then `Screen::QUIET` (12 ms) with nothing new, then a lone `ESC [ 5 n` answered only once it is done drawing, then the next frame (`Screen::next_at`) — so a slow terminal never queues more and never draws half a frame, and the wheel glides only on a terminal that draws frames whole (DEC 2026) at a measured pace of 30 frames a second or better — a status answer says a frame was read, not drawn, and Konsole/GNOME drew the glide as stutter — elsewhere a notch jumps (`Screen::keeps_up`, `App::terminal_keeps_up`); the terminal's answers are `Key::Terminal` reports, never keys; width is measured with `ansi::width` (columns, not chars).
- Transcript scroll (`draw.rs` `chat_top`): the reader is held by an `Anchor` — the first non-blank row's text plus its `Place` (drawn group, row inside it, the group's height, the width): the same row of the same group when the width held (the text searched near it), the same fraction of the group after a reflow (side panel toggled, terminal resized), never a bare row number. An overlay that replaces the chat (`/help`, `/logs`, `/context`, `/undo`, …) scrolls in its own `PanelView` (`ui/panel_view.rs`) and never touches the chat's place. `/undo` and `/context` start at the top and keep semantic item/source-line anchors through split/resize; only navigation/preview requests reveal the chosen rendered range, so page/wheel reads never snap back. `/undo` draws one file per row, turn/time in fixed columns, hanging path continuations, counts against the right edge and the Rune `›` chevron; `/context` separates tools/messages and their metadata with headings and rules; source text is plain, indented four columns, without a decorative left gutter. Renderer-owned ranges govern scrolling; stale panel/preview responses never reopen or re-arm a superseded choice. Scrolled away from the newest row, the centred hint `Press Ctrl+↓ Jump to latest` is laid over the chat's last row, covering only its own columns and a blank each side (`ansi::overlay`; `JUMP_HINT`; hidden under an overlay, a card, a form or the slash palette; a click on it jumps); `Key::CtrlDown` jumps from anywhere. A wheel notch moves `ui.scroll_lines` (default 2) rows whatever the pace (no acceleration — owner); with Ctrl or Alt held `FAST_WHEEL` (3×) as far through the same glide (`wheel_scroll_at`); terminals may keep these combinations for themselves (Konsole zooms on Ctrl+wheel unless its profile says otherwise; Qt turns Alt+wheel sideways), so they are extras, never the only way.
- Input: `ui/editing.rs` owns keymaps; `ui/editor.rs` geometry; `ui/navigation.rs` screen ownership. Contracts and regressions: `docs/architecture.md`.
- Composer: an empty input stays one editable row; multiline input grows to at most 11 editable rows, clamped to preserve conversation space on short terminals. Keyboard, mouse and soft wrap use the same plain editor projection and glyph-width measure (tabs shown as four spaces, control/escape sequences never styles; combining suffixes, variation selectors and ZWJ sequences never split between visual rows), translating display positions back to original UTF-8 source bytes. A message leaves the composer at its Enter: one sent while the host has an edit unconfirmed waits in `composition.submits` (the composer as it stood at its Enter, the host brought to exactly that, sent in order once it holds it), and what is typed meanwhile is the next message's — never glued on (`a_message_is_what_was_there_at_its_enter_whatever_the_host_still_confirms`). A late prompt ACK never rolls the authoritative composer revision back; the renderer publishes row hit geometry, so a click places the caret on that visual row and blank space goes to its end. Mouse presses/drags/releases reach the shared click/selection handler even in Settings and MCP input; wheel events retain their surface-specific routing. Settings/navigation tolerate one-cell release jitter; real drags select rather than activating controls. The session picker publishes its own rendered card hits: a click selects, a click on the selected card resumes. Sent user messages are display-folded to the same four visual rows and `lines cut` footer as tool previews; clicking the box opens/refolds it. Their complete content is stored and sent unchanged, with fold state only in CLI blocks and cache fingerprints.
- Main-chat previews (`Cli/src/ui/viewport.rs`) and permission readers are different surfaces. Non-open tool previews start at minimal height (command only when no output yet) and grow as content arrives up to at most four visual content lines, cutting the remaining suffix below with `… N lines cut. Click to open all`. The fold marker is always AFTER the entire preview (head preview), never between a tool notice and its output or at the top; it is a display fold, not deletion. Explicit Open All click expands to full output. `↑/↓ N rows above/below · wheel here` belongs only to genuinely scrollable readers such as permissions and the sidebar. Counts come from rendered visual lines. Terminal output box does not reserve blank padding: before output arrives it has no divider and no output rows; once output arrives it grows line-by-line up to 4 lines, retaining only the live rows actually occupied so erase frames do not flicker. Permission/question readers retain their separate larger height allowance, pinned controls and scroll geometry. Ask-user custom answer caret renders after the final character without right-margin truncation.
- Permission UI (`Cli/src/ui/permission.rs`): every permission is one bounded scrollable document with pinned answer buttons. The wheel is row-scoped, including spent directions; Up/Down and PageUp/PageDown move an overflowing card, while the transcript above stays wheel-readable. Terminal permission contains the shell command only and uses `Bash` as its title; only engine-confirmed reach/service/unconfined facts add a compact warning in that title, never a duplicate list of path candidates. The reach scanner recognises inline awk programs as programs (not paths rooted at `/`), while still scanning script files, input operands and redirections; the jail/sandbox remain the execution boundary. Create/patch use `Create <path> +N` / `Patch <path> -N +N` as one box title, with added/removed counts green/red and no nested code/diff box. Shell commands and create bodies reuse the syntax highlighter; patch bodies retain diff colours only. The renderer publishes geometry/hit ranges, and the document/diff is cached per request and width.
- Foreground terminal output (`Engine/src/terminal_screen.rs`): AVT interprets the PTY stream incrementally in a private grid shared by the CLI and the final model-visible result, including backspace, CR, cursor movement, erase and alternate-screen operations. The screen gets the grid's rows; the model gets the command's lines — a row the grid wrapped (AVT's own wrap mark, never guessed from width) is joined back, so a narrow box never splits a line the model reads (`terminal_screen.rs` `Row`). Only plain screen rows leave the adapter; command escapes cannot resize the grid, set the outer window title, or access the clipboard. `ToolOutput` carries the actual PTY rows/cols; a live session keeps complete geometry segments (bounded by `terminal.max_output_size`) until the result replaces them, never an arbitrary raw-byte tail that loses cursor state. The CLI sizes the PTY for its terminal box at session start and on layout changes, and output revisions invalidate same-length spinner redraws in the transcript cache. The non-open box starts command-only, grows monotonically with output up to four rows, and retains live occupied row slots during erase frames to avoid height flicker. Output is head-previewed, and `lines cut` appears below. Ask→Allow/Full use identical preview geometry. A background log is read through the same grid (drained rows → log, the grid → `tail`).
- Media: type from bytes, not from the extension; a model that cannot accept a file is still told it exists. One decision for every reader (`media::kind_of` over `media::SNIFF_BYTES`): a prompt attachment, `inspect_file` (text read with line numbers, only what is not text attached) and `search_text` ask the same question; binary = a NUL among bytes that are not UTF-8 (NULs inside UTF-8 text — a log a power cut ended with zeros — stay text, shown as `␀`).
- Tests = contracts: unit tests in the same file; integration tests in `Engine/tests/` (real end-to-end, no stubs beneath the provider); `Cli/tests/` + Python PTY fixtures.

## Owner rules (binding)

1. **Memo** = the coding agent's project memory, outside the repository (Rune: `@memory/`; Claude Code: built-in auto memory). After every audit, implementation, or change → save its summary there, unless the owner forbids it. Never store secrets.
2. **Ambiguous → ask first.** Do not work on anything that is not certain.
3. **Think and design like a senior architect.** Start by understanding the existing system: proven helpers and patterns are reused before anything new is written. Every change is designed with the best industry-standard architecture: each module has a single responsibility and a firm boundary, contracts between layers are explicit, the impact on other parts is traced before code is written, and the result is easy for others to maintain and extend. Weigh several alternatives, choose the most robust one for the long term, and resolve the root cause permanently (a temporary solution only when asked). Code born from this kind of consideration is tidy and consistent by itself. This file's conventions rank above general practice.
4. Every fix = a regression test + run the tests of the affected feature.
5. **No silent scope expansion:** ask before a user-owned decision, external installation change, or security tradeoff.
6. **Standalone Git repository:** `Studio/` is the repository root, with remote `https://github.com/TakuyaSeija/RuneCLI.git`; the parent `Atoryn/` is only a container for independent projects and must stay free of Studio's Git/config/docs. Each sibling project owns its own repository; `Engine/` and `Cli/` remain crates in this one repository, not nested Git repos. Track source/tests/assets, `Cargo.lock`, and `.cargo/config.toml`; ignore build/runtime/secret data and root `tmp/` (local scratch only, never a build input). Run Git/Cargo from Studio, see `docs/git.md`, and run `python3 scripts/check_git_policy.py --check-tracked` plus `python3 -B scripts/test_git_policy.py` after changing Git policy. Keep `AGENTS.md` and `CLAUDE.md` synchronized. Inspect status and preserve owner changes before a refactor; never silently stash, reset, commit, push, select a license, or configure global Git identity. Untracked/uncommitted files have no committed recovery point — copy to `~/.local/share/RuneBackups/` before a multi-file refactor when Git cannot safely recover their current state.
7. **Security stands level with architecture.** Rune's security is weighed from the plan onward with the same weight as its architectural design, not patched in afterward. Every change is reviewed from the trust-boundary side: model output, file contents, MCP/network responses, and frontend input are treated as untrusted until they pass the single gates (`perm::Gate`, `write_guard`, `net`); access is granted at the minimum needed; failure ends in denial, not in relaxation; secrets stay in the vault and `net/redact`. If a change widens the attack surface or weakens a layer of defense, say so and ask the owner before continuing (rule 2).
8. **Cross-platform from the design stage.** Rune targets Linux, Windows, and macOS across many versions, so its behavior must not depend on the user's system configuration (e.g. `fstab`, mount points, shell profiles, distro directory layout, system tools assumed to be installed). The engine brings everything it needs; OS capabilities are detected at runtime, not assumed from a distro name or version. OS-specific code is confined behind `platform/` (gate: `platform::boundary`) with the same contract on every OS, and the core guarantees (`perm::Gate`, `write_guard`, jail) stay held by the engine so they are identical on every OS; kernel mechanisms such as Landlock are a per-platform layer on top of them.
9. **CLAUDE.md is a living document.** Update this file together with the change when a rule or piece of project information is permanent and long-lived, e.g. a workspace that had no Git now uses it; the owner explicitly asks for this file to change; or a thorough refactor of a feature makes the description here no longer true. Its content is always the current state, not a change history. Anything temporary, task-specific, or fast-changing goes in the memo only (rule 1).
10. **Speak the owner's language.** Every reply, question, and report to the owner is written in the language the owner is using, and follows when the owner switches. If a message mixes languages (e.g. a question in one language about pasted text in another), use the language of the owner's own words.

## Known pitfalls

- The engine reads project instructions from the workspace's **`AGENTS.md`** (`AGENTS_FILE` in `session/prompt.rs`), not from this CLAUDE.md.
- Live `~/.rune/`: do not delete `rune.db-wal`/`-shm` and `*.lock` (active, not junk); tests must not mutate it; never read or print `master.key` and `secrets.vault`.
- macOS/Windows: verified only by CI on real machines (`studio-ci.yml`; on `crossplatform` macOS needs `[ci macos]` in the commit), type-checked by `scripts/xcheck.sh <triple> clippy …`; Wine is a smoke test, never a reason for a weaker design (owner, 2026-10-17). Windows ACL grants are recorded before written (`rune -sandbox reset`), never on Windows's own folders.
